## What Didn't Go Well

### C-1: Near-miss on deleting wrong theoretical-profit module (Story 100.2)
Two modules with similar names: `src/lib/theoretical-profit.ts` (standalone, NOT deprecated, used by TheoreticalProfitCard + ProfitBreakdownPopover) vs the daily-pipeline version in `src/lib/daily/aggregation.ts` (deprecated). The only defense was a dev-note warning in the story spec. No structural protection.

### C-2: High review-finding count for a "deletion" epic
22 total findings across 3 stories that were scoped as simple deletions. Deletion has wider blast radius than expected: re-exports, baselines, stale references, skeleton counts, test fixtures.

### C-3: Baseline churn across every story
Every story changed at least one quality-gate baseline. 100.1: tests 7244→7216. 100.2: tests 7216→7205, TS 20→21, citations 13→20. 100.3: TS 21→19. Each required CLAUDE.md Accepted Baselines updates.

### C-4: "Commit before done" agreement broken for 3rd consecutive epic
Despite explicit team agreement in Epic 97 retro and reaffirmed in Epics 98 and 99, all 3 stories in Epic 100 were marked `done` before committing. The workflow lacks structural enforcement.

### C-5: 0 of 4 Epic 99 action items fully closed
A-1 (CI integration): not done. A-2 (fix-propagation monitoring): not tested. A-3 (any warnings): passive reduction only. A-4 (TS errors): passive reduction only. Carry-forward rate is concerning.

### C-6: AC numbers drifted in story specs
As baselines shifted between stories, acceptance criteria in story files became stale. Story 100.3's 2nd-pass M-1 updated AC #6 from "21 errors" to "19 errors" to match actual output.

## Lessons Learned

1. **Deletion has wide blast radius** — removing code cascades to re-exports, test fixtures, baselines, skeleton counts, and JSDoc references. 22 review findings across 3 "simple" deletion stories proves this. (Stories 100.1-100.3)
2. **Similar-name modules need structural protection** — dev-note "DO NOT DELETE" warnings are insufficient. Add a greppable marker comment at the top of surviving modules listing active consumers. (Story 100.2 near-miss)
3. **Empty describe blocks cause Vitest suite failures** — always remove or populate. An empty `describe()` with zero test cases causes the entire suite to fail. (Story 100.2 H-1)
4. **Phantom story references in JSDoc need `FUTURE:` prefix** — references to stories not yet created confuse future developers. Use `FUTURE:` prefix for forward references. (Story 100.2 M-3)
5. **Skeleton card count must match data card count** — after removing a card, update both the data array AND the loading-state skeleton Array(N). Grid mismatch is a visible UI bug. (Story 100.3 H-1)
6. **Process agreements without structural enforcement decay** — "commit before done" broken 3 epics running despite explicit agreement. Prose-only commitments need automated enforcement. (Epics 98-100 systemic pattern)
