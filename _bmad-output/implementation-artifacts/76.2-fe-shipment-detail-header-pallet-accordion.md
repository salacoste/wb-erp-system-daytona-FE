# Story 76.2: Shipment Detail — Header + Pallet Accordion

Status: done

## Story

As a **seller**,
I want to view and edit shipment details with an expandable pallet layout,
So that I can organize my shipment's physical structure before calculating costs.

## Acceptance Criteria

1. **Header display** — Given a shipment at `/shipments/:id`, display: name (or "—" if null), status badge (ЧЕРНОВИК outline / ПОДТВЕРЖДЕНА default), delivery mode label, cost field formatted via `parseDecimal()` → `formatCurrency()`, created/updated dates via `formatDate()`.
2. **Edit dialog (DRAFT only)** — "Редактировать" button opens dialog pre-filled with current values: name, cost field (totalDeliveryCost for FIXED_VEHICLE, palletRate for PER_PALLET). Note: `deliveryMode` is NOT updatable (backend rejects). Submit → `PUT /v1/shipments/:id`. Dialog uses `<form onSubmit>` + `<Button type="submit">`, blocks close during pending.
3. **Delete shipment (DRAFT only)** — "Удалить отправку" button opens confirmation dialog with text "Вы уверены? Это действие невозможно отменить." Confirming → `DELETE /v1/shipments/:id` → navigate to `/shipments` list.
4. **Add pallet (DRAFT only)** — "Добавить паллету" button → `POST /v1/shipments/:id/pallets` (empty body). New pallet appears expanded by default. palletNumber auto-incremented by backend.
5. **Pallet accordion rendering** — Each pallet shows as collapsible section: header "Паллета #N" + box line count "(X товаров)". All pallets independently expandable/collapsible via shadcn Collapsible.
6. **Remove pallet (DRAFT only)** — Each pallet has remove button. Confirmation warns: "При удалении паллеты будут удалены все товары в ней." Confirming → `DELETE /v1/shipments/:id/pallets/:palletId`.
7. **CONFIRMED state** — When status=CONFIRMED: hide edit/delete/add-pallet/remove-pallet buttons. Show lock indicator (e.g., Lock icon in header).
8. **Component extraction** — All files ≤ 200 lines. Sub-components: `ShipmentDetailHeader.tsx`, `ShipmentEditDialog.tsx`, `PalletAccordion.tsx`, `PalletAccordionItem.tsx`. Page file `[id]/page.tsx` ≤ 100 lines.
9. **Loading/error states** — Loading skeleton → Error alert with retry → Detail content. Follow existing page pattern from `box-types/page.tsx`.
10. **All files ≤ 200 lines**, 0 ESLint errors, 0 TypeScript errors.

### Architecture Patterns (MUST follow)

**API client** — Add to existing `src/lib/api/shipment-cost/shipments-api.ts`:
```typescript
/** POST /v1/shipments/:id/pallets — empty body, auto-numbers */
export async function addPallet(shipmentId: string): Promise<Pallet> {
  return apiClient.post<Pallet>(`/v1/shipments/${shipmentId}/pallets`)
}

/** DELETE /v1/shipments/:id/pallets/:palletId — 204, cascade box lines */
export async function removePallet(shipmentId: string, palletId: string): Promise<void> {
  await apiClient.delete(`/v1/shipments/${shipmentId}/pallets/${palletId}`)
}
```

### Backend API Endpoints

| Method | Endpoint | Request | Response | Notes |
|--------|----------|---------|----------|-------|
| GET | `/v1/shipments/:id` | — | `Shipment` (full with pallets/boxLines) | Already in 76.1 hooks |
| PUT | `/v1/shipments/:id` | `ShipmentUpdateRequest` | `Shipment` | DRAFT only. `deliveryMode` NOT updatable |
| DELETE | `/v1/shipments/:id` | — | 204 No Content | DRAFT only, cascade all |
| POST | `/v1/shipments/:id/pallets` | (empty) | `Pallet` | Auto-number, DRAFT only |
| DELETE | `/v1/shipments/:id/pallets/:palletId` | — | 204 No Content | DRAFT only, cascade box lines |

**Error codes**: 400 (validation), 404 (not found), 409 (confirmed — cannot mutate).

**IMPORTANT: Backend uses PUT, NOT PATCH.** The existing `updateShipment` function already uses `apiClient.put`. The epic spec mentions PATCH but backend actually uses `@Put()`. Keep using PUT.

### CONFIRMED State UI

When `shipment.status === ShipmentStatus.CONFIRMED`:
- **Hide**: Edit button, Delete button, "Добавить паллету" button, pallet remove buttons
- **Show**: Lock icon (from lucide-react) next to status badge
- All content is **readonly** — pallets still expandable but no mutations

### Edit Dialog Specifics

The edit dialog should:
1. Pre-fill `name` from current shipment
2. Show cost field label based on `deliveryMode` (same as CreateShipmentDialog)
3. Pre-fill cost value from `parseDecimal(shipment.totalDeliveryCost)` or `parseDecimal(shipment.palletRate)`
4. **deliveryMode is NOT editable** — display as read-only label, no radio group
5. Validate: name required, cost > 0
6. Submit via `useUpdateShipment()` with `{ id, data: { name, [costField]: costNum } }`
7. Wrap mutateAsync in try/catch, show error on failure

### Anti-Patterns to Avoid

1. **Do NOT use `AlertDialogAction`** for async submit buttons — use `<Button>` with manual dialog close
2. **Do NOT use `vi.doMock()`** in tests — use mutable variable + getter in `vi.mock()` factory
3. **Do NOT forget `aria-label`** on icon-only buttons (edit, delete, remove pallet, expand/collapse)
4. **Do NOT forget `aria-describedby` + `aria-invalid`** on form inputs with validation errors
5. **Do NOT forget `DialogDescription`** — Radix warns without it
6. **Do NOT create duplicate types** — all shipment types live in `src/types/shipment-cost.ts`
7. **Do NOT exceed 200 lines** in any file — split early if approaching 180+
8. **Do NOT try to edit deliveryMode** — backend returns 409; show as read-only label in edit dialog
9. **Do NOT forget `skipDataUnwrap: true`** if adding any paginated endpoint (76.1 lesson: auto-unwrap strips `{ data: [...] }`)
10. **Do NOT forget try/catch** on `mutateAsync` calls — show error feedback to user (76.1 code review finding)
