## Dev Notes

### Architecture Patterns (MUST follow)

**Test file organization** — All component tests go in `src/components/custom/shipments/__tests__/`. Hook tests in `src/hooks-v1/__tests__/`. Page state tests in `src/app/(dashboard)/shipments/__tests__/`.

**Test utilities** — Always use:
```typescript
import { createTestQueryClient, createQueryWrapper } from '@/test/utils/test-utils'
// For component tests:
import { render, screen } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
// For hook tests:
import { renderHook, waitFor, act } from '@testing-library/react'
```

**Mock patterns** — All hooks tests mock API functions (NOT hooks) and use `vi.mocked()` for type-safe assertions:
```typescript
vi.mock('@/lib/api/shipment-cost', () => ({
  addPallet: vi.fn(),
  removePallet: vi.fn(),
}))
import { addPallet, removePallet } from '@/lib/api/shipment-cost'
```

**Component mock patterns** — Mock hooks (NOT API functions) at the hook level:
```typescript
vi.mock('@/hooks/use-shipments', () => ({
  useDeleteShipment: () => ({ mutateAsync: mockDeleteAsync, isPending: false }),
}))
```

**Query keys to verify** — Defined in `use-shipments.ts`:
```typescript
shipmentsQueryKeys.all()       // ['shipments']
shipmentsQueryKeys.list(params) // ['shipments', 'list', params]
shipmentsQueryKeys.byId(id)    // ['shipments', 'detail', id]
```

**File size limit** — All source files MUST stay under 200 lines. Test files should aim for <200 but may slightly exceed if needed (ESLint rule `max-lines-per-file` is configured but doesn't actually fire — it uses a non-standard rule name).

### Previous Story Intelligence (76.5)

**Key learnings from 76.5 code review**:
1. Optional chaining short-circuit: `onCallback?.(await asyncFn())` — if `onCallback` is undefined, `asyncFn()` is NEVER called. Always use 2-line pattern: `const result = await asyncFn(); onCallback?.(result)`
2. Always add generic error toast fallback in catch blocks — don't silently swallow non-400/non-409 errors
3. `useAuthStore` selector pattern: `useAuthStore(state => state.user?.role)` — use selector, never `getState()` in render
4. Test async error paths need `waitFor` wrapping: `await waitFor(() => { expect(toast.error)... })`
5. The `src/hooks` symlink to `src/hooks-v1` causes ESLint parsing errors on `hooks-v1/` path — this is pre-existing, not a real issue. Import through `@/hooks/` path for clean ESLint.
6. Dual cache invalidation: mutations always invalidate both `shipmentsQueryKeys.byId(id)` AND `shipmentsQueryKeys.all()`

**Code review fixes applied in 76.5**:
- `handleMutationError()` helper for DRY error handling
- `queryClient.invalidateQueries({ queryKey: ['shipments'] })` on 409 conflict
- Email guard: `if (!userEmail) { toast.error(...); return }`
