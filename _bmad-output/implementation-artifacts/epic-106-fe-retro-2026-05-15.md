## What Didn't Go Well

### C-1: 1st-pass review's allowlist count was inaccurate
1st-pass reviewer said "66 → 65" — actual count was 64 → 63 per the agent triage report cited in the epic spec. Off-by-2 in the count means the reviewer didn't grep precisely. Not a code defect but an attestation drift in the review itself. Caught by 2nd-pass which used `grep -c` and reported correct counts (64 before, 63 after). Authoritative-source-citation discipline (Story 97.2-FE) applies to reviewers too, not just authors.

### C-2: Story 106.1 initial implementation had high test-update count not in commit message
Executor's commit message said "2 test assertions updated" but actually modified 4 (across 2 files). 2nd-pass reviewer flagged this as LOW attestation drift. Pattern: count-the-things claims should be grep-verified at commit-message-draft time. Recurrence of the same pattern as Story 104.2's "8 vs 7 fields" off-by-one — author memory under-counts.

### C-3: Reducer null-preservation logic required careful design
Story 106.1's 2-pass review fix introduced a smarter reducer in `table-columns.ts:188-191`: `day.theoreticalProfit === null && acc.theoreticalProfit === null ? null : (acc ?? 0) + (day ?? 0)`. The pattern preserves null only when both accumulator and current day are null, becomes numeric on first real value. This is a non-trivial logic — easier to get wrong than right. A future contributor copying the pattern without understanding could write `?? 0 + ?? 0` for "simplicity" and re-introduce the same bug Story 106.1 fixed. The codification in CLAUDE-PATTERNS.md AGGREGATION-REDUCE pattern needs the "null-preserving accumulator" footnote, which it has — but discoverability depends on authors reading the pattern doc.

### C-4: Pattern documentation took ~15% of total epic effort
Story 106.3 (~0.5 SP estimate) ended up consuming significant time on Russian-grammar review, file:line citation verification, and don't-confuse-with edge case enumeration. Documentation work has hidden long-tail effort that's underestimated. Not a defect but worth flagging for future process-tooling epic estimation.

### C-5: Delegation-notice hook fired ~25 times this session
Same recurring noise issue from Epic 104-FE A-4 and Epic 105-FE A-3. Still unresolved. Each fire bloats context with a system reminder. The hook heuristic is "command contains `>`" or similar — fires for benign read-only stuff like `grep > head` pipes, `bash scripts/check-*` (which only modify baseline files), etc. Should be a structural fix but is structurally lower priority than feature work.

## Lessons Learned

1. **Pre-flight triage scope-revision is the empirical proof of Story 105.2-FE's value** — Epic 106 initial estimate 6-8 SP, post-triage estimate 2.5 SP, actual delivery 2.5 SP. The triage agent saved 4-5 SP of speculative scope. Make pre-flight verification AT EPIC SPEC AUTHORING TIME standard practice, not just at story dev time. (Epic 106-FE)
2. **Type-widening fixes propagate to producers AND consumers** — Story 106.1's `number | null` change required updates in: 1 source-of-truth, 2 producers (`createEmptyDailyMetrics`, `calculateTotals` initial), 3 consumers (display guards, reducer, sort comparator), and 4 tests. The "type widened in one place" mental model under-counts by ~6x. 2-pass review caught the gap; structural enforcement is hard. (Story 106.1 2-pass)
3. **Canonical-pattern documentation works best with don't-confuse-with sections** — each of the 6 Anti-Pattern #8 Exceptions has a "Anti-pattern (don't confuse with)" subsection explaining how to distinguish from a real violation. Without this, the BACKEND-CONTRACT-NON-NULL pattern could be over-applied to any field; SEMANTIC-ZERO could be misused for `revenue: 0` (which is NOT semantic-zero). The negative examples define the boundary. (Story 106.3)
4. **63-of-64 legitimate exceptions reframe the discipline** — going in, the assumption was "many allowlists are real violations." Going out, the truth was "99% are legitimate; 1 was a real catch." This is good news — the ESLint rule's false-positive rate is high but acceptable when paired with the exception taxonomy. Future Anti-Pattern style rules should plan for similar high-FP-rate-with-allowlist-taxonomy approach. (Triage findings)
5. **Mechanical sweeps work when the triage table is the source of truth** — Story 106.2 executor used the explorer agent's triage table directly as the per-site rationale source. Zero ambiguity, zero ad-hoc decisions during the sweep. Pre-computed truth tables are the executor's friend. (Story 106.2)
