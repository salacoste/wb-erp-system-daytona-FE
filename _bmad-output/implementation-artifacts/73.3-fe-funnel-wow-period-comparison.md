### Previous Period Calculation

The funnel page uses **date ranges** (not ISO weeks). The "WoW" comparison here means:
- Current period: `from` to `to` (e.g., 2026-02-07 to 2026-03-08 = 30 days)
- Previous period: shift back by same duration (2026-01-08 to 2026-02-06 = 30 days)

```typescript
import { differenceInDays, subDays, format } from 'date-fns'

export function calculatePreviousPeriod(from: string, to: string) {
  const fromDate = new Date(from)
  const toDate = new Date(to)
  const days = differenceInDays(toDate, fromDate) + 1 // inclusive
  const prevTo = subDays(fromDate, 1)
  const prevFrom = subDays(prevTo, days - 1)
  return {
    prevFrom: format(prevFrom, 'yyyy-MM-dd'),
    prevTo: format(prevTo, 'yyyy-MM-dd'),
  }
}
```

### Reusable Comparison Infrastructure

The project already has comparison utilities in `src/lib/api/analytics-comparison.ts`:
- `calculateDelta(current, previous): DeltaValue` — returns `{ absolute, percent }`
- `getChangeDirection(delta): 'up' | 'down' | 'neutral'`

**Decision**: Create local `calculateFunnelDelta` instead of importing from analytics-comparison, because:
1. The analytics-comparison module is tightly coupled to weekly/ISO-week comparison
2. We need a simpler return type (`{ percent, direction }` not `DeltaValue`)
3. Keeps funnel self-contained, avoiding cross-module dependency for simple math
4. If future stories need shared delta logic, refactor then (YAGNI)

### Inverted Metric Semantics

For most metrics, "up" = good (green), "down" = bad (red). But for **cancelCount**, the semantics are inverted:
- cancelCount going UP = bad → red arrow
- cancelCount going DOWN = good → green arrow

Implementation: Add `invertedMetric?: boolean` to the card definition, default false. The `getDeltaColor` function flips colors when `isInverted` is true.

### URL Param Toggle Pattern

Following existing patterns from `src/app/(dashboard)/analytics/orders/page.tsx` and others:

```typescript
'use client'
import { useSearchParams, useRouter, usePathname } from 'next/navigation'

// Read
const searchParams = useSearchParams()
const compare = searchParams.get('compare') === 'wow'

// Toggle
const router = useRouter()
const pathname = usePathname()
function toggleCompare() {
  const params = new URLSearchParams(searchParams.toString())
  if (compare) {
    params.delete('compare')
  } else {
    params.set('compare', 'wow')
  }
  const qs = params.toString()
  router.replace(qs ? `${pathname}?${qs}` : pathname)
}
```

**Important**: `useSearchParams()` requires `<Suspense>` boundary in Next.js 15. The funnel page (`src/app/(dashboard)/analytics/funnel/page.tsx`) should already have this since it uses client components. Verify during implementation.
