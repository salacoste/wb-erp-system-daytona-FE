## Dev Notes

### Proven Extraction Patterns (from Stories 74.1-74.6)

**Sub-Component Extraction** (proven in 74.1, 74.6):
```typescript
// Co-located sub-component file
'use client' // REQUIRED if component uses React hooks/state
export function SectionComponent({ data }: Props) { ... }
```

**Chart Config Extraction** (proven in 74.1 PnLWaterfall, 74.3 charts):
```typescript
// *-config.ts — pure data/config, NO 'use client'
export const CHART_CONFIG = { ... } as const
export function getChartOptions(data: ChartData) { ... }
```

**Page State Hook Extraction** (proven in 74.2 analytics pages):
```typescript
// use*PageState.ts — extracts all useState/useMemo/useCallback from page
'use client'
export function usePageState(params) {
  const [state, setState] = useState(...)
  // ... all state logic
  return { state, handlers }
}
```

**Barrel Re-Export** (proven in all 74.x stories — CRITICAL for backward compatibility):
```typescript
// Keep original file as thin orchestrator importing extracted pieces
export { Component } from './extracted-component'
export type { ComponentProps } from './extracted-types'
```

### Critical Rules

1. **NEVER change functionality** — pure structural refactoring only
2. **`'use client'` rules**:
   - Original has `'use client'`? Extracted sub-components with hooks/state ALSO need it
   - Original has NO `'use client'`? Don't add to extracted files unless they use hooks/state
   - `orders/page.tsx` is the ONLY file without `'use client'` — extra care required
   - Pure config/data files NEVER need `'use client'`
3. **Run tests after EACH file split** — don't batch validation
4. **Aim for 150-180 lines** — leave headroom below 200-line limit (74.6 review finding: files at 197 have too little headroom)
5. **Extracted files must also be ≤200 lines** — don't just move the problem
6. **Barrel re-exports** preserve consumer import paths — no codebase-wide updates
7. **Don't duplicate types** — import from source files (74.2 code review finding)
8. **Don't duplicate utils** — check if shared util exists before creating per-component utils (74.6 code review finding: `top-table-utils.ts` deduplication)
9. **Delete dead code** — don't leave orphan files from failed extraction attempts (74.6 code review finding)
