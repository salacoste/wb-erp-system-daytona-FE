The convergence validates the 2-pass model — same defect class found independently, with the 2nd pass providing stronger severity calibration via authoritative-source citation.

## What Didn't Go Well

### C-1: Initial triage over-reported "real" work scope
The 32 "Remaining frontend action" file triage from earlier today identified 9 "REAL" items; verification showed 8 of 9 were already shipped, leaving only 1 real gap (advertising fetcher enrichment). The triage agent's pattern-match was too loose — files describing "what backend offers" got conflated with "what FE needs to do." The triage should have included grep-verification against `src/` for each candidate.

### C-2: Original "10th category" framing was a triage misread
My backend-open-blockers memo from earlier today said "Unit Economics dashboard shows 9 categories instead of 10 (missing `delivery_to_warehouse`)" — but actually 10 categories exist including `delivery_to_warehouse`. The framing came from backend's own message ("Почему 9 категорий вместо 10?") which itself may have been based on a stale observation or a debugging session that pre-dated Story 77.5's shipping. Never propagate counts from another team's message without verifying against current source.

### C-3: Initial Story 104.2 implementation collapsed nullability without thinking
The executor used `?? 0` for all 9 fields by default — a reasonable defensive pattern, but wrong for money/ratio fields per project convention. This is the 6th instance of an Anti-Pattern #8 violation across Epics 87-104. The discipline is codified in CLAUDE-ANTI-PATTERNS.md but doesn't ship as an automated lint rule, so the only countermeasure is 2-pass review. The Epic 87-FE retrospective flagged this exact class as Anti-Pattern #8; 17 epics later it still recurs.

### C-4: Story 104.2 commit message had off-by-one ("8 new fields" vs 7)
The 2nd-pass review flagged: commit `9b26306` body says "extend AdvertisingDailyData with 8 new fields" — but only 7 were added (`views`, `clicks`, `ctr`, `cpc`, `orders`, `revenue`, `roas`). Pre-existing was `date` + `total_spend` (2). The title "all 9 fields" is correct (2 + 7). Commit messages are immutable post-commit per discipline — can't fix retroactively. Logged as attestation drift; mitigation for future: count fields explicitly in HEREDOC drafts before committing.

### C-5: Soft delegation-notice hook fired ~15 times during session for read-only commands
The `[DELEGATION NOTICE]` hook is heuristic-based and fires for ANY bash command that "may modify source files" — including read-only `grep`, `git log`, `bash scripts/check-*.sh` invocations. Over the session this generated significant noise (each fire is a system reminder added to context). Not a defect in this epic's code, but a process-tooling debt item: the heuristic should be tightened to actually-write commands.

## Lessons Learned

1. **Verify before implementing — pre-flight source-trace saves duplicate work** — Stories 104.1 (no-op via Epic 91-FE) and 104.3 (no-op via Epic 77-FE) both shipped without code changes after empirical verification. The pattern is: read the existing code first, identify the real gap, then scope the story. Skipping verification leads to "reimplementing what's already there" waste. (Stories 104.1 + 104.3)
2. **Anti-Pattern #8 recurrence chain validates the 2-pass review discipline** — 6th instance of `?? 0` on money/ratio fields across Epics 87-104. The codified anti-pattern doc isn't enough; only 2-pass review with the explicit document reference catches it consistently. Consider an ESLint custom rule to detect `?? 0` on fields named `revenue|profit|cost|spend|roas|ratio|*_pct` — would convert this discipline to automated enforcement. (Story 104.2 review)
3. **Don't propagate counts from other teams' messages without verification** — Backend's "9 vs 10 categories" framing was wrong (categories were already 10); but it was embedded in my tracking memo and shaped Story 104.3 scope. When another team makes a numerical claim, grep the source before treating it as authoritative. This is the authoritative-source-citation discipline (Story 97.2-FE) applied to cross-team coordination. (Story 104.3 verification)
4. **Backend coordination messages benefit from "what's shipped" verification on FE side** — The 32-file triage from earlier today over-reported real work because requests describe "what's available from backend" not "what FE needs to do." Future cross-team audits should pair backend's status with FE-side grep-verification of each item. (Epic 104-FE planning)
5. **Citation baseline can drift downward as a positive side effect** — Story 104.2's file growth resolved 2 stale broken citations (citations to lines that no longer exceed file length). Periodic legitimate file growth corrects historical citation drift. Don't panic when the baseline diff shows resolution; check whether the resolution is genuine before updating. (Story 104.4 gate verification)

## Action Items for Next Epic / Process

### A-1: ESLint custom rule for `?? 0` on money/ratio field names

**Context**: Anti-Pattern #8 recurred 6+ times across Epics 87-104 despite explicit codification. Only 2-pass review catches it. Prose enforcement has empirically high skip rate per Story 97.7 investigation finding.

**Action**: Author an ESLint custom rule (or use `no-restricted-syntax` regex) that flags `?? 0` on identifiers matching `/revenue|profit|cost|spend|roas|margin|ratio|_pct|_amount/i` in `src/` outside test files. Exception list for legitimate count-like uses (`spend` could be both money and "total amount spent" depending on context — case-by-case override comment required).

**Owner**: SM agent (scripting + ESLint config)
**Success criterion**: Story authoring time `npm run lint` flags new `?? 0` violations on money/ratio names; 0 manual catches needed in next 3 epics.

### A-2: Pre-flight source-trace verification step in dev-story workflow

**Context**: Stories 104.1 + 104.3 (and Story 103.1/103.2/103.3 earlier) all turned out to be already-shipped after source verification. Each "is this really missing?" check saves a duplicate story.

**Action**: Extend dev-story workflow Step 1 (validation) with: "Before implementation, grep the codebase for ALL nouns/endpoints mentioned in the story acceptance criteria. If hits exist, read those files; if behavior matches AC, mark story done with verification evidence. Spend implementation budget only on genuinely-missing scope."

**Owner**: SM agent (workflow extension)
**Success criterion**: Next 3 epics report at least 1 story closed via pre-flight verification without code changes.

### A-3: Cross-team-coordination "verify before incorporating" protocol

**Context**: Backend's "9 vs 10 categories" framing was wrong but propagated into my tracking memo for hours. Authoritative-source-citation discipline (Story 97.2) applies to cross-team messages too.

**Action**: When incorporating numerical/structural claims from another team's message into FE docs, append `(verified [DATE] via [METHOD])` or `(unverified — needs FE-side grep)` to the claim. Don't propagate as fact without verification.

**Owner**: PM agent (tracking-memo writing protocol)
**Success criterion**: Next coordination cycle produces zero misclassified items in tracking memos.

### A-4: Tighten delegation-notice hook heuristic to write-only commands

**Context**: The `[DELEGATION NOTICE]` hook fired ~15 times this session for read-only commands (grep, git log, bash scripts/check-*.sh). Each fire bloats context with a system reminder.

**Action**: Update the hook script to only fire when command starts with patterns like `vim`, `cat > `, `tee `, `sed -i`, or `git commit` (i.e., write-intent commands). Read-only patterns like `grep`, `find`, `git log`, `ls`, `bash scripts/check-*` should not trigger.

**Owner**: DevOps / tooling agent
**Success criterion**: Hook fire-rate drops by ≥80% in next session.

### A-5: Add fixture factory for advertising daily test data (deferred from Story 104.2 review)

**Context**: 5 inline fixture sites in 3 test files now declare 8 zeroed fields each. Per CLAUDE.md Pattern 3 (Story-1 fixture seeding), shared factory should exist.

**Action**: Create `src/test/fixtures/advertising-daily.ts` with `makeAdvertisingDay(overrides)` factory. Refactor 3 test files to use it. Low effort; high DRY win.

**Owner**: SM agent (story creation for future polish epic)
**Success criterion**: Next epic that touches advertising daily tests uses the factory; no inline duplication.
