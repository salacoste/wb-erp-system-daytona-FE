## Dev Notes

### Scale & Strategy

This story covers **69 files** (vs. epic's estimated 48). Most files need only 20-50 lines extracted. Use **7+ parallel agents** to handle domain groups simultaneously. Each agent should handle one Task (2-8).

### Proven Extraction Patterns (from Stories 74.1-74.7)

**Sub-Component Extraction** (most common for components):
```typescript
// Co-located sub-component file
'use client' // REQUIRED if component uses React hooks/state
export function SectionComponent({ data }: Props) { ... }
```

**Config/Constants Extraction** (for lib files):
```typescript
// *-config.ts or *-constants.ts — pure data, NO 'use client'
export const CONFIG = { ... } as const
export function helperFn(input: Type) { ... }
```

**Hook Helper Extraction** (for hooks):
```typescript
// hook-name-utils.ts — pure functions, NO 'use client'
export function transformData(raw: RawType): TransformedType { ... }
export const QUERY_KEYS = { ... } as const
```

**API Endpoint Group Extraction** (for api/ files):
```typescript
// api/domain-subgroup.ts — pure API functions
export async function getSubgroupData(params: Params) { ... }
```

### Critical Rules

1. **NEVER change functionality** — pure structural refactoring only
2. **`'use client'` rules**:
   - Extracted sub-components with hooks/state → NEED `'use client'`
   - Pure config/data/utility files → NEVER need `'use client'`
3. **Barrel re-exports MANDATORY** for files with ≥3 consumers (see Task 1)
4. **Aim for 150-180 lines** — leave headroom below 200-line limit
5. **Extracted files must also be ≤200 lines**
6. **Don't duplicate types** — import from source files
7. **Don't duplicate utils** — check if shared util exists before creating new ones
8. **Delete dead code** — don't leave orphan files from failed attempts
9. **Run tests after EACH task** — don't batch validation
