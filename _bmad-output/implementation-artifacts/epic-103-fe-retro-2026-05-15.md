## What Went Well

### S-1: 2-pass review caught cabinet-isolation gap from BOTH passes independently
Story 97.5-FE's multi-tenant cabinet-isolation discipline mandates `cabinetId` in TanStack Query queryKeys. The initial Epic 103 implementation omitted it. **Both** review passes flagged this independently — 1st pass rated MEDIUM ("matches existing codebase pattern, arguably architectural"), 2nd pass rated CRITICAL ("Story 97.5-FE explicit mandate, 4-instance recurrence in Epic 96"). The 2nd pass's reclassification was correct: this is exactly the defect class the discipline was codified to catch. The overlap validates the 2-pass model — same defect, different severity assessments, both pointing at the same fix.

### S-2: Pre-existing test regression caught + fixed by sweep
While running the full vitest baseline check, a pre-existing failure in `priceCalculatorUtils.story-44.37.test.ts` surfaced — completely unrelated to Epic 103 work. Investigation traced it to commit `9afa140` (Story 44.42 Phase 6) which re-introduced `box_type` + `turnover_days` to the API request after backend started accepting them. The Story 44.37 combined test wasn't updated. Fixed in `5b47b1d` — restored baseline `0 failed` gate before the polish work landed. This is the "fix all issues" mandate working: a regression hiding for ~3 weeks surfaced because the gate was actually run.

### S-3: Defensive Frontend Principle applied at normalizer boundary
1st-pass review CRITICAL finding: `predictions.map()` on possibly-null array (when ML model not trained, cache miss, or rollback). Fixed with `(raw.predictions ?? []).map(...)` + added 2 normalizer tests for the null/missing cases. This matches the Defensive Frontend pattern: backend may return malformed shapes; normalizer is the wall.

### S-4: Phase 3 disposition framework applied cleanly
AC 3 (brand/cabinet selector) was a UX decision that couldn't be auto-fixed. Used the disposition (a/b/c) framework from Story 96.17-FE precedent. User chose (c) drop brand pending backend brand-list endpoint. Cabinet level kept as implicit aggregation. Pure-function extraction (`computeForecastQueryParams` + 10 helper tests) closed AC 7. Decision and execution were both fast — the framework reduces decision overhead for "deferred-pending-other-team" items.

### S-5: Empirical browser verification surfaced 4 polish gaps not visible in source
Chrome visual verification of `/analytics/forecast` revealed: Russian declension bug ("21 дней" should be "21 день"), column anglicism ("Банд" should be "Диапазон"), missing brand selector input, and "Epic 109" implementation-detail leak in empty-state copy. None of these were code defects — all were UX/locale/copy issues only visible to a Russian-speaking user actually using the page. Reinforces "test the feature, not just the code" — type-check + tests can pass while UX is broken.

## What Didn't Go Well

### C-1: Epic 103 src/ implementation shipped untracked (out of git)
When this session started, the entire Epic 103 implementation (`src/app/(dashboard)/analytics/forecast/`, `src/hooks/useAiForecast.ts`, `src/lib/api/ai-forecast-api.ts`, `src/types/ai-forecast.ts`) was authored but never committed. Sprint-planning auto-discovery marked stories 103.1/2/3 as `backlog` despite the code existing because git didn't know about them. The closure-attestation gap was only caught when the user (or auto-commit hook) ran a parallel commit during this session. Lesson: ship work in atomic commits as it lands, don't accumulate untracked source for a working tree review later.

### C-2: Polish backlog spec described pre-fix state as findings even after fixes shipped
2nd-pass review caught: `docs/backlog/ai-forecast-polish-103-4.md` § Findings described the bugs in present tense ("hardcoded `{d} дней` displays '21 дней'") with file:line citations, but the ACs section marked them as shipped. The narrative said the bugs exist; the AC table said they don't. Both true at different points in time, but the doc didn't distinguish surfaced-state from current-state. Fixed with a state-note at the top of the spec, but the underlying pattern (write findings BEFORE applying fixes, then forget to past-tense them) is a documented propagation drift defect (Pattern 4 § Fix-block propagation discipline, Story 97.1-FE). This was the 12th+ instance in the chain.

### C-3: Empty-state copy leaked "Epic 109" — internal BMAD identifier exposed to end users
The original copy "Нет данных прогноза. Убедитесь, что модель обучена (Epic 109)." referenced an internal epic number. End-user sellers have no context for "Epic 109". This is a basic copywriting hygiene failure — implementation details should never appear in user-facing strings. Caught by visual verification, not by source review or tests. No automated guard would have caught it.

### C-4: Missing `cabinetId` in queryKey was a recurrence of Story 97.5-FE defect class
Despite Story 97.5-FE codifying multi-tenant cabinet-isolation discipline only 5 stories prior, the Epic 103 implementation missed it. The discipline exists precisely because it's repeatedly forgotten. This is the 5th instance in the recurrence chain (4 in Epic 96 + this one). The fact that BOTH review passes caught it independently is reassurance; the fact that it shipped untested is the failure. Lesson: every new TanStack Query hook in a cabinet-switching context needs an explicit cabinetId-in-queryKey check at PR author time, not just at review time.

### C-5: Russian declension hardcoded "{d} дней" — locale-aware logic forgotten in dropdown items
The horizon dropdown displayed "21 дней" instead of "21 день". The codebase has a `russian-plural.ts` helper since Story 90.3-FE specifically for this — but it wasn't used here. The author either didn't know it existed or didn't think dropdown items needed declension. Mitigation: extending `russian-plural.ts` with `DAY_FORMS` was trivial once recognized; the failure was not reaching for the helper. Russian-locale awareness needs to be an active design consideration, not opt-in.

## Lessons Learned

1. **2-pass review catches discipline-class defects with independent severity assessments** — Story 97.5-FE's cabinetId mandate was caught by both passes independently. 1st pass rated it MEDIUM (matched existing pattern); 2nd pass rated it CRITICAL (explicit mandate + recurrence chain). Both correct from their analytical lens. The 2-pass model produces robust severity calibration through redundancy. (Epic 103-FE, Story 103.4 polish 2-pass)
2. **Run the gate to find the bug — pre-existing test failures hide until someone actually runs `npm test`** — The `priceCalculatorUtils.story-44.37` failure existed for ~3 weeks. It surfaced only because Story 103.4 polish work required confirming baseline before the new commits landed. Gates that nobody runs aren't gates. Periodic full-suite execution catches drift the developer-of-the-moment doesn't trip over. (Commit `5b47b1d` discovery)
3. **Visual verification of UI features surfaces defects type-check + unit tests can't see** — 4 of 4 Story 103.4 polish findings (declension, anglicism, missing selector, copy leak) were invisible to ESLint, TypeScript, and existing tests. Russian locale, UX intent, copy hygiene, and information-architecture defects need a human (or Chrome+a11y-tree probe) actually using the feature. (Epic 103-FE visual verification)
4. **Disposition (a/b/c) framework reduces decision overhead for "blocked-pending-other-team" items** — AC 3 brand selector needed backend brand-list endpoint. Disposition (c) — drop the feature pending external work — closed the AC cleanly without scope-creeping the story. Two prior precedents (Story 96.17-FE, Story 86.2-FE) had established the framework. Reusing it cost ~30 seconds of decision time. (Story 103.4 Phase 3)
5. **Boundary normalizer null-safety needs explicit tests for "model not trained / cache miss / rollback" paths** — ML-backed endpoints have more failure modes than CRUD endpoints. Backend may return `predictions: null`, `predictions: []`, or omit the field entirely. The normalizer needs to coalesce all three to `[]` and have tests for each. Default to defensive: optional fields in the raw type, `?? []` in the map, dedicated null/missing tests. (Story 103.4 F1 finding)
