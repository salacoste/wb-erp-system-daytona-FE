### Architecture Patterns (MUST follow)

**E2E directory structure** — Mirror the `e2e/supplies/` pattern exactly:
```
e2e/
├── shipments/
│   ├── shipments-list.spec.ts      ← List page tests
│   ├── shipments-detail.spec.ts    ← Detail page tests
│   ├── shipments-lifecycle.spec.ts ← Serial CRUD flow
│   └── shipments-a11y.spec.ts      ← Accessibility (axe-core + keyboard)
├── supplies/                        ← TEMPLATE — read these first!
│   ├── supplies-list.spec.ts
│   ├── supply-detail.spec.ts
│   ├── supply-lifecycle.spec.ts
│   └── supplies-a11y.spec.ts
└── fixtures/
    └── test-data.ts                 ← Centralized test data, routes, timeouts
```

**Playwright config** — `playwright.config.ts`:
- `testDir: './e2e'`, `fullyParallel: true`
- Auth: uses `e2e/.auth/user.json` from `auth.setup.ts`
- Timeouts: action 15s, navigation 30s, expect 10s, test 60s
- CI: retries=2, workers=1, screenshots/videos on failure
- Base URL: `http://localhost:3100` (from `E2E_BASE_URL`)

**Authentication** — All specs inherit authenticated state from `auth.setup.ts`. No manual login needed. Test user: `test@test.com` / `[REDACTED-TEST-PASSWORD]`.

**File size limit** — All source files MUST be under 200 lines. This is tight for E2E specs — the supplies specs are 500-650 lines each. **ESLint `max-lines-per-file` rule does NOT apply to E2E specs** (they're outside `src/`). But keep individual test groups focused.

### Critical Test Patterns (from supplies/ template)

**1. Flexible Selectors** — Use `.or()` chains:
```typescript
const row = page.locator('[data-testid="shipment-row"]')
  .or(page.locator('tr').filter({ hasText: shipmentName }))
```

**2. Conditional Test Skipping** — Data-dependent tests must skip gracefully:
```typescript
const rows = page.locator('table tbody tr')
if ((await rows.count()) === 0) {
  test.skip(true, 'No shipments in test data')
  return
}
```

**3. Serial Lifecycle** — Use `test.describe.serial` with shared state:
```typescript
test.describe.serial('Shipment Lifecycle', () => {
  let shipmentId: string | null = null

  test('Create shipment', async ({ page }) => {
    // ... create and capture ID from URL
    shipmentId = page.url().split('/shipments/')[1]
  })

  test('Add pallet', async ({ page }) => {
    if (!shipmentId) test.skip(true, 'No shipment created')
    await page.goto(`/shipments/${shipmentId}`)
    // ...
  })
})
```

**4. Wait for API** — After mutations, wait for network:
```typescript
await page.waitForLoadState('networkidle')
// Or for specific response:
const responsePromise = page.waitForResponse(
  resp => resp.url().includes('/shipment-cost/shipments') && resp.status() === 200
)
await submitButton.click()
await responsePromise
```

**5. Calculate Timeout** — The calculate endpoint may take >1s. Use extended timeout:
```typescript
const calcResponse = page.waitForResponse(
  resp => resp.url().includes('/calculate') && resp.status() === 200,
  { timeout: 15_000 }
)
await page.getByRole('button', { name: 'Рассчитать' }).click()
await calcResponse
```

**6. Dialog Testing** — Use role-based selectors:
```typescript
await page.getByRole('button', { name: 'Создать отправку' }).click()
const dialog = page.getByRole('dialog')
await expect(dialog).toBeVisible()
await dialog.locator('#sp-name').fill('Test Shipment')
// Close with Escape:
await page.keyboard.press('Escape')
await expect(dialog).not.toBeVisible()
```

**7. Accessibility (axe-core)** — Already installed (`@axe-core/playwright`):
```typescript
import AxeBuilder from '@axe-core/playwright'

const results = await new AxeBuilder({ page })
  .withTags(['wcag2a', 'wcag2aa'])
  .analyze()
expect(results.violations).toEqual([])
```

**8. API Error Mocking**:
```typescript
await page.route('**/shipment-cost/shipments**', route =>
  route.fulfill({ status: 500, body: JSON.stringify({ message: 'Server Error' }) })
)
```

### Anti-Patterns (DO NOT)

- DO NOT use `test.only()` — CI check with `forbidOnly: !!process.env.CI`
- DO NOT hardcode shipment IDs — use dynamic creation in lifecycle tests
- DO NOT assume specific data exists — use conditional skipping with `test.skip()`
- DO NOT use short timeouts for calculate endpoint — use 15s minimum
- DO NOT test internal state — only test user-visible behavior (page content, navigation, toasts)
- DO NOT duplicate test data inline — use `e2e/fixtures/test-data.ts` for shared constants
- DO NOT use `page.waitForTimeout()` — use `waitForResponse`, `waitForLoadState`, or `waitForSelector` instead
- DO NOT test confirmed shipment deletion — the API prevents it; test that the delete button is not shown
