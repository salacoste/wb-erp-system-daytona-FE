## What Went Well

### S-1: Boundary Normalizer Pattern scaled to 16 endpoints without architectural strain
Story 108.1 took the existing `ai-forecast-api.ts` (52 lines, 1 endpoint) and added 14 more endpoints. The Boundary Normalizer Pattern (Epic 88-FE) handled each endpoint cleanly — separate raw/canonical types, defensive normalizers with `?? null` for money/ratio + `?? 0` for counts, ≥1 unit test per normalizer. The subdirectory split (`src/types/ai/`, `src/lib/api/ai/`) preserved Epic 103/104 imports via barrel re-exports — zero consumer breakage.

### S-2: Pre-flight verification (Story 105.2-FE) saved time on every story
Every story executor prompt included an explicit grep-based pre-flight check. Story 108.1 confirmed zero conflicting types. Stories 108.3-5 confirmed zero conflicting hooks/components. The pattern is now baked into the delegation workflow — no wasted implementation cycles on already-shipped infrastructure.

### S-3: 2-pass review caught convergent defects systematically
Each story's 2-pass review surfaced 5-10 findings, with HIGH-severity findings consistently caught by BOTH passes independently:
- Story 108.1: confidence scale (0-100 vs 0-1) — BOTH passes
- Story 108.2: `useMutation` 4th generic missing → unsafe `as` cast — 1st-pass; readiness-fallback spec contradiction — 2nd-pass
- Story 108.3: internal-identifier leak ("Story 108.4-FE" in JSX) — 2nd-pass
- Story 108.5: WCAG accessibility (trend icons missing aria-label + text) — 2nd-pass

The convergence pattern (BOTH passes finding the same critical issue) is the strongest signal that 2-pass review is structurally load-bearing, not redundant. Story 97.4-FE meta-pattern validated at scale.

### S-4: Pure-function extraction enabled direct testability throughout
Each story extracted at least one pure helper:
- `computeForecastQueryParams` (Epic 103 — already existed, reused)
- `resolveReadinessRoute` (Story 108.3 — 7 test cases without React)
- `shouldPollAiStatus` (Story 108.3 fix-up — 4 test cases on the refetchInterval callback)
- View/Container split for every UI component (8 view tests, 11 view tests for AiEngineStatusBadge, etc.)

This pattern from Story 88.5 / Epic 89 lessons is paying compound returns. Test count growth this epic (~200 tests for ~10 SP of code) suggests pure-function discipline is working.

### S-5: Backward-compat barrels enabled zero-downtime migration
Splitting `src/types/ai-forecast.ts` (43 lines, 1 file) into `src/types/ai/` subdirectory (7 files) required NO consumer changes — barrel re-exports preserved every existing import path. Epic 103/104 hooks/components continued working unchanged. The pattern is reusable for future type/API expansions.

### S-6: TanStack Query v5 polling-stop callback worked cleanly
Story 108.3's `refetchInterval: (query) => query.state.data?.readinessLevel === 'ready' ? false : 60_000` correctly stops polling once cabinet hits ready state. Saves network bandwidth (60s vs no polling at all). Story 108.4 fix-up extracted this into pure `shouldPollAiStatus` function for direct testing.

## What Didn't Go Well

### C-1: Confidence scale ambiguity shipped to commit `bb8b27e` undetected by initial implementation
Story 108.1 first implementation had JSDoc claiming `confidence: 0-100` (matching backend guide line 164) but `getConfidenceBand` used 0.7/0.4 thresholds (0-1 scale) and `ForecastTable.tsx:45` rendered `confidence * 100`. The two test files contradicted: `forecast.test.ts` used 82 (0-100), `ai-forecast-api.test.ts` used 0.42 (0-1). Both 2-pass reviewers flagged this independently. Without 2-pass review, this would have shipped — UI would display `confidence: 82 * 100 = "8200%"` or `getConfidenceBand(82) → 'high'` (correct but on wrong scale). The fix: normalize to 0-1 at boundary per Boundary Normalizer Pattern's intent.

### C-2: Internal identifier leaks recurred in Stories 108.3 placeholders
Story 108.3 created placeholder components with text "Подробности появятся после реализации Story 108.4-FE" visible in user-facing JSX. Caught by 2nd-pass review. Same defect class as Epic 104-FE retro A-3 (no internal-identifier leaks in user-facing strings). The discipline exists, but the placeholder-as-temporary mindset bypassed it. Pattern: any text that will REPLACE later should still be user-friendly today.

### C-3: WCAG 2.1 AA accessibility regression in Story 108.5
Initial `TrendIcon` component rendered icons only — no `aria-label`, no visible text. Violates project's WCAG 2.1 AA mandate (CLAUDE.md) AND epic spec line 134 requiring Russian text "Растёт"/"Стабильно"/"Снижается". Backend guide line 87 also specifies BOTH arrow AND text. 2nd-pass review caught this. Pattern: accessibility is easy to forget when icons are visually self-explanatory; spec compliance check catches what intuition misses.

### C-4: Commit message count drift in `9daa910`
Commit `9daa910` for combined Stories 108.4+5 claimed "+28 new tests across 6 files" — actual was +32 tests across 5 files. Caught by 2nd-pass review. Cannot fix shipped commit. Same defect class as Story 104.2 ("8 fields" actually 7), Story 106.1 ("2 test assertions" actually 4) — author memory under-counts. Epic 106 retro A-4 proposed grep-verified counts in commit drafts; still informal practice. After 4 instances in 4 epics, consider a scripted helper.

### C-5: Two-layer defensive fallback in readiness handling undocumented
Story 108.1 normalizer (`src/lib/api/ai/status.ts:27`) AND Story 108.3 router (`readiness-router.ts:22`) both default unknown `readinessLevel` to `'ready'`. Each guards a different failure mode (backend enum drift vs TanStack loading/error state), but the redundancy wasn't documented. 2nd-pass review caught this — Story 108.3 fix-up added JSDoc explaining the "Layer 2 of 2" defense-in-depth.

### C-6: Tautological tests in `useAiStatus.test.tsx` shipped initially
First-pass implementation of `useAiStatus.test.tsx` had 3 tests with names like "stops polling when readinessLevel is ready" but assertions only verified the mock data value (tautological — mock returns what you set). Caught by 1st-pass review. Fix-up extracted `shouldPollAiStatus` as a pure function for direct testing. Pattern: test names that describe BEHAVIOR but assert on STATE are red flags — verify the behavior directly.

## Lessons Learned

1. **The 2-pass review discipline catches contract-class defects systematically — keep applying it for behavior-changing source** — Across 5 stories with 2-pass review (108.1, 108.2, 108.3, 108.5, 108.4+5 combined), every single critical/high-severity finding was caught. Several were caught by BOTH passes independently (confidence scale, cabinetId queryKey, internal-identifier leak). The convergence pattern is the empirical proof that 2-pass works. Reaffirms Epic 107-FE codification: 2-pass is structurally permanent for behavior-changing source.

2. **Pre-flight verification at executor prompt level scales discipline** — Every story executor prompt for Epic 108 began with "Step 1: Pre-flight verification (Story 105.2-FE Step 4.5) — run `grep -rln ...` to confirm zero conflicts". This caught Stories 108.4/5 reuse opportunities and prevented duplicate work. Pattern: bake pre-flight into delegation prompts, not just dev-story workflow.

3. **Backend guide field-name camelCase vs frontend canonical `predictedSales` rename pattern** — Backend's `predictedUnits` mapped to FE `predictedSales` (Epic 103 contract). Story 108.1 preserved this. Pattern: Boundary Normalizer is the right place to rename fields when backend uses ambiguous terms (`predictedUnits` could be products, orders, etc.) — frontend canonical names should be domain-clear.

4. **Backward-compat barrels enable infrastructure migration without consumer churn** — Splitting types/API client into subdirectories preserved Epic 103/104 imports via re-export barrels. Pattern: any time you split a file >150 lines into multiple files, keep the original path as a barrel. Zero migration cost; clean architecture.

5. **WCAG accessibility is invisible to keyboard-and-screen-reader-blind authors — bake into spec** — Story 108.5's trend icons "looked correct" visually but failed accessibility silently. The fix (aria-label + visible text) is trivial; the discovery requires either testing tools or explicit spec mandate. Add an "accessibility check" line to each UI story's AC: "every icon has accessible name (aria-label OR adjacent text). screen reader test passes."
