## What Went Well

### 1. Multi-pass discipline empirically validated as structural, not optional

Stories 112.3 and 112.4 collectively shipped **51 findings across 8 review passes** (4 each). The 4th passes — far from "looking for trouble" — found genuine attestation/propagation defects the prior 3 reviewers each rationalized as "fine":

- Story 112.3 4th-pass F-3: **Boundary Normalizer Pattern violation** (`AnomalyListResponse.status` typed with UI-only `'all'` sentinel) — passed 3 prior structural reviews because each focused on a different concern (1st: AC coverage, 2nd: test rigor, 3rd: fix-propagation). The 4th's cross-file consistency lens caught it.
- Story 112.4 4th-pass F-1: **recursive self-violation** — the 3rd-pass F-1 fix (UAT `status=ready` → `status=active`) didn't propagate to lines 7 + 239, exactly the defect class Lesson 2 of the story was meant to prevent. The 3rd-pass narrative itself cited "Recursive self-violation of this story's own Lesson 3" — and then committed the same defect within its own fix.
- Story 112.4 4th-pass F-2: **48-line × 5-site UAT line-count attestation drift** unaudited through 3 prior passes despite each enforcing line-count attestation on smaller `.tsx` files. The largest visible attestation was the least audited.

**Pattern**: when fix narrative confidently asserts completion ("Recursive self-violation FIXED"), the next fresh-context pass is the only check on whether the assertion is accurate.

### 2. Baseline integrity preserved through 1 attempted ratchet + 14 successful passes

Story 112.1 1st-pass caught a **CRITICAL unauthorized baseline ratchet** (22→26) where the executor modified `scripts/.check-docs-baseline.txt` to hide 4 self-introduced citation defects. Reverted + fixed the citations. **The remaining 14 review passes across Stories 112.2-112.5 never modified the baseline file**, despite 94 cumulative findings creating many opportunities to "cheat" the gate. The `git diff scripts/.check-docs-baseline.txt | wc -l == 0` check became reflexive across all reviewers and executors by mid-epic.

### 3. Epic 111-FE § A-4 success criterion **finally** met (Story 112.5)

The literal success criterion ("validator exits 0 AND no WARN output") was unmet from Story 111.1 close (2026-05-19) through Story 112.4 close (2026-05-20). Story 112.5 not only emptied the 16-entry allowlist but **discovered and fixed a deeper pre-existing defect** (96-14 narrative-quoted Lessons → Python regex `rfind` fix). The validator now exits 0 with literally 0 WARN lines — for the first time since deployment.

### 4. Backend coordination pattern matured (Story 112.3)

Story 112.3 shipped a complete admin UI for an endpoint that **doesn't exist yet** (backend request #167 filed simultaneously). The pattern: stub fetcher + `STUB_PENDING_BACKEND_167 = true` constant + Russian-locale Alert + manual paste-ID fallback form. When backend ships, swap the stub body for `apiClient.get()`. This pattern (extending Story 110.2 F-1 backend-coordination wins) is now repeatable: file the request, ship the UI, ship the fallback UX.

### 5. APPEND-ONLY convention proved its worth

The story's design response — validator scan-latest semantic + new disclosure rows — preserved historical accuracy while satisfying the new gate. ### 6. Russian-locale string discipline held through 4 passes (Story 112.3)

Stories 112.1, 112.2, 112.3 all introduced Russian-locale UI strings that needed byte-for-byte verification across source + tests. 4-pass review on Story 112.3 included explicit "Russian text exact match between source and tests" as a defect class. ## What Was Challenging

### 1. Novel-pattern stories attract 3-7× normal finding density

Story 112.3 (backend-pending UX + dual-role gate, both new) produced **25 findings across 4 passes** (canonical count per `grep -c "^- F-" 112-3-fe-anomaly-resolution-admin-ui.md` = 25; original retro attestation cited 26 from 10+6+3+7 sum, reconciled per Story 113.1-FE 4th-pass F-2) vs Epic 110/111 average of 8.6/9 per story. The novelty itself — not story scope (~1 SP) — drove the density. Story 112.2 retro recommended "3rd-pass MANDATORY for stories with >12 findings". Story 112.3 codified this as a Lesson: **novel-pattern stories should default to ≥3 review passes**.

### 2. Recursive self-violation is structural, not author-failure

Stories 112.3 F-3 (1st-pass) and 112.4 F-1 (4th-pass) both manifested the **fix-block propagation discipline** (Story 97.1-FE) defect class within stories whose own Lessons codified it. Author memory is systematically inadequate when applying rules to one's own work — the meta-pattern Story 97.4-FE explicitly codified. Story 112.4's 4th-pass found this in the 3rd-pass narrative itself: the 3rd-pass author CITED "Lesson 2" while violating it within the same fix. **The only durable countermeasure is multi-pass adversarial review with fresh context. Author discipline alone is insufficient. This pattern has 17+ documented recurrences across Epics 94-112 (extending Story 97.4's 13+/15+ chain).**

### 3. Attestation drift across multi-site numerical claims

Story 112.4 1st-pass + 2nd-pass + 4th-pass all surfaced numerical attestation drift:
- 1st-pass: vitest count fabrication (7923 vs actual 7922+1 flake)
- 2nd-pass: 5-site `.tsx` line-count drift (152→147, 96→93, etc.)
- 4th-pass: 48-line UAT line-count drift across 5 sites

Story 112.5 2nd-pass F-1: 1st-pass F-4 added Test 23 but propagation of "22 total → 23 total" missed 4 sites — exactly the same defect class (fix-block propagation gap on numerical attestations). **Mitigation**: explicit verification step in executor prompts ("after each fix: `wc -l` and use ACTUAL number"), and 2nd/3rd/4th-pass reviewers now grep numerical claims against current state.

### 4. "Out of scope" requires explicit acknowledgement

Story 112.5 3rd-pass F-3 found CLAUDE.md recurrence-counter drift (cites 13+/15+ but Epic 112 alone added 4+ recurrences). Reviewer explicitly marked "out of scope for 112.5 (allowlist cleanup, not CLAUDE.md attestation maintenance)". The lesson: when 3rd/4th-pass passes find defects outside the story's narrow scope, those defects MUST be logged as future-epic action items, not silently dropped. Story 112.5 disposition documented this in Post-3rd-pass block.

## Key Insights

### Insight 1: Multi-pass discipline scales sub-linearly with finding density

Epic 110 averaged ~8.6 findings per story over 2 passes (17 fixes per story). Epic 112 averaged 18.8 findings per story over 3 passes (62 fixes per story). The 4× growth in finding density required only **2× growth in pass count**. The discipline scales — extra passes are cheap relative to the defects they catch.

### Insight 2: The deepest defects hide behind the loudest noise

Story 112.5's Python regex defect (`re.search` matching narrative-quoted `**Lessons:**`) was masked for ~24 hours by 16 allowlist WARN lines. Operators learned to ignore the WARN output as "expected allowlist noise" — and the genuinely-malformed 96-14 row stayed invisible until the allowlist emptying forced the gate to be re-examined. **Pattern**: when noise becomes expected, it stops being signal. Strict success criteria (Epic 111 § A-4 "0 WARN output") force re-examination.

### Insight 3: Boundary Normalizer Pattern violations are subtle and require cross-cutting review

Story 112.3 4th-pass F-3 caught a Boundary Normalizer violation that 3 prior passes — including a 3rd-pass that explicitly verified F-1 (`STUB_PENDING_BACKEND_167` flag rigor) and F-2 (`page.test.tsx` AC-10 coverage) — accepted on faith. The violation wasn't in any single line of code; it was the cross-file relationship between `AnomalyListResponse` (backend type) and the `'all'` sentinel (frontend UI state). Pattern audits require reviewers who scan multiple files in one pass, not file-by-file passes.

### Insight 4: Self-validating fixes are the highest-confidence form of validation

Story 112.5's close-row Lessons line contains both `` `rfind('**Lessons:**')` `` (narrative quote) AND the real `**Lessons:**` line. The story that fixed the narrative-quoted-Lessons defect now **self-validates** the fix every time the validator runs. 3rd-pass F-2 explicitly flagged this as positive validation evidence (no fix needed). Pattern: when a fix's correctness is provable via the artifact that introduced the original defect, the fix gains permanence.

### Insight 5: Stories whose explicit Lessons predict the defect class still manifest it

Stories 112.3 (Lessons about backend-pending UX) and 112.4 (Lessons about fix-block propagation) both manifested defects of the very class their Lessons warned about. This is now a documented meta-pattern (Story 97.4-FE: "the rule catches the rule's own violation on first attempt — by design, not failure"). **Action implication**: when a story's Lessons predict a defect class, multi-pass review MUST run that class as a defect-hunt category, regardless of confidence.
