# Story 75.3: SKU Packaging Page — Single & Bulk Operations

Status: done

## Story

As a **seller**,
I want to bind my SKUs to box types with units-per-box counts,
so that the system knows how each product is packaged for delivery cost calculation.

## Acceptance Criteria

1. **Empty state (no packaging)**: When no packaging configs exist, display "Привяжите товары к типам коробок" with CTA "Добавить упаковку"
2. **Empty state (no box types)**: If no box types exist yet, show additional hint: "Сначала добавьте типы коробок" with a link to `/shipments/box-types`
3. **DataTable**: When packaging configs exist, display columns: Товар (nmId + название), Тип коробки, Штук в коробке, Действия
4. **Create dialog**: Form with: SKU (searchable combobox via `/v1/products`), Box Type (dropdown of active box types), Units per Box (required, > 0). Submits `POST /v1/sku-packaging`, refreshes list
5. **Edit dialog**: nmId is read-only, box type and units per box are editable. Submits `POST /v1/sku-packaging` (upsert), refreshes list
6. **Delete**: Confirmation dialog, then `DELETE /v1/sku-packaging/:nmId`. Config removed from list
7. **Bulk add**: Textarea accepts CSV/tab-separated rows: `nmId, boxTypeId, unitsPerBox`. Preview table shows parsed rows. Submits `POST /v1/sku-packaging/bulk`. Partial success: green for created, red with error for failed
8. **Loading/error states**: Skeleton loading, error alert with retry button
9. **All files ≤ 200 lines**, `@/` imports, no `any` types, `'use client'` only on files with React hooks

### Previous Story Learnings (75.1 + 75.2)

**Critical patterns to follow:**
- `parseDecimal()` from `@/lib/decimal-utils` for ALL Decimal-as-string fields (boxType dimensions/volume)
- Page pattern: `page.tsx` → `usePageState` hook → sub-components in `components/custom/`
- Use `<form onSubmit>` wrapper in dialogs for Enter-key support
- Use `aria-label` on icon-only buttons (NOT `title`), `aria-describedby` + `aria-invalid` on form inputs
- Use regular `Button` (NOT `AlertDialogAction`) for async operations in AlertDialogs — AlertDialogAction auto-closes before async completes
- Block dialog close during pending mutation: `onOpenChange={v => !v && !mutation.isPending && onClose()}`
- Use proper column interface instead of `as const` tuple: `interface Column { key: string; label: string; align?: 'right' }`

### Backend API — SKU Packaging (Exact Spec)

| Method | Path | Status | Notes |
|--------|------|--------|-------|
| `POST` | `/v1/sku-packaging` | 201 | Upsert by nmId. Body: `{ nmId: number, boxTypeId: string, unitsPerBox: number }`. Errors: 400 validation, 404 product not found, 409 inactive box type |
| `POST` | `/v1/sku-packaging/bulk` | 201 | **Always 201** even with errors. Body: `{ items: [...] }`. Response: `{ created: number, updated: number, errors: SkuPackagingBulkError[] }` |
| `GET` | `/v1/sku-packaging` | 200 | Returns `SkuPackaging[]`. Optional: `?nmId=&boxTypeId=` |
| `GET` | `/v1/sku-packaging/:nmId` | 200/404 | Returns single `SkuPackaging` |
| `DELETE` | `/v1/sku-packaging/:nmId` | 204 | Hard delete. Returns no content |

**IMPORTANT**: Create and Edit both use `POST /v1/sku-packaging` (upsert). There is NO PUT endpoint for SKU packaging.

### Bulk Add — Textarea Parse Pattern

The epic specifies a textarea accepting CSV/tab-separated format. Implementation approach:

1. **Input**: `<Textarea>` with placeholder showing format example
2. **Parse**: Split by newlines → split each line by comma or tab → validate each row
3. **Preview table**: Show parsed rows with: nmId, boxTypeId (or name if resolvable), unitsPerBox, Status (valid/error)
4. **Submit**: Collect valid rows → `POST /v1/sku-packaging/bulk` with `{ items: [...] }`
5. **Results**: Update preview table with actual API results — green for success, red with error text for failures

### Anti-Patterns to Avoid

- **Do NOT use `AlertDialogAction`** for async delete — use regular `Button` (75.2 lesson)
- **Do NOT use `title`** on icon-only buttons — use `aria-label`
- **Do NOT import `formatCurrency`** — this page has no monetary values
- **Do NOT create a PUT endpoint call** — backend uses POST upsert for both create and edit
- **Do NOT use react-hook-form or zod** — use plain React state for forms (project convention)
- **Do NOT skip `aria-describedby`/`aria-invalid`** on form inputs with validation errors
