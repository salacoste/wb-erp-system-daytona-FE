## Dev Notes

### Proven Extraction Patterns (from Stories 74.1-74.5)

**Table Column Extraction** (proven in 74.1 FinancialSummaryTable, 74.3 analytics tables):
```typescript
// *-columns.tsx — pure column definition, needs 'use client' ONLY if using hooks
import type { ColumnDef } from '@tanstack/react-table'
export const columns: ColumnDef<RowType>[] = [...]
```

**Sub-Component Extraction** (proven in 74.1 BulkCogsForm, PnLWaterfall):
```typescript
// Co-located sub-component file
'use client' // REQUIRED if component uses React hooks/state
export function SectionComponent({ data }: Props) { ... }
```

**Chart Config Extraction** (proven in 74.1 PnLWaterfall):
```typescript
// *-config.ts — pure data/config, NO 'use client'
export const CHART_CONFIG = { ... } as const
export function getChartOptions(data: ChartData) { ... }
```

**Barrel Re-Export** (proven in all 74.x stories — CRITICAL for backward compatibility):
```typescript
// Keep original file as thin orchestrator importing extracted pieces
// Consumers don't need import path updates
export { Component } from './extracted-component'
export type { ComponentProps } from './extracted-types'
```

### Critical Rules

1. **NEVER change functionality** — pure structural refactoring only
2. **`'use client'` rules for components**:
   - Original file has `'use client'`? Extracted sub-components with hooks/state ALSO need it
   - Original file has NO `'use client'`? Don't add it to extracted files unless they use hooks/state
   - Pure config/data/column-definition files NEVER need `'use client'`
3. **Run tests after EACH file split** — don't batch validation
4. **Aim for 150-180 lines** — leave headroom below 200-line limit
5. **Extracted files must also be ≤200 lines** — don't just move the problem
6. **Barrel re-exports** preserve consumer import paths — no codebase-wide updates
7. **Don't duplicate types** — import from source files (74.2 code review finding)
8. **Internal helpers stay non-exported** unless needed for cross-file import
