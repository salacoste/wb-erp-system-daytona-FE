### Known Risks and Mitigations

**Risk: `git mv` with symlinks** — `git mv src/hooks-v1 src/hooks` may fail because `src/hooks` (the symlink) already exists. **Mitigation**: Remove symlink first (`rm src/hooks`), then rename (`mv src/hooks-v1 src/hooks`). Stage both changes: `git add -A src/hooks src/hooks-v1`.

**Risk: jsx-a11y `anchor-is-valid` rule + Next.js** — Next.js `<Link>` component wraps `<a>` tags; jsx-a11y may flag these. **Mitigation**: If `anchor-is-valid` conflicts with Next.js Link pattern, disable with comment:
```json
"jsx-a11y/anchor-is-valid": ["error", { "components": ["Link"], "specialLink": ["hrefLeft", "hrefRight"], "aspects": ["invalidHref", "preferButton"] }]
```

**Risk: Test files mocking `@/hooks-v1/` path** — The 2 test files mock `@/hooks-v1/...` paths. After directory rename, these mocks point to a non-existent path. **Mitigation**: Update mock paths to `@/hooks/...` in Task 2.

### Anti-Patterns (DO NOT)

- DO NOT create a new symlink pointing the other direction (`hooks-v1` → `hooks`) — eliminate symlinks entirely
- DO NOT modify `tsconfig.json` paths — `@/*` → `./src/*` already handles this correctly
- DO NOT run `git add -A` or `git add .` — stage specific files to avoid committing unrelated changes
- DO NOT suppress jsx-a11y rules wholesale — only disable individual rules with justification
- DO NOT edit `src/components/ui/` files (shadcn/ui — never edit manually)
