# Story 71.5: Search Orders Tab

Status: done

## Story

As a **Jam-subscribed seller viewing the Search Analytics page**,
I want to see summary cards and a sortable table of search-attributed orders grouped by keyword,
so that I can identify which search queries drive the most orders and revenue.

## Acceptance Criteria

1. **AC1: Summary cards render** — Given search orders data loads successfully, When the "Заказы" tab is active, Then 3 summary cards display: "Поисковые заказы" (totalSearchOrders), "Выручка от поиска" (totalSearchRevenue formatted as currency), "Доля поисковых заказов" (searchOrderShare formatted as percentage).
2. **AC2: Orders table renders** — Given search orders data has items, When groupBy='query' (default), Then a table displays columns: "Запрос" (key), "Заказы" (totalOrders), "Выручка" (totalRevenue), "Товаров" (uniqueProducts). Rows are sorted by totalOrders descending by default.
3. **AC3: Table sorting** — Given the table is rendered, When user clicks a column header, Then rows re-sort by that column. Clicking the same header toggles asc/desc.
4. **AC4: Date range picker** — Given the page loads, When user selects a date range, Then summary cards and table refresh with new data. Default range: last 30 days.
5. **AC5: Loading/empty/error states** — Given data is loading, Then skeleton placeholders show. Given no data for period, Then "Нет данных за выбранный период" message. Given API error, Then destructive Alert with retry suggestion.
6. **AC6: Tests pass** — Unit tests cover: summary cards rendering, table columns, sorting toggle, loading state, empty state, error state. `npm run lint && npm run type-check` passes.
7. **AC7: All source files under 200 lines** — Each component and test file under 200 lines.

### Previous Story Intelligence (71.1 through 71.4)

- `useSearchOrders(from, to, params?)` at `src/hooks-v1/use-search-analytics.ts:44-54` — enabled when `!!from && !!to`
- Response type `SearchOrdersResponse` at `src/types/search-analytics.ts:115-120`: `{ period, groupBy, items: SearchOrderItem[], summary: SearchOrdersSummary }`
- `SearchOrderItem.key` is `string | number` — when `groupBy='query'` it's a string (the search query text)
- `SearchOrderItem.totalRevenue` — backend note: "hardcodes revenue: 0 in sync processor" for by-product/by-query, but search/orders endpoint DOES return real revenue from orders data
- `SearchOrdersSummary`: `{ totalSearchOrders: number, totalSearchRevenue: number, searchOrderShare: number }`
- `searchOrderShare` is already a percentage value (e.g., 12.5 means 12.5%)
- `SEARCH_CACHE`: staleTime=4min, gcTime=30min
- `RequireJam requiredTier="standard"` — already wraps the entire page in SearchPageContent (Story 71.4)
- `hooks` symlink: `src/hooks` → `src/hooks-v1/`, imports use `@/hooks/use-search-analytics`

### SearchPageContent Modification Pattern

Story 71.4 creates `SearchPageContent.tsx` with placeholder tabs. This story modifies it to:
1. Add date range state + `DateRangePickerExtended` between header and tabs
2. Replace "Заказы" tab placeholder with `<SearchOrdersTab from={apiFrom} to={apiTo} />`

Follow `FunnelPageContent.tsx` (109 lines) pattern exactly:
```typescript
import { useState } from 'react'
import { format, subDays } from 'date-fns'
import { DateRangePickerExtended } from '@/components/custom/DateRangePickerExtended'
import type { DateRange } from '@/types/date-range'

function getDefaultRange(): DateRange {
  const to = new Date()
  to.setHours(23, 59, 59, 999)
  const from = subDays(to, 29)
  from.setHours(0, 0, 0, 0)
  return { from, to }
}

function formatApi(date: Date): string {
  return format(date, 'yyyy-MM-dd')
}
```

**CRITICAL**: `DateRange` type from `@/types/date-range` has `from: Date` and `to: Date` (Date objects, NOT strings). Convert to API strings with `formatApi()`.

### Table Pattern

Follow `FunnelTable.tsx` (199 lines) — client-side sorting with `SortButton`:
```typescript
const [sort, setSort] = useState<string>('totalOrders')
const [order, setOrder] = useState<'asc' | 'desc'>('desc')

const handleSort = (field: string) => {
  if (sort === field) {
    setOrder(prev => (prev === 'desc' ? 'asc' : 'desc'))
  } else {
    setSort(field)
    setOrder('desc')
  }
}

const sorted = [...items].sort((a, b) => {
  const aVal = a[sort] ?? 0
  const bVal = b[sort] ?? 0
  return order === 'desc' ? Number(bVal) - Number(aVal) : Number(aVal) - Number(bVal)
})
```

**Columns for groupBy='query'**:
| Header | Field | Format | Sortable |
|--------|-------|--------|----------|
| Запрос | `key` (string) | as-is | No (text) |
| Заказы | `totalOrders` | `toLocaleString('ru-RU')` | Yes (default) |
| Выручка ₽ | `totalRevenue` | currency format | Yes |
| Товаров | `uniqueProducts` | `toLocaleString('ru-RU')` | Yes |

**No pagination needed** — API `limit` param can control count, and search orders typically return <100 items. If needed later, add in Story 71.8 polish.
