# Story 76.1: Shipments List Page

Status: done

## Story

As a **seller**,
I want to see all my shipments with filtering and pagination,
So that I can manage my delivery planning and track shipment statuses.

## Acceptance Criteria

1. **Empty state** — When no shipments exist, display: "Создайте первую отправку для расчёта стоимости доставки" with CTA "Создать отправку". If no SKU packaging configs exist, show hint: "Сначала настройте упаковку товаров" with link to `/shipments/sku-packaging`.
2. **DataTable** — Paginated table with columns: Название, Статус (Badge: ЧЕРНОВИК / ПОДТВЕРЖДЕНА), Способ доставки, Паллет (count), Дата создания, Действия.
3. **Pagination** — Page size selector + next/prev controls. Query params: `?page=1&limit=10`.
4. **Status filter** — Tabs or select: Все / ЧЕРНОВИК / ПОДТВЕРЖДЕНА. Filters via `?status=DRAFT` query param.
5. **Sort by date** — Ascending/descending toggle on "Дата создания" column.
6. **Create dialog** — Form with: Название (required), Способ доставки (radio: Фиксированная стоимость / За паллету). When "Фиксированная стоимость" selected → show `totalDeliveryCost` field (required, > 0). When "За паллету" → show `palletRate` field (required, > 0). Switching mode clears other field (XOR). Submit → `POST /v1/shipments` → navigate to shipment detail page.
7. **API layer** — `src/lib/api/shipment-cost/shipments-api.ts` with: `getShipments`, `getShipment`, `createShipment`, `updateShipment`, `deleteShipment`.
8. **Hooks** — `src/hooks/use-shipments.ts` with: `useShipments`, `useShipment`, `useCreateShipment`, `useUpdateShipment`, `useDeleteShipment`.
9. **Page state** — `useShipmentsPageState.ts` for filters, pagination, sort state.
10. **All files ≤ 200 lines**, 0 ESLint errors, 0 TypeScript errors.

## Dev Notes

### Architecture Patterns (MUST follow)

**API client** — Follow `box-types-api.ts` pattern exactly:
```typescript
// src/lib/api/shipment-cost/shipments-api.ts
import { apiClient } from '@/lib/api-client'
import type { Shipment, ShipmentListResponse } from '@/types/shipment-cost'

// Note: getShipments returns ShipmentListResponse (paginated envelope)
// apiClient auto-unwraps { data: ... } — but ShipmentListResponse IS the data
// The response shape is: { data: Shipment[], total, page, limit }
// So after auto-unwrap you get ShipmentListResponse directly
```

**Hooks** — Follow `use-box-types.ts` pattern:
- Location: `src/hooks/use-shipments.ts` (NOT hooks-v1 — epic spec says `src/hooks/`)
- Include `'use client'` directive
- Export `shipmentsQueryKeys` object with `all()`, `list(params)`, `byId(id)` keys
- `staleTime: 60_000`, `gcTime: 300_000`, `retry: 1`
- Mutations invalidate `shipmentsQueryKeys.all()`

**Page** — Follow `box-types/page.tsx` pattern:
- `'use client'` directive
- Extract state to `useShipmentsPageState` co-located hook
- Loading skeleton → Error alert with retry → Empty state or DataTable
- Keep page.tsx under 100 lines (leave room for growth in 76.2+)

**Create dialog** — Follow Epic 75 rules:
- Use `<form onSubmit>` wrapper for Enter-key support
- Use regular `<Button>` for submit (NOT `AlertDialogAction` — it auto-closes before async completes)
- Block close during pending: `onOpenChange={v => !v && !isPending && onClose()}`
- Add `aria-label` on all icon-only buttons
- Add `aria-describedby` + `aria-invalid` on inputs with validation errors

### Backend API Endpoints

| Method | Endpoint | Request | Response | Notes |
|--------|----------|---------|----------|-------|
| GET | `/v1/shipments?status=DRAFT&page=1&limit=10` | Query params | `ShipmentListResponse` | Paginated |
| GET | `/v1/shipments/:id` | — | `Shipment` | Full with pallets/boxLines |
| POST | `/v1/shipments` | `ShipmentCreateRequest` | `Shipment` | 201 Created |
| PUT | `/v1/shipments/:id` | `ShipmentUpdateRequest` | `Shipment` | DRAFT only |
| DELETE | `/v1/shipments/:id` | — | 204 No Content | DRAFT only |

**Error codes**: 400 (validation), 404 (not found), 409 (duplicate name / already confirmed).

**XOR validation**: `totalDeliveryCost` and `palletRate` are mutually exclusive based on `deliveryMode`. Backend enforces this — frontend should also validate client-side.
