## User Story

**As a** seller viewing advertising analytics,
**I want** to see a warning badge on SKUs that run in multiple campaigns,
**so that** I know their profit numbers may be overstated due to ad spend double-attribution.

### Important Notes

1. **Backend returns warnings automatically**: No new parameter needed — `multiCampaignSkuWarnings` is returned when deduplication detects overlapping campaign SKUs.
2. **sku_id matching**: PerformanceMetricsTable items have `sku_id: string` (from AdvertisingItem type). Badge matches via `Number(item.sku_id)` against warning's `nmId: number`.
3. **Pre-existing over-limit files**: `advertising-analytics.ts` (575 lines), API client (376 lines), `page.tsx` (477 lines), `PerformanceMetricsTable.tsx` (681+ lines). Adding small changes to each is acceptable as pre-existing.
4. **Yellow warning color**: `#F59E0B` (design system semantic color for warnings, per front-end-spec.md).
5. **Group view consideration**: When `group_by=campaign`, nmId is not the row key. Badge should only render when `group_by=sku` or `group_by=product` (when individual products are visible). Check that item has a valid `nmId` before matching.
6. **Predecessor intelligence (72.3)**: DRY pattern — re-export shared utilities instead of duplicating. Use labels from config, not hardcoded strings.
7. **Backend Request #77**: Documents the multi-campaign profit multiplication issue — this story addresses the frontend UX warning.
