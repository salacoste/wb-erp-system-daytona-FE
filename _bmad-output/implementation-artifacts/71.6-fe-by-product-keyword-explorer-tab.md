## User Story

**As a** Wildberries seller with Jam Standard tier,
**I want to** select a product and see all search queries driving traffic to it,
**so that I can** understand which keywords generate impressions, clicks, and orders for my products.

### Key Types (already exist in `src/types/search-analytics.ts`)

```typescript
interface SearchByProductResponse {
  nmId: number
  period: SearchPeriod
  queries: SearchQueryItem[]
  totalQueries: number
}

interface SearchQueryItem {
  searchQuery: string
  avgPosition: number
  totalImpressions: number
  totalClicks: number
  avgCtr: number
  totalOrders: number
  totalRevenue: number  // NOTE: Backend hardcodes to 0
}
```

### Hook (already exists in `src/hooks/use-search-analytics.ts`)

```typescript
useSearchByProduct(nmId: number | undefined, from: string, to: string)
// enabled when !!nmId && !!from && !!to
```

### Product Hook (for combobox — `src/hooks-v1/useProducts.ts`)

```typescript
useProducts({ search: string, limit: 20 })
// Returns ProductListResponse { products: ProductListItem[], pagination }
// ProductListItem has: nm_id (string!), sa_name, brand, vendor_code
```

### Important Notes

1. **nmId type mismatch**: `useSearchByProduct` expects `number`, but `ProductListItem.nm_id` is `string`. Convert with `Number(nmId)`.
2. **totalRevenue = 0**: Backend search sync processor hardcodes revenue to 0. Still show the column but it will display "0 R" for all rows. This is a known backend limitation.
3. **Product combobox vs existing**: Don't reuse `ProductSearchSelect` from price-calculator — it's coupled to `useProductsWithDimensions` and has calculator-specific UI. Create a lightweight version using `useProducts` hook.
4. **Sort pattern**: Follow `SearchOrdersTable.tsx` exactly — useState for field+order, SortButton component, spread+sort array.
5. **File size limit**: Each file MUST stay under 200 lines (ESLint enforced).
