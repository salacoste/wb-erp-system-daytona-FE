### Important Notes

1. **Pre-existing ESLint violation**: `advertising-analytics.ts` is 538 lines (200-line limit). This is a pre-existing issue predating Epic 72. Do NOT attempt to split the file in this story — file splitting is a separate refactoring task.
2. **Pre-existing ESLint violation**: `advertising-analytics.ts` API client is 364 lines (200-line limit). Same — pre-existing, not this story's scope.
3. **Backend sort_by DTO gap**: The backend service type includes `profit_after_ads` in `AdvertisingSortBy`, but the DTO `@IsEnum` validation at `advertising-query.dto.ts:113` does NOT include it. This means `sort_by=profit_after_ads` will be rejected with 400 until backend DTO is updated. Frontend adds the type now; backend fix is a separate request.
4. **API client wiring is free**: `buildQueryString({ ...params })` already spreads all params and skips undefined. Adding `include_daily` to the type is sufficient — no API client logic change needed.
5. **No UI changes in this story**: Fields are only added to types. No table columns, no sort buttons, no daily chart rendering.
6. **No test changes needed**: No existing tests assert on `AdvertisingAnalyticsParams.sort_by` values or `include_daily` field. Adding to union types is backward-compatible.
7. **MergedGroupTable has separate SortField**: `MergedGroupTable.tsx:37` has its own `SortField` for merged group sorting (`totalSales`, `totalRevenue`, etc.). This is NOT the same as PerformanceMetricsTable's SortField. Do NOT modify MergedGroupTable.
8. **`getAdvertisingDailyData` already uses include_daily**: `src/lib/api/daily-analytics/api.ts:77` hardcodes `include_daily: 'true'` via URLSearchParams. This story adds it to the main params type so callers of `getAdvertisingAnalytics` can also request daily data.
