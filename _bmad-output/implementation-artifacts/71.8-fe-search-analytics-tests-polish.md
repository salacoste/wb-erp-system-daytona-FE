### Important Notes

1. **SortButton is duplicated 3 times**: Identical ~20-line component in SearchOrdersTable (lines 97-117), SearchByProductTable (lines 122-142), SearchByQueryTable (lines 143-164). Only SearchByQueryTable has `type="button"`. Extract to shared component.
2. **SortButton location**: Keep in the search components folder (`src/app/(dashboard)/analytics/search/components/SortButton.tsx`) since it's only used by search tables. Do NOT put in `src/components/ui/` or `src/components/custom/`.
3. **Hook tests pattern**: Use `renderHook` from `@testing-library/react` + `createTestQueryClient`/`createQueryWrapper` from `src/test/utils/test-utils.tsx`. Mock `@/lib/api/search-analytics` module.
4. **E2E test pattern**: Follow `e2e/analytics/analytics-hub.spec.ts` — use `page.goto()`, `page.waitForLoadState('networkidle')`, check heading and tab labels.
5. **91 tests already exist**: 48 component + 23 API + 20 RequireJam. This story adds ~20 more (hook tests + SortButton tests + E2E).
6. **Do NOT create MSW mocks** for hook tests. Simply mock the API module functions with `vi.mock()` — the hooks are thin wrappers around `useQuery`, testing the config is sufficient.
7. **aria-busy pattern**: Wrap skeleton containers in `<div role="status" aria-busy="true">`. Remove aria-busy when data loads (React handles this via conditional rendering).
8. **File size limit**: Each file MUST stay under 200 lines (ESLint enforced).
9. **Do NOT modify** types, API client, or page.tsx — they are already complete and tested.
