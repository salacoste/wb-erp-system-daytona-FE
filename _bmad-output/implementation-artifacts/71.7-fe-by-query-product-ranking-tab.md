## User Story

**As a** Wildberries seller on the Search Analytics page,
**I want to** enter a search term and see how my products rank for it,
**so that I can** identify which products need SEO improvement for specific keywords.

### Key Types (already exist in `src/types/search-analytics.ts`)

```typescript
interface SearchByQueryResponse {
  query: string
  period: SearchPeriod
  products: SearchProductItem[]
  totalProducts: number
}

interface SearchProductItem {
  nmId: number
  vendorCode: string | null
  avgPosition: number
  totalImpressions: number
  totalClicks: number
  avgCtr: number
  totalOrders: number
  totalRevenue: number  // NOTE: Backend hardcodes to 0
}
```

### Hook (already exists in `src/hooks/use-search-analytics.ts`)

```typescript
useSearchByQuery(query: string, from: string, to: string)
// enabled when query.length >= 2 && !!from && !!to
```

### Important Notes

1. **No combobox needed**: Unlike 71.6 (product selector), this tab uses a simple text input — no dropdown, no API for suggestions. Just debounce the raw input and pass to `useSearchByQuery`.
2. **Default sort is ascending**: Position 1 is best, so default sort is `avgPosition` ascending (unlike 71.6 which defaults to `totalImpressions` descending).
3. **Position badge**: Color-coded badge around position value. Use inline Tailwind classes — no new component needed (just a helper function).
4. **totalRevenue = 0**: Backend search sync processor hardcodes revenue to 0. Still show the column but it will display "0 ₽" for all rows. Known backend limitation.
5. **vendorCode can be null**: Show nmId always, show vendorCode below it only when present.
6. **Sort pattern**: Follow `SearchByProductTable.tsx` exactly — useState for field+order, SortButton component, spread+sort array.
7. **Debounce pattern**: Use `useRef<NodeJS.Timeout>` + `setTimeout` pattern from ProductCombobox (300ms). Do NOT use a library.
8. **File size limit**: Each file MUST stay under 200 lines (ESLint enforced).
