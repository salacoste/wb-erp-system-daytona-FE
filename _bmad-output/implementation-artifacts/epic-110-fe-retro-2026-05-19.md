## What Went Well

### S-1: Epic 109 stubs made Story 110.1 zero-infrastructure
Story 108.1 pre-created `src/types/ai/evaluations.ts` and `src/lib/api/ai/evaluations.ts` as stubs. Story 110.2 consumed them directly. No new type files or API module files were created — only normalizers and hooks were added on top. Epic 109 A-2 action item ("consume stubs") delivered exactly as planned.

### S-2: Backend coordination mid-Epic caught before merge (Story 110.2 F-1)
The `?modelId=` filter on `/v1/ai/evaluations` was not in the original API contract — the backend shipped it during Story 110.2 development. The 1st-pass review caught that the hook was missing the filter param and that `EvaluationsTable` would need the `modelId` prop threaded through. Fix propagated to both files before merge. Pattern: mid-Epic backend additions caught by adversarial review rather than discovered post-merge.

### S-3: Pre-emptive backend request filed (Story 110.3 — Request #166)
Story 110.3 identified that `naiveAccuracyPercent` and `evaluationCount` were needed in the SKU accuracy response but not yet in the backend contract. Request #166 was filed before implementation, and the fields were added to types + normalizer with AP#8 null guards. Backend coordination happened proactively, not reactively.

### S-4: Pure-function discipline enabled direct, fast test coverage
All CSV helpers (`exportEvaluationsToCsv`, `exportSkuAccuracyToCsv`, `escapeCsvCell`, `prefixUtf8Bom`) are pure functions with zero React dependency. 37 tests run in <100ms with no component mounting, no mock setup, no QueryClient. This is the "pure functions over hook mocking" pattern from the project memory — Story 110.5 separated string-build from side-effect download, fixing the Story 77.5 anti-pattern.

### S-5: 3-pass review on Stories 110.3+110.4 caught additional defect class
Story 110.3's 3rd-pass review surfaced the char-count meta-pattern: Lessons lines exceeded 120 chars through two fresh-context passes without detection. Story 110.4 codified measurement via `python len()` as part of the Lessons-line discipline. This is the only new defect class surfaced in Epic 110 — all others were established patterns.

### S-6: A11y ratchet completed cleanly (Epic 109 A-4)
All 17 `jsx-a11y/control-has-associated-label` violations fixed in Story 110.1 — 13 files, all icon-only buttons now have `aria-label`. Rule ratcheted from `warn` to `error`. ESLint baseline maintained at 112 warnings (all pre-existing `no-explicit-any`). Epic 109 A-4 closed.

### S-7: Route registration upfront prevented inline template proliferation (Epic 109 A-5)
Story 110.1 registered `ROUTES.ANALYTICS.MODELS_EVALUATIONS`, `buildModelSkuAccuracyRoute`, `buildModelFeedbackRoute` in `src/lib/routes.ts` before any story needed them. Zero inline route template findings across the entire epic. Epic 109 A-5 closed.

## What Didn't Go Well

### C-1: Story 110.4 2nd-pass caught CRITICAL state-machine bug missed by 1st-pass
`FeedbackButtons` auto-reset used `mutation.submittedAt` which is not a property of TanStack Query's mutation object. The auto-reset `useEffect` was reading `undefined` and never firing. 1st-pass reviewed the state machine and marked it correct; 2nd-pass caught the incorrect field name. Pattern: property-name errors in hook state access require fresh-context verification, not just logic review.

### C-2: Story 110.3 char-count Lessons violations escaped two fresh-context passes
The Lessons-line char-count discipline (≤120 chars per lesson per Story 94.4-FE) was violated in Story 110.3's Lessons line. Two separate review passes — both reading the story file — did not catch it. Only the 3rd-pass (meta-review) noticed. Root cause: reviewers verified the Lessons requirement ("present and non-empty") but did not mechanically measure char counts. Discipline requires mechanical verification, not visual inspection.

### C-3: Story 110.3 F-8 opaque ID discipline was not in CLAUDE.md before the finding
The `String(nmId)` vs `formatNumber(nmId)` distinction for opaque identifiers was not a documented rule — it was discovered during Story 110.3 2nd-pass review (F-8). The finding was correct: `formatNumber(12345)` produces `'12 345'` with non-breaking space, which is wrong for IDs shown as search keys. The fix was propagated to Story 110.2 `EvaluationsTable` (fix-block propagation discipline). The rule should have been in CLAUDE.md before implementation began.

### C-4: Story 110.2 EvaluationsTable lacked `modelId` prop initially
The `modelId` prop was missing from `EvaluationsTable` at initial implementation — `FeedbackButtons` inside the table needed it to post feedback. 1st-pass caught this, but it required threading the prop through 3 levels (EvaluationsList → EvaluationsTable → FeedbackButtons). The fix was straightforward but adds evidence that component prop-threading requirements should be traced top-down before implementation, not discovered during review.

---

## Lessons Learned

1. **Opaque IDs (nmId, productId) must use `String(id)`, never `formatNumber` — locale spaces break copy-paste search.**
2. **Lessons char-count: use `python len()`, not visual — 2 passes missed >120-char violations.**
3. **Property-name errors in state machines need fresh-context verification, not just logic review.**

## Action Items for Epic 111

### A-1: Document opaque-ID formatting rule in CLAUDE.md Known Anti-Patterns

**Context**: Story 110.3 F-8 established that numeric IDs used as search keys (nmId, productId, etc.) must use `String(id)` not `formatNumber(id)`. `formatNumber(12345)` → `'12 345'` (non-breaking space) which is wrong for copy-paste search usage. This is not yet in CLAUDE.md.

**Action**: Add as Anti-Pattern #10 (or append to AP#8 corollary): "Opaque numeric IDs (nmId, productId, forecastId) must render via `String(id)`, never `formatNumber(id)` — locale formatting destroys search-key usability."

**Owner**: SM agent (story 111.1 pre-flight)
**Success criterion**: `CLAUDE.md` contains the rule before first Epic 111 story implements a numeric ID column.

### A-2: Implement `scripts/check-lessons-length.sh` mechanical validator

**Context**: Story 110.3's 3rd-pass meta-pattern showed that >120-char Lessons lines escape visual inspection across two fresh-context review passes. Only a mechanical validator is reliable. Story 110.4 codified the `python len()` measurement discipline, but it's manual. An automated script would prevent recurrence.

**Action**: Create `scripts/check-lessons-length.sh` that:
1. Scans story files in `docs/stories/` for `**Lessons:**` lines.
2. Splits on `(N)` markers and measures each lesson's char count.
3. Exits non-zero if any lesson exceeds 120 chars.
4. Add to CI or as an optional `npm run check:lessons` script.

**Owner**: Dev executor (Story 111.1 or dedicated infra story)
**Success criterion**: `bash scripts/check-lessons-length.sh` exits 0 on all existing story files; exits 1 on a deliberately injected 130-char lesson in a test fixture.

### A-3: Visual UAT for AI evaluations + feedback when test cabinet has data

### A-4: Consider explicit scoping decision tree for TanStack Query invalidation

**Context**: Story 110.4 `useAiFeedback` invalidates `['ai', 'evaluations']` after a feedback POST. The question of when to invalidate `['ai']` root vs `['ai', 'evaluations']` domain-specific has been decided case-by-case without a documented rule. This led to one review finding in Story 110.4 (scope too broad vs too narrow).

**Action**: Document the invalidation scoping decision tree in `docs/process/ai-module-architecture.md`:
- `['ai']` root: only when a feedback/training action may affect ALL ai subdomains simultaneously.
- `['ai', domain]`: standard for domain-local mutations (feedback → evaluations only).
- `['ai', domain, 'detail', id]`: for per-entity mutations with narrow cache scope.

**Owner**: SM agent / architect
**Success criterion**: Epic 111 retrospective has zero invalidation-scoping review findings.
