## What Didn't Go Well

### C-1: F-10 chain-defect in Story 109.5 — state-precedence inversion created symmetric defect
Story 109.5's 2nd-pass review caught F-10: when the 1st-pass fixed the error-state check order for `useAiModels.isLoading`, it introduced a parallel misclassification for `useAiModels.isError` — the same fix-block propagation pattern documented in Story 97.1-FE. After 5 explicit table rows in `CLAUDE-PATTERNS.md` Pattern 4 and 13+ chain-link recurrence count, it manifested again. The structural lesson (Story 97.4-FE): fix-block propagation defects recur even with explicit rules because single-context authors cannot reliably enumerate all parallel locations. Only multi-context adversarial review catches them reliably.

### C-2: Story 109.1 1st-pass missed an AC-mandated regression test that 2nd-pass caught
Story 109.3 spec required a regression test for AC-5 (rollbackNotice) and AC-6 (explanation) — both were missing after the 1st-pass review. The 2nd pass caught it. This is the only CRITICAL-class gap in the review chain for Epic 109: the 1st-pass missed something the spec explicitly mandated. Pattern: 1st-pass reviewers focus on code logic; 2nd-pass reviewers cross-check against AC list. Both passes serve different defect classes.

### C-3: MAPE scale contract ambiguity required executor verification against integration guide
Story 109.5 executor had to verify whether backend returns MAPE as 0-1 or 0-100 before implementing `formatPercentage`. The integration guide was ambiguous (backend doc said "percentage" without specifying scale). Boundary normalizer needed an explicit scale decision. Pattern: for numeric ratio/percentage fields from backend, the normalizer must document the input scale assumption (0-1 vs 0-100) as a JSDoc comment, not leave it implicit.

### C-4: Story 109.3 1st-pass attestation drift — claimed L-3 addressed but didn't apply the fix
2nd-pass of Story 109.3 caught that the 1st-pass review record claimed "L-3 addressed" but the actual fix was not applied to the sibling test file. The fix-block entry said it was done; it wasn't. Attestation drift in the review record itself — the meta-defect of a review that self-reports completion without verifying it. This has appeared in prior epics (Stories 97.1, 97.2); remains a structural pattern.

### C-5: `buildModelPerformanceRoute` was missing at Story 109.3 close — caught mid-Story 109.5
Story 109.3 closed with a row-click handler using an inline template literal (`/analytics/models/${id}/performance`) instead of a route helper. Story 109.5 F-6 caught this when implementing the dynamic route. The fix was deferred to 109.5 which was correct (109.3 didn't own the performance route yet), but it demonstrates that inline route templates are a magnet for future route-drift. Story 109.5 codified `buildModelPerformanceRoute` in `src/lib/routes.ts` — now locked.

## Lessons Learned

1. **State-precedence inversion fixes create symmetric chain-defects in sibling error paths — audit ALL parallel error sources on every fix** (F-10, Story 109.5; 6th recurrence of Story 97.1-FE propagation pattern). Fix-block discipline alone is insufficient; executors must enumerate all equivalent code paths before marking a fix complete.

2. **1st-pass and 2nd-pass reviews catch different defect classes** — 1st-pass catches code logic and typing errors; 2nd-pass catches AC-compliance gaps, attestation drift, and fix-propagation misses. Across Epic 109's 5 reviewed stories, every 2nd-pass finding was either (a) a consequence of a 1st-pass fix or (b) an AC-list compliance gap the 1st reviewer didn't check. The two passes are non-redundant by design.

3. **Recharts chart stories should pre-plan the jsdom vi.mock template before implementation** — both ForecastChart (109.2) and MapeTrendChart (109.5) needed the `vi.mock('recharts', () => ({ ResponsiveContainer: ..., ... }))` boilerplate. Future chart stories should include an explicit "copy jsdom-mock template from FunnelOverlayChart" step in Task 1 to avoid the HIGH finding of "tooltip components weren't tested because the mock swallowed them."

4. **Boundary normalizer JSDoc must document input scale for ratio/percentage fields** — MAPE, confidence, and aiVsNaive fields arrived with ambiguous scales. The normalization decision (0-1 vs 0-100) must be documented as a JSDoc `@param` or inline comment at the normalizer call site, not left implicit. Future AI/ML fields: assume `null` until verified, document scale assumption explicitly (Story 109.5 lesson).

5. **`MODEL_TYPE_LABELS` pattern generalizes: shared cross-feature constants belong in `src/types/`, not component files** — Story 109.3 Task 2 extract proved zero-churn migration is possible via backward-compat barrel. Apply this pattern to any constant that appears in 2+ component files: extract to `src/types/[domain]/[file].ts` on first duplication.
