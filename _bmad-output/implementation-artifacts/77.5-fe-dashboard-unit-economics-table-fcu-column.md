# Story 77.5: Dashboard Unit Economics Table — FCU Column

Status: done

## Story

As a **seller using the unit economics dashboard**,
I want **to see the delivery-to-warehouse cost (DCU) as a dedicated column and summary card**,
so that **I can assess the full cost structure including my own shipment costs alongside WB fees**.

## Acceptance Criteria

1. **`UnitEconomicsTable.tsx` has new "Доставка" column** showing `delivery_to_warehouse` % (from merged FCU data), positioned after "Хранение %" and before "Маржа %"
2. **Column renders DCU value** with `formatPercentage()` when present, or "—" (em dash) when no confirmed shipment exists for that SKU
3. **Column is sortable** (ascending/descending) — extend the existing sort mechanism to support `delivery_to_warehouse` field
4. **Column has a tooltip**: "Стоимость доставки на единицу товара из последней подтверждённой отправки" (accessible via `title` attribute or `Tooltip` component)
5. **`UnitEconomicsSummaryCards` has new card**: "Ср. доставка" showing average DCU (₽) across all SKUs with confirmed shipments, with Truck icon, teal background
6. **`calculateHealthScore()` optionally factors in delivery cost coverage**: bonus points if >80% of revenue-generating SKUs have confirmed FCU (new 4th component, rebalance weights)
7. **All files remain under 200 lines** (ESLint enforced)
8. **Unit tests** for: new column rendering + sort, summary card display, health score update, null/undefined handling

### Sort Implementation — Nulls-Last Pattern

For the new sortable column, items without `delivery_to_warehouse` should sort to the bottom regardless of sort direction:

```typescript
// In sort comparison:
const aVal = a.costs_pct.delivery_to_warehouse
const bVal = b.costs_pct.delivery_to_warehouse
if (aVal == null && bVal == null) return 0
if (aVal == null) return 1  // nulls last
if (bVal == null) return -1 // nulls last
return sortOrder === 'asc' ? aVal - bVal : bVal - aVal
```

**Important**: Current sorting is server-side (via `queryParams.sort_by`). The delivery_to_warehouse sort must be **client-side only** since the backend doesn't know about merged FCU data. Keep server-side sort for `revenue` and `net_margin_pct`; add client-side sort for `delivery_to_warehouse`.

### Average DCU Calculation

For the summary card, compute average **per-unit** delivery cost (not per-revenue %):

```typescript
const itemsWithDelivery = data.data.filter(
  item => item.costs_rub.delivery_to_warehouse != null && item.units_sold && item.units_sold > 0
)
const avgDcu = itemsWithDelivery.length > 0
  ? itemsWithDelivery.reduce((sum, item) => sum + (item.costs_rub.delivery_to_warehouse! / item.units_sold!), 0) / itemsWithDelivery.length
  : undefined
```

### Health Score Rebalance

Current weights (total 100):
- Margin: 40pts → **35pts**
- Profitable ratio: 40pts → **35pts**
- COGS coverage: 20pts → **20pts** (unchanged)

The function signature change is backward-compatible: `deliveryCoverageRatio` defaults to `undefined`, meaning existing callers get the old behavior (max score 90 + 10 delivery bonus).

### Anti-Patterns (DO NOT)

- **DO NOT** show `0` for missing delivery data — always use "—" (em dash `\u2014`)
- **DO NOT** add `delivery_to_warehouse` to server-side sort params (backend doesn't support it)
- **DO NOT** include delivery_to_warehouse in `calculateWbFeesPct/Rub()` — it's a seller cost
- **DO NOT** modify `mergeDeliveryCosts()` — it's already complete from 77.4
- **DO NOT** create a separate component file just for the delivery column cell — use inline rendering in `UnitEconomicsTableRow`
- **DO NOT** use `CostCell` for the delivery column (it would show 0 as red) — use custom rendering with "—" fallback
- **DO NOT** import from `hooks-v1/` — the directory was renamed to `hooks/` in 77.1
