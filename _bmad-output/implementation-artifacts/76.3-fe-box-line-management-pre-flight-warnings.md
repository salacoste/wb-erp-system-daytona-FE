# Story 76.3: Box Line Management + Pre-flight Warnings

Status: done

## Story

As a **seller**,
I want to add products (box lines) to each pallet with packaging warnings,
So that I can specify exactly what goes on each pallet before cost calculation.

## Acceptance Criteria

1. **Add box line (DRAFT only)** — Given an expanded pallet in a DRAFT shipment, "Добавить товар" button opens a form/dialog with: SKU (searchable combobox via `/v1/products`), Box Count (required, number > 0), Total Units override (optional, number — for partial boxes). Submit → `POST /v1/shipments/:id/pallets/:palletId/box-lines` with `{ nmId, boxCount, totalUnits? }`.
2. **Box line table** — Given box lines exist in a pallet, the pallet content renders a table: Товар (nmId + product name), Коробок, Штук в коробке (from packaging config or "—"), Всего штук, Действия (edit/remove). Empty pallet shows placeholder: "Товары ещё не добавлены".
3. **Edit box line (DRAFT only)** — Clicking edit on a box line opens form with boxCount and totalUnits editable, nmId read-only. Submit → `PUT /v1/shipments/:id/box-lines/:boxLineId` with `{ boxCount, totalUnits }`. Note: UPDATE uses shipment-level path (no palletId).
4. **Remove box line (DRAFT only)** — Clicking remove opens confirmation. Confirming → `DELETE /v1/shipments/:id/box-lines/:boxLineId`. Note: DELETE also uses shipment-level path (no palletId).
5. **Pre-flight warning: missing packaging** — When a seller adds a box line with an nmId that lacks SKU packaging config (404 from `/v1/sku-packaging/:nmId`), an inline `<Alert variant="warning">` appears: "У товара {nmId} нет настройки упаковки" with a `<Link>` to `/shipments/sku-packaging`. Non-blocking — box line can still be added.
6. **Pre-flight warning: missing COGS** — When a seller adds a box line with an nmId that lacks COGS (`has_cogs === false` from product data), an inline `<Alert variant="warning">` appears: "У товара {nmId} не указана себестоимость" with a `<Link>` to `/products?filter={nmId}`. Non-blocking — box line can still be added.
7. **CONFIRMED state** — When status=CONFIRMED: hide "Добавить товар" button, hide edit/remove actions in box line table. Table columns are readonly.
8. **Component extraction** — All files ≤ 200 lines. Sub-components: `BoxLineTable.tsx` (line listing), `BoxLineForm.tsx` (add/edit form), `PreflightWarnings.tsx` (warning banners). Hooks in `src/hooks/use-box-lines.ts`.
9. **Types** — Add `BoxLineCreateRequest` and `BoxLineUpdateRequest` to `src/types/shipment-cost.ts`.
10. **All files ≤ 200 lines**, 0 ESLint errors, 0 TypeScript errors.

## Dev Notes

### Architecture Patterns (MUST follow)

**API client** — Create `src/lib/api/shipment-cost/box-lines-api.ts`:
```typescript
import { apiClient } from '@/lib/api-client'
import type { BoxLine, BoxLineCreateRequest, BoxLineUpdateRequest } from '@/types/shipment-cost'

/** POST /v1/shipments/:id/pallets/:palletId/box-lines — CREATE uses 3-level nesting */
export async function addBoxLine(
  shipmentId: string,
  palletId: string,
  data: BoxLineCreateRequest
): Promise<BoxLine> {
  return apiClient.post<BoxLine>(
    `/v1/shipments/${shipmentId}/pallets/${palletId}/box-lines`,
    data
  )
}

/** PUT /v1/shipments/:id/box-lines/:boxLineId — UPDATE uses 2-level (no palletId!) */
export async function updateBoxLine(
  shipmentId: string,
  boxLineId: string,
  data: BoxLineUpdateRequest
): Promise<BoxLine> {
  return apiClient.put<BoxLine>(
    `/v1/shipments/${shipmentId}/box-lines/${boxLineId}`,
    data
  )
}

/** DELETE /v1/shipments/:id/box-lines/:boxLineId — DELETE uses 2-level (no palletId!) */
export async function removeBoxLine(
  shipmentId: string,
  boxLineId: string
): Promise<void> {
  await apiClient.delete(`/v1/shipments/${shipmentId}/box-lines/${boxLineId}`)
}
```

**CRITICAL: Asymmetric API paths!**
- **CREATE** box line: `POST /v1/shipments/:id/pallets/:palletId/box-lines` — needs palletId (3-level)
- **UPDATE** box line: `PUT /v1/shipments/:id/box-lines/:boxLineId` — NO palletId (2-level)
- **DELETE** box line: `DELETE /v1/shipments/:id/box-lines/:boxLineId` — NO palletId (2-level)
This is by backend design — update/delete only need shipmentId + boxLineId because boxLineId is globally unique.

**Hooks** — Create `src/hooks/use-box-lines.ts`:
```typescript
'use client'
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { shipmentsQueryKeys } from '@/hooks/use-shipments'
import { addBoxLine, updateBoxLine, removeBoxLine } from '@/lib/api/shipment-cost'
import type { BoxLineCreateRequest, BoxLineUpdateRequest } from '@/types/shipment-cost'

export function useAddBoxLine(shipmentId: string, palletId: string) {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: (data: BoxLineCreateRequest) => addBoxLine(shipmentId, palletId, data),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.byId(shipmentId) })
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.all() })
    },
  })
}

export function useUpdateBoxLine(shipmentId: string) {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: ({ boxLineId, data }: { boxLineId: string; data: BoxLineUpdateRequest }) =>
      updateBoxLine(shipmentId, boxLineId, data),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.byId(shipmentId) })
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.all() })
    },
  })
}

export function useRemoveBoxLine(shipmentId: string) {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: (boxLineId: string) => removeBoxLine(shipmentId, boxLineId),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.byId(shipmentId) })
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.all() })
    },
  })
}
```

**useAddBoxLine** takes `palletId` as parameter (needed for create path) while **useUpdateBoxLine** and **useRemoveBoxLine** don't need it.

### Backend API Endpoints

| Method | Endpoint | Request Body | Response | Notes |
|--------|----------|-------------|----------|-------|
| POST | `/v1/shipments/:id/pallets/:palletId/box-lines` | `{ nmId, boxCount, totalUnits? }` | `BoxLine` | 3-level nesting, DRAFT only |
| PUT | `/v1/shipments/:id/box-lines/:boxLineId` | `{ boxCount?, totalUnits? }` | `BoxLine` | 2-level, DRAFT only |
| DELETE | `/v1/shipments/:id/box-lines/:boxLineId` | — | 204 | 2-level, DRAFT only |

**Error codes**: 400 (validation), 404 (not found), 409 (shipment is CONFIRMED — cannot mutate).

**IMPORTANT: Backend uses PUT, NOT PATCH** for box-line updates (same pattern as shipment updates in Story 76.2).

### Pre-flight Warnings Implementation

The `PreflightWarnings` component should:
1. Accept `nmId: number | null` — when null, render nothing
2. Use `useSkuPackagingByNmId(nmId)` — if error/404, show packaging warning
3. Use `useProducts({ search: String(nmId), limit: 1 })` or `useProductDetail(nmId)` — check `has_cogs === false`, show COGS warning
4. Both warnings are non-blocking (display only, no form validation effect)
5. Each warning has a `<Link>` to the relevant page:
   - Missing packaging → `ROUTES.SHIPMENTS.SKU_PACKAGING` (`/shipments/sku-packaging`)
   - Missing COGS → `/products?filter=${nmId}`
6. Use `<Alert variant="warning">` with `<AlertTriangle>` icon
7. Warnings appear in the BoxLineForm when an nmId is selected, before submitting

### BoxLineForm Implementation

**Two modes**: Create (no editingLine) and Edit (editingLine provided):
- **Create mode**: ProductCombobox enabled, all fields empty, submits via `useAddBoxLine`
- **Edit mode**: ProductCombobox disabled (nmId read-only), boxCount/totalUnits pre-filled, submits via `useUpdateBoxLine`

**Form fields**:
- SKU (ProductCombobox) — required in create mode, read-only in edit mode
- Box Count (number input) — required, > 0
- Total Units (number input) — optional, for partial boxes. Hint text: "По умолчанию = коробок × штук/коробку"

**Dialog pattern** — Follow Epic 75 rules:
- `<form onSubmit>` wrapper for Enter-key support
- `<Button type="submit">` (NOT AlertDialogAction)
- Block close during pending: `onOpenChange={v => !v && !isPending && onClose()}`
- `aria-label` on all buttons
- `aria-describedby` + `aria-invalid` on inputs with validation errors
- `DialogDescription` for Radix accessibility
- try/catch on `mutateAsync`

### BoxLineTable Implementation

**Columns**:
| Column | Source | Notes |
|--------|--------|-------|
| Товар | `boxLine.nmId` | Show nmId only (product name not in BoxLine type) |
| Коробок | `boxLine.boxCount` | Integer |
| Штук/коробку | packaging config `unitsPerBox` or "—" | Need to resolve from packaging data |
| Всего штук | `boxLine.totalUnits ?? '—'` | null before calculate |
| Действия | Edit + Remove buttons | Hidden when !isDraft |

**Note on "Штук/коробку" column**: The BoxLine type does NOT include `unitsPerBox`. Two approaches:
1. **Simple**: Show "—" for this column (data not available in BoxLine response) — acceptable for MVP
2. **Rich**: Fetch packaging data per nmId — expensive, many queries. NOT recommended.
→ **Choose approach 1** — show "—" in this column. After `/calculate`, `totalUnits` will be populated with the correct value (boxCount × unitsPerBox).

### Anti-Patterns to Avoid

1. **Do NOT use `AlertDialogAction`** for async submit buttons — use `<Button>` with manual dialog close
2. **Do NOT use `vi.doMock()`** in tests — use mutable variable + getter in `vi.mock()` factory
3. **Do NOT forget `aria-label`** on icon-only buttons (edit, remove box line)
4. **Do NOT forget `aria-describedby` + `aria-invalid`** on form inputs with validation errors
5. **Do NOT forget `DialogDescription`** — Radix warns without it
6. **Do NOT create duplicate types** — all shipment types live in `src/types/shipment-cost.ts`
7. **Do NOT exceed 200 lines** in any file — split early if approaching 180+
8. **Do NOT confuse API paths** — CREATE uses 3-level `/pallets/:palletId/box-lines`, UPDATE/DELETE use 2-level `/box-lines/:boxLineId`
9. **Do NOT forget try/catch** on `mutateAsync` calls — show error feedback to user
10. **Do NOT show calculation-result columns** (unitCostRub, FCU, etc.) — those are Story 76.4 scope
11. **Do NOT fetch packaging data per row for "Штук/коробку" column** — show "—" instead (too many queries)
12. **Do NOT block form submission** on pre-flight warnings — they are informational only

### Previous Story Intelligence (76.2)

Key learnings from Story 76.2:
- **`variables` from useMutation**: Use TanStack Query's `variables` to track which specific item is being operated on (prevents shared pending state across all items)
- **`defaultOpen` pattern**: Track new items via state and pass as prop to auto-expand
- **Backend uses PUT, not PATCH**: All update endpoints use `apiClient.put()`
- **`deliveryMode` is NOT updatable**: Backend returns 409 (relevant if BoxLineForm accidentally tries)
- **Dual cache invalidation**: Always invalidate both `byId(shipmentId)` AND `all()` in mutations
- **Delete confirmation inline**: AlertDialogAction is OK for non-async confirmations (just triggers mutation)
- **PalletAccordionItem children**: Slot is ready — `children ?? placeholder` pattern
