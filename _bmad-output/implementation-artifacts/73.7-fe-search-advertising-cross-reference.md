## User Story

**As a** seller with both search and advertising data,
**I want** to see organic vs paid keyword overlap and compare search position against ad spend,
**so that** I can optimize my advertising budget by identifying where organic search is already strong.

## Dev Notes

### Architecture: Frontend-Only Data Merge (No Backend Endpoint)

There is **NO backend cross-reference endpoint**. This story merges data from TWO existing API calls client-side:

```
Search Analytics API                    Advertising Analytics API
─────────────────                      ──────────────────────────
GET /v1/analytics/search/orders        GET /v1/analytics/advertising
  ?from=&to=&groupBy=product             ?from=&to=&view_by=sku
                                         &sort_by=spend&sort_order=desc
Returns: SearchOrderItem[]              Returns: AdvertisingItem[]
  { key: nmId, totalOrders,               { key: "sku:NNN", spend,
    totalRevenue, vendorCode }              revenue, clicks, views, ... }

          ↓                                        ↓
          └──────── JOIN ON nmId ─────────────────┘
                         ↓
              CrossReferenceItem[]
                { nmId, vendorCode,
                  avgPosition, searchClicks,  ← from search
                  adSpend, adClicks,          ← from advertising
                  channel: 'organic'|'ad'|'both' }
```

### Critical: Data Join Strategy

**Option A (Recommended): Search Orders (groupBy=product) + Advertising (view_by=sku)**
- Search orders endpoint returns `SearchOrderItem` with `key: nmId` when `groupBy='product'`
- Advertising endpoint returns `AdvertisingItem` with `key: "sku:NNNNN"` — extract nmId from key
- Join: parse `sku:` prefix from advertising key → match with search nmId
- Pros: Both endpoints return product-level data, single call each
- Cons: Search orders lacks `avgPosition` — would need separate by-product calls per nmId

**Option B: Search By-Product (per product) + Advertising (view_by=sku)**
- Call `getSearchByProduct(nmId, from, to)` for EACH product with ad spend
- Gets full search data: avgPosition, impressions, clicks, CTR per keyword
- Cons: N+1 API calls (one per advertised product), expensive with many products
- AVOID this approach — too many API calls

**Option C (Best Compromise): Search Orders + Advertising, position from search metadata**
- Use search orders (groupBy='product') for organic product list
- Use advertising analytics for ad product list
- For avgPosition: search orders doesn't return it. Either:
  - (a) Accept no position data in cross-reference (simplify AC-4)
  - (b) Batch-load top-N products' search data via by-product endpoint
  - (c) Request backend to add avgPosition to search orders endpoint (out of scope)

**RECOMMENDED: Option A without position data, with note that AC-4 insights cards may show "позиция неизвестна" if avgPosition unavailable from the orders endpoint.**

### Key Data Field Mapping

| Cross-Reference Field | Source | API Field |
|----------------------|--------|-----------|
| nmId | Both | search: `key` (number), ad: parse from `key` ("sku:NNN") |
| vendorCode | Both | search: `vendorCode`, ad: `sku_id` |
| searchClicks | Search | `SearchOrderItem` doesn't have clicks — use `totalOrders` as proxy OR drop this column |
| adSpend | Advertising | `AdvertisingItem.spend` |
| adClicks | Advertising | `AdvertisingItem.clicks` |
| channel | Computed | 'organic' if only in search, 'ad' if only in ad, 'both' if in both |

### IMPORTANT: Search Data Limitations

1. **`totalRevenue` is always 0** — backend hardcodes it in search sync processor
2. **Search orders (groupBy=product)** returns: `key` (nmId), `totalOrders`, `totalRevenue`, `vendorCode`, `uniqueQueries` — NO avgPosition, NO clicks, NO impressions
3. **Search by-product** returns full data (avgPosition, clicks, impressions) but requires individual nmId calls
4. **Jam subscription required** — search data only available with "standard" tier

### Channel Classification Logic

```typescript
type Channel = 'organic' | 'ad' | 'both'

function classifyChannel(inSearch: boolean, inAd: boolean): Channel {
  if (inSearch && inAd) return 'both'
  if (inSearch) return 'organic'
  return 'ad'
}
```

### API Call Strategy

```typescript
// In CrossReferencePageContent.tsx:
const { data: searchData } = useSearchOrders(from, to, { groupBy: 'product' })
const { data: adData } = useAdvertisingAnalytics({
  from, to,
  view_by: 'sku',
  sort_by: 'spend',
  sort_order: 'desc',
  limit: 500, // Get all products, not paginated
})

// Merge client-side:
const mergedData = useMemo(() => {
  if (!searchData?.items || !adData?.data) return []
  return mergeSearchAndAdData(searchData.items, adData.data)
}, [searchData, adData])
```

### Important: Advertising Key Parsing

Advertising items use `key: "sku:270937054"` format. Extract nmId:
```typescript
function parseNmId(adKey: string): number | null {
  const match = adKey.match(/^sku:(\d+)$/)
  return match ? parseInt(match[1], 10) : null
}
```
