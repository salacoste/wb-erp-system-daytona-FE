## User Story

**As a** seller viewing the advertising analytics page,
**I want** to see daily trend charts for ad spend, impressions, clicks, and orders,
**so that** I can identify trends and react quickly to daily performance changes.

### Backend Verification

The backend `AdvertisingDailyDto` (advertising-response.dto.ts:645-693) has ALL required fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `date` | `string` | Yes | Date YYYY-MM-DD |
| `spend` | `number` | Yes | Total ad spend |
| `views` | `number` | Yes | Total impressions |
| `clicks` | `number` | Yes | Total clicks |
| `ctr` | `number` | No | Click-through rate |
| `cpc` | `number` | No | Cost per click |
| `orders` | `number` | Yes | Orders attributed to ads |
| `revenueAttributed` | `number` | No | Ad-attributed revenue |

Backend returns `daily?: AdvertisingDailyDto[]` in `AdvertisingResponseDto` when `include_daily=true`.

### Type Additions

**`AdvertisingDailyItem`** (advertising-analytics.ts) — new type:
```typescript
/** Daily advertising metrics breakdown (Request #157) */
export interface AdvertisingDailyItem {
  /** Date in YYYY-MM-DD format */
  date: string
  /** Total ad spend in rubles */
  spend: number
  /** Total ad impressions (views) */
  views: number
  /** Total ad clicks */
  clicks: number
  /** Orders attributed to ads */
  orders: number
  /** Click-through rate (optional, calculated) */
  ctr?: number
  /** Cost per click (optional, calculated) */
  cpc?: number
  /** Ad-attributed revenue (optional) */
  revenue_attributed?: number
}
```

**`AdvertisingAnalyticsResponse.daily`** — add field:
```typescript
/** Daily breakdown when include_daily=true (Request #157) */
daily?: AdvertisingDailyItem[]
```

### API Adapter Mapping

In `getAdvertisingAnalytics()` adapter, after mapping `data`, add:
```typescript
daily: backendResponse.daily?.map((day: any) => ({
  date: day.date,
  spend: day.spend ?? 0,
  views: day.views ?? 0,
  clicks: day.clicks ?? 0,
  orders: day.orders ?? 0,
  ctr: day.ctr,

```

### Important Notes

1. **Use main API, NOT dashboard daily API**: This story uses `getAdvertisingAnalytics()` with `include_daily: true`, NOT `getAdvertisingDailyData()` from `daily-analytics/api.ts`. The dashboard daily API only maps `spend`, while the main API adapter will map all 4 fields.
2. **Backend has all fields**: The `AdvertisingDailyDto` includes `date`, `spend`, `views`, `clicks`, `orders`, `ctr`, `cpc`, `revenueAttributed`. No backend request needed.
3. **File organization**: Chart goes in `advertising/components/` alongside existing components (PerformanceMetricsTable, AdvertisingSummaryCards, etc.) — NOT in `components/custom/dashboard/` which is for the main dashboard.
4. **Pre-existing ESLint violations**: `advertising-analytics.ts` (550 lines) and API client (365 lines) are already over the 200-line limit. Adding ~15 lines to each is acceptable as pre-existing.
5. **page.tsx is 472 lines**: Already over 200-line limit (pre-existing). Adding ~5 lines for chart import and rendering is acceptable.
6. **Recharts v3.4.1**: Already installed. Use `LineChart`, `Line`, `XAxis`, `YAxis`, `CartesianGrid`, `Tooltip`, `ResponsiveContainer` from `recharts`.
7. **No new hooks needed**: `useAdvertisingAnalytics()` already accepts full `AdvertisingAnalyticsParams` including `include_daily`. Just add `include_daily: true` to the page's params.
8. **Predecessor intelligence (72.2)**: `include_daily` param was added to `AdvertisingAnalyticsParams` in story 72.2. `buildQueryString` already passes it through.

## Dev Notes

- **This is a 3 SP story** with 3 new files + 3 modified files. Main complexity is the chart component and adapter mapping.
- **Predecessor intelligence (72.2)**: Types-only stories complete fast. This story builds on the `include_daily` param added in 72.2.
- **Backend confirmed**: All 4 metrics (spend, views, clicks, orders) are available in `AdvertisingDailyDto`. No backend request needed.
- **Dashboard daily API stays separate**: The `daily-analytics/api.ts` `getAdvertisingDailyData()` function is for the main dashboard, not the advertising page. This story adds daily mapping to the main advertising API adapter.
- **Color choices**: Purple for spend (matches dashboard advertising convention), Blue for views, Green for clicks, Red for orders. These don't conflict with the dashboard chart colors for different purposes.
- **Pre-existing test failures**: 7 failed test files (9 tests) are pre-existing and unrelated to advertising.
- **Dual Y-axis rationale**: Spend (RUB, thousands/millions) has a vastly different scale than views/clicks/orders (integer counts). Dual Y-axis prevents spend from flattening the count metrics.
