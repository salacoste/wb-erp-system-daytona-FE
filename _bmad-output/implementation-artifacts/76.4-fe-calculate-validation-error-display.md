# Story 76.4: Calculate + Validation Error Display

Status: done

## Story

As a **seller**,
I want to calculate delivery cost per unit and see all validation errors at once,
So that I can fix issues and understand the true cost of shipping each product.

## Acceptance Criteria

1. **Calculate button** — Given a DRAFT shipment with at least one pallet and box line, a "Рассчитать" button is visible in the header area. Clicking it calls `POST /v1/shipments/:id/calculate`. On success, the shipment query is invalidated and refetched (NOT optimistic update). Button shows loading state during the request.
2. **Calculation results display** — On successful calculation, results display per SKU: nmId, product name, PCU (unitCostRub), DCU (deliveryCostPerUnit), FCU (finalCostPerUnit = PCU + DCU), total units, total line cost (finalCostLine). All monetary values use `formatCurrency()` with Russian locale. **Note**: `/calculate` returns numbers (not Decimal strings) — no `parseDecimal()` needed.
3. **Validation error panel** — When calculation returns validation errors, ALL errors display simultaneously (not just the first). Each error shows: error code, human-readable message in Russian, affected item identifiers.
4. **MISSING_COGS navigation** — `MISSING_COGS` error displays a clickable link navigating to `/products?filter={nmId}` for each affected SKU. Affected box lines in the pallet accordion are highlighted (red border/background).
5. **MISSING_PACKAGING navigation** — `MISSING_PACKAGING` error displays a clickable link navigating to `/shipments/sku-packaging`. Affected box lines are highlighted.
6. **All 9 error codes handled** — `MISSING_COGS`, `MISSING_PACKAGING`, `EMPTY_SHIPMENT`, `EMPTY_PALLET`, `ZERO_UNITS`, `ZERO_VOLUME`, `MISSING_DELIVERY_COST`, `DUPLICATE_SKU_IN_PALLET`, `INVALID_BOX_COUNT`. Each has: Russian message, icon, severity, navigation link pattern (where applicable).
7. **CONFIRMED state** — The "Рассчитать" button is disabled/hidden when status=CONFIRMED.
8. **Component extraction** — All files ≤ 200 lines. Sub-components: `CalculationResults.tsx` (results table), `ValidationErrorPanel.tsx` (error list container), `ValidationErrorItem.tsx` (single error with navigation), `validation-error-config.ts` (error code → message/icon/link mapping). Hook: `useCalculateShipment` in `src/hooks/use-shipment-calculations.ts`.
9. **All files ≤ 200 lines**, 0 ESLint errors, 0 TypeScript errors.

## Dev Notes

### Architecture Patterns (MUST follow)

**API function** — Create `src/lib/api/shipment-cost/shipment-calculations-api.ts`:
```typescript
import { apiClient } from '@/lib/api-client'
import type { CalculateShipmentResponse } from '@/types/shipment-cost'

/** POST /v1/shipments/:id/calculate — no body, returns results OR errors */
export async function calculateShipment(shipmentId: string): Promise<CalculateShipmentResponse> {
  return apiClient.post<CalculateShipmentResponse>(
    `/v1/shipments/${shipmentId}/calculate`
  )
}
```

**Response type** — Add to `src/types/shipment-cost.ts`:
```typescript
/** Combined calculate response — success returns results, validation failure returns errors */
export interface CalculateShipmentResponse {
  results: CalculationResultItem[]
  errors?: ValidationError[]
}
```

**CRITICAL: Backend response behavior** — The `/calculate` endpoint can return:
- **Success (200)**: `{ results: [...], errors: [] }` — shipment calculated, status may stay DRAFT
- **Validation failure (400)**: `{ errors: [...] }` — all 9 error types checked simultaneously (FR10)
- The API client may throw on 400 — handle in `catch` block, extract errors from error response body

**Hook** — Create `src/hooks/use-shipment-calculations.ts`:
```typescript
'use client'
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { shipmentsQueryKeys } from '@/hooks/use-shipments'
import { calculateShipment } from '@/lib/api/shipment-cost'
import type { CalculateShipmentResponse } from '@/types/shipment-cost'

export function useCalculateShipment(shipmentId: string) {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: () => calculateShipment(shipmentId),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.byId(shipmentId) })
      queryClient.invalidateQueries({ queryKey: shipmentsQueryKeys.all() })
    },
  })
}
```

### Backend API Endpoints

| Method | Endpoint | Request Body | Response | Error Cases |
|--------|----------|-------------|----------|-------------|
| POST | `/v1/shipments/:id/calculate` | — (empty) | `CalculateShipmentResponse` | 400 (validation errors), 404 (not found) |

From `test-api/35-shipment-cost.http`:
- Calculate: `POST /v1/shipments/{{shipmentId}}/calculate` — no body
- MISSING_COGS example → returns 400 with `{ errors: [{ code: "MISSING_COGS", message: "...", affectedIds: ["box-line-id-1"] }] }`
- SHIPMENT_NOT_CONFIRMED on recalculate DRAFT → 400 (that's Story 76.5 scope)
- Already-confirmed shipment → 409 on confirm (that's Story 76.5 scope)

**Error response handling**: The apiClient throws on 4xx. The error response body contains `{ errors: ValidationError[] }`. Extract via:
```typescript
try {
  const result = await calculateAsync()
  setCalculationResult(result)
  setValidationErrors([])
} catch (err: unknown) {
  // apiClient error contains response data
  const apiError = err as { response?: { data?: { errors?: ValidationError[] } } }
  const errors = apiError?.response?.data?.errors
  if (errors?.length) {
    setValidationErrors(errors)
    setCalculationResult(null)
  }
}
```

**Important**: Investigate the actual error shape from `apiClient` — the above pattern is a starting point. Check `src/lib/api-client.ts` for how errors are thrown to get the exact structure.

### CalculationResultItem Fields (numbers, NOT Decimal strings)

```typescript
interface CalculationResultItem {
  nmId: number
  productName: string
  unitCostRub: number     // PCU — себестоимость (production cost per unit)
  deliveryCostPerUnit: number // DCU — стоимость доставки на единицу
  finalCostPerUnit: number    // FCU = PCU + DCU
  totalUnits: number
  finalCostLine: number       // FCL = FCU × totalUnits
}
```

Use `formatCurrency()` directly on these numbers — no `parseDecimal()` needed (unlike other shipment fields).

**affectedIds mapping**: Validation errors contain `affectedIds` which are box line IDs. Collect all affected IDs across all errors:

```typescript
function getAffectedBoxLineIds(errors: ValidationError[]): string[] {
  return [...new Set(errors.flatMap(e => e.affectedIds ?? []))]
}
```

### Anti-Patterns to Avoid

1. **Do NOT use `parseDecimal()`** on `/calculate` response — it returns numbers, not Decimal strings
2. **Do NOT use `AlertDialogAction`** for the calculate button — it's an async operation needing loading state
3. **Do NOT show only the first error** — FR10 requires collect-all validation, display ALL simultaneously
4. **Do NOT use optimistic updates** for calculate — server-computed transform, must refetch
5. **Do NOT forget `aria-label`** on icon-only buttons and links
6. **Do NOT forget `aria-describedby`** on interactive elements in error items
7. **Do NOT create types in component files** — all types live in `src/types/shipment-cost.ts`
8. **Do NOT exceed 200 lines** in any file — split early if approaching 180+
9. **Do NOT forget try/catch** on `mutateAsync` — extract validation errors from error response
10. **Do NOT implement confirm/recalculate** — those are Story 76.5 scope
11. **Do NOT use `vi.doMock()`** in tests — use mutable variable + getter in `vi.mock()` factory
12. **Do NOT forget `DialogDescription`** — Radix warns without it (applies if any dialogs are used)
13. **Do NOT hardcode error messages** — use validation-error-config.ts mapping for all 9 codes

### Previous Story Intelligence (76.3)

Key learnings from Story 76.3:
- **`src/hooks` is a symlink to `src/hooks-v1`** — they are the SAME directory. Never treat as duplicates.
- **AlertDialogAction auto-closes** — causes dead loading/disabled states for async operations. Use `<Button>` with manual close for async.
- **`useSkuPackagingByNmId` guard fix** — `enabled: nmId > 0` (not `nmId != null`, since nmId is typed as number)
- **Dual cache invalidation** — Always invalidate both `byId(shipmentId)` AND `all()` in mutations
- **Component barrel exports** — Update `src/components/custom/shipments/index.ts` when adding new components
- **Mutable mock variable pattern** — For test mocking: `let mockX = false` with getter in `vi.mock()` factory
- **Test behavior, not implementation** — Use specific text assertions instead of fragile DOM structure checks
- **ARIA accessibility** — Every review found missing aria-labels. Add from the start on all interactive elements.
