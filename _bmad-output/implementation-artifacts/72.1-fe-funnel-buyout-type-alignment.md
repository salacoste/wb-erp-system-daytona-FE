## Dev Notes

- **This is a 1 SP types-only story.** No components, no hooks, no API client changes, no tests to write.
- Backend SQL queries already return all these fields. The frontend types just need to declare them.
- Existing code that destructures these types will not break -- adding new optional or required fields to an interface is backward-compatible in TypeScript (existing consumers just ignore the new fields).
- The `FunnelResponse.items` union type `(FunnelProductItem | FunnelDayItem)[]` means both item types will now have overlapping conversion fields, which is correct since the backend returns them for both groupBy modes.
