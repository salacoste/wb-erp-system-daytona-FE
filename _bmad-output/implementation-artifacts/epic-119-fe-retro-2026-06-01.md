## What Didn't Go Well

### D-1 — 3 consecutive Pass-2 reviews were 100% Pattern 4 propagation drift
Stories 119.1, 119.2, 119.3 each had a Pass-2 that was **entirely** fix-block propagation drift (Story 97.1-FE Pattern 4) — fixes applied in Pass-1 not propagated to all parallel locations (sprint-status rows, File Lists, cross-references). 1C+2H+3M (119.1), attestation drift (119.2), 1C+2H+3M (119.3). **Author intuition continues to systematically underestimate the parallel-locations search space** — the exact failure Pattern 4 was codified to catch, recurring 3× in one epic. The 2nd pass remains load-bearing; never short-circuit it.

### D-2 — Pass-1 fix introduced a CRITICAL test regression (119.1 P2-1)
Story 119.1 Pass-1 F-2 (`toCount` → `toNullableNumber` for AP#8 ratio preservation) broke a pre-existing `expect(searchOrderShare).toBe(0)` assertion — the field now correctly returns `null`. Caught only by Pass-2 P2-1 as a CRITICAL. **A correctness-improving fix silently broke an existing test**; without the 2nd pass it would have shipped red. Reinforces D-1's "never short-circuit Pass-2" — and that fixes touching nullability must grep existing assertions for the old value.

### D-3 — Next.js 15 `searchParams` typegen gotcha (119.2 P2-1 CRITICAL)
The Search page deep-link wiring declared `searchParams` synchronously; `tsc` passed but `next build` typegen requires `searchParams?: Promise<...>` + `await` in Next.js 15 server components. Caught by Pass-2 as CRITICAL. **`type-check` (tsc) does NOT exercise Next.js route-type generation** — a gap between the local gate and the production build. Fixed via `async function` + `Promise` param + `Array.isArray` guard; adjacent routes confirmed the pattern.

### D-4 — Live backend auth blocked an entire verification path (119.3)
`POST /v1/auth/login` returned 500 (`wb_user` DB-credentials invalid), blocking the live verify-first path for 119.3. Worked around with static source grep + filed Request #179, but the blocker is environmental and will recur for any future story needing live auth against this backend until #179 is resolved. **Carry-forward dependency, not closed.**

### D-5 — Two pre-existing check-lessons violations surfaced but were out-of-scope
`check-lessons` exits 1 on a pre-existing violation in CLOSED Stories 119.1/119.2 close-row lessons. Correctly held out-of-scope per APPEND-ONLY (can't edit closed rows), but the gate now exits non-zero as steady-state for Epic 119 doc-only stories — a standing yellow that future stories must remember is NOT theirs to fix and NOT a regression they introduced.

## Key Insights

### I-1 — Mixed-discipline epics can split the review floor by story type without losing drift-catch
Epic 119 ran 2-pass for source-code and 1-pass for doc-only request-filing in one epic. The 1-pass doc stories still caught propagation drift (119.4 W-4). **The 2-pass floor is about logic-defect classes (which doc-request stories lack), not drift** — drift is caught by any adversarial pass. The spec's per-story-type discipline split is sound and should be the template for future mixed epics.

### I-2 — Pattern 4 propagation drift is the dominant defect class in drift-heavy epics
3-of-3 source/2-pass stories had 100%-Pattern-4 Pass-2s. When work is "wire-up + attestation" rather than "novel logic", the residual defect surface is almost entirely propagation drift (sprint-status rows, File Lists, cross-refs lagging the fix). **Reviewers of wire-up/doc stories should hunt propagation drift first** — it's where the findings are.

### I-3 — Local gates don't fully model the production build (Next.js 15 typegen)
D-3 proved `npm run type-check` (tsc) passes code that `next build` rejects (async `searchParams` contract). The local gate is necessary but not sufficient for server-component route changes. **Stories touching App Router page signatures should run `next build` (or at least typegen) as part of verification**, not just tsc.

### I-4 — Verify-first beats spec prediction in BOTH directions
117.2 found a field ABSENT vs spec; 119.2 found a field RICHER than spec. The spec's prediction is a hypothesis, not a contract — backend reality diverges up and down. **Verify-first's value is the divergence-detection itself**, independent of direction; it should remain mandatory for any story consuming a backend shape the FE doesn't own.

## Epic-Level Lessons

1. **Mixed epics can split the 2-pass floor by story type** — source-code stays 2-pass (logic-defect classes), doc-only request-filing relaxes to 1-pass; both retain propagation-drift catch (119.4 proved 1-pass still catches drift).
2. **Pattern 4 propagation drift dominates wire-up/doc work** — 3-of-3 source-story Pass-2s were 100% drift; hunt parallel-location lag first in attestation-heavy stories.
3. **`tsc` ≠ `next build`** — Next.js 15 async-`searchParams` contract passes type-check but fails production typegen; source-story verification needs a build-level check (A-1).
4. **Verify-first detects spec divergence in both directions** — 117.2 (field absent) and 119.2 (field richer) both beat the spec hypothesis; mandatory for unowned backend shapes.
5. **A nullability-correctness fix can silently break an existing test** — 119.1 P2-1 (`toBe(0)`→`toBeNull()`); fixes touching null-vs-zero must grep existing assertions for the old value.
