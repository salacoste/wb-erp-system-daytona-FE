# Story 77.4: Unit Economics Types & Waterfall — Add Delivery Cost Category

Status: done

## Story

As a **seller**,
I want to see my delivery-to-warehouse costs in the unit economics breakdown,
so that I can understand the true total cost per unit including logistics.

## Acceptance Criteria

1. **Types extended** — `CostsPct` and `CostsRub` types in `src/types/unit-economics.ts` have new `delivery_to_warehouse?: number` field (optional for backward compat)
2. **Config updated** — `COST_CATEGORIES` in `src/lib/unit-economics-config.ts` includes new `delivery_to_warehouse` category (label: "Доставка на склад", color: #06B6D4 teal/cyan, group: `'seller_costs'`)
3. **Waterfall updated** — `transformToWaterfallData()` in `src/lib/unit-economics-utils.ts` handles the new category (shows bar when data present, omits when absent)
4. **WB fees exclusion** — `calculateWbFeesPct/Rub()` does NOT include `delivery_to_warehouse` (it's a seller cost, not a WB fee)
5. **API client created** — `src/lib/api/shipment-cost/fcu-aggregation-api.ts` with `getFcuBySku(week?: string)` calling `GET /v1/shipment-cost/by-sku`
6. **Hook created** — `src/hooks/use-fcu-aggregation.ts` with `useFcuBySku(week)` TanStack Query hook, `enabled` guard for when endpoint is unavailable
7. **Fallback** — if FCU endpoint returns error or is not available, `delivery_to_warehouse` shows as "—" (not 0)
8. **Unit tests** — tests for new waterfall category, type extensions, API client, and hook

## Dev Notes

### Architecture Patterns (MUST follow)

**CostCategoryConfig type** (`src/types/unit-economics.ts:223-232`):
```typescript
export interface CostCategoryConfig {
  key: keyof CostsPct
  label: string
  color: string
  group: 'cogs' | 'wb_fees' | 'other'  // Add 'seller_costs' here
}
```

**COST_CATEGORIES ordering** — Insert `delivery_to_warehouse` after `storage` (index 5), before `penalties` (index 6). The waterfall chart position matters: delivery is a known/planned cost like storage. Current order:
```
cogs → commission → logistics_delivery → logistics_return → storage → [NEW: delivery_to_warehouse] → penalties → other_deductions → advertising
```

**Key distinction**: `delivery_to_warehouse` (seller ships TO WB warehouse) ≠ `logistics_delivery` (WB ships FROM warehouse TO customer). Different cost bearers, different data sources.

### FCU Aggregation API (from Request #162)

**Endpoint**: `GET /v1/shipment-cost/by-sku?week=2026-W10`

**Response** (standard `{ data: [...] }` envelope, auto-unwrapped by apiClient):
```typescript
interface FcuBySkuItem {
  nmId: number
  productName: string
  latestPcu: number      // Production Cost per Unit (from COGS at calc time)
  latestDcu: number      // Delivery Cost per Unit (calculated by allocation)
  latestFcu: number      // Final Cost per Unit = PCU + DCU
  shipmentId: string
  shipmentName: string
  confirmedAt: string    // ISO timestamp
}
```

**Critical**: This endpoint uses standard data unwrap (NOT `skipDataUnwrap` like `getShipments()`). The `apiClient.get<FcuBySkuItem[]>('/v1/shipment-cost/by-sku')` will auto-unwrap the `{ data: [...] }` envelope.

**Backend status**: Endpoint requested in Request #162, may not be deployed yet. Hook MUST have `enabled` guard and graceful error fallback.

### TanStack Query Hook Pattern (follow `src/hooks/useUnitEconomics.ts`)

```typescript
export const fcuAggregationKeys = {
  all: ['fcu-aggregation'] as const,
  bySku: (week?: string) => [...fcuAggregationKeys.all, 'by-sku', week] as const,
}

export function useFcuBySku(week?: string) {
  return useQuery({
    queryKey: fcuAggregationKeys.bySku(week),
    queryFn: () => getFcuBySku(week),
    enabled: !!week,
    staleTime: 5 * 60_000,   // FCU changes only on shipment confirmation
    gcTime: 30 * 60_000,
    retry: 1,                 // Don't hammer if endpoint not deployed
  })
}
```

### `transformToWaterfallData()` — No Code Change Needed (verify only)

The function at `src/lib/unit-economics-utils.ts:35-78` iterates `COST_CATEGORIES` and checks `costsRub[category.key] > 0`. Since:
- `delivery_to_warehouse` is optional (`?: number`) → `undefined > 0` is `false` → skipped when absent
- When present and > 0 → included as a waterfall bar

No change to the transform function. Just add the category to `COST_CATEGORIES` and the type to `CostsPct`/`CostsRub`.

### `calculateWbFeesPct/Rub()` — No Code Change Needed (verify only)

These functions at lines 81-100 explicitly list fields: `commission + logistics_delivery + logistics_return + storage + paid_acceptance`. They do NOT use dynamic iteration over `COST_CATEGORIES`, so adding `delivery_to_warehouse` to `COST_CATEGORIES` does NOT affect them. Verified safe.

### Anti-Patterns (DO NOT)

- DO NOT add `delivery_to_warehouse` to `calculateWbFeesPct/Rub()` — it's a seller cost, not a WB fee
- DO NOT use `skipDataUnwrap: true` for the FCU endpoint — it uses standard envelope unwrap
- DO NOT show `0` when FCU data is missing — show `"—"` (empty dash) to distinguish "no data" from "zero cost"
- DO NOT make the `delivery_to_warehouse` field required on `CostsPct`/`CostsRub` — optional preserves backward compatibility
- DO NOT import from `hooks-v1/` — that directory was renamed to `hooks/` in Story 77.1
- DO NOT break existing waterfall by modifying `transformToWaterfallData()` — the function's `for...of COST_CATEGORIES` loop auto-includes new categories
