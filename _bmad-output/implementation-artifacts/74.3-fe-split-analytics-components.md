## Dev Notes

### Proven Extraction Patterns (from Stories 74.1 + 74.2)

**Page State Hook Extraction** (74.2, analytics pages):
```typescript
'use client'
export function useComponentState() {
  // All useState, useMemo, useCallback, handlers
  return { ...state, ...handlers, ...derived }
}
```

**Sub-Component Extraction** (74.1, PnLWaterfall):
```typescript
interface SectionProps { data: SomeType; onAction: () => void }
export function SectionComponent({ data, onAction }: SectionProps) { ... }
```

**Constants/Config Extraction** (74.1, 74.2):
```typescript
// Pure data files do NOT need 'use client'
export const STATUS_ICONS = { ... } as const
export function getActionButton(status: string) { ... }
```

### Critical Rules

1. **NEVER change functionality** — this is pure structural refactoring
2. **Keep `'use client'` directive** — must be on every .tsx component file and hook files using React hooks
3. **Pure data/config files do NOT need `'use client'`** — lesson from 74.2 code review
4. **Don't duplicate types** — import from source, don't re-declare (74.2 code review finding)
5. **Run tests after EACH file split** — don't batch validation
6. **File size limit is 200 lines** — ESLint enforced, no exceptions
7. **Extracted files also ≤200 lines** — don't just move the problem
8. **Keep files well under 200** — aim for 150-180 to leave headroom for future changes
9. **DRY: Don't create near-identical components** — use parameterized shared components when possible (74.2 code review finding)
