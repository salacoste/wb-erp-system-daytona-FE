## Acceptance and Stop Conditions

- Same account + same key + same payload resolves to one canonical operation/cabinet.
- Same key + different payload rejects deterministically.
- Unknown/in-progress/succeeded/failed states and safe retries are explicit.
- JWT identity is authoritative; lookup cannot leak another account's operation.
- Concurrent/repeated/late transport outcomes cannot create another cabinet.
- Database constraints, migration, API docs, endpoint drift, auditability, and targeted/full local tests pass.
- Two independent review passes have no unresolved accepted finding.
- Exact backend merge SHA, proof it is an ancestor of current backend `main`, and local/remote branch plus worktree cleanup evidence are recorded before any frontend artifact advances Story 167.8 or Story 167.9 starts.

Stop on true overlapping ownership without a valid freshly rechecked non-overlapping hunk reservation, uncertain migration safety, unresolved security/idempotency findings, required production access, or scope expansion. This plan authorizes no deploy, production operation, direct push to `main`, force-push, or destructive cleanup.
