# OMX Plan — Story 169.14: Establish the Authoritative Paid-Storage Import Lifecycle and Result Contract

## Outcome

Establish one truthful paid-storage import request, start, polling, result, and failure contract before any frontend consumer changes. A valid trigger uses the documented request keys; the start response uses a documented lifecycle value; polling exposes only `pending | processing | completed | failed`; completion carries the authoritative imported-row result; failure carries actionable error detail; and no partial-success state is invented.

This is a non-route, cross-repository prerequisite for Stories 169.15 and 169.12. It does not migrate UI, change the route ledger, change the import's all-or-failure processing semantics, or claim either frontend Story complete.

## Authority and exact scope

- **Repository:** `/Users/r2d2/Documents/Code_Projects/wb-repricer-system-new`.
- **Owned/allowed production files:**
  - `src/imports/controllers/paid-storage-import.controller.ts`;
  - `src/imports/dto/paid-storage-import.dto.ts`;
  - `src/imports/dto/import-status.dto.ts`, only to add an optional paid-storage result field without broadening any unrelated import response;
  - only the paid-storage-specific result/error projection path in `src/imports/services/import-status-builder.service.ts`.
- **Owned/allowed direct evidence:** direct colocated specs for the files above; `test/imports/paid-storage.e2e-spec.ts`; `docs/API-PATHS-REFERENCE.md`; Story-specific validation/review evidence.
- **No implicit conditional paths:** if RED evidence proves that a paid-storage-only fixture, OpenAPI assertion, or any other file outside the explicit allowed manifest is necessary, stop before editing and obtain an ownership correction that updates this plan and its reviewed manifest. An environment variable or delivery note alone cannot expand the allowed surface.
- **Forbidden:** frontend repository; `prisma/**`; processor/orchestration/import-storage semantics; unrelated queue/import/controller/service paths; casts or changes to unrelated `ImportStatusDto` fields/consumer response shapes; unrelated API documentation; package/dependency changes; deploy/production operations; direct push to `main`; force-push.
- Preserve JWT/cabinet isolation, queue selection, scheduling, retry behavior, processor return semantics, database writes, and existing all-or-failure date-range processing.
- Inventory every `ImportStatusDto` producer and consumer before editing. The optional paid-storage result field must leave all unrelated import status consumers source-compatible and runtime-identical; DTO/OpenAPI regression proof is mandatory.
- A need outside the exact allowed surface is a stop condition and requires a new ownership decision.

## Acceptance and stop conditions

- Request serialization keys exactly match the documented DTO and validation policy.
- Start uses a documented lifecycle value; polling uses only `pending | processing | completed | failed`.
- Completed status exposes the authoritative imported-row result through an optional paid-storage field on `ImportStatusDto`; failed status exposes actionable error detail.
- DTO/OpenAPI regression evidence proves unrelated `ImportStatusDto` producers and consumers remain unchanged, with no cast or unrelated response-shape broadening.
- Cabinet isolation, queue behavior, retry behavior, processor/orchestration/storage semantics, and all-or-failure processing remain unchanged.
- No partial-success state, partial counts, retry subset, new dependency, schema migration, or production behavior is introduced.
- Targeted/full tests, docs/endpoint checks, build/type/lint/format, diff/scope audit, two reviews, PR/merge, and mandatory cleanup pass.

Stop on overlapping ownership, unclear request/response authority, need to alter processor/orchestration/storage semantics, unresolved cabinet-isolation/error-disclosure findings, required production access, or scope expansion. No deploy, production operation, direct push to `main`, force-push, or destructive cleanup outside the exact documented post-merge removal of this Story's merged branch and temporary worktree is authorized.
