# План решения: Revenue всегда 0 в трендах

**Дата:** 2025-11-22  
**Story:** 3.4 (Trend Graphs for Key Metrics)  
**Приоритет:** HIGH

---

## 🔍 Диагностика проблемы

### Факты

1. **В БД для активного кабинета:** `sale_gross_total = 0.00` для всех недель
2. **В БД для других кабинетов:** `sale_gross_total` имеет ненулевые значения (например, W36: 311381.04)
3. **Frontend код:** Корректно извлекает `sale_gross_total` из `summary_total`
4. **Проблема:** Либо данные в БД неправильные, либо нужно использовать другой источник данных

### Структура БД

**Таблица `weekly_payout_total`:**

- Есть только `sale_gross_total` (консолидированное значение)
- Нет отдельных полей `sale_gross_rus`, `sale_gross_eaeu`
- Для активного кабинета все значения = 0.00

### Структура API ответа

**Endpoint:** `/v1/analytics/weekly/finance-summary?week={week}`

**Формат ответа:**

```json
{
  "summary_total": {
    "sale_gross_total": 0.00,  // ← Проблема: всегда 0
    "to_pay_goods_total": 195470.62
  },
  "summary_rus": {
    "sale_gross": ???,  // ← Возможно, здесь есть данные?
  },
  "summary_eaeu": {
    "sale_gross": ???,  // ← Возможно, здесь есть данные?
  }
}
```

### Этап 2: Решение проблемы

#### Решение A: Использовать summary_rus + summary_eaeu

**Если данные есть в региональных summary:**

**Проблема:** `summary_total.sale_gross_total = 0`, но `summary_rus.sale_gross` и/или `summary_eaeu.sale_gross` имеют значения.

**Решение:**

```typescript
// В useTrends.ts, строка 68
// Сначала попробовать summary_total
// Если 0 или undefined, суммировать региональные данные
const revenueFromTotal = summaryResponse.summary_total?.sale_gross_total ?? 0
const revenueFromRus = summaryResponse.summary_rus?.sale_gross ?? 0
const revenueFromEaeu = summaryResponse.summary_eaeu?.sale_gross ?? 0

// Если summary_total = 0, но есть региональные данные, использовать их сумму
const revenue = revenueFromTotal > 0
  ? revenueFromTotal
  : (revenueFromRus + revenueFromEaeu) || 0
```

**Обоснование:**

- Если `summary_total` правильно агрегирован → используем его
- Если `summary_total = 0`, но есть региональные данные → суммируем их
- Это временное решение, пока backend не исправит агрегацию

#### Решение B: Использовать другое поле

**Если поле называется по-другому:**

**Проблема:** Поле `sale_gross_total` не существует или называется иначе в API ответе.

**Решение:**

1. Проверить документацию backend
2. Проверить DTO файлы backend
3. Обновить `FinanceSummary` interface
4. Обновить код извлечения данных

**Пример:**

```typescript
// Если поле называется по-другому
const revenue = summary.revenue_total ?? summary.revenue ?? summary.sale_gross_total ?? summary.sale_gross ?? 0
```

#### Решение C: Backend проблема (требуется исправление на backend)

**Если данные в БД действительно 0, но должны быть ненулевыми:**

**Проблема:** Backend не правильно агрегирует `sale_gross_total` при создании `weekly_payout_total`.

**Решение:**

1. Создать запрос к backend team в `@request-backend`
2. Описать проблему:
   - В БД `sale_gross_total = 0.00` для всех недель активного кабинета
   - У других кабинетов есть ненулевые значения
   - Frontend корректно отображает данные из БД
   - Нужно проверить агрегацию данных на backend

**Шаблон запроса:**

```markdown
# Проблема: sale_gross_total всегда 0 в weekly_payout_total

## Описание
Для кабинета {cabinet_id} все значения `sale_gross_total` в таблице `weekly_payout_total` равны 0.00, хотя должны быть ненулевыми.

## Данные
- Кабинет: f75836f7-c0bc-4b2c-823c-a1f3508cce8e
- Недели: Все 16 недель имеют sale_gross_total = 0.00
- to_pay_goods_total: Имеет ненулевые значения (например, W40: 384079.04)

## Вопросы
1. Почему sale_gross_total = 0 для этого кабинета?
2. Правильно ли агрегируются данные при создании weekly_payout_total?
3. Нужно ли использовать summary_rus + summary_eaeu вместо summary_total?
```

#### Решение D: Использовать расчетное значение

**Если revenue можно рассчитать из других полей:**

**Проблема:** `sale_gross_total` не заполняется, но можно рассчитать из других полей.

**Решение:**

1. Проверить формулу расчета revenue из документации
2. Использовать расчетное значение как fallback

**Пример (если формула известна):**

```typescript
// Если revenue = to_pay_goods + expenses (пример, нужно проверить реальную формулу)
const revenue = summary.sale_gross_total ??
  (summary.to_pay_goods_total + summary.logistics_cost_total + summary.storage_cost_total + ...) ??
  0
```
