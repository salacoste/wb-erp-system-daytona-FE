# Проблема: Окно обработки финансовых данных показывается неправильно

**Дата:** 2025-11-21  
**Stories:** 3.2, 3.3  
**Приоритет:** HIGH

---

## 🔍 Анализ проблемы

### Симптомы

- Окно "Обработка финансовых данных" показывается с прогрессом 0%
- Данные уже обработаны и доступны (есть в `weekly_payout_total`)
- Метрики и расходы отображаются корректно
- Окно не исчезает, хотя обработка завершена

### Текущая логика

**Файл:** `src/app/(dashboard)/dashboard/page.tsx` (строки 40-42)

```typescript
const isFinancialDataProcessing =
  processingStatus?.reportLoading?.status === 'in_progress' ||
  processingStatus?.reportLoading?.status === 'pending'
```

**Файл:** `src/hooks/useProcessingStatus.ts` (строки 31-42)

```typescript
const reportLoading = {
  progress: financesTask?.progress ?? 0,
  status:
    financesTask?.status === 'completed'
      ? 'completed'
      : financesTask?.status === 'failed'
        ? 'failed'
        : financesTask?.status === 'in_progress'
          ? 'in_progress'
          : 'pending',  // ← ПРОБЛЕМА: Если задачи нет, статус = 'pending'
  taskUuid: financesTask?.uuid,
}
```

### Корневая причина

**Проверка БД показала:**

- В таблице `tasks` для кабинета `f75836f7-c0bc-4b2c-823c-a1f3508cce8e` **НЕТ задач типа `finances_weekly_ingest`**
- Есть только `products_sync` (completed) и `weekly_sanity_check` (pending/completed)
- Данные в `weekly_payout_total` уже есть (16 недель обработано)

**Почему задача не находится:**

1. Задача `finances_weekly_ingest` не создавалась вообще (данные обработаны другим механизмом)
2. Задача была удалена после завершения
3. Задача находится за пределами `limit=20` в API запросе
4. Backend использует другой тип задачи для обработки финансов

**Почему показывается окно:**

- Когда `financesTask` = `undefined`, статус по умолчанию становится `'pending'`
- Dashboard видит `reportLoading.status === 'pending'` и показывает окно обработки
- Но данные уже обработаны и доступны через API

## 💡 Решение

### Подход 1: Проверка наличия данных (РЕКОМЕНДУЕТСЯ)

**Идея:** Если данные доступны через API (`available-weeks` возвращает недели), значит обработка завершена, независимо от статуса задачи.

**Преимущества:**

- ✅ Надежно: проверяет фактическое наличие данных
- ✅ Не зависит от наличия задачи в БД
- ✅ Работает даже если задачи удалены или не создавались

**Реализация:**

1. **Изменить логику в `dashboard/page.tsx`:**

   ```typescript
   // Проверяем наличие данных через available-weeks
   const { data: availableWeeks } = useQuery({
     queryKey: ['dashboard', 'available-weeks'],
     queryFn: async () => {
       const response = await apiClient.get('/v1/analytics/weekly/available-weeks')
       return response.data || []
     },
     staleTime: 60000, // 1 minute
   })

   // Если есть данные, обработка завершена
   const hasFinancialData = availableWeeks && availableWeeks.length > 0

   // Показываем окно только если:
   // 1. Нет данных И
   // 2. Обработка в процессе или ожидает
   const isFinancialDataProcessing =
     !hasFinancialData && (
       processingStatus?.reportLoading?.status === 'in_progress' ||
       processingStatus?.reportLoading?.status === 'pending'
     )
   ```

2. **Альтернатива: использовать данные из `useDashboardMetrics`:**
   ```typescript
   // Если метрики загружены, значит данные есть
   const hasFinancialData = metrics && (metrics.totalPayable !== undefined || metrics.revenue !== undefined)

   const isFinancialDataProcessing =
     !hasFinancialData && (
       processingStatus?.reportLoading?.status === 'in_progress' ||
       processingStatus?.reportLoading?.status === 'pending'
     )
   ```

### Подход 2: Улучшить логику в `useProcessingStatus`

**Идея:** Если задачи нет, но данные доступны, считать обработку завершенной.

**Реализация:**

1. **Изменить `aggregateProcessingStatus` для проверки данных:**

   ```typescript
   async function aggregateProcessingStatus(
     tasks: Task[],
     hasFinancialData: boolean = false
   ): Promise<ProcessingStatus> {
     const financesTask = tasks.find((t) => t.type === 'finances_weekly_ingest')

     const reportLoading = {
       progress: financesTask?.progress ?? 0,
       status:
         financesTask?.status === 'completed'
           ? 'completed'
           : financesTask?.status === 'failed'
             ? 'failed'
             : financesTask?.status === 'in_progress'
               ? 'in_progress'
               : hasFinancialData  // ← Если данных нет, но задача есть
                 ? 'completed'      // ← Считать завершенной
                 : 'pending',       // ← Иначе pending
       taskUuid: financesTask?.uuid,
     }
     // ...
   }
   ```

2. **Изменить `useProcessingStatus` для проверки данных:**
   ```typescript
   export function useProcessingStatus() {
     const { cabinetId } = useAuthStore()

     // Проверяем наличие данных
     const { data: availableWeeks } = useQuery({
       queryKey: ['dashboard', 'available-weeks'],
       queryFn: async () => {
         const response = await apiClient.get('/v1/analytics/weekly/available-weeks')
         return response.data || []
       },
       enabled: !!cabinetId,
     })

     const hasFinancialData = availableWeeks && availableWeeks.length > 0

     return useQuery({
       queryKey: ['processing-status', cabinetId],
       queryFn: async (): Promise<ProcessingStatus> => {
         // ... получение задач
         return aggregateProcessingStatus(relevantTasks, hasFinancialData)
       },
       // ...
     })
   }
   ```

### Подход 3: Увеличить limit или использовать пагинацию

**Идея:** Увеличить `limit` или использовать `next_cursor` для поиска старых задач.

**Недостатки:**

## 📝 Дополнительные замечания

### Почему `metrics !== undefined` недостаточно

- `metrics` может быть `{}` (пустой объект) если данных нет
- Нужно проверять наличие конкретных полей (`totalPayable`, `revenue`)

### Почему проверка `available-weeks` лучше

- Более надежная проверка наличия данных
- Не зависит от загрузки метрик
- Но требует дополнительного запроса

### Компромисс

- Использовать `metrics` для проверки (уже загружены)
- Если нужно более надежно → добавить проверку `available-weeks`
