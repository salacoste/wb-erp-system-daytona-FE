## Краткое описание проблемы

При верификации финансовых данных за неделю W47 (18-24 Nov 2024) было обнаружено, что показатель **"Продажи"** в нашей системе отличается от WB Dashboard:

| Показатель  | Наша система    | WB Dashboard    | Разница         |
| ----------- | --------------- | --------------- | --------------- |
| **Продажи** | **309,896.32₽** | **209,691.98₽** | **100,204.34₽** |

**Важно**: Это **НЕ баг**. Оба значения технически корректны, но означают разное:

- Наша система показывает `retail_price_with_discount` — что **заплатил покупатель**
- WB Dashboard показывает `gross` — что **получил продавец** (после вычета комиссии WB)

Все остальные метрики (Логистика, Хранение, Итого к оплате и т.д.) **совпадают на 100%**.

## Детальное описание

### Что показывает наша система

Мы отображаем поле `retail_price_with_discount` из WB Excel детализации:

```
Продажи (gross): 309,896.32₽
```

Это сумма, которую покупатели заплатили за товары (цена со скидкой × количество).

**Источник данных**: Колонка "Цена розничная с учетом согласованной скидки" в WB Excel.

### Что показывает WB Dashboard

WB показывает поле `gross` (также называемое "Продажа" в WB терминологии):

```
Продажа: 209,691.98₽
```

Это сумма, которую WB начислил продавцу за реализованные товары — **после вычета комиссии WB**.

**Формула WB**: `gross = retail_price_with_discount - wb_commission`

### Почему значения отличаются

```
retail_price_with_discount:  309,896.32₽  (наша система)
- Комиссия WB:               -96,086.34₽  (удержание WB)
───────────────────────────────────────────
= gross:                     213,809.98₽  (расчётное)
= WB Dashboard показывает:   209,691.98₽  (с возвратами и сторно)
```

**Разница ~4K₽** между расчётным и фактическим `gross` объясняется:

- Возвратами товаров
- Сторно операциями
- Корректировками

## Варианты решения

### Вариант A: Показывать `gross` как WB Dashboard

**Описание**: Изменить поле "Продажи" на значение `gross` (как в WB Dashboard).

**UI изменение**:

```
Было:    Продажи (gross): 309,896.32₽
Станет:  Продажи:         209,691.98₽   ← совпадает с WB
```

**Плюсы**:

- ✅ Полное совпадение с WB Dashboard — пользователь видит те же цифры
- ✅ Меньше путаницы при сверке с ЛК WB
- ✅ Показывает реальный доход продавца (после комиссии)

**Минусы**:

- ❌ Пользователь не видит полную сумму продаж (что заплатили покупатели)
- ❌ Комиссия WB "скрыта" в этом значении
- ❌ Сложнее понять структуру: откуда взялась разница между ценой и доходом

**Технические изменения**:

- `FinancialSummaryTable.tsx` — изменить поле с `retail_price_with_discount` на `gross`
- `PnLWaterfall.tsx` — изменить первую строку на `gross`
- Labels: убрать "(gross)" из названия

### Техническая справка

**Поля в WB Excel детализации**:

- `retail_price_with_discount` — "Цена розничная с учетом согласованной скидки" (что платит покупатель)
- `gross` — "Вайлдберриз реализовал Товар (Пр)" (доход продавца после комиссии)
- `total_commission_rub` = `retail_price_with_discount` - `gross` (комиссия WB)

**Формула**:

```
gross = retail_price_with_discount × (1 - wb_commission_rate)
```

Где `wb_commission_rate` зависит от категории товара (обычно 15-25%).

## PM Decision

> ✅ **РЕШЕНО** — 2025-12-13

**Выбранный вариант**: **Вариант A + элементы Вариант B**

**Показывать `sale_gross` (как WB Dashboard) + tooltip с полной информацией**

### Обоснование:

1. **Доверие пользователей** — главная цель финансовой аналитики. Расхождение 100K₽ с WB Dashboard вызывает недоверие ко всей системе, даже если остальные метрики совпадают на 100%.

2. **WB терминология — стандарт отрасли**. Все продавцы WB обучены: "Продажа" = доход продавца (после комиссии). Наш термин "Продажи (gross)" = GMV путает их.

3. **P&L Waterfall уже показывает полную картину**. Детализация GMV → Комиссия → Payout есть в CFO-компоненте. Не нужно дублировать в FinancialSummaryTable.

4. **Простота важнее полноты** для основного dashboard.

### Дополнительные требования:

1. **FinancialSummaryTable**: Изменить отображение:
   - Было: "Продажи (gross)" = `sales_gross` (309K₽)
   - Станет: "Продажи" = `sale_gross` (209K₽) — **как в WB Dashboard**

2. **Tooltip обязателен** для "Продажи":

   ```
   "Сумма, которую WB начислил вам за реализованные товары (после вычета комиссии).
    Покупатели заплатили: 309,896₽ (до комиссии WB 96,086₽)"
   ```

3. **Убрать "(gross)" из названий** — это технический термин, пользователю не нужен.

4. **PnLWaterfall** — оставить без изменений ✅ (уже показывает полную цепочку)

5. **Request #41 остаётся актуальным** — раздельный учёт `sales_gross`/`returns_gross` нужен для PnLWaterfall.
