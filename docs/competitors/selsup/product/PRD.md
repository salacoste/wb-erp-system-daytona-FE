# PRD: воссоздание SelSup

> Каркас Product Requirements Document для полного воссоздания функциональности платформы SelSup. Документ построен на основе 16 спецификаций модулей (`product/specs/*.md`) и предназначен для продакт-менеджера, восстанавливающего продукт «с нуля». Статус: каркас, dev-ready на уровне epic / user story / ключевых функциональных требований; точные контракты API, схемы БД и формулы требуют отдельной технической детализации (см. раздел 7).

---

## 1. Контекст и цели продукта

### 1.1. Что такое SelSup
SelSup — SaaS-платформа для селлеров на маркетплейсах (Wildberries, Ozon, Яндекс Маркет, СберМегаМаркет, AliExpress, Avito, Магнит Маркет, Lamoda, М.Видео, Детский мир, Takealot и др.), объединяющая в «едином окне» управление всем циклом продаж: карточки товаров (PIM), цены и репрайсер, остатки и склад (FBS/FBO, адресное хранение), заказы и сборка (FBS/FBO/DBS/realFBS/Express), маркировка и Честный Знак, отгрузки/поставки на склады маркетплейсов, интеграции (маркетплейсы, 1С, МойСклад, СБИС, CMS, логистика), закупки/производство/комплекты/себестоимость, CRM/покупатели/конкуренты, AI-модули, аналитика и финансы (P&L, ABC, юнит-экономика), автоматизация/задания/настройки.

### 1.2. Ключевой продукт-принцип
«Единый внутренний справочник товаров (PIM), который не зависит от площадки»: селлер создаёт/ведёт карточку один раз в SelSup, а SelSup транслирует параметры, фото, видео, rich-контент, габариты, штрихкоды, цены, остатки, заказы, маркировку и документы в формат каждого маркетплейса и обратно. SelSup — единый центр управления продажами, обменивающийся с маркетплейсами и учётными системами через API/CommerceML/Excel/YML/почту.

### 1.3. Цели воссоздания
- Полностью покрыть функциональность SelSup, достаточную для запуска MVP и последовательного достижения паритета.
- Зафиксировать пользовательские сценарии (workflows), ключевые сущности, бизнес-правила, ограничения и зависимости между модулями.
- Выделить то, что в исходных доках не раскрыто (формулы, контракты API, тарифы) и требует отдельной проработки.

### 1.4. Метрики успеха (для воссозданного продукта)
- Паритет по поддерживаемым маркетплейсам и схемам работы (FBS/FBO/DBS/realFBS/Express/опт/розница/дропшиппинг/КГТ/B2B).
- Покрытие сквозных сценариев: от создания карточки до закрытия поставки с маркировкой и сверки P&L.
- Точность финансовой аналитики (сверка с ЛК маркетплейсов по публичным формулам).

## 2. Пользователи и роли

### 2.1. Целевые пользователи
- **Владелец/директор** — полный доступ, финансы, стратегия.
- **Закупщик** — закупки, поставщики, закупочные цены, взаиморасчёты, себестоимость.
- **Менеджер товаров / контент-менеджер** — карточки, каталог, фото/видео,rich-контент (без доступа к закупочным ценам и поставщикам — разделение конфиденциальности).
- **Менеджер цен / рекламщик-аналитик** — цены, стратегии, репрайсер, акции, реклама, аналитика.
- **Сотрудник склада / упаковщик** — сборка, комплектация, упаковка, приёмка, инвентаризация, адресное хранение, работа через ТСД/смартфон/сканер.
- **Оператор (упрощённый интерфейс заданий)** — строго ограниченный набор действий на складе, сдельная оплата.
- **Консультант** — чаты, вопросы, отзывы (CRM).
- **Фулфилмент-агентство / внешний менеджер** — работа с несколькими аккаунтами клиентов (связанные аккаунты), «кабинет вьюера» с ограничением прав.

### 2.2. Предустановленные роли и права доступа
Роли определяют видимость разделов, меню, аналитики, финансов, закупочных цен, а также границы действий:

| Роль | Видит / делает |
|---|---|
| **Администратор** | Полный доступ; единственный, кто удаляет организации. |
| **Менеджер товаров** | Отгрузки, карточки, заказы; без аналитики, финансов, закупочных цен. |
| **Оператор** | Только задания (упрощённый интерфейс), без основного меню и товаров. |
| **Рекламщик / аналитик** | Только аналитика и статистика. |
| **Закупщик** | Закупки, закупочные цены, поставщики, взаиморасчёты. |
| **Сотрудник склада** | Отгрузки, заказы, приёмка, сборка, инвентаризация (создание инвентаризаций). |
| **Контент-менеджер** | Создание/редактирование карточек. |
| **Просмотр карточек** | Только просмотр раздела «Товары». |
| **Консультант** | Чаты, вопросы, отзывы. |
| **Управление ценами** | Цены и акции. |

### 2.3. Тонкое разграничение доступа
- Ограничение по **организациям** (одна, несколько или все).
- Ограничение по **брендам** (видны только товары выбранных брендов в «Товары»/«Цены» и в выгрузках).
- Переключатели: «Разрешить обновлять и сохранять карточки на маркетплейсе», «Возможность собирать заказы без сканирования».
- **Привязка менеджера к товару** («Менеджер товара основной», «Менеджер WB/Ozon/Yandex») — используется в отчётах (Юнит-экономика, AI-стратегии — только основной менеджер, РНП).
- **Аудит действий сотрудников**: запись всех операций (кто собрал заказ, создал карточку, сделал отправку).

### 2.4. Учётная запись и сессии
- Логин — email; регистрация по телефону и email; 2FA.
- **Лимит устройств: не более 2 сессий** на учётную запись; при превышении предыдущие сессии сбрасываются (настройки принтера «слетают»).
- Восстановление доступа: сброс пароля по email; при потере почты — ссылка в SMS + смена email в профиле; отключение 2FA через поддержку (SMS-код → письмо с email на info@ в течение 5 мин).
- Перенос тарифа при смене владельца: платёж 1 рубль от организации-плательщика; переносятся только тарифы, без данных и токенов.

### Архитектурные принципы связей
- **PIM (M2) — ядро**: единый справочник товаров, на который опираются цены, остатки, заказы, маркировка, аналитика.
- **Организации (M1) — контейнер**: товары, остатки, ключи API, тарификация привязаны к организациям; 1 организация = 1 ключ API маркетплейса; 1 схема работы = 1 организация для мульти-схемных площадок (Яндекс.Маркет, МегаМаркет).
- **SKU / партионный учёт (M6/M12)**: внутренний ID учёта остатков; один SKU у товаров, объединённых по остатку; меняется при объединении/разъединении.
- **Маркетплейс-интеграционный слой (M10)**: единая точка обмена; SelSup не работает напрямую с маркетплейсами из модуля 1С — только через API SelSup.

## 4. Требования по модулям

> Для каждого модуля: обзор, ключевые user stories (US), функциональные требования (FR), зависимости. Полные перечни capabilities/workflows — в `product/specs/<slug>.md`.

### 4.1. M1 — Онбординг, аккаунт, тарифы и организации

**Обзор.** Базовый слой доступа и первичной настройки SelSup под компанию: регистрация → быстрый старт (мастер выбора МП + настройка интеграции + первый импорт + автозагрузка аналитики за 2 недели) → управление учётной записью (вход, 2FA, восстановление, переключение аккаунтов клиентов) → тарифы (просмотр/изменение опций/переход/оплата/закрывающие документы/партнёрка) → организации (ИНН, налоговый режим, реквизиты, печать/подпись, ключи API, стратегии остатков, перенос/объединение) → сотрудники (должности, роли/права, ограничения по брендам/организациям) → настройки интерфейса (видимость меню, таблицы, фильтры). Сопутствующие сервисы: браузерное расширение (PIM + AI Финдир), сертификаты/декларации, «Кадровый партнёр», платное внедрение.

**Ключевые user stories**
- US-1.1 Как новый селлер, я хочу зарегистрироваться и пройти быстрый старт, чтобы за один сеанс подключить маркетплейс и импортировать товары.
- US-1.2 Как владелец, я хочу управлять тарифом (добавить модуль/маркетплейс/организацию/товары/сотрудников/хранилище) с пропорциональной оплатой, не дожидаясь конца периода.
- US-1.3 Как администратор, я хочу добавить организацию по ИНН с автозаполнением, указать налоговый режим, реквизиты, загрузить печать/подпись.
- US-1.4 Как администратор, я хочу добавить сотрудника, назначить роль, ограничить по организациям и брендам, выдать флаги работы с карточками и сборки без сканирования.
- US-1.5 Как фулфилмент-агент, я хочу переключаться между связанными аккаунтами клиентов с доступом к их остаткам и данным.
- US-1.6 Как селлер, я хочу массово объединить остатки между организациями (главная = наибольший остаток) и перенести данные между организациями через Excel/ВПР.

**Функциональные требования**
- FR-1.1 Регистрация по телефону + email с согласием на обработку ПД и договор-оферту; без пробного периода (только полноценная подписка).
- FR-1.2 Быстрый старт: выбор МП → раздел «Интеграции» → настройка подключения → «Импортировать товары» → автозагрузка аналитики за 2 недели.
- FR-1.3 2FA; лимит 2 устройства на аккаунт; восстановление доступа (email/SMS); перенос тарифа при смене владельца (платёж 1 рубль).
- FR-1.4 Тариф: план, период (1/3/6/12/24 мес.), лимиты (организации/товары/сотрудники/склады/хранилище), модули, маркетплейсы; изменение опций — пропорционально оставшимся дням; переход — после окончания текущего; оплата картой (автоактивация) или по счёту (через поддержку); закрывающие документы — после окончания тарифа.
- FR-1.5 Организация: ИНН (автозаполнение), налоговый режим (УСН доход), юр. адрес, банковские реквизиты, печать/подпись, ключи API (1 орг = 1 ключ МП), ID в ЭДО, стратегия остатков (одинаковые если не 1 шт./одинаковые/разделение по продажам), формирование артикула, резерв с одного склада, бренд/производитель по умолчанию, мин/макс остаток FBS, тумблеры синхронизации/импорта, пороги FBO.
- FR-1.6 Удаление организации — только администратором, с подтверждением кодом из email; мягкое удаление + восстановление через «Удалённые организации»; каскадное удаление ключей API, товаров, остатков, заказов, истории.
- FR-1.7 Сотрудники: ФИО, должность, логин/пароль, телефон, email, роль, организация(и), бренды, флаги; лимит по тарифу; один логин нельзя использовать несколькими одновременно (лимит 2 устройства).
- FR-1.8 Должности: произвольные с полем «Работа по умолчанию».
- FR-1.9 Привязка менеджера к товарам (Excel): «Менеджер WB/Ozon/Yandex», «Менеджер товара основной».
- FR-1.10 Аудит действий сотрудников (история операций).
- FR-1.11 Настройка интерфейса: видимость разделов/подразделов меню; таблицы (поиск, столбцы, порядок перетаскиванием, фильтры).
- FR-1.12 Сертификаты/декларации: название (полное с ЕАЭС), номер, тип, срок, бренды, категории, изображение; сопоставление с карточками по бренду и категории.
- FR-1.13 Браузерное расширение: PIM (копирование карточек конкурентов) + AI Финдир (позиции, рейтинг/отзывы, СПП WB, CTR/показы); «Запустить все»; ежедневный автозапуск по расписанию.
- FR-1.14 Безопасность: ключи API шифруются AES-256; 2FA; реестр российского ПО.

**Зависимости.** Базовый слой для всех модулей. Тарифы определяют лимиты (M2–M15). Стратегии остатков (M6), сертификаты (M9), расширение (M4/M13).

### 4.2. M2 — Карточки товаров и каталог (PIM)

**Обзор.** Ядро товарного каталога: единый внутренний справочник товаров, не зависящий от площадки. Создание/ведение/массовое редактирование карточек: параметры (3 уровня: модель/цвет/размер), характеристики, теги, бренды, категории, фото/видео/rich-контент, статусы и история изменений. Публикация на маркетплейсы через тумблеры-«курки». Поддержка трёхуровневой модели (Модель → Цвет → Размер), групповых карточек, AI-Формализатора, генерации SEO, копирования карточек конкурентов, массовых операций через Excel и интерфейс.

**Ключевые user stories**
- US-2.1 Как контент-менеджер, я хочу создать карточку один раз и опубликовать её на несколько маркетплейсов тумблерами.
- US-2.2 Как контент-менеджер, я хочу, чтобы AI-Формализатор извлёк параметры МП из текста и подсветил их оранжевым для подтверждения, не перезаписывая заполненные поля.
- US-2.3 Как селлер, я хочу массово редактировать карточки через Excel и через интерфейс с отправкой на МП.
- US-2.4 Как селлер, я хочу скопировать карточку конкурента через расширение и адаптировать под свой бренд.
- US-2.5 Как селлер, я хочу вести rich-контент (Ozon) визуальным редактором с сохранением в JSON.
- US-2.6 Как селлер, я хочу видеть историю изменений карточки с возможностью отката и историю SKU.

**Функциональные требования**
- FR-2.1 Создание карточки: раздел «Товары → Создать товар»; варианты «Один товар или несколько модификаций» / «Скопировать карточку конкурента» / создание из раздела «Закупки».
- FR-2.2 Публикация тумблерами МП (WB, Ozon, Яндекс Маркет, AliExpress, МегаМаркет, Честный Знак); отправка одного размера; отправка сразу на несколько МП.

- FR-2.5 Служебные параметры SelSup (артикул объединения, название, бренд, тип товара, организация, производитель, страна, название для этикетки, цены, закупочная, себестоимость, НДС, габариты, штрихкод и др.).

- FR-2.12 Теги (массово через `;`), теги в листе сборки FBS.

- FR-2.15 Rich-контент: визуальный редактор (Текст/Таблица/Видео/Витрина/Список), сохранение в JSON, отправка на Ozon по API.

### 4.3. M3 — Импорт/экспорт и перенос карточек

**Ключевые user stories**

- US-3.4 Как селлер, я хочу массово создать карточки на новом маркетплейсе через эталонную карточку + Excel.
- US-3.5 Как селлер, я хочу перенести карточки между организациями (интерфейс/Excel) с опциями штрихкодов и объединения по остаткам.

- FR-3.3 Ночной автоимпорт (тумблер per организация/МП), быстрый импорт (только новые, без параметров, фоновое подтягивание), импорт по бренду.

- FR-3.5 Матчинг (авто по ШК/артикулу, ручное/массовое объединение); уникальность комбинации «Артикул + Цвет + Размер».

### 4.4. M4 — AI-модули

**Обзор.** Все ИИ-функции SelSup. Три слоя: (1) создание контента — Формализатор (авто-заполнение параметров), AI-редактор фото (генерация по промту, фотосессии, фотоворонка продаж, шаблоны, инструменты), генерация видео, подбор ключевых слов и SEO-описания (PIM); (2) принятие решений — AI-стратегии (конвейер задач по товарам, только WB), отчёты «Рука на пульсе» (сводный) и «Рука на пульсе по-товарно» (финдир + рекомендации), сбор данных расширением; (3) планирование операций — «Точные поставки» (AI-планировщик: что/сколько/на какие склады везти, WB/Ozon). Тарифицируются как отдельные дополнения.

**Ключевые user stories**
- US-4.1 Как селлер, я хочу получить от AI-стратегий готовый список приоритетных задач по товарам с эффектом, прибылью и ответственным (цикл Открыто → В работе → Готово).
- US-4.2 Как контент-менеджер, я хочу, чтобы Формализатор заполнил параметры МП из описания, не трогая заполненные поля.
- US-4.3 Как селлер, я хочу сгенерировать серию продающих фото (фотоворонка на 7–10 фото) в едином стиле и добавить в карточку.
- US-4.4 Как селлер, я хочу сгенерировать видео из 2 фото + промта движения и отправить на Ozon/WB.
- US-4.5 Как селлер, я хочу подобрать ключевые слова и сгенерировать SEO-описание под правила МП.
- US-4.6 Как селлер, я хочу рассчитать поставку (что/сколько/на какие склады) с учётом выгоды, а не только рекомендаций МП.
- US-4.7 Как селлер, я хочу видеть «Рука на пульсе по-товарно» с подсказками-рекомендациями при наведении на изменившийся показатель.

**Функциональные требования**
- FR-4.1 AI-стратегии: задачи (проблема, действие, эффект/приоритет, прибыль-дельта, статус, владелец, исполнитель, товар, МП); сортировка по эффекту; топ-20/неделя; только WB; «Менеджер товара основной» в отчёте.
- FR-4.2 Формализатор: извлечение из текста в формат МП; «показать-подтвердить» (оранжевые значения, крестик, «Сохранить»); не перезаписывает заполненные; требует категорию МП; сохраняет формат единиц.
- FR-4.3 AI-редактор фото: генератор по промту («Добавить в начало»/«Заменить»), AI-фотосессии (модель/ракурс/промт), фотоворонка продаж (контент-план 7/8/9/10), «Мои шаблоны», инструменты (удалить фон, улучшить, галерея, размер, текст как объект, фигуры, загрузить фон), глубокие настройки (фильтры, слои), умный предпросмотр Ozon/WB; требует дополнение (счётчик генераций).
- FR-4.4 Генерация видео: 2 фото + промт движения; «Сохранить» + тумблер Ozon/WB.
- FR-4.5 PIM/SEO: подбор ключевых слов (частота запросов, группы), генерация SEO-описания под правила МП; несколько групп на модель.
- FR-4.6 Точные поставки: режимы (Ручное распределение; «Умное Распределение» — в разработке); кластеры/склады, период анализа, дата поставки, «Планировать на» (дн., по умолч. 30), «Рекомендовать от», тумблеры (Считать по заказам, Учитывать FBS, Распределять не попавшие); вкладки Рекомендация/Детализация/Документы поставок; ручная корректировка; создание поставок; WB/Ozon.
- FR-4.7 AI Финдир (расширение): позиции в выдаче, рейтинг/отзывы, СПП WB, CTR/показы (воронка); «Запустить все»; доступность по тарифу/модулям.
- FR-4.8 «Рука на пульсе» (сводный, бета): план/факт продаж, прибыль/расходы, остаток; фильтры; без выгрузки.
- FR-4.9 «Рука на пульсе по-товарно»: фильтры (организация, МП, период, поиск, выбор показателей); формируется по избранным + топ по заказам за 2 месяца (~до 1000); автообновление каждую ночь + ручное; подсказки-рекомендации (зелёная↗/красная↘); целевые нормативы (ДРР ≤ 10%, маржинальность ~30%, оборачиваемость ≤ дней до конца сезона); нагрузка менеджера до 15 карточек на МП; ручные поля (Комментарий, Бюджет реклама план, Дней до конца сезона, Размеры, Подсорт план, Выручка план шт., Стратегия).

**Бизнес-правила.** AI-стратегии — только WB; у каждой задачи один владелец; Формализатор не перезаписывает; генерация фото — платное дополнение (счётчик); фото с внешних сайтов может блокироваться доменом; нельзя заменить одежду на нижнее бельё на готовом фото; текст — как объект; Точные поставки — только WB/Ozon, округление вверх, отрицательная рекомендация = 0, FBS распределяется пропорционально FBO-спросу; типы упаковки и коэффициенты складов WB — справочно; «Рука на пульсе» — бета; для Ozon требуется интеграция + Ozon Performance (реклама).

**Зависимости.** M2 (карточки/категории/менеджеры), M5 (цены/СПП), M6 (остатки FBO), M8 (поставки), M13 (расширение/воронка/позиции/рейтинг/СПП), M14 (аналитика/реклама/ABC).

### 4.5. M5 — Цены, стратегии ценообразования и акции

**Обзор.** Центральное место управления ценообразованием на всех подключённых МП. 4 задачи: (1) управление ценами/скидками (одна цена или разные по площадкам, общая таблица, пакетная правка, отправка по API, защита через минимальную цену); (2) планирование юнит-экономики и расчёт розничных цен (калькулятор по габаритам/тарифу/комиссии/логистике/налогу/марже или прибыли); (3) стратегии ценообразования и репрайсер (контроль МРЦ, ночной репрайсер); (4) акции и автоакции МП (анализ выгоды, добавление/удаление, защита от автоакций Ozon, расчёт прибыли по автоакциям WB, баллы Ozon).

**Ключевые user stories**
- US-5.1 Как селлер, я хочу управлять ценами на все МП из единой таблицы с цветовой маркировкой и постолбцовыми фильтрами.
- US-5.2 Как селлер, я хочу рассчитать розничную цену под желаемую маржу или прибыль с учётом комиссии, логистики, налога.
- US-5.3 Как селлер, я хочу, чтобы минимальная цена защищала от ухода в минус (не отправляется ниже порога).
- US-5.4 Как селлер, я хочу настроить репрайсер (контроль МРЦ, ночной репрайсер) для выгодного участия в акциях.
- US-5.5 Как селлер, я хочу анализировать выгодность акций Ozon/Яндекс (маржа до/после, валовая прибыль) и добавлять/удалять товары.
- US-5.6 Как селлер, я хочу рассчитать прибыль по акциям WB через файл из ЛК и защититься от автоакций Ozon.

**Функциональные требования**
- FR-5.1 Единая таблица цен по всем МП (общий столбец или по каждому МП); цветовая маркировка (WB фиолетовый, Ozon синий, Яндекс жёлтый, МегаМаркет зелёный, AliExpress красный).
- FR-5.2 Фильтры (МП, категория, поставщик, организация, бренд, тип товара, дубли, остатки FBO/FBS, избранные, архивные; тумблеры «без закупочной», «без доп. расходов», «в наличии»); постолбцовые фильтры; управление столбцами.
- FR-5.3 Изменение цен в интерфейсе и через Excel; цена на каждый размер (кроме WB — по цвету); синхронизация дублей; управление ценами в групповых карточках; массовый перенос цен между МП (на %/сумму).
- FR-5.4 Минимальная цена (защита; только снижение); расширенная юнит-экономика для WB/Ozon (логистика, обратная логистика, комиссия с НДС, СПП WB, штрафы, хранение, доплаты, услуги, эквайринг Ozon); средний % затрат для Яндекс/МегаМаркета.
- FR-5.5 Тип тарифа организации (FBO/FBS/DBS/realFBS/ПВЗ); для Ozon FBO — кластеры поставки/доставки, стоимость обработки отправления.
- FR-5.6 Комиссия за платные услуги (отдельно WB/Ozon); ручные параметры расходов (налог, постоянные расходы, реклама %, % для акций, коэффициент логистики склада WB, КТР, ИРП, стоимость доставки до выдачи Ozon).
- FR-5.7 Стратегии ценообразования (название; стандартные РЦ/Целевая цена/Цена слива; не снижает цену автоматически; в отчётах Товарная аналитика/ABC).
- FR-5.8 Репрайсер: контроль МРЦ (автоподдержание, ориентир — Москва), ночной репрайсер (время, скидка %, МП); для Ozon не поддерживается.
- FR-5.9 Акции (вкладки WB/Ozon/Яндекс; синхронизация каждую ночь + «Обновить»; вкладки Все/Участвуют/Кандидаты/Не найдено; фильтры, минимальная маржа).
- FR-5.10 Расчёт выгоды участия в акции (маржа/прибыль до и после, цена/скидка до и под акцию, % выкупа); добавление/удаление товаров (Ozon/Яндекс — через SelSup по API; WB — только в ЛК).
- FR-5.11 Защита от автоакций Ozon (ночью исключает товары; завышенная минимальная цена для сохранения отдельных); расчёт прибыли по автоакциям WB (файл из ЛК); расчёт через Excel-файл акций (обогащение колонками SelSup, файл «Promotion»).
- FR-5.12 История цен (товар, ШК, новые/старые цены, источник, пользователь, дата, статус, ошибка); файл ошибок (статус WB/Ozon/Яндекс).
- FR-5.13 Настройки мин. цен Ozon («равные новой цене со скидкой» / «указанную в SelSup»); пересчёт комплектов (закупка/доп. расходы); баллы Ozon (1 балл = 1 рубль, база налога); региональные валюты (расчёты в RUB, аналитика в валюте МП).

**Бизнес-правила.** SelSup не меняет цены автоматически без действия пользователя (кроме репрайсера/защиты); защита минимальной цены (не отправляется ниже, только снижается); WB — отправляется скидка целым числом (округление вниз), «Со скидкой новая расчётная» vs «желаемая», вкладка «Карантин»; Ozon — доставка до выдачи 25 ₽, комиссия с эквайрингом, репрайсер недоступен; тип тарифа обязателен; комиссия зависит от связи категории; синхронизация дублей — только через «Цены»; автоакции Ozon каждую ночь; валюта — расчёты в RUB, пересчёт в BYN вручную; файл акций — оставить только родные столбцы; акции Ozon Hot Sales поддержаны; оборачиваемость за 2 недели (999 при отсутствии заказов, норма до 70 дней); доступ к составу акций WB/автоакций — только через ЛК WB.

**Зависимости.** M2 (габариты, категории, связи, комплекты, дубли, групповые карточки), M6 (остатки FBO/FBS), M14 (фактические расходы, СПП, оборачиваемость, P&L, ABC), M13 (СПП через расширение), M4 (расчёт выгоды акций в AI-Финдире).

### 4.6. M6 — Остатки, склад и адресное хранение

**Обзор.** Полный складской учёт: учёт остатков по FBS и FBO (по API/виртуальные склады), синхронизация с МП (авто при заказе/изменении, ночной импорт, ручная), операции (обнуление/списание/перемещение/объединение/разделение, резерв/снятие, возврат), инвентаризация (Excel/ТСД, срок годности, дата производства, ГТД), адресное хранение (проход → стеллаж → полка → ячейка, раскладка, маршрутизация, ТСД), приёмка/поступления (закупочная цена, доп. расходы, ГТД, срок годности, ячейка), аналитика по остаткам, сверка. Модель: 1 физический склад = 1 склад в SelSup; партионный учёт (ID остатка + SKU).

**Ключевые user stories**
- US-6.1 Как сотрудник склада, я хочу видеть остатки FBS/FBO в реальном времени и вручную менять остаток с отправкой на МП.
- US-6.2 Как селлер, я хочу синхронизировать остатки (авто/ночь/ручная) с защитой от случайного обнуления.
- US-6.3 Как селлер, я хочу настроить мин/макс остаток FBS, «Уменьшать остаток на», минимальный порог FBO (Умный склад).
- US-6.4 Как сотрудник склада, я хочу списать/переместить остатки (между складами/ячейками) с листом сборки.
- US-6.5 Как сотрудник склада, я хочу провести инвентаризацию (Excel/ТСД) с поддержкой сроков годности/ГТД.
- US-6.6 Как сотрудник склада, я хочу вести адресное хранение (структура, раскладка, маршрутизация сборки, ТСД).
- US-6.7 Как селлер, я хочу объединить остатки по SKU и сверить с МП/МойСклад.

**Функциональные требования**
- FR-6.1 Просмотр остатков FBS (реал-тайм) и FBO (по API WB/Ozon; виртуальные склады FBO); ручное изменение остатка + галочка отправки; фильтры (склад, «есть/нет остаток», «обновлять на МП», «дубликаты», «по всем складам»); рассчитанные остатки для комплектов; столбцы «Ошибка», «Место»; скачивание Excel.
- FR-6.2 Синхронизация: «Синхронизировать остатки», «Автоматический импорт заказов» (раз в минуту проверка новых FBS), «Онлайн остатки» (робот автоотправки), ночной импорт в 00:00 МСК + ручной; «Обновлять только существующие остатки»; «Уменьшать остаток на»; мин/макс остаток FBS; минимальный порог FBO (Умный склад); отключение передачи (тумблер/конкретные МП/игнорируемые склады).
- FR-6.3 Обнуление (5+ способов), списание (документ), перемещение (между складами/ячейками, лист сборки), возврат остатка после отмены/возврата (авто до сборки; ручной через приёмку/задание/кнопку).
- FR-6.4 Приоритет списания (1, 2…; поиск по складам со связью к складу МП).
- FR-6.5 Объединение/разделение по SKU (массово через Excel); объединение карточек с разных МП (по ШК/артикулу); по цветам/моделям; дубликат/оригинал.
- FR-6.6 Инвентаризация (без адресного хранения: Excel; для адресного: ТСД-сканирование или Excel по ячейкам); доп. столбцы (срок годности, дата производства, ГТД); завершённые инвентаризации.
- FR-6.7 Адресное хранение: структура (проход → стеллаж → полка → ячейка), динамическое (разные товары в ячейке), закрепление ячейки, ячейка по умолчанию, две схемы хранения (с уникальным кодом / без), задания «Ячейки хранения»/«Раскладка»/«Инвентаризация»/«Сборка» через ТСД, маршрутизация и сортировка ячеек, печать этикеток ячеек, скрытие/удаление.
- FR-6.8 Приёмка/поступления: название, организация, поставщик, склад, способ ввода в оборот; товары (сканер/+1/Excel); поля (закупочная цена, доп. расходы, ячейка, срок годности, дата производства, ГТД, маркировка); накладные расходы; оприходование/отмена; связанные документы (закупка); перенос остатков (кнопкой/файлом).
- FR-6.9 Поставки: группа заказов на 1 день; ШК коробов/поставки; сверка с WB («Проблемные заказы»); массовое распределение заказов FBS по поставкам.
- FR-6.10 История отправки остатков (3 месяца), история операций с товаром (по ID остатка), сверка (WB/Ozon/МойСклад), отчёт «Товарный остаток», расчёт дней остатка комплектующей.
- FR-6.11 ТСД (мобильное приложение, Android/Honeywell EDA50k; смартфон с камерой).

**Бизнес-правила.** 1 физический склад = 1 склад; фулфилмент — отдельный склад; партионный учёт; SKU — одинаковый = общий остаток, нельзя вставлять произвольный; «Обновлять только существующие» — иначе обнуление; история остатка обязательна для передачи 0; отрицательные не используются; защита от обнуления (синхронизацию включать после переноса); сверка только WB/Ozon/МойСклад; FBO по API только WB/Ozon; Яндекс/МегаМаркет FBO только файлом; авто-возврат только до сборки; инвентаризация через «Задания» — только для первоначального размещения; инвентаризация — Администратор/Сотрудник склада; удаление элемента с остатками запрещено; объединение не при конфликте идентификаторов; разделение — из карточки оригинала; «Уменьшать остаток на» не списывает; повторный перенос невозможен при наличии остатков; история отправки 3 месяца; FBO/FBS в динамике только WB/Ozon.

**Зависимости.** M1 (организации, склады, приоритет), M2 (карточки, ШК, объединение), M7 (заказы/резерв/списание), M8 (поставки FBO), M11 (МойСклад/1С/СБИС), M12 (приёмки/себестоимость).

### 4.7. M7 — Заказы и сборка (FBS/FBO/DBS)

**Обзор.** Единый центр управления заказами и отгрузками вместо ЛК МП. Импорт заказов (авто/ручной/с обновлением остатков), многотиповая обработка (FBS, FBO, Express, DBS/realFBS, гибридные DBS, DBW/DBM, B2B, опт, розница, дропшиппинг, КГТ), лента заказов, динамика заказов, разделение на отправления, этикетки/лента/лист сборки, 5 способов сборки FBS, сборка через задания, адресное хранение, сборка FBO, комплекты, маркированные товары (Честный Знак), передача ГТД, отгрузка WB в ПВЗ, закрытие поставок, DBS через ТК, опт/розница, дропшиппинг, синхронизация статусов, камера как сканер, работа через 1С/МойСклад.

**Ключевые user stories**
- US-7.1 Как сотрудник склада, я хочу видеть ленту заказов со всеми типами и статусами и массово менять статусы.
- US-7.2 Как сотрудник склада, я хочу собрать FBS-заказ одним из 5 способов или через задание, с адресным хранением и маршрутизацией.
- US-7.3 Как сотрудник склада, я хочу собрать заказ с маркировкой Честного Знака (скан → КИЗ, проверка GTIN, срок годности).
- US-7.4 Как сотрудник склада, я хочу разделить FBS-заказ на отправления (Ozon/Яндекс/МегаМаркет).
- US-7.5 Как сотрудник склада, я хочу отгрузить WB-заказы в ПВЗ (короба WB-TRBX).
- US-7.6 Как селлер, я хочу обработать DBS-заказ через СДЭК (накладная, стикер, трек на Ozon).
- US-7.7 Как селлер, я хочу оформить оптовый/розничный заказ (счёт, заказ в МойСклад, отправка в СДЭК).

**Функциональные требования**
- FR-7.1 Импорт заказов: автоматический (по событию API), ручной «Импорт заказов» (без изменения остатков МП), «Импорт с обновлением остатков»; первый импорт — за 3 месяца; «Перезагрузить за неделю».
- FR-7.2 Многотиповая обработка в одном интерфейсе (FBS, FBO, Express, DBS/realFBS, гибридные DBS, DBW/DBM, B2B, опт, розница).
- FR-7.3 Лента заказов (обновление по API каждые 30 мин; фильтры; финансы; график; Excel) и динамика заказов.
- FR-7.4 Массовое изменение статусов; разделение FBS на отправления (ручное/авто при импорте; Ozon/Яндекс/МегаМаркет; не WB; не маркируемые; ≥2 шт.); массовое распределение по поставкам.
- FR-7.5 Этикетки (без этикетки → загрузка; авто-поставка для WB; статус МП «Ожидает доставки» для остальных); лента заказов/умная лента (этикетки МП PDF, товарные/сборочные — браузер, совмещённый PDF через QZ Tray); лист сборки (PDF, шаблоны FBS/FBO/перемещения).
- FR-7.6 5 способов ручной сборки FBS; сборка через задания (Комплектация/Сборка/Проверка/Сборка FBO/Сборочное задание); сборка с адресным хранением (ячейка, проход, строгий контроль ТСД); сборка FBO (резерв для сборки, «Собран»/«Нет остатка», расхождения).
- FR-7.7 Сборка комплектов (2 режима замены; автопечать этикетки комплекта; фиксация времени).
- FR-7.8 Маркированные товары (Честный Знак): настройка признака + ТН ВЭД; скан ШК → КИЗ (или по GTIN); проверка GTIN; привязка КИЗ; дата производства/срок годности; дубликат кода; авто ввод/вывод из оборота.
- FR-7.9 Передача ДТ/ГТД (номер в приёмке, массово через инвентаризацию; авто в заказ Ozon/WB из резерва).
- FR-7.10 Сборка для отгрузки WB в ПВЗ (режим «Отгружаться на ПВЗ», короб WB-TRBX).
- FR-7.11 Закрытие поставок (индивидуальное/массовое; «Проверить и закрыть» со сверкой для WB; QR WB; акты; способы доставки).
- FR-7.12 DBS/realFBS (настройки, фильтры, авто-импорт, стикеры, авто-статусы; ТК — СДЭК, Почта России, Деловые Линии, Яндекс Доставка; трек на Ozon).
- FR-7.13 Оптовые заказы (грузополучатель — контрагент; резерв/списание; счёт; заказ в МойСклад; аналитика) и розничные (данные покупателя; СДЭК до двери/ПВЗ; статус вручную).
- FR-7.14 Дропшиппинг (регулярный обмен: email/YML/Excel/JSON API/прямая Sima-Land/кастомный; обнуление; заказ поставщику; закупки из заказов; карточки из YML).
- FR-7.15 КГТ (Ozon; отдельный склад; «Игнорировать/только склады FBS»); B2B (значок портфеля; WB — раздельные поставки; Ozon — смешивание).
- FR-7.16 Синхронизация статусов (до отгрузки — внутренние; после — синхронизация с МП); камера как сканер; работа через 1С/МойСклад.

**Бизнес-правила.** Статусная модель до отгрузки — внутренние статусы не передаются; сопоставление товара «символ в символ» (WB по ШК, Ozon по артикулу); разделение — Ozon/Яндекс/МегаМаркет, до этикеток, не маркируемые, ≥2 шт.; маркировка — этикетка после КИЗ, для Яндекс сначала КИЗ потом этикетка; срок годности WB ≥30 дней; поставки закрывать через SelSup (WB — сверка); B2B — WB раздельные, Ozon смешивание; резерв/списание — опт при выходе из «Новый»/«На сборке», розница при финальном; нельзя удалять отгруженный заказ; адресное хранение — ячейка при оприходовании; КГТ — отдельный склад; первый импорт без обновления остатков; код маркировки в ленте после резервирования; расхождения 15–30 мин; МойСклад — разделить в SelSup до создания в МС; FBO — поставки не через API, SelSup не управляет остатками FBO.

**Зависимости.** M6 (остатки/резерв/адресное хранение), M8 (поставки FBO), M9 (маркировка/Честный Знак), M11 (1С/МойСклад/СДЭК), M10 (интеграции).

### 4.8. M8 — Отгрузки, упаковка и поставки на склады маркетплейсов (FBO)

**Обзор.** Полный цикл поставок на склады МП по FBO и частично FBS (ПВЗ WB): создание заказов/поставок на отгрузку (WB/Ozon/Яндекс), резервирование/списание остатков с переносом на виртуальные склады МП, планирование объёмов, упаковка по коробам (ШК коробов, контроль вложения, автопечать), файлы для ЛК, маркировка Честный Знак, хранение актов приёмки WB, контроль расхождений. Статусы SelSup меняются вручную (МП не передают статусы FBO по API), кроме Ozon (до таймслота). Требует полного товарного учёта.

**Ключевые user stories**
- US-8.1 Как сотрудник склада, я хочу создать заказ на отгрузку FBO с резервированием остатков и типом поставки (WB).
- US-8.2 Как сотрудник склада, я хочу упаковать товары по коробам (скан ШК короба и товаров, автопечать, файл ШК коробов).
- US-8.3 Как сотрудник склада, я хочу создать поставку на WB/Ozon/Яндекс (файлы, ручная связка с ЛК, статусы).
- US-8.4 Как сотрудник склада, я хочу отгрузить поставки FBS в ПВЗ WB (короба WB-TRBX).
- US-8.5 Как сотрудник склада, я хочу проконтролировать расхождения при упаковке и после приёмки WB (акт).
- US-8.6 Как селлер, я хочу спланировать объём поставки (продажи, остатки, оборачиваемость).

**Функциональные требования**
- FR-8.1 Создание заказа на отгрузку FBO (организация, МП, склад МП, склад списания, «Списать остатки», тип поставки для WB); «Создать из файла» (Акт приёмки WB xlsx / Уведомление о выкупе — УПД по НДС WB XML).
- FR-8.2 Планирование поставок (расчёт по продажам/заказам, остаткам, в пути, оборачиваемости; WB/Ozon/Яндекс).
- FR-8.3 Резервирование остатков (при «Новый» — резерв; при смене статуса — списание; возврат резерва через приёмку возврата); виртуальный склад FBO; сверка остатков FBO.
- FR-8.4 Упаковка FBO (по собранному заказу: скан ШК короба, скан товаров с автопечатью, контроль вложения, файл ШК коробов; WB/Ozon) и упаковка с добавлением в заказ FBO (товар + заказ + короба; поиск по GTIN; WB/Ozon).
- FR-8.5 Генерация/печать ШК коробов/QR-коробов (WB — 100/1000; QR по ID магазина; «предварительные короба» Ozon — внутренние QR с заменой на ШК Ozon через Excel); учёт коробов (справочник, журнал).
- FR-8.6 Кратность короба (количество штук в коробе).
- FR-8.7 Отгрузка поставок FBS в ПВЗ WB (модель «Маркетплейс»: ШК короба WB-TRBX, распределение по коробам в «Комплектации», «Отгружаться на ПВЗ»).
- FR-8.8 Маркировка Честный Знак из отгрузки FBO (блок получения кодов и ввода в оборот; WB/Ozon/Яндекс; для маркируемых категорий с ТН ВЭД).
- FR-8.9 Хранение актов приёмки WB (импорт xlsx/zip, бессрочное хранение, выгрузка excel); контроль расхождений при упаковке (WB/Ozon) и при приёмке (WB).

**Бизнес-правила.** Резерв только система; списание при смене статуса/ночью; «Списать остатки» нельзя отключить после «Новый»; добавление товаров только в «Новый»; удаление поставки снимает резерв; не удалять/восстанавливать отгруженный заказ; FIFO; склад для FBS по связи + «Использовать для заказов» + приоритет; запрет объединять товары разного типа поставки; один ШК короба на гофрокороб; ограничения микс/моно/моно-паллет/суперсейф и паллет; требования к упаковке WB по категориям (КГТ и др.); требования к ПВЗ (штраф 30% за другую зону, приёмка 15/75 ₽); упаковка FBO только WB/Ozon; расхождения при приёмке только WB; заказ в Ozon создаётся один раз; для Яндекс — не более 1 склада на организацию; статусы SelSup вручную (кроме Ozon до таймслота); ШК коробов сохраняются только через «Упаковка FBO».

**Зависимости.** M6 (остатки/резерв/виртуальные склады FBO/сверка), M7 (заказы FBS/ПВЗ), M9 (маркировка/Честный Знак), M10 (WB/Ozon/Яндекс).

### 4.9. M9 — Маркировка, Честный Знак, этикетки и печать

**Обзор.** Сквозная работа с обязательной маркировкой (Честный Знак/МЕРКУРИЙ) и печатью этикеток всех типов. Два сценария: (1) коды уже получены/переданы — хранение, резервирование, сканирование, передача на МП; (2) получение кодов через SelSup — создание карточек в Национальном каталоге, заказ через СУЗ, подпись ЭЦП, ввод в оборот, печать КИЗ+ШК, вывод из оборота. Параллельно по FBS и FBO, агрегация (комплекты/наборы/транспортные упаковки), возвраты, обработка ошибок, передача между организациями, УПД/УПД ДОП, шаблоны этикеток, принтеры (QZ Tray), штрихкоды, уникальные коды.

**Ключевые user stories**
- US-9.1 Как селлер, я хочу подготовиться к работе с Честным Знаком (ЭЦП, КриптоПро, ГС1 РУС, интеграция, производители, категории, сертификаты, этикетки).
- US-9.2 Как сотрудник склада, я хочу получить коды маркировки через СУЗ (заказ ≤10 позиций, по типам), подписать ЭЦП, ввести в оборот, распечатать КИЗ+ШК.
- US-9.3 Как сотрудник склада, я хочу вывести коды из оборота (FBS — выкупленные заказы; FBO — 10-й отчёт WB) и вернуть при отмене/возврате.
- US-9.4 Как сотрудник склада, я хочу агрегировать коды (наборы/комплекты, задание «Агрегация»).
- US-9.5 Как сотрудник склада, я хочу передать коды на МП при сборке с проверкой принятия и повторной отправкой.
- US-9.6 Как сотрудник склада, я хочу настроить шаблоны этикеток и печатать в один клик через QZ Tray (разные принтеры под форматы).

**Функциональные требования**
- FR-9.1 Хранилище кодов маркировки (централизованное, видимость свободных/зарезервированных, привязка к товарам/заказам/поставкам).
- FR-9.2 Создание карточек в Национальном каталоге/ЧЗ (создание → подписание ЭЦП → модерация → публикация; архив).

- FR-9.4 Подписание ЭЦП (КриптоПро + браузер-плагин; токен ЧЗ на 10 ч).

- FR-9.8 Резервирование свободных кодов (FBO-поставка/FBS-заказ; снятие резерва); передача между организациями (УПД; обе организации в «Мои организации»; владелец по ИНН).

**Бизнес-правила.** Для получения маркировки — категория «маркируется» + ТН ВЭД + товарная группа + карточка в ЧЗ подписана/опубликована; коды ровно по количеству; заказ СУЗ ≤10 позиций и отдельный на тип; криптохвост удаляется после ввода; статусы кода для операций; срок вывода — 3 рабочих дня (FBS) или 30 календарных (порча/возврат/инвентаризация); по FBO ввод/вывод обычно МП; цена продажи обязательна; передача между организациями — обе в «Мои организации», владелец по ИНН; агрегация — вложенные введены в оборот, выведенные агрегировать нельзя, минимум 2 кода, GLN 7 цифр; комплект — в оборот комплектующие, комплект вводит ЧЗ; принятые коды FBO — только из Акта WB; печать КИЗ в ленте только при резервировании через «Заказы на отгрузку» и только на прямой принтер; карточки в ЧЗ нельзя удалить — только архив; одинаковый ТН ВЭД в категории; второй GTIN — в поле «Штрих-код»; ИНН производителя как в ЧЗ/ЭЦП; GS1 РУС — бесплатно до 100 карточек, далее 3000 ₽/год; код маркировки — 60 коп. с НДС; уникальные коды — премиум/доп. плата; объединение этикетки товара и заказа в один PDF — только BullZip.

**Зависимости.** M2 (карточки/категории/производители/ШК), M6 (приёмки/остатки/ячейки), M7 (сборка/комплектация/возврат), M8 (отгрузки FBO/акты), M12 (комплекты/агрегация), M10 (МП), M1 (организации/сертификаты).

### 4.11. M11 — Интеграция с 1С, МойСклад, СБИС и API

**Ключевые user stories**

- US-11.4 Как селлер, я хочу синхронизировать товары/остатки/заказы с МойСклад (двусторонне, FBS/FBO).
- US-11.5 Как селлер, я хочу настроить регулярный обмен с поставщиком (почта/Excel/YML/JSON API) с обновлением остатков/цен и защитой от массового обнуления.

- FR-11.6 Регулярный обмен (Дропшиппинг → Регулярные обмены): типы (Почта/Почта XLS/Excel/YML/JSON API); IMAP-настройки (Яндекс/Mail.ru/Gmail); XPath-теги YML; CRON ≥30 мин (кроме тарифа «Бизнес»); обновление остатков/закупочных/розничных цен; обнуление при окончании; защита 50% от массового обнуления; прайс-листы (разовая загрузка).
- FR-11.7 API-ключи и токены (хранение, удаление, токены на чтение для отладки).

**Бизнес-правила.** Модуль 1С не на демо/файловых базах; не работает напрямую с МП — только через API SelSup; схема сопоставления товаров — одна, не комбинируется; обмен остатками — только изменения; для нового товара нужны обе выгрузки (`import.xml` затем `offers.xml`); CommerceML — 1С забирает только заказы; CommerceML не поддерживает файлы/картинки; SelSup — остатки вручную, МойСклад — через документы; МойСклад — один ключ на все организации; не включать авто-создание заказов сразу; проверка нумерации; возврат — через возвратный документ МС; НДС при заполненном значении в карточке; действие «Создать отгрузку» — один статус; МойСклад FBO — начальные остатки обязательны; разделённые FBS-заказы — сначала в SelSup; СБИС — «Артикул» обязателен; Битрикс — каталог только через YML; регулярный обмен ≥30 мин; защита 50%; «Любой артикул» может приводить к ошибкам (лучше «Внешний артикул»); WB — лучше «Внешний артикул»; Excel — прямая ссылка, значения не формулы; прайс-лист — названия колонок из шапки; токены на чтение для отладки; скорость сборки +80%.

**Зависимости.** M2 (карточки), M6 (остатки/склады), M7 (заказы), M9 (маркировка), M10 (интеграции/МП), M12 (закупки/поставщики/дропшиппинг).

### 4.12. M12 — Закупки, производство, комплекты и себестоимость

**Обзор.** Полный цикл управления запасами «до продажи»: планирование/оформление закупок у поставщиков, база поставщиков и взаиморасчёты, производственные операции (процессы, техкарты, производственные заказы), комплекты (создание/сборка/маркировка/себестоимость), 3 режима расчёта себестоимости (классический FIFO, упрощённый FIFO, последняя себестоимость), ввод/обновление закупочных цен, товары со сроком годности (FIFO/FEFO, этикетки хранения), возвраты и брак. Преимущество: разделение конфиденциального процесса закупок и контента, точный партийный учёт себестоимости.

**Ключевые user stories**
- US-12.1 Как закупщик, я хочу создать заказ поставщику с авто-расчётом розничной цены и приёмкой с выявлением расхождений.
- US-12.2 Как закупщик, я хочу спланировать закупки (продажи/заказы, остатки, дни) или сформировать закупки из заказов (дропшиппинг).
- US-12.3 Как закупщик, я хочу вести базу поставщиков, привязывать их к товарам, считать взаиморасчёты.
- US-12.4 Как производитель, я хочу вести техкарты и производственные заказы (из FBS-заказов тоже) с расчётом норматива и диаграммой Ганта.
- US-12.5 Как селлер, я хочу создать комплект с авто-расчётом остатков и себестоимости.
- US-12.6 Как селлер, я хочу работать с товарами со сроком годности (FIFO/FEFO, этикетка хранения).
- US-12.7 Как сотрудник склада, я хочу обработать возврат/брак (скан заказа/товара, возврат в ячейку с исходной ценой).

**Функциональные требования**
- FR-12.1 Заказ поставщику (название, организация, валюта, поставщик, товары с фото/количеством/закупочной/доставкой; авто-расчёт розничной `(закупка × K) + доставка`; номер; связанный документ в МойСклад; Excel/«Шаблон для карго»).
- FR-12.2 Приёмка из закупки (связь; расхождения; поля «Есть?», «Брак», «Комментарий»).
- FR-12.3 Планирование закупок (период, дни, «рекомендованное от», «пропускать дни без остатков», «по заказам»/по продажам; «Рассчитать» + добавление).
- FR-12.4 Закупки из заказов (дропшиппинг; FBS «Новый»/«На сборке», не в актуальной закупке; фильтр по поставщику; статус «В закупке»).
- FR-12.5 «Заменять комплекты на компоненты» (в Excel закупок/FBS-заказов).
- FR-12.6 База поставщиков (карточка/Excel/в момент закупки; поля; экспорт); привязка к товарам (Excel; несколько поставщиков; «Для закупки» — рейтинг).
- FR-12.7 Взаиморасчёты (обороты за период таблица/диаграмма; детализация по поставщику; ручные платежи; редактирование; Excel); отчёт «Продажи по поставщикам» (продажи/возвраты шт./руб., выручка, остаток, проданный товар в закупочных, средняя фактическая цена).
- FR-12.8 Дропшиппинг-обмен с поставщиком (регулярный; остатки поставщика → МП).
- FR-12.9 Единицы измерения (поле, количество; массово через Excel; перезагрузка аналитики; товарооборот в единицах).
- FR-12.10 Производство: процессы/этапы, техкарты (Материалы/Результат/Зарплата/Документы; копирование), производственные заказы (детали/материалы/результат; подтверждение со складами; резервирование; «Выполнен» — списание/оприходование; аналитика), производственные заказы из FBS-заказов (техкарта с материалом/результатом/планом/≥1 этапом; склады; объединение; норматив с округлением вверх; флаг «Есть производственный заказ?»; ошибки), диаграмма Ганта.
- FR-12.11 Комплекты (тип «Комплект»; состав; массово через Excel; редактирование; из товаров разных организаций — флаг «Не учитывать организацию»; смена типа Комплект↔Товар).
- FR-12.12 Авто-расчёт остатков комплектов (минимум по компонентам; + ручной остаток; пересчёт при заказе; связывание только комплекта), авто-учёт остатков на МП (каскадный пересчёт), гибкий расчёт себестоимости комплектов (тумблеры пересчёта).
- FR-12.13 Сборка заказов с комплектами (FBS/FBO/DBS; состав с фото; подсказки; замена на компоненты).
- FR-12.14 Маркировка комплектов (карточка в ЧЗ: GTIN, тип Набор/Комплект/Групповая упаковка; коды комплекта и комплектующих; агрегация; печать сгруппированно; ввод только комплектующих).
- FR-12.15 3 режима себестоимости (классический FIFO, упрощённый FIFO, FIFO выключен); ввод закупочных цен (интерфейс/Excel; `себестоимость = закупка + доп. расходы`; доп. расходы в руб. или %; «Обновить закупочные цены в аналитике»); обновление по режимам; «Проданный товар в закупочных ценах»; FIFO при работе со складом (FBS/FBO; адресное хранение — ранняя ячейка; возвращённые по дате первоначальной приёмки).
- FR-12.16 Товары со сроком годности (ввод в приёмке; срок в КИЗ; автоподстановка из КИЗ; FIFO/FEFO-выдача; этикетка хранения; уникальные коды партии).
- FR-12.17 Возвраты и брак (задание «Возврат товара»; скан заказа/товара; авто-возврат с исходной ценой и ячейкой; частичный; «Возврат получен»; в аналитике не учитываются).
- FR-12.18 Интеграция с МойСклад (заказ поставщику; импорт комплектов); разделение прав (закупки vs контент).

**Бизнес-правила.** Разделение прав закупок и контента; розничная цена по умолчанию `(закупка × K) + доставка`; себестоимость = закупка + доп. расходы; «Планирование закупок» только при выключенной опции «Закупки из заказов»; «Закупки из заказов» — FBS «Новый»/«На сборке», не в актуальной закупке, не связаны с остатками; статус «В закупке» внутренний; рассчитанный остаток комплекта = минимум по компонентам (+ ручной); достаточно связать только комплект; себестоимость комплекта по умолчанию отдельно (автосумма при тумблерах); FIFO — из партий, при отсутствии — из карточки, при «Нет FIFO» — всегда из карточки; классический FIFO — цена только через новую приёмку; упрощённый FIFO — запаздывающая аналитика; «Нет FIFO» — пересчёт всей истории; WB аналитика по неделям; производственный заказ требует техкарту; норматив округляется вверх; один общий заказ для нескольких FBS-заказов; карточка комплекта сначала в ЧЗ; в оборот только комплектующие; комплекты не по артикулу WB; «Не учитывать организацию» нельзя при одинаковых ШК; смена Комплект→Товар не удаляет состав; FIFO/FEFO; возвраты/брак не в аналитике; «Проданный товар» из «Закупочной цены на момент операции»; отчёт «Продажи по поставщикам» требует поставщика в карточке.

**Зависимости.** M2 (карточки/категории/типы товаров), M6 (остатки/приёмки/склады), M9 (маркировка/Честный Знак/этикетки), M11 (МойСклад/1С/дропшиппинг), M14 (аналитика/себестоимость).

## 6. Глоссарий

- **PIM** — Product Information Management; единый внутренний справочник товаров SelSup.
- **SKU** — внутренний ID единицы хранения; одинаковый SKU = общий остаток у объединённых товаров.
- **FBS** — товар на складе продавца, сборка/отгрузка продавцом.
- **FBO / FBY** — товар на складе маркетплейса.
- **DBS / realFBS** — доставка продавцом/ТК.
- **Express** — срочная доставка (Яндекс GO, Ozon Express).
- **DBW / DBM** — Delivery by Marketplace (товар у продавца, доставка МП).
- **КГТ** — крупногабаритные товары.
- **B2B** — заказы от юридических лиц.
- **Тумблеры-«курки»** — переключатели публикации карточки на каждый МП.
- **Матчинг** — объединение карточек из разных источников в одну по ШК/артикулу.
- **SKU/партионный учёт** — каждая приёмка создаёт остаток с уникальным ID (партия).
- **FIFO / FEFO** — First/First Expired In/Out (по дате прихода/сроку годности).
- **КИЗ / DataMatrix** — код маркировки Честного Знака.
- **GTIN** — глобальный код товара (для ЧЗ/Национального каталога; начинается с 2 или 4).
- **ТН ВЭД** — код товарной номенклатуры (для маркировки/категорий).

- **ЭЦП / УКЭП** — усиленная квалифицированная электронная подпись.
- **ОМС Id / СУЗ** — идентификатор/станция управления заказами кодов маркировки.
- **ГС1 РУС / GS1** — глобальный регистр штрихкодов (GTIN на «46…»).
- **СПП** — скидка постоянного покупателя (WB).
- **МРЦ** — минимальная розничная цена.
- **ДРР** — доля рекламных расходов.
- **КТР / ИРП** — коэффициент территориального распределения / индекс распределения продаж (WB).
- **ABC-анализ** — разбиение ассортимента A (80%)/B (15%)/C (5%).
- **P&L** — отчёт о прибылях и убытках.
- **Юнит-экономика** — экономика на единицу товара.
- **CommerceML** — протокол обмена 1С с сайтом (`import.xml`/`offers.xml`).

### 7.2. Продуктовые неопределённости
- **Ролевая модель.** Точная матрица ролей × разрешений (объекты доступа, granular permissions) не приведена ни в одном модуле.
- **Статья «Автоматическое обновление цен и остатков» (M15) недоступна (404).** Не описаны частота (сверх «ежеминутно»), приоритеты отправки, обработка коллизий, пакетная/пакетная отправка, поведение при ошибках API.
- **Расписание и гарантии синхронизации.** Полного расписания фоновых задач, приоритетов обновления, retry-политик, идемпотентности импорта заказов нет (флаги «Онлайн остатки»/«Синхронизировать»/«Автоматический импорт заказов» пересекаются).
- **Маркетплейсные ограничения.** Rate-limit и retry-логика для WB/Ozon/МегаМаркет недокументированы; политика поддержки версий API и миграции — только для AliExpress сказано «не поддерживается».
- **Поведение при конфликтах.** Матчинг при совпадении ШК, но разных брендах/категориях; приоритет списания при равных остатках; race conditions при нескольких складах с одним складом МП; разрешение коллизий значений параметров на уровнях модель/цвет/размер и категория-карточка.
- **Версионирование/откат.** Нет отката инвентаризации/списания/перемещения после закрытия; нет undo при массовом редактировании через Excel; история изменения закупочной цены в карточке не ведётся.
- **Сроки хранения.** Истории операций с товаром (указан только 3 мес. для истории отправки), собранных данных расширения (позиции/рейтинг/СПП), логов аудита — не заданы.
- **СберМегаМаркет/AliExpress.** В модулях цен/акций/аналитики фактически отсутствует детальное описание (только столбцы/цвет); формулы, комиссии, интеграции не раскрыты.
- **«В разработке» (явно отмечено).** AI: Умное Распределение, AI-Прогноз, Ограничить по остатку FBS, авто-заполнение «Дней до конца сезона», фильтр по менеджеру в «Рука на пульсе», AI-стратегии для Ozon/Яндекс/МегаМаркет/AliExpress. Склад: иерархия категорий, групповые карточки (массовое объединение/аналитика), конкуренты. Заказы: разделение маркированных Ozon, поставки МегаМаркета через API, срок годности в UI, вывод срока в лист сборки. Реклама МегаМаркета. Гипотезы производства. «Закажи и забери» МегаМаркет.

### 7.3. Риски воссоздания
- **Зависимость от API МП.** Объём возможностей определяется API сервиса (Avito — без подтверждения/маркировки/этикеток; Lamoda/SimaLand/Webasyst — только связь; МегаМаркет — без API по карточкам/аналитике; Takealot — без редактирования/цен/статусов). Изменения API МП (AliExpress) могут ломать интеграции.
- **Статусы FBO по API не передаются.** Статусы SelSup и ЛК МП не связаны автоматически (кроме Ozon до таймслота) — ручное поддержание согласованности.
- **FBO-остатки не по API (Яндекс/МегаМаркет).** Требуется ручная загрузка файлов.
- **Сложность маркировки/ЭДО.** УКЭП, КриптоПро, ГС1 РУС, агрегация, УПД ДОП — высокая зависимость от клиентского ПО и операторов ЭДО.
- **Сложность финансовой модели.** Разные формулы процента выкупа, состава логистики, периодов детализации и авто-корректировки по МП — риск расхождений с ЛК.
- **Мульти-схемная тарификация.** 1 организация = 1 ключ API; 1 схема = 1 организация (Яндекс/МегаМаркет) — требует аккуратной модели биллинга.
