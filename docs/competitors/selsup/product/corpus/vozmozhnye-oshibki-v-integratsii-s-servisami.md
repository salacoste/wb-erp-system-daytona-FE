## Общая информация

Что-то сломалось, уже чиним Перезагрузите страницу или попробуйте позже

Если в одной из организаций заполнен API-токен маркетплейса или сервиса, но он стал невалидным или был отозван, SelSup показывает в верхней части интерфейса отдельное уведомление для каждого такого токена. В уведомлении будет указано, в какой организации или организациях возникла проблема.

Это может произойти, например, если у токена закончился срок действия или маркетплейс отозвал его. В таком случае нужно заново создать токен по инструкции для нужного маркетплейса и вставить новый токен в настройки интеграции SelSup.

Уведомление помогает быстро заметить проблему и перейти в нужную интеграцию для обновления токена по кнопке **«Перейти к настройкам»**.

Оно отображается во всех разделах SelSup, чтобы вы могли вовремя увидеть проблему и устранить её, независимо от того, в каком разделе работаете.

## Wildberries

**Ошибка: Не настроена интеграция с Wildberries, либо ключ не действителен.**

**Решение**:\
1. Перейдите в раздел [Интеграции, вкладка Wildberries](https://selsup.ru/application/integration/wildberries) и проверьте отсутствие ошибок с ключами. Если ошибка есть, создайте новый ключ и нажмите кнопку копирования ключа (она есть у каждого маркетплейса). Важно! Никогда не копируйте ключи выделением.

2\. Проверьте, что вы вводите правильный ключ по инструкции под полем.\
![](../../out/selsup.ru/_kage/selsup.ru/wp-content/webp-express/webp-images/uploads/2024/07/insrukciya.png.webp)Для Wildberries важно правильно выбрать тип ключа (рекомендуется выбирать все типы ключа для корректной работы).

3\. Ошибка может возникать временно, если у маркетплейса сломалась авторизация. Подождите и обновите страницу через некоторое время.

**Ошибка: Токен нового API Wildberries просрочен или не валидный.**

Ошибка возникает, когда вы неправильно указали ключ API Wildberries.

**Решение**: Не копируйте ключ выделением, используйте только кнопки копирования ключа. Также проверьте, что вы выбрали все типы ключа.

## Ozon

**Ошибка: Не настроена интеграция с Ozon.**

Ошибка может возникать, если в интеграциях вы не указали Client ID или ключ API Ozon.

**Решение**: перейдите на [страницу Интеграции с Ozon](https://selsup.ru/application/integration/ozon) и проверьте, указаны ли у вас оба поля.

*Важно! При формировании ключа нужно выбирать тип токена “Admin”. Проверьте отсутствие ошибки и красных предупреждений о невалидности токена.\*

## Яндекс. Маркет

**Ошибка: Токен Яндекс.Маркет не валидный или отозван.**

**Решение**: Авторизуйтесь на Яндекс.Маркете под логином, у которого есть доступ к соответствующему магазину на Яндекс.Маркете. Нужно чтобы у аккаунта, под которым Вы авторизованы в Яндекс.Маркете, был доступ “Администратор” или “Владелец” к магазину на Яндекс.Маркете в партнерском интерфейсе.

Только после этого нажмите кнопку “Получить токен” на странице интеграции с Яндекс.Маркетом, скопируйте его и вставьте на страницу интеграции в SelSup.

**Ошибка: Неактивен токен, который нужно скопировать.**

SelSup не использует синхронную модель интеграции с Яндекс.Маркетом, когда Яндекс.Маркет отправляет заказы, так как это приводит к скрытию остатков товара при переключении на эту модель. Поэтому указывать авторизационный токен не нужно, если работаете по FBY (FBO): интеграция настраивается вручную.

**Решение**: На странице интеграции укажите ID кабинета и номер компании (указать их можно в том числе для FBY магазина, однако номер компании нужно посмотреть в адресе страницы, так как для FBY магазина не выводится настройка интеграции по API). Нажмите на кнопку “Подключить магазин” для получения токена.

**Ошибка: У вашего аккаунта нет нужного доступа (аккаунт должен быть Владелец или Администратор) для получения ключа API или неправильно указан ID кабинета или номер компании.**

**Решение**: Проверьте правильность заполнения ID кабинета или номер компании.\
Также проверьте доступ в учетной записи, так как для интеграции между SelSup и Яндекс.Маркет необходимо быть авторизованным под учетной записью владельца аккаунта Яндекс.Макркета.  Если у вас аккаунт пользователя с правами администратора Яндекс.Маркет выдаст ошибку.

## Честный знак

**Ошибка запроса к API SUZ: Экземпляр интеграционного решения (внешнего подключения) с наименованием SelSup уже был зарегистрирован.**

Ошибка возникает из-за того, что вы пытаетесь добавить еще одно подключение к организации, для которой уже настроена работа с API СУЗ.

**Решение**: Если вы удаляли организацию и не удалили перед этим подключение, зайдите в личный кабинет «Честного знака», в «Станцию управления заказами» и на вкладке «Устройства» удалите существующее подключение, чтобы добавить новое.

Если вы хотите настроить у другого магазина (организации) в SelSup интеграцию с СУЗ, при этом у существующей организации уже настроена интеграция, не нажимайте кнопку «Получить идентификатор соединения», а скопируйте существующий идентификатор с предыдущей организации и нажмите кнопку «Сохранить»  в нижней части страницы.

**Ошибка: Вставьте ключевой носитель.**

**Решение:**

Если вы оправляете карточку в Честный знак, то:

- проверьте, что носитель с сертификатом вставлен в компьютер. Носитель должен соответствовать выбранному сертификату в разделе [Интеграции](https://selsup.ru/application/integration/).
- переустановите личный сертификат через КриптоПро CSP по [инструкции](https://support.kontur.ru/ca/38784-kak_ustanovit_lichnyj_sertifikat_cherez_kriptopro).

Если вы не отправляете карточку в Честный знак, то выключите переключатель "Отправить в" со значком Честного знака у карточек товара рядом с кнопкой "Сохранить".\
Если вы не работаете с Честным знаком, то выключите переключатель "Работать с Честным знаком" в [Интеграции](https://selsup.ru/application/integration/crpt).

**Ошибка запроса к API SUZ: Проверка учетных данных УОТ не пройдена. Маркер безопасности не найден.**

**Решение**: Необходимо заново вставить OMS ID и Идентификатор соединения СУЗ из Честного знака в SelSup на странице интеграции с Честным знаком и нажать "Получить токен".

## CDEK

**Ошибка: Не указан пункт отправления для транспортной компании.**

Ошибка возникает когда у склада SelSup для заказа не настроено на какой пункт отправления транспортной компании будут отгружаться заказы и с какими условиями доставки. Посмотрите склад указанный у заказа.\
![](../../out/selsup.ru/_kage/selsup.ru/wp-content/webp-express/webp-images/uploads/2024/03/snimok-ekrana-2024-03-28-v-11.16.45.png.webp)

**Решение**:\
Проверьте на странице интеграции с транспортной компанией для DBS заказа, указаны ли настройки доставки заказа для указанного склада, если их нет - добавьте.\
![](../../out/selsup.ru/_kage/selsup.ru/wp-content/webp-express/webp-images/uploads/2024/03/snimok-ekrana-2024-03-28-v-12.09.29.png.webp)\
**Ошибка API CDEK: По данному направлению при заданных условиях выбранный тариф недоступен.**

Данная ошибка возникает, если в настройках интеграции со CDEK указан один тариф, который нельзя использовать из-за ограничений по габаритам отправления или веса, либо доставка данным тарифом не доступна по указанному пункту доставки. Список доступных тарифов и ограничения указаны [тут](https://api-docs.cdek.ru/63345430.html).\
Доступен ли тариф можете посмотреть в калькуляторе [на сайте](https://www.cdek.ru/ru/business/tariffs/).

**Решение:\**
Чтобы исправить ошибку:\
1)Проверьте корректность указания габаритов и веса в карточке товара, чтобы он не превышал указанные для тарифа лимиты\
2)Укажите другой тариф, в настройках интеграции со СДЭК, который так же может использовать SelSup, чтобы он мог выбрать из нескольких тарифов. Проверьте доступные тарифы между указанными вами пунктами по ссылкам выше.
