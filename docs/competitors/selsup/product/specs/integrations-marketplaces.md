# Интеграции с маркетплейсами и сервисами

> Спецификация модуля для воссоздания функционала. Источник — статьи базы знаний SelSup
> (раздел «Интеграции в SelSup: Маркетплейсы и Сервисы», навигационная статья «Интеграция»,
> статьи по возможностям и настройке каждой интеграции, статьи об ошибках, ЭЦП/КриптоПро,
> УПД ДОП, фулфилментам).

## Назначение

Модуль «Интеграции с маркетплейсами и сервисами» — это единый центр подключения внешних
площадок и систем к SelSup. Через раздел **Настройки → Интеграции** продавец подключает
маркетплейсы, интернет-магазины/CMS, логистические службы, фулфилменты, систему маркировки
«Честный ЗНАК» и учётные системы, после чего SelSup становится «единым окном» для работы с
товарами, ценами, остатками, заказами (FBS/FBO/DBS/realFBS), маркировкой и документооборотом
(УПД ДОП, ЭДО).

Интеграции отличаются по глубине: для одних сервисов доступна полноценная двусторонняя
работа (товары, заказы, остатки, цены), для других — только часть операций (например, только
передача остатков или только импорт). Объём возможностей определяется API самого сервиса.
Часть интеграций подключается бесплатно и без условий, часть — за отдельную помесячную
плату, часть требует индивидуальной разработки силами SelSup.

## Возможности (capabilities)

### Общие возможности модуля интеграций

1. **Единый каталог подключаемых сервисов.** Раздел `Настройки → Интеграции` показывает
   список всех доступных маркетплейсов и сервисов с кнопками «Настроить» / статусы
   «Уже настроено» / «Частично настроено».
2. **Многокомпанийность (несколько организаций).** Ключ/токен API привязывается к конкретной
   организации. Можно настраивать интеграцию поочерёдно для каждой организации.
3. **Статусы настройки интеграции.** Кнопка-индикатор показывает: «Настроить» — не
   настроено; «Уже настроено» — настроено для всех организаций; «Частично настроено» —
   настроено не для всех организаций (по клику видно, для каких именно).
4. **Уведомления о невалидных токенах.** Если API-токен маркетплейса/сервиса просрочен,
   отозван или стал невалидным, SelSup показывает отдельное уведомление в верхней части
   интерфейса (для каждого токена с указанием организации) с кнопкой «Перейти к
   настройкам». Уведомление отображается во всех разделах.
5. **Импорт карточек товаров** из подключённых маркетплейсов в SelSup (быстрый и обычный
   импорт) — где поддерживается API.
6. **Создание и редактирование карточек** в SelSup с публикацией на маркетплейс (через
   интерфейс, массово через Excel, через PIM-систему).
7. **Синхронизация остатков** (двусторонняя или однонаправленная — из SelSup на площадку),
   автоучёт по FIFO, контроль сроков хранения.
8. **Передача и управление ценами** (минимальная цена, защита от ухода в минус, массовая
   передача цен между площадками через Excel, расчёт юнит-экономики).
9. **Импорт и обработка заказов** по схемам FBS, FBO (FBY), DBS/realFBS, Express (Яндекс GO).
10. **Сборка заказов** в модуле «Умный склад»: печать этикеток, маршрутизация, видеофиксация,
    адресное хранение, работа без ТСД (через смартфон).
11. **Маркировка «Честный ЗНАК»**: генерация кодов, печать этикеток с ШК и КИЗ, передача
    кодов при сборке, формирование и отправка УПД ДОП через ЭДО.
12. **Логистические интеграции** (СДЭК, Почта России) для схемы DBS/realFBS: автоматическое
    формирование накладных, получение трек-номеров, передача документов на маркетплейс.
13. **YML-фид** для площадок, работающих через фид (Avito, МегаМаркет, Яндекс.Маркет) —
    генерация ссылки на фид, выгрузка каталога, цен, остатков.
14. **Связь товаров SelSup с товарами площадки** (по артикулу, Avito ID, МегаМаркет-артикулу
    и т. п.) — для корректного сопоставления при обмене остатками и заказами.
15. **Сопоставление статусов заказов** между площадкой и SelSup (например, для WooCommerce,
    Lamoda, МегаМаркета).
16. **Удаление интеграции и организации** (управление жизненным циклом подключения).
17. **Пробные периоды** для платных интеграций (7 дней бесплатно) и помесячная оплата.

### Возможности по конкретным площадкам (выборка ключевых отличий)

- **Wildberries**: API-токен с ограниченным сроком действия; полный импорт карточек
  (быстрый/обычный), создание/редактирование, FBO+FBS, автоакции, минимальная цена,
  маркировка, возврат цен после автоакций.
- **Ozon**: Client ID + ключ API (тип токена «Admin»); дополнительно Ozon Performance
  (client_id/client_secret) для потоварной аналитики расходов на рекламу.
- **Яндекс.Маркет**: 1 схема работы = 1 организация (FBS, FBO/FBY, DBS/Express — отдельные
  магазины); campaign_id + business_id; FBO-остатки по API не передаются — загружаются
  файлом вручную; Express (Яндекс GO) — отдельные тумблеры.
- **Avito**: оплачивается отдельно, 7 дней бесплатно; нужен подтверждённый ИНН и кабинет
  Avito Pro; остатки передаются по API по Avito ID (YML для остатков не используется);
  подтверждение заказов и маркировка в типовой версии не реализованы; печать этикеток
  недоступна (ограничение API Avito).
- **AliExpress**: токен API из раздела «Токены API»; нужен шаблон доставки в ЛК; разработка
  API больше не поддерживается (риск ошибок при изменениях на стороне маркетплейса).
- **Amazon**: экспериментальный режим; подключение через Solution Provider Portal (SP-API,
  тип Sandbox, LWA Client ID и Client Secret); импорт товаров/заказов, обновление остатков.
- **МегаМаркет (СберМегаМаркет)**: FBS и FBO (отдельные организации); авторизационный токен
  + методы создания отправления и отмены лотов; карточки создаются через YML-фид; импорт
  по кнопке невозможен; нет API аналитики (отчёты загружаются вручную); «Закажи и забери» —
  в разработке.
- **Магнит Маркет**: Seller API, ключ с полным доступом; импорт карточек, FBS, остатки;
  создание карточек из SelSup не реализовано.
- **Лемана ПРО (Леруа Мерлен)**: логин/пароль ЛК + x-api-key (через поддержку Лемана) +
  логин/пароль для остатков; переключение обновления остатков с Excel на API (через
  поддержку); остатки и цены — из SelSup на площадку (обратное получение цен не
  поддерживается); этикетки и Акт приёма-передачи не выгружаются; статус отмены не
  синхронизируется; трек-номер по DBS не передаётся.
- **Детский мир**: Client ID + API-ключ (Профиль → API); связь товаров, FBS, остатки,
  импорт заказов; подключение — через поддержку SelSup.
- **М.Видео**: импорт товаров не поддерживается, связь вручную через Excel (столбец
  «Артикль М.Видео»); FBS, остатки; подключение — через поддержку.
- **Uzum**: связь товаров через импорт; FBS, остатки, импорт заказов; подключение — через
  поддержку.
- **Lamoda**: Client ID + Client Secret (через менеджера); карточки не импортируются и не
  создаются (ограничение API) — только связь; FBS, DBS; статусы заказов по внутренней
  логике сопоставления.
- **SimaLand**: ключ API; карточки не импортируются/не создаются — только связь;
  дропшиппинг (через поддержку) для остатков и закупочных цен; FBS, DBS.
- **Takealot**: API-ключ (Seller API); импорт товаров и заказов, передача остатков; НЕ
  поддерживаются: редактирование карточек с передачей, передача цен, обмен статусами из
  SelSup в Takealot (статусы подтягиваются только при импорте).
- **inSales**: Идентификатор + Пароль + URL магазина (из «Разработчикам»); тариф inSales
  должен поддерживать API; интеграция только с одним магазином; API не позволяет
  редактировать карточки напрямую; цена передаётся из поля «Цена со скидкой» вместе с
  остатками (требуется настроенная интеграция с Ozon); для FBS нужен мультисклад inSales.
- **Webasyst**: URL сайта, OAuth-подтверждение («Разрешить»); карточки не
  импортируются/не создаются — только связь; FBS, DBS.
- **WooCommerce**: домен магазина + Consumer key + Consumer secret (права «Чтение/Запись»);
  импорт карточек возможен, создание из SelSup — нет; передача остатков только из SelSup в
  магазин (напрямую в карточку, без склада); сопоставление статусов заказов; для импорта
  заказов и синхронизации должны быть включены ОБА тумблера («Синхронизировать остатки» и
  «Автоматический импорт заказов FBS»).
- **OpenCart**: платное расширение REST Admin API; адрес сайта + ключ API; связь товаров,
  FBS, передача остатков.
- **Tilda**: синхронизация через CommerceML (ссылка на коннектор, имя пользователя, пароль);
  ID цены = 1, ID цены со скидкой = 2; выгрузка каталога, цен и остатков (два тумблера
  работают вместе); фото не передаются (ограничение API); импорт заказов.
- **СДЭК**: идентификатор + пароль из ЛК СДЭК; телефон отправителя, склад отгрузки, регион,
  приоритет, отправка нулевой объявленной стоимости, доп. услуги; создание заказов на
  доставку (DBS).
- **Почта России**: логин/пароль ЛК + токен авторизации; телефон отправителя, пункты
  отгрузки, пункт доставки (индекс), приоритет, доп. услуги (SMS, проверка комплектности,
  «Осторожно/Хрупко»); оплачивается отдельно (1500 руб/мес), 7 дней бесплатно.

## Ключевые сценарии (workflows)

### WF-1. Подключение новой интеграции (типовой сценарий)

1. Открыть `Настройки → Интеграции`, выбрать нужный сервис, нажать «Настроить» (для
   платных — сначала «Попробовать N дней бесплатно»).
2. Включить тумблер «Работать с маркетплейсом/сервисом».
3. Выбрать организацию (если их несколько).
4. Получить учётные данные в личном кабинете сервиса по инструкции справа (API-токен /
   Client ID + Client Secret / логин+пароль / ссылка на коннектор и т. п.).
   - ВАЖНО: копировать ключи только кнопкой копирования, не выделением.
5. Вставить данные в соответствующие поля в SelSup, заполнить доп. параметры (телефон,
   склад, регион, приоритет, ID цен и т. д.).
6. Нажать «Сохранить» / «Подключить». Убедиться, что статус сменился на «Уже настроено».
7. (Для фид-площадок) Скопировать ссылку YML-фида и вставить в ЛК маркетплейса
   (Автозагрузка / Ассортимент), настроить расписание или ручную загрузку.

### WF-2. Импорт карточек из маркетплейса (пример — Wildberries)

1. После подключения интеграции открыть `Товары → Импорт товаров → Wildberries`.
2. Выбрать производителя (для печати этикеток с указанием производителя).
3. Настроить параметры импорта.
4. Выбрать режим: **быстрый импорт** (только новые товары, без обновления существующих)
   или **обычный импорт** (полные данные по карточкам).
5. Запустить импорт.

### WF-3. Создание карточки и публикация на маркетплейс (через API)

1. Сопоставить категории: `Товары → Категории`, указать категорию нужного маркетплейса.
2. Создать/открыть товар в `Товары`.
3. Включить тумблер нужного маркетплейса, заполнить параметры (название, бренд, артикул,
   цены со/без скидки, размеры, вес, описание). Избегать запрещённых символов
   `!@#$%^&*"№;%:?*+`.
4. Сохранить — карточка отправится на маркетплейс (или попадёт в YML-фид).

### WF-4. Массовое создание/редактирование через Excel

1. `Товары → Импорт товаров → Массовое редактирование` → «Скачать Excel».
2. В выгруженном файле заполнить параметры (красные столбцы — обязательные; салатовые
   ячейки — доступны для импорта цен).
3. Загрузить файл обратно (выбором или перетаскиванием), выбрать действие
   «Отправить карточки в …».
4. Также доступны правила заполнения параметра в зависимости от другого (например, цвет
   Wildberries → цвет Avito).

### WF-5. Работа по FBS (единый сценарий для большинства площадок)

1. Удостовериться, что товары SelSup связаны с товарами маркетплейса.
2. Создать склад в SelSup, перенести остатки (`Склад → Склады`, блок «Связи со складами
   маркетплейсов»).
   - Перед переносом проверить отсутствие заказов в статусе «Новый» (чтобы избежать
     повторного резервирования).
3. Настроить автозагрузку/импорт FBS-заказов (включить «Автоматический импорт заказов
   FBS» в настройках организации; фоновой задачей ~раз в 2 минуты).
4. Собирать заказы в модуле «Умный склад» (`Заказы на отгрузку → Со своего склада (FBS)`),
   печатать этикетки, при необходимости видеофиксацию.
5. Передать коды маркировки (для маркированных товаров) при сборке через ТСД/Задания.

### WF-6. Работа по FBO (пример — Яндекс.Маркет)

1. В интеграции включить тумблер «Магазин FBO», ввести ID кабинета и номер кампании,
   нажать «Подключить магазин».
2. (Важно) По API остатки FBO не передаются — выгрузить их вручную из ЛК Яндекс.Маркета
   (`Логистика → Остатки на складах → Сформировать`, убедиться, что выбран FBO).
3. В SelSup: `Аналитика и финансы → Отчёты → Товарный остаток → Загрузка остатков FBO
   файлом`, загрузить файл.

### WF-7. Работа по DBS/realFBS (через СДЭК или Почту России)

1. Включить работу с DBS: `Заказы на отгрузку → Со своего склада → Настройки` (синяя
   шестерёнка), активировать «Работать с заказами DBS».
2. Фильтр «Показать FBS и DBS заказы» / «Показать DBS заказы».
3. Найти заказ DBS (в столбце «Покупатель» — имя/фамилия), перевести в «На сборке» —
   появится телефон покупателя, отправится запрос на накладную.
4. Собрать заказ, перевести в «Собран» — заказ создаётся в службе доставки, в столбце
   «Доставка» появляется значок скачивания накладной.
5. Трек-номер автоматически отправляется на маркетплейс (для Лемана ПРО по DBS трек-номер
   НЕ передаётся).
6. Отгрузить заказ.

### WF-8. Передача остатков на Avito (особый сценарий)

1. В настройках связи склада указать: `Avito → организация → ID склада Avito`.
   - Если складов несколько — указать ОДИНАКОВЫЙ ID склада Avito для всех, чтобы остатки
     корректно суммировались.
2. Остатки обновляются по API по Avito ID (YML для остатков не используется).
3. Автообновление: при изменении остатка по товару (заказ/документы) и при nightly-запуске
   «Импорт с обновлением остатков» (можно запустить вручную).

### WF-9. Синхронизация остатков с WooCommerce

1. Включить в `Настройки → Мои организации` ОБА тумблера: «Синхронизировать остатки» и
   «Автоматический импорт заказов FBS».
2. Передача остатков из SelSup → WooCommerce одним из способов:
   - `Склад → Остатки на складе`: включить «Обновлять на маркетплейсе», указать остаток,
     нажать синюю галочку;
   - через карточку товара → вкладка «Остатки»;
   - через «Импорт с обновлением остатков».
3. Напрямую импортировать остатки из WooCommerce в SelSup нельзя.

### WF-10. Маркировка и УПД ДОП для Wildberries

1. Получить УКЭП (в налоговой), выбрать оператора ЭДО, установить КриптоПро CSP +
   браузер-плагин КриптоПро ЭЦП.
2. Включить интеграцию с «Честным ЗНАКом».
3. В ЛК Wildberries (`Поставки`) открыть поставку → «Скачать документы → Акт приёмки»
   (zip-файл).
4. В SelSup `Заказы на отгрузку → На склад маркетплейса` → «Создать из файла», выбрать
   акт приёмки.
5. Открыть созданный заказ → кнопка «УПД»:
   - «Отправить УПД с маркировкой» — авт. отправка в ЭДО (через Контур.Диадок недоступно);
   - «УПД с маркировкой» — скачать файл, загрузить вручную в ЭДО оператора.
6. При ошибке «неправильно обрезается код маркировки»: `Маркировка → Коды маркировки` →
   «Обновить все» (запрос товарной группы из Честного ЗНАКА).
7. Загрузить УПД в ЭДО оператора (Диадок / ЭДО Лайт / СБИС). Для ЭДО Лайт указать ID
   абонента ЭДО в `Мои организации`.

### WF-11. Обработка ошибок интеграции

1. При уведомлении о невалидном токене — нажать «Перейти к настройкам», перевыпустить
   токен в ЛК сервиса, вставить новый.
2. Для токенов выбирать правильный тип (WB — все типы ключа; Ozon — «Admin»;
   Яндекс — права «Полное управление кабинетом», аккаунт «Владелец»).
3. Не копировать ключи выделением — только кнопкой копирования.
4. См. раздел «Бизнес-правила и ограничения» и статьи об ошибках.

## Сущности (entities)

### 1. Integration (Подключение интеграции)
- **service** — тип сервиса (Wildberries, Ozon, Яндекс.Маркет, …).
- **organization** — организация SelSup, к которой привязано подключение.
- **status** — `не настроено` / `уже настроено` / `частично настроено`.
- **credentials** — набор учётных данных (зависит от сервиса): API-токен / Client ID +
  Client Secret / логин + пароль / ссылка на коннектор + имя + пароль / домен + consumer
  key + secret и т. п.
- **scheme** — схема работы (FBS / FBO / FBY / DBS / realFBS / Express) — для сервисов с
  несколькими схемами.
- **payment** — бесплатная / платная (помесячно, напр. 1500 руб/мес) / индивидуальная
  разработка.
- **trial** — пробный период (7 дней).

### 2. Organization (Организация)
- идентификатор бизнеса (ИНН/название);
- список интеграций;
- настройки-тумблеры: «Синхронизировать остатки», «Автоматический импорт заказов FBS»;
- ID в ЭДО (для УПД);
- лимит количества организаций (важен для МегаМаркета, где 1 схема = 1 организация).

### 3. Warehouse (Склад) и связи складов
- склад SelSup;
- **connections** (Связи со складами маркетплейсов): `Маркетплейс → организация →
  ID склада маркетплейса` (для Avito, МегаМаркета, WooCommerce и др.);
- режимы работы (FBS/FBO), адресное хранение (ячейки).

### 4. Product (Товар/Карточка) и связи
- карточка SelSup;
- **links** — связи с товарами конкретных маркетплейсов (артикул WB, Avito ID, артикул
  МегаМаркета, «Артикль М.Видео», артикул ЛеманаПРО, Карточка ЛеманаПРО и т. д.);
- тумблеры включения на каждом маркетплейсе;
- параметры по каждому маркетплейсу (категория, цена со/без скидки, минимальная цена,
  характеристики, правила заполнения параметров).

### 5. Price (Цена)
- цена со скидкой / без скидки (на каждом маркетплейсе);
- минимальная цена (порог защиты);
- рекомендованная цена (из юнит-экономики);
- «Новая желаемая в Avito» (и аналогичные столбцы для других площадок в Excel).

### 6. Stock / Остаток
- количество на складе SelSup;
- тумблер «Обновлять на маркетплейсе»;
- режим автоучёта (FIFO), контроль сроков хранения.

### 7. Order (Заказ)
- источник (маркетплейс/сервис), схема (FBS/FBO/DBS/Express);
- статус в SelSup и связь со статусом маркетплейса (mapping);
- покупатель (для DBS — имя/фамилия/телефон), трек-номер, накладная.

### 8. YML-фид
- ссылка на фид (Avito, МегаМаркет, Яндекс.Маркет);
- состав: каталог, цены, остатки (зависит от площадки);
- отчёт об автозагрузке / история загрузок с ошибками.

### 9. Category Mapping (Сопоставление категорий)
- категория SelSup ↔ категория маркетплейса (WB, Ozon, Яндекс, AliExpress, Avito и т. д.).

### 10. Status Mapping (Сопоставление статусов заказов)
- статус магазина (WooCommerce/Lamoda/МегаМаркет) ↔ статус SelSup.

### 11. Marking Code (Код маркировки / КИЗ)
- код, товарная группа, статус, привязка к заказу/поставке, крипто-хвост.

### 12. Document (УПД ДОП)
- файл УПД (.xml), оператор ЭДО, коды маркировки в документе.

### 13. Notification (Уведомление о токене)
- организация, сервис, признак невалидности, действие «Перейти к настройкам».

## Настройки (settings)

### На уровне организации (`Настройки → Мои организации`)
- **Синхронизировать остатки** — отвечает за передачу остатков на подключённые сервисы
  (обязательна для WooCommerce и др.).
- **Автоматический импорт заказов FBS** — фоновая загрузка заказов (~раз в 2 минуты);
  обязательна для WooCommerce (вместе с «Синхронизировать остатки»).
- **ID в ЭДО** — идентификатор абонента ЭДО (для УПД ДОП через ЭДО Лайт).

### На уровне интеграции (по сервису)
- Тумблер «Работать с маркетплейсом/сервисом».
- Выбор организации.
- Поля учётных данных (см. таблицы выше).
- Для схемных площадок — тумблеры схемы: «Магазин FBO», «Магазин Express», «Работать с
  заказами Express», «Автоматически принимать заказы Express и переводить в доставку».
- Для Tilda: тумблеры «Выгружать каталог товаров», «Выгружать цены и остатки» (вместе);
  ID цены (1), ID цены со скидкой (2); настройка объединения по моделям; настройка
  названия конкретного товара vs модели.
- Для Avito: тумблер «Avito Доставка».
- Для СДЭК/Почты России: телефон отправителя, склад/пункт отгрузки, регион, индекс
  доставки (Почта), приоритет, отправка нулевой объявленной стоимости, доп. услуги.
- Для WooCommerce: сопоставление статусов заказов.
- Для WB: тумблер «Базовая цена» (синхронизация с аналогичной настройкой Яндекс.Маркета).

### На уровне склада
- **Связи со складами маркетплейсов**: `Маркетплейс → организация → ID склада маркетплейса`
  (Avito, МегаМаркет, WooCommerce, Takealot и др.).

### На уровне заказов (`Заказы на отгрузку → Настройки`)
- **Работать с заказами DBS**.
- Фильтр отображения (FBS и DBS / только DBS).

### На уровне импорта
- **Перезаписать данные из файла** (в `Заказы на отгрузку → На склад маркетплейса`) — для
  переноса кода маркировки из старого заказа в новый при повторном импорте акта.

## Бизнес-правила и ограничения

### Общие правила
- **1 схема работы = 1 организация** для мульти-схемных площадок (Яндекс.Маркет: FBS/FBO/
  Express; МегаМаркет: FBS/FBO). Проверять лимиты по количеству организаций.
- **Ключи API копировать только кнопкой копирования**, никогда выделением (WB, Ozon и др.).
- **Типы токенов**: WB — выбирать все типы ключа; Ozon — тип «Admin»; Яндекс — права
  «Полное управление кабинетом», аккаунт «Владелец» (не «Администратор», иначе ошибка).
- **Срок действия токенов** ограничен (особенно WB) — регулярно обновлять.
- **Привязка ключа к аккаунту**: один магазин — один аккаунт; подключение того же магазина
  на другом аккаунте блокируется; перенос между аккаунтами — только при оплате подписки;
  удаление ключа из кабинета не освобождает его для других аккаунтов.
- Возможности интеграции определяются **API самого сервиса** — где API не даёт функцию,
  SelSup её не предоставляет.

### Ограничения по площадкам (важные)
- **Avito**: подтверждение заказов и передача маркировки не реализованы в типовой версии;
  печать этикеток невозможна (API); остатки только по Avito ID, не по YML; для нескольких
  складов — обязательный одинаковый ID склада Avito (иначе остатки могут обнуляться).
- **Lamoda / SimaLand / Webasyst**: карточки не импортируются и не создаются из SelSup —
  только связь товаров.
- **МегаМаркет**: импорт карточек по кнопке невозможен; нет API аналитики (отчёты
  вручную); карточки создаются только через YML-фид; нельзя указывать ссылку на YML в ЛК,
  если товары уже в продаже по FBS (могут уйти из продажи).
- **Лемана ПРО**: переключение обновления остатков с Excel на API — через поддержку;
  этикетки/Акт приёма-передачи не выгружаются; статус отмены не синхронизируется;
  получение текущих цен в SelSup не поддерживается; трек-номер DBS не передаётся.
- **WooCommerce**: остатки только из SelSup в магазин; для импорта заказов и синхронизации
  нужны ОБА тумблера организации.
- **inSales**: тариф должен поддерживать API; 1 магазин; редактирование карточек через API
  недоступно; цена передаётся только вместе с остатками и только при настроенной
  интеграции с Ozon; без мультисклада inSales остатки не синхронизируются.
- **Tilda**: фото не передаются (API); каталог и цены+остатки выгружаются только вместе.
- **Takealot**: нет редактирования карточек с передачей, передачи цен, обмена статусами
  из SelSup в Takealot.
- **М.Видео**: импорт товаров не поддерживается — связь вручную через Excel.
- **Amazon**: экспериментальный режим, доступность зависит от настроек аккаунта.
- **AliExpress**: разработка API больше не поддерживается — риск ошибок при изменениях.
- **Яндекс.Маркет FBO**: остатки по API не передаются — загрузка файлом вручную.
- **Контур.Диадок**: отправка УПД с маркировкой из SelSup недоступна (ограничение Диадока)
  — скачивать файл и грузить вручную.
- **ЭДО Лайт**: название файла накладной нельзя менять (проверяется соответствие названия
  и содержимого); файлы с добавленной цифрой (1) в имени не загружаются.

### Ценообразование и защита
- **Минимальная цена**: SelSup не допускает продажу ниже заданного порога.
- **Возврат цен после автоакций** (WB, Ozon), чтобы товар не остался с убыточной ценой.
- **Расчёт юнит-экономики**: закупочная цена, налоги, расходы, прибыль → рекомендованная цена.
- Запрещённые символы в параметрах карточки: `!@#$%^&*"№;%:?*+` (приводят к ошибкам).

### Маркировка и УПД ДОП
- Для маркировки нужна **УКЭП** (усиленная квалифицированная), обычная не подойдёт.
- Код маркировки с крипто-хвостом передаётся в Яндекс.Маркет только сканированием через
  «Задания → Сборка заказов».
- Коды, внесённые сканированием, не имеют товарной группы — нужно «Обновить все» перед
  формированием УПД, иначе код обрезается неверно.
- При повторном импорте акта приёмки код маркировки автоматически не переносится из
  старого заказа в новый (защита от дублей) — нужен тумблер «Перезаписать данные из файла».
- Отсутствие УПД ДОП → штраф 1 руб. за каждый товар (WB).

### Типовые ошибки и решения
- «Не настроена интеграция / ключ недействителен» → перевыпустить токен, проверить тип
  ключа, копировать кнопкой.
- «Что-то сломалось, уже чиним» → перезагрузить страницу/повторить позже (временная).
- Ошибка API СУЗ «Экземпляр интеграционного решения SelSup уже зарегистрирован» → удалить
  старое подключение в «Станции управления заказами» Честного ЗНАКа или скопировать
  существующий идентификатор соединения для новой организации.
- «Вставьте ключевой носитель» / «отсутствует сертификат» → проверить установку/настройку
  КриптоПро CSP и браузер-плагина, наличие сертификата.
- «В УПД указаны КИЗы, отсутствующие в акте приёмки» → обновить статусы кодов
  маркировки, переформировать УПД, загрузить в ЭДО.
- Ошибка доступа Яндекс «аккаунт должен быть Владелец или Администратор» → авторизоваться
  под владельцем; проверить ID кабинета и номер кампании.
- Для FBY магазина Яндекс: авторизационный токен не нужен, интеграция настраивается
  вручную (указать ID кабинета и номер компании).

## Открытые вопросы / чего не хватает в доках

1. **Точные форматы API и контракты** — в статьях описаны только поля учётных данных и
   шаги настройки; нет схем API-запросов, эндпоинтов, форматов YML, форматов Excel-файлов
   массового редактирования, формата акта приёмки WB и УПД ДОП (.xml). Для воссоздания
   потребуется реверс-инжиниринг или доступ к реальным файлам.
2. **Детальный mapping статусов заказов** — упоминается для Lamoda/WooCommerce/МегаМаркета,
   но полная таблица соответствия статусов каждой площадки статусам SelSup не приведена
   (ссылка на отдельную статью, которой нет в корпусе).
3. **Расписание и гарантии синхронизации** — указано «примерно раз в 2 минуты» для
   WooCommerce и ночной импорт остатков для Avito, но полного расписания фоновых задач и
   приоритетов обновления остатков/заказов по всем площадкам нет.
4. **Поведение при частичных сбоях и повторах** — не описаны идемпотентность импорта
   заказов, разрешение конфликтов при одновременном изменении остатков, retry-политики,
   очереди (кроме «синхронной модели» для Яндекс.Маркета, от которой намеренно отказались).
5. **Лимиты и тарифы** — упомянуты: «Почта России — 1500 руб/мес», «Avito — доп. оплата,
   7 дней бесплатно», «фулфилмент — от тарифа Бизнес», «индивидуальная разработка —
   отдельная стоимость», «лимиты по количеству организаций». Конкретная сетка тарифов и
   лимитов по организациям/интеграциям не приведена.
6. **Управление несколькими складами Avito** — правило «одинаковый ID склада Avito»
   описано, но нет деталей, как именно SelSup суммирует остатки и что считается
   «произвольным ID склада».
7. **Дропшиппинг SimaLand** — заявлено «обратитесь в поддержку для подключения
   дропшиппинга» для остатков и закупочных цен; технических деталей схемы нет.
8. **«Закажи и забери» МегаМаркет** — «в разработке»; текущий статус и дата неизвестны.
9. **Amazon (экспериментальный режим), М.Видео, Uzum, Детский мир** — подключаются через
   поддержку; нет публичной документации по их API и ограничениям.
10. **Аналитика по площадкам без API** (МегаМаркет, Avito) — описана ручная загрузка
    отчётов, но форматы файлов и правила сверки (кроме ссылки на статью сверки МегаМаркета)
    не детализированы.
11. **Безопасность токенов и аудит** — не описано хранение токенов, ротация, журналирование
    действий по интеграциям, RBAC на уровне интеграций.
12. **Версионирование API маркетплейсов** — для AliExpress прямо сказано, что разработка
    не поддерживается; для остальных нет политики поддержки версий API и миграции.
13. **Глубина PIM-связок и правил параметров** — упомянуты «правила заполнения параметра
    в зависимости от другого» (WB→Avito цвет), но механизма конструктора правил в корпусе
    нет.
14. **FBO-сценарии и ШК коробов** (фулфилмент) — описано кратко (ускорение в 8 раз,
    сканирование ШК короба и товаров), но детального workflow формирования поставок FBO и
    работы с коробами Ozon/WB нет (вынесено в модули «Умный склад»/«FBO-поставки», которых
    нет в данном корпусе).
