# Поддержка, отладка и служебные статьи

## Назначение

Вспомогательный раздел базы знаний SelSup, покрывающий оставшиеся (не относящиеся к продуктовым модулям) статьи: регламент работы технической поддержки, отладочные процедуры (HAR-файлы) и служебные страницы (404 «страница не найдена», «в разработке», а также удалённые/устаревшие дубликаты статей по карточкам Ozon, Честному Знаку, FBS, сборке заказов и др.).

Фактическое наполнение по прочитанным 12 статьям:
- **2 содержательные статьи** — регламент техподдержки и инструкция по сбору HAR-файлов;
- **1 заглушка** «В разработке» (раздел готовится к выпуску);
- **9 страниц 404 «Упс! Данная страница не найдена»** — это удалённые из публичной базы знаний статьи, ранее дублировавшие контент модулей (массовая работа с карточками Ozon, настройка Честного Знака, ошибки карточек Ozon, преимущества FBS, сборка заказов, удаление товаров из автоакций Wildberries, выгрузка остатков FBO файлом, задания для операторов, финансы).

Для продакт-менеджера: раздел задаёт SLA поддержки и диагностический процесс, а сами продуктовые сценарии удалённых страниц восстанавливаются из соответствующих модулей (карточки/цены/склад/заказы/маркировка/аналитика), а не отсюда.

## Возможности (capabilities)

### Техническая поддержка
- **Стандартная поддержка на всех тарифах** — входит в стоимость любого тарифного плана, покрывает консультации по штатному функционалу.
- **Консультирование по работе платформы** — разъяснения по функционалу, тарифам, типовым настройкам аккаунта.
- **Диагностика сбоев и ошибок** — помощь в выявлении причин некорректной работы в рамках функционала SelSup.
- **Консультации по интеграциям SelSup** — поддержка собственных интеграций платформы.
- **Маршрутизация и приоритизация обращений** — автоматические и организационные механизмы учёта, классификации и контроля заявок.
- **Каналы обращения** — виджет «Техподдержка» в правом нижнем углу каждой страницы сервиса; Telegram-бот поддержки (@SelSupBot).
- **Обработка запросов на доработку** — отдельный процесс: подтверждение получения, уточнение требований, оценка целесообразности/стоимости/сроков, возможный отказ без объяснения технических деталей.

### Отладка
- **Сбор HAR-файлов** — запись сетевых запросов браузера через Консоль разработчика (DevTools) для диагностики проблем на стороне клиента.
- **Сбор сопутствующих диагностических материалов** — загружаемые файлы/изображения, видеозапись действий пользователя, фиксация ошибочных запросов (красные строки в Network).

### Служебные страницы
- **Страница 404** — «Упс! Данная страница не найдена» со ссылкой на главную `https://selsup.ru/`.
- **Заглушка «В разработке»** — уведомление, что раздел готовится к выпуску.

## Ключевые сценарии (workflows)

### WF-1. Подача обращения в техподдержку (через сайт)
1. Пользователь нажимает кнопку «Техподдержка» в правом нижнем углу любой страницы.
2. В открывшемся окне описывает вопрос/проблему.
3. Если не авторизован — вводит имя и e-mail, нажимает «Отправить».
4. SelSup регистрирует обращение, классифицирует тип и приоритет.
5. В пределах целевого срока ответа заявка принимается к рассмотрению / запрашиваются недостающие сведения.

### WF-2. Подача обращения через Telegram
1. В SelSup: «Настройки → Telegram-боты» → нажать ссылку «Техподдержка», либо перейти напрямую на `https://t.me/SelSupBot`.
2. В Telegram нажать «Start Bot» / «Запустить».
3. Ввести e-mail и текст вопроса.
4. Общение продолжается в Telegram; сообщение конфиденциально.

### WF-3. Оформление качественного обращения
1. Перед подачей проверить базу знаний (`/help/index.html`).
2. Указать: логин в системе; краткое описание; действия перед возникновением проблемы; ссылку на страницу/карточку/документ/заказ; текст ошибки или скриншот; ожидаемый результат; при необходимости файл отчёта.
3. Одно обращение = один вопрос (несколько несвязанных вопросов могут быть разделены).
4. Не дублировать заявку после подтверждения получения.

### WF-4. Сбор HAR-файла для отладки
1. Поддержка просит клиента открыть Консоль разработчика (DevTools, F12).
2. Проверить вкладку Network — убедиться, что фиксируются все запросы.
3. **Обновить страницу** при открытой панели, чтобы записались все запросы.
4. Дождаться окончания всех запросов (не сохранять сразу).
5. Произвести целевые действия на странице.
6. При ошибках зафиксировать красные (ошибочные) запросы в Network.
7. Скачать HAR-файл; большой файл залить на Яндекс.Диск и прислать ссылку.
8. Дополнительно приложить загружаемые файлы/изображения и видеозапись действий.

### WF-5. Обработка обращения по срокам (по приоритету)
- **Критичный** — ответ до 30 минут, первичная обработка до 4 рабочих часов.
- **Существенный** — ответ до 1 рабочего часа, обработка до 8 рабочих часов.
- **Средний** — ответ до 4 рабочих часов, обработка до 1 рабочего дня.
- **Незначительный** — ответ до 4 рабочих часов, обработка до 2 рабочих дней.
Сроки считаются только в рабочее время (МСК): будни 05:00–00:00, суббота 09:00–21:00, воскресенье и праздники 09:00–18:00.

### WF-6. Приостановление и закрытие обращения
- Приостановка: клиент не дал данные / проблему нельзя воспроизвести / в обращении несколько несвязанных проблем / нужна доработка / вопрос вне поддержки или стороннего сервиса / оформление неполное.
- Закрытие: дан ответ/статус/рекомендация; проблема не подтвердилась; перевод в доработку/услугу/внедрение; клиент не дал данные; клиент не ответил в течение 1 рабочего дня.

## Сущности (entities)

- **Обращение (тикет)**: атрибуты — тип (Инцидент / Консультация / Запрос на настройку / Запрос на доработку), приоритет (Критичный / Существенный / Средний / Незначительный), логин пользователя, описание, ссылка на объект, текст/скриншот ошибки, ожидаемый результат, вложения, статус (зарегистрировано / в работе / приостановлено / закрыто), временна́я метка поступления.
- **HAR-файл**: HTTP Archive — запись сетевых запросов браузера; сопровождается видео и исходными файлами.
- **Каналы поддержки**: сайт-виджет (имя, e-mail, текст), Telegram-бот (привязка по e-mail).
- **Рабочее расписание поддержки**: будни 05:00–00:00, суббота 09:00–21:00, воскресенье/праздники 09:00–18:00 (МСК).

## Интеграции

- **Telegram** — бот @SelSupBot как канал обращения; ссылка доступна в разделе «Настройки → Telegram-боты». Конфиденциальное общение, идентификация по e-mail.
- **Яндекс.Диск** — внешний канал передачи больших HAR-файлов и диагностических материалов по ссылке.
- **Браузерная DevTools (Консоль разработчика)** — инструмент сбора HAR и фиксации сетевых ошибок (не серверная интеграция, а клиентская процедура).

## Настройки (settings)

- Раздел «Настройки → Telegram-боты» содержит ссылку «Техподдержка» для перехода в бот.
- Регистрация неавторизованного пользователя в виджете — по имени и e-mail.

## Бизнес-правила и ограничения

- Стандартная поддержка действует только в пределах штатного функционала SelSup.
- **Не входит в стандартную поддержку**: разработка нового функционала; изменение логики по индивидуальному запросу; внедрение/кастомизация; массовая ручная обработка данных; индивидуальные отчёты; юр./налоговые/бухгалтерские консультации; работы, зависящие от сторонних сервисов/маркетплейсов/внешних API; доработки, требующие отдельной оценки.
- Окончательная квалификация типа и приоритета обращения — за SelSup, может быть изменена после первичной проверки.
- Целевые сроки — организационные ориентиры, а не гарантия устранения причины.
- Время ожидания данных от клиента не включается в сроки обработки.
- Одно обращение = одна проблема; дублирование не ускоряет обработку.
- Официально зарегистрированными считаются только обращения через сайт-виджет и Telegram-бот.
- Запросы на доработку обрабатываются по отдельному процессу, вне SLA стандартной поддержки; возможен отказ без технических пояснений.
- Закрытие автоматически, если нет ответа клиента 1 рабочий день.
- Конфиденциальность: сообщения поддержки запрещено раскрывать/распространять.
