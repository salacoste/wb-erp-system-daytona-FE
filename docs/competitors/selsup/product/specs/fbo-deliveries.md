# Отгрузки, упаковка и поставки на склады маркетплейсов

## Назначение

Модуль обеспечивает полный цикл поставок товаров на склады маркетплейсов по модели **FBO** (Fulfillment by Operator — товар отгружается на склад маркетплейса) и частично **FBS** (в части упаковки поставок в ПВЗ Wildberries). Модуль позволяет: создавать заказы/поставки на отгрузку по FBO на Wildberries, Ozon и Яндекс.Маркет; резервировать и списывать остатки с физических складов продавца с переносом их на виртуальные склады маркетплейсов; планировать объём поставок на основе продаж и оборачиваемости; упаковывать товары по коробам с генерацией ШК коробов и контролем вложения; формировать файлы для загрузки в личные кабинеты маркетплейсов; работать с маркировкой «Честный знак»; хранить акты приёмки Wildberries и контролировать расхождения при упаковке и после приёмки маркетплейсом.

Важно: маркетплейсы **не передают данные по заказам и этапам отгрузок FBO через API**, поэтому статусы и материалы отгрузок SelSup и личного кабинета маркетплейса **не связаны автоматически** — статус заказа в SelSup меняется вручную. Исключение — Ozon: отгрузку можно создать напрямую из SelSup вплоть до этапа выбора таймслота доставки.

Функционал модуля работает только при условии, что продавец ведёт в SelSup полный товарный учёт: закупки, приёмки и отгрузки на склады маркетплейсов.

## Возможности (capabilities)

1. **Создание заказа на отгрузку по FBO** — формирование заказа-отгрузки на склад маркетплейса с указанием организации, маркетплейса, склада маркетплейса, склада списания остатков. Кнопка «Создать заказ». Для WB доступно поле «Тип» поставки (микс/моно/моно-паллет/суперсейф).

2. **Создание документов из файла** («Создать из файла») — отдельный инструмент: формирует на основе загруженного файла либо **Акт приёмки** (создаёт заказ с названием «Акт №», формат xlsx), либо **Уведомление о выкупе** (формирует УПД по НДС для WB в формате XML, без создания заказа на отгрузку).

3. **Планирование поставок** — расчёт рекомендуемого количества товара к поставке на каждый склад маркетплейса на основе продаж/заказов, остатков, товаров в пути и оборачиваемости. Работает для WB, Ozon, Яндекс.Маркета.

4. **Резервирование остатков под отгрузку FBO** — при сохранении заказа в статусе «Новый» товар автоматически резервируется на складе списания; при переводе в следующие статусы резерв списывается; поддержан возврат резерва через приёмку возврата.

5. **Настройка виртуального склада FBO** — создание склада с флагом «Склад для учёта остатков FBO» для учёта себестоимости по FIFO и контроля остатков на складах маркетплейсов. Учёт остатков FBO по API доступен для WB и Ozon.

6. **Сверка остатков FBO** — инструмент «Сверка остатков FBO»: сравнивает остатки на складе маркетплейса с остатками в SelSup и позволяет массово актуализировать расхождения.

7. **Упаковка FBO** (задание) — упаковка товаров в короба по уже собранному заказу: сканирование ШК короба, сканирование товаров с автопечатью этикеток, контроль вложения, автогенерация файла ШК коробов. Доступно для WB и Ozon.

8. **Упаковка с добавлением в заказ FBO** (задание) — упаковка, при которой товар одновременно добавляется в пустой заказ и распределяется по коробам (без предварительного заполнения заказа). Поиск товара по GTIN из кода маркировки с автоматической привязкой. Доступно для WB и Ozon.

9. **Генерация и печать ШК коробов / QR-коробов** — генерация ленты ШК коробов WB (сразу 100 или 1000 шт.), генерация QR-коробов WB (по ID магазина и номеру последнего короба), создание «предварительных коробов» для Ozon (внутренние QR-коды SelSup с последующей заменой на официальные ШК Ozon через Excel).

10. **Учёт коробов** — раздел «Короба» со справочником всех коробов и журналом: кто, когда и во сколько упаковал каждый короб; поиск короба по ШК.

11. **Кратность коробов (квант короба)** — параметр карточки товара «Количество штук в коробе», используется при планировании поставок для корректного расчёта упаковки.

12. **Упаковка и отгрузка поставок по модели «Маркетплейс» FBS в ПВЗ Wildberries** — формирование отгрузок заказов FBS на пункты выдачи WB: печать ШК короба (префикс WB-TRBX), распределение заказов по коробам в задании «Комплектация заказов» с переключателем «Отгружаться на ПВЗ».

13. **Работа с маркировкой «Честный знак» из отгрузки FBO** — блок получения кодов маркировки и ввода их в оборот прямо из заказа на отгрузку (для категорий с флагом «Товары категории маркируются» и указанным ТНВЭД). Поддержано для WB, Ozon, Яндекс.Маркета.

14. **Хранение актов приёмки Wildberries** — импорт акта приёмки WB (xlsx/zip) в заказ, бессрочное хранение, выгрузка обратно в формате excel. Компенсирует срок хранения актов в WB (3 месяца).

15. **Контроль расхождений при упаковке** — вкладка «Расхождения»: разница между количеством в заказе и фактически упакованным товаром. Доступно для WB и Ozon.

16. **Контроль расхождений при приёмке WB** — импорт акта приёмки WB и сравнение фактически принятых маркетплейсом товаров с упакованными. Доступно только для WB.

17. **Кнопка «Исправить заказ»** — корректировка количества товара в FBO-поставке после комплектации (например, при браке/недостаче) с синхронизацией изменений с маркетплейсом.

18. **Создание отгрузки на Ozon напрямую из SelSup** — вплоть до этапа выбора таймслота доставки (частичная API-интеграция).

19. **Управление статусами заказа на отгрузку** — строка статусов: Новый → Собран → Упакован → Готов к поставке → Отгружен → Закрыт (+ Возврат). Переходы кнопкой «Следующий шаг».

20. **Формирование файла заказа и файла ШК коробов** — выгрузка Excel-файла заказа для загрузки в ЛК маркетплейса и файла ШК коробов с распределением товаров (формат зависит от маркетплейса).

21. **Получение пропуска (для WB)** — фиксация в заказе данных пропуска: количество коробов, данные водителя, автомобиль, тип упаковки (короба/паллеты), штрих-код поставки на А4.

22. **Обработка изменения типа поставки / разделения заказа WB** — если WB изменил тип поставки — откат на шаг назад в SelSup и смена типа; если WB разделил заказ на несколько — выгрузка каждого заказа из WB в Excel и создание отдельных заказов в SelSup.

## Ключевые сценарии (workflows)

### WF-1. Полный цикл отгрузки по FBO (общий, схема)
Создать заказ на отгрузку → добавить товары (планированием, сканером, из списка, файлом) → указать количество → настроить печать этикеток → Сохранить (остатки резервируются) → собрать товар → упаковать по коробам (задание Упаковка) → скачать файл заказа и файл ШК коробов → загрузить файлы в ЛК маркетплейса → создать поставку в ЛК → скопировать внешний номер поставки в SelSup → указать поле «Поставка» (дата + название) → сменить статус на «Готов к поставке» → отгрузить → статус «Отгружен» → статус «Закрыт» после приёмки маркетплейсом.

### WF-2. Создание заказа на отгрузку FBO
1. Раздел «Заказы на отгрузку — На склад маркетплейса» → «Создать заказ».
2. Заполнить поля: Название, Организация, Маркетплейс, Склад маркетплейса, Склад списания остатков. Включить «Списать остатки» при ведении учёта. Для WB выбрать «Тип» поставки.
3. Добавить товары (планирование / штрих-код / кнопка +1 / файл).
4. Указать количество в столбце «Количество».
5. Настроить этикетки (в «Настройки — Этикетки» или в столбце «Печать»).
6. «Сохранить» → остатки переходят в резерв.

### WF-3. Резервирование и списание остатков FBO
1. В заказе указать «Склад списания остатков», включить «Списать остатки» (появляется колонка «Резервы/Списания остатков»).
2. Добавить товары и количество, «Сохранить» → количество уходит в резерв, свободный остаток уменьшается.
3. Перевод в статус «Собран» + «Сохранить» → резерв списывается (либо автоматическое ночное списание для статусов Собран/Упакован/Готов к поставке/Отгружен/Закрыт).
4. После выхода из статуса «Новый» галочку «Списать остатки» отключить нельзя.
5. Резерв нельзя списать вручную без смены статуса; каждый день резервы автоматически обновляются по актуальным заказам.

### WF-4. Возврат остатков (непринятая поставка)
1. Заказ должен быть в статусе «Закрыт» (или закрыть кнопкой «Следующий шаг»).
2. Нажать «Следующий шаг» → статус «Возврат», появляется кнопка «Создать приёмку возврата».
3. Создаётся приёмка с товарами из отгрузки; после сохранения и оприходования товары возвращаются на склад.

### WF-5. Планирование поставок
1. В заказе на отгрузку раскрыть вкладку «Планирование поставок».
2. Указать: период анализа, «На сколько дней планировать остатки», «Рекомендованное количество от» (необязательно), маркетплейс.
3. Настроить точность: «Пропускать дни без остатков», «Делать расчёт по заказам», «Коэффициент коррекции» (на товаре).
4. Выбрать склад или группу складов.
5. Нажать «Рассчитать» → список рекомендованных товаров с количеством.
6. «Добавить» / «Добавить все товары в заказ» → при необходимости скорректировать количество в основном заказе.

### WF-6. Упаковка FBO (по собранному заказу)
1. Предусловие: заказ создан, товар собран, включена настройка контроля количества.
2. Раздел «Задания — Упаковка FBO» → выбрать отгрузку (видны только заказы в статусе «Новый»).
3. Отсканировать ШК короба (определяется по префиксу).
4. При необходимости включить «Автопечать этикеток» и выбрать шаблон.
5. Отсканировать товары заказа (поштучно или с указанием количества); система контролирует соответствие заказу и предупреждает об ошибке.
6. После корректной сборки SelSup автоматически создаёт файл с ШК коробов.
7. Скачать файл ШК коробов из раздела «Заказы на отгрузку».

### WF-7. Упаковка с добавлением в заказ FBO
1. Создать пустой заказ (склад + маркетплейс), сохранить без товаров.
2. Раздел «Задания — Упаковка с добавлением в заказ FBO» → выбрать заказ.
3. Отсканировать ШК короба.
4. Выбрать шаблон этикетки при необходимости.
5. Сканером считывать штрих-код/маркировку товара → товар добавляется в заказ и в указанный короб, формируется файл коробов. При сканировании кода маркировки товар ищется по GTIN, маркировка привязывается автоматически.
6. Статус упаковки виден во вкладке «Упаковка» заказа.

### WF-8. Создание поставки на Wildberries (ручная связка с ЛК)
1. Создать заказ в SelSup, скачать Excel-файл заказа.
2. В ЛК WB «Поставки» → «Создать поставку» → загрузить Excel (проверить количество, сумму, баркоды).
3. Указать склад назначения, тип упаковки (короб/монопаллета), выбрать дату/слот.
4. Сгенерировать и распечатать ШК коробов в WB; скопировать номер поставки WB.
5. Вставить номер в поле «Внешний номер» в SelSup.
6. Заполнить поле «Поставка» (дата + номер заказа WB) → присваивается внутренний номер поставки.
7. Заполнить пропуск (короба, водитель, авто, тип упаковки), распечатать ШК поставки.
8. Дождаться статуса «Приемка разрешена» (~20–30 мин), проверить колонку «Ошибки».
9. Загрузить файл ШК коробов из SelSup во вкладку «Упаковка» поставки WB.
10. Сменить статусы SelSup вручную: Готов к поставке → Отгружен → Закрыт.

### WF-9. Создание поставки на Ozon (частично через API)
1. Создать заказ в SelSup с маркетплейсом Ozon.
2. Нажать «Создать заказ» в заказе → заказ создаётся в Ozon напрямую.
3. В ЛК Ozon (FBO — Заявки на поставку) выбрать тип и способ доставки, таймслот.
4. Получить ШК коробов: вкладка «Грузоместа» → выбрать короба/палеты → «Сгенерировать» → распечатать. Альтернатива — «Добавить предварительные короба» (внутренние коды SelSup) с последующей заменой на ШК Ozon через Excel.
5. Упаковать через задание «Упаковка» с QR-кодами SelSup → запросить точное число ШК коробов Ozon → заменить коды в Excel → переклеить короба.
6. Проверить расхождения, при необходимости «Изменить заказ».
7. Нажать «Создать заказ в Ozon» (только после упаковки — заказ в Ozon создаётся один раз и не редактируется).
8. «Скачать ШК коробов» → в ЛК Ozon «Грузоместа» → «Указать ГМ» → «Состав через XLS» → загрузить файл → заполнить авто → «Сохранить».
9. Сменить статусы SelSup вручную до «Закрыт».

### WF-10. Создание поставки на Яндекс.Маркет
1. Создать заказ в SelSup, скачать файл заказа.
2. ЛК Яндекс.Маркета → «Логистика — Поставки товаров» → «Создать заявку».
3. Выбрать «Склад хранения», загрузить файл заказа из SelSup.
4. Выбрать способ и время поставки → «Сохранить» → «Создать поставку».
5. Скопировать внешний номер поставки → вставить в поле заказа SelSup → «Сохранить».
6. Сменить статусы SelSup вручную до «Закрыт».
Примечание: SelSup не может использовать связи со складами для Яндекс.Маркета — для одной организации должно быть не более 1 склада Яндекс.Маркета.

### WF-11. Отгрузка поставок FBS в ПВЗ Wildberries (модель «Маркетплейс»)
1. Раздел «Задания — Комплектация заказов» → активировать «Отгружаться на ПВЗ».
2. Выбрать поставку → «Новый короб» → печать ШК короба (префикс WB-TRBX).
3. Сканировать заказы WB — они добавляются в короб; при заполнении — «Новый короб»; для дозагрузки существующего короба сканировать его ШК.
4. Выбрать ПВЗ той же зоны, что и склад (иначе штраф 30% от стоимости заказа, мин 100 ₽ / макс 100 000 ₽).
5. Привезти поставку, дождаться сканирования стикеров (статус «Отсортировано»), при необходимости закрыть короб скотчем.
6. Проверить, что заказы перешли во вкладку «Архив».

### WF-12. Контроль расхождений
- **При упаковке:** вкладка «Расхождения» заказа — разница между заказом и фактически упакованным (WB, Ozon).
- **После приёмки (только WB):** скачать «Акт приёмки» в ЛК WB → в SelSup «Импорт акта WB» → вкладка «Расхождения — Расхождения при приемке WB» (показываются только расхождения: что упаковано / сколько упаковано / сколько принято).
- **Кнопка «Исправить заказ»** при расхождении (брак/недостача): обновляет количество и синхронизирует с маркетплейсом; не удаляет товары автоматически (удаление — вручную).

### WF-13. Хранение акта приёмки WB
1. ЛК WB → «Поставки» → «Скачать документы» → «Акт приемки» (zip).
2. SelSup → заказ → «Импорт акта WB» → загрузить файл.
3. В любое время скачать через «Скачать документы — Скачать акт WB» (в формате excel).

## Сущности (entities)

### Заказ на отгрузку FBO (Order)
- Название
- Организация
- Маркетплейс (WB / Ozon / Яндекс.Маркет)
- Склад маркетплейса (грузополучатель)
- Склад списания остатков
- Флаг «Списать остатки»
- Тип поставки (для WB: микс / моно / моно-паллет / суперсейф; QR-короб)
- Позиции товаров (товар, размер/характеристика, количество, количество к печати)
- Статус (Новый / Собран / Упакован / Готов к поставке / Отгружен / Закрыт / Возврат)
- Внешний номер поставки маркетплейса
- Поставка (ссылка на сущность Поставка)
- Резервы/Списания остатков (история)
- ID магазина WB (для QR-коробов)
- Блок «Честный знак» (для маркируемых категорий)

### Поставка (Shipment)
- Внутренний номер поставки SelSup
- Дата поставки
- Название (обычно номер заказа WB)
- Тип поставки
- Объединяет заказы одного типа, отправляемые в один день

### Склад (Warehouse)
- Виртуальный склад FBO: флаг «Склад для учёта остатков FBO», маркетплейс, организация
- Физический склад продавца
- Связи со складами маркетплейсов
- Флаг «Использовать для заказов»
- Приоритет списания остатков

### Остаток (Stock)
- Свободный остаток по складу
- Резерв
- Остатки FBO (по API: WB, Ozon)
- Остатки FBS
- Товары в пути (от клиента на склад)
- Товары, которые уже поставляются

### Короб (Box)
- Уникальный ШК короба (ШК WB, QR-код SelSup, ШК Ozon, префикс WB-TRBX для ПВЗ)
- Тип короба (микс / моно / QR / предварительный / ПВЗ)
- Состав: товары и количество в коробе
- Кто упаковал, когда, во сколько
- Принадлежность к заказу/поставке

### Параметр товара для планирования
- Кратность короба (количество штук в коробе)
- Коэффициент коррекции

### Акт приёмки (WB)
- Файл акта (zip/xlsx)
- Привязка к заказу/поставке
- Данные о принятых маркетплейсом товарах и количестве

### Маркировка «Честный знак»
- Категория с флагом «Товары категории маркируются»
- ТНВЭД
- Коды маркировки (привязка к товару по GTIN)

### Тип поставки WB
- Микс / Моно / Моно-паллет / Суперсейф
- Ограничения по размеру, весу, количеству SKU, категории, складу приёмки

## Интеграции

1. **Wildberries (ЛК + частично API)** — учёт остатков FBO по API (столбец «Остатки FBO», обновление через «Мои организации»); передача файла заказа и файла ШК коробов вручную через ЛК; импорт акта приёмки; QR-поставки по ID магазина; отгрузки FBS в ПВЗ. Материалы и статусы отгрузок FBO по API не передаются.

2. **Ozon (API + ЛК)** — прямое создание отгрузки на склад маркетплейса из SelSup вплоть до выбора таймслота; учёт остатков FBO по API; выгрузка файла ШК коробов / грузомест (XLS) для вкладки «Грузоместа»; работа с предварительными коробами.

3. **Яндекс.Маркет (ЛК)** — выгрузка файла заказа и ручная загрузка в «Логистика — Поставки товаров»; вставка внешнего номера поставки. Связи со складами для Яндекс.Маркета не используются.

4. **Честный знак (Маркировка)** — получение кодов маркировки и ввод их в оборот из заказа на отгрузку FBO (WB, Ozon, Яндекс.Маркет).

5. **ЭДО (косвенно)** — формирование УПД по НДС для WB в формате XML (из «Уведомления о выкупе») для передачи данных по НДС через ЭДО.

6. **ТСД / сканер штрих-кодов** — использование в заданиях «Упаковка FBO», «Упаковка с добавлением в заказ FBO», «Комплектация заказов».

## Настройки (settings)

- **Склады:** флаг «Склад для учёта остатков FBO» (привязка маркетплейс + организация); связи со складами маркетплейсов; флаг «Использовать для заказов»; приоритет списания остатков.
- **Настройки этикеток:** товарная этикетка, количество к печати; печать одновременно 2 этикеток (для товара и для упаковки).
- **Настройки упаковки / поставок:**
  - «Не превышать количество товаров при упаковке» (контроль количества).
  - «Разрешить сканировать только маркировку при упаковке FBO» (запрет сканирования обычного штрихкода).
  - «Проверять коды маркировки».
  - «Автопечать этикеток» и выбор шаблона.
- **Настройки товаров:** флаг «Товары категории маркируются», ТНВЭД, кратность короба (количество штук в коробе), коэффициент коррекции.
- **Настройки → Товары:** кнопка «Обновить остатки в товарах» (принудительное обновление кэша остатков и резервов).
- **Планирование поставок:** период анализа, количество дней планирования, «Рекомендованное количество от», «Пропускать дни без остатков», «Делать расчёт по заказам», выбор склада/группы складов.

## Бизнес-правила и ограничения

### Резервирование и остатки
- Резерв создаётся автоматически при сохранении заказа в статусе «Новый»; резервы нельзя изменять вручную — только система.
- Резерв списывается только при смене статуса заказа или отгрузки; списание также происходит ночью для статусов Собран/Упакован/Готов к поставке/Отгружен/Закрыт.
- После выхода из статуса «Новый» флаг «Списать остатки» отключить нельзя.
- Добавлять новые товары в заказ можно только в статусе «Новый»; изменять количество и удалять позиции — в статусах Новый/Собран/Упакован/Готов к отгрузке.
- Удаление поставки автоматически снимает резерв и возвращает количество в доступный остаток.
- Не удалять и не восстанавливать уже отгруженный заказ для повторной отгрузки — остатки не вернутся в резерв (нужно создавать новый заказ).
- Себестоимость и остатки учитываются по FIFO; продажа со склада маркетплейса списывает товар со склада FBO, возврат — возвращает остаток (приоритет списания у более старого остатка).
- Определение склада для FBS-заказов: по связи со складом маркетплейса + флагу «Использовать для заказов» + приоритету; при отсутствии остатка — поиск по складам со связью даже без флага «Использовать для заказов».

### Короба и типы поставок WB
- Запрещено объединять товары разного типа поставки в одном коробе/паллете.
- На каждом гофрокоробе — один уникальный ШК короба; других штрихкодов быть не должно.
- **Микс-короб:** несколько разных SKU; нет ограничений по размеру и количеству SKU; вес ≤ 25 кг; размер не больше палеты 120×80 см; без наполнителя для объёма; объём поставки > 1 м³ → обязательный паллет.
- **Моно-короб:** один SKU (один ШК); лимит штук (обычно 5 или 10); макс. размер 60×40×40 см; минимального нет; вес ≤ 25 кг; > 1 м³ → паллет.
- **Моно-паллет:** один товар на паллете.
- **Суперсейф:** дорогие товары определённых категорий/брендов (Apple и др.).
- Паллеты: только евро 80×120 см, высота ≤ 180 см; ШК поставки на паллет, номер паллета («1 из 2»).
- Ювелирная продукция — приёмка только на складе Коледино; суперсейф — Коледино и Казань.

### Требования к упаковке WB (по категориям)
- Общее: стрейч-плёнка упаковкой не является; индивидуальная упаковка закрыта со всех сторон; штрихкод согласованного формата.
- **Крупногабаритные (КГТ):** сторона > 50 см или сумма 3 сторон > 90 см, вес > 5 кг; макс. 115 см по стороне, сумма ≤ 200 см, вес ≤ 25 кг; жёсткая упаковка 3–5 слоёв картона; на паллете с упаковочным листом.
- Текстиль/аксессуары, книги, посуда, грунт, очки, товары для взрослых, хрупкие, косметика/химия/питание, верхняя одежда/вешалки, продукты/зоотовары, ювелирные, обувь/коробки, сумки/рюкзаки — отдельные требования по материалам и упаковке.

### Требования к упаковке для ПВЗ (модель «Маркетплейс» FBS)
- Каждый товар в индивидуальной упаковке (лучше сейф-пакет); товары в транспортировочных коробах; короб закрыт; сторона ≤ 60 см; сумма 3 сторон ≤ 120 см; вес ≤ 5 кг; при > 1 м³ — на паллете; зазор от паллет до края кузова ≥ 10 см.
- Штраф за отгрузку в ПВЗ другой зоны: 30% от стоимости заказа (мин 100 ₽, макс 100 000 ₽).
- Приёмка: первые 50 товаров/сутки — 15 ₽/шт, далее 75 ₽/шт (считается отдельно по каждой зоне).

### Маркетплейс-зависимые ограничения
- Задания «Упаковка FBO» и «Упаковка с добавлением в заказ FBO» — только WB и Ozon.
- Отслеживание расхождений при приёмке — только WB.
- Отслеживание расхождений при упаковке — WB и Ozon.
- Заказ в Ozon создаётся один раз и не редактируется после отправки → «Создать заказ в Ozon» только после упаковки.
- Для Яндекс.Маркета — не более 1 склада на организацию.

### Статусы и документооборот
- Статусы SelSup меняются вручную (кроме Ozon до таймслота), так как статусы маркетплейсов по API не передаются.
- ШК коробов сохраняются (привязываются к упаковке) только через задание «Упаковка FBO»; во вкладке «ШК коробов» через загрузку файла — только печать, без сохранения.

## Открытые вопросы / чего не хватает в доках

1. **Алгоритм сверки остатков FBO** — детальные правила разрешения расхождений при сверке (какие именно операции создаются при «Изменить выбранные остатки», влияние на FIFO-слои) не описаны.
2. **Механика «предварительных коробов» Ozon** — не описан точный формат Excel-файла замены внутренних QR-кодов SelSup на ШК Ozon и правила маппинга.
3. **Автоматическое ночное списание резерва** — не указано точное время запуска, поведение при ошибках и конфликтах резервов нескольких заказов на один остаток.
4. **Приоритет списания остатков** — нет описания, как именно настраивается и применяется приоритет при нескольких складах с одинаковой связью.
5. **Разделение заказа WB на несколько типов** — не описан автоматический механизм переноса уже распределённых коробов и резервов при разделении.
6. **Получение кодов маркировки «Честный знак»** — детальный пошаговый процесс вынесен в отдельную статью («Работа с Честным знаком по FBO»), в данном модуле описан только триггер появления блока.
7. **Таймслоты Ozon** — не описано, что именно SelSup передаёт/получает после этапа создания заказа в Ozon и где заканчивается API-интеграция.
8. **Параметры расчёта «товары в пути» и «товары, поставляемые от клиента»** — термины используются в формуле планирования, но их точное определение и источник данных не раскрыты.
9. **Поведение «Коэффициента коррекции» и кратности короба совместно** — не указано, применяется ли кратность до или после коэффициента коррекции при планировании.
10. **Хранение и срок актов приёмки** — не описаны ограничения по размеру/формату и поведение при повторном импорте акта.
11. **QR-короба WB** — не описана валидация ID магазина и нумерации коробов при ошибках рассинхронизации с WB.
12. **Многомашинные поставки WB** — частично описано (машины в один день), но нет логики фиксации нескольких пропусков/ШК поставки в заказе SelSup.
13. **Яндекс.Маркет** — отсутствуют задания упаковки и контроля расхождений; не описан путь упаковки и генерации ШК коробов для Яндекс.Маркета (только файл заказа).
14. **СБЕРМегаМаркет / AliExpress / другие** — в данном модуле не упомянуты; объём поддержки FBO за пределами WB/Ozon/Яндекс не ясен.
