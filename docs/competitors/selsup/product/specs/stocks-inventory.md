# Остатки, склад и адресное хранение

> Спецификация модуля SelSup для воссоздания функционала. Источник: 46 статей базы знаний (corpus). Все утверждения основаны на текстах статей.

## Назначение

Модуль обеспечивает полный складской учёт товаров продавца на маркетплейсах:

- **Учёт остатков по двум схемам**: FBS (товар на физических складах продавца, списание под заказы FBS) и FBO (товар на складах маркетплейсов; отображается по API и на виртуальных складах для корректного расчёта аналитики по FIFO).
- **Синхронизация остатков** между SelSup и маркетплейсами (Wildberries, Ozon, Яндекс Маркет, МегаМаркет, СберМегаМаркет, AliExpress, Магнит Маркет) — автоматическая (при заказе/изменении остатка, ночной импорт в 00:00 МСК) и ручная (кнопка «Импорт с обновлением остатков»).
- **Операции с остатками**: обнуление/списание, перемещение между складами и ячейками, объединение/разделение по SKU, резервирование и снятие резерва под заказы, возврат остатков после отмен/возвратов.
- **Инвентаризация**: сверка фактических остатков с учётными через Excel-файл или ТСД, с поддержкой сроков годности, дат производства, номеров ГТД.
- **Адресное хранение**: структура склада (проход → стеллаж → полка → ячейка), раскладка, перемещения между ячейками, поиск по штрихкоду, сборка по маршруту, работа с ТСД.
- **Приёмка на склад (поступления)**: оприходование остатков с закупочной ценой, доп. расходами, ГТД, сроком годности, ячейкой хранения.
- **Аналитика по остаткам**: отчёты «Товарный остаток» (Текущий остаток, Остаток по складам, Динамика остатков), история операций и отправки остатков, сверка с маркетплейсами.

Ключевая модель: **1 физический склад = 1 склад в SelSup** (даже при множестве организаций); фулфилмент — отдельный склад. Остатки учитываются партиями (партионный учёт), у каждой партии свой **ID остатка** и **SKU**.

## Возможности (capabilities)

### Учёт и просмотр остатков
1. **Просмотр остатков FBS** в реальном времени — раздел «Склад → Остатки на складе → Остатки на моих складах», а также вкладка «Остатки FBS» в карточке товара (данные в разделе «Товары» обновляются раз в сутки).
2. **Просмотр остатков FBO по API** (Wildberries, Ozon) — в разделе «Товары», в отчётах, в ценах.
3. **Виртуальные склады FBO** — отдельная вкладка для корректного отображения остатков товаров, отгруженных через SelSup по FBO, и расчёта закупочных цен по FIFO; при создании отгрузки товары резервируются, по мере поступления на склады Ozon — списываются.
4. **Ручное изменение остатка** прямо в таблице (поле «Остаток» + галочка для сохранения и отправки на маркетплейс при включённом «Обновлять на маркетплейсе»).
5. **Фильтры и поиск** по остаткам: по складу, «есть остаток» / «нет остатка», «обновлять на маркетплейсе», «показать дубликаты», «остатки по всем складам» (отдельные столбцы), поиск по названию/штрихкоду/артикулу/бренду.
6. **Рассчитанные остатки для комплектов** — столбец показывает остаток комплекта как остаток составных частей ÷ количество товаров в комплекте (напр. 200 ручек / 6 = 33 комплекта).
7. **Столбец «Ошибка»** — индикация причин, по которым остаток не передаётся на конкретный/все маркетплейсы.
8. **Столбец «Место»** — указание ячейки хранения для товара (адресное хранение).
9. **«Остатки товаров данной модели»** — раздел с детализацией по конкретной модели: статус, фото, ШК, артикул, уникальный номер остатка, текущий остаток, резерв, отгружено, рассчитанный остаток, склад, место, закупочная цена, маркировка, этикетка, SKU.
10. **Скачивание остатков** в Excel — общий файл (товар — остаток) или с разбивкой по ячейкам хранения; по маркетплейсу+организации или по конкретному складу (кнопка «SELSUP»).

### Синхронизация и передача остатков
11. **«Синхронизировать остатки»** (в «Мои организации») — включает моментальное обновление остатков на маркетплейсах при «Импорте с обновлением остатков».
12. **«Автоматический импорт заказов»** — SelSup раз в минуту проверяет новые FBS-заказа и (при включённой синхронизации) обновляет остатки на всех маркетплейсах.
13. **«Онлайн остатки»** — робот для автоматической отправки изменений остатков (отражается в истории отправки).
14. **Ночной автоматический импорт** «Импорт с обновлением остатков» в 00:00 МСК по всем товарам + ручной запуск.
15. **«Обновлять только существующие остатки»** (Настройки → Остатки) — если включено, обновляются только заведённые в SelSup товары; если выключено — SelSup полностью управляет остатками и обнуляет позиции, которых нет в базе.
16. **«Уменьшать остаток на»** (карточка товара) — отправлять на маркетплейс остаток меньше фактического на заданную величину (не списывает со склада).
17. **Минимальный остаток FBS** — при остатке ниже порога передаётся 0 (защита от отмен, особенно в сезон); настраивается в карточке, массово через Excel, или для всей организации.
18. **Максимальный остаток FBS** — скрывает реальные остатки от сервисов аналитики: если фактический остаток выше порога, передаётся порог; если ниже — передаётся фактический.
19. **Минимальный порог FBO (функция «Умный склад»)** — когда FBO достигает нуля/порога, автоматически начинается передача остатка FBS (защита от снижения СПП и out-of-stock на WB).
20. **Отключение передачи остатков** — тумблер «Убрать с остатков FBS» (все МП) или выбор конкретных маркетплейсов; «Игнорируемые склады» — отключение передачи на конкретные склады маркетплейса.

### Обнуление, списание, перемещение
21. **Обнуление остатков FBS** — 5+ способов: через «Отключить остатки» (по организации+МП), через карточку товара, массово через Excel, через связи со складами, обнуление FBS при наличии FBO, инвентаризация (не рекомендуется, т.к. обнуляет остатки в SelSup).
22. **Списание остатков** (раздел «Склад → Списание остатков») — документ со складом списания, добавление товаров (сканер ШК / Excel / выбор +1), сохранение → закрытие (проведение); редактирование после проведения (только увеличение количества).
23. **Перемещение остатков между складами** (раздел «Склад → Перемещения») — склад списания + склад принятия, товары, количество, ячейка (при адресном хранении); лист сборки; «Удалить принятые остатки», «Отменить оприходование».
24. **Перемещение между ячейками** (внутри склада) — через «Перемещение» с одинаковым складом списания/принятия, поля «Взять с ячейки» / «Разместить в ячейке».
25. **Возврат остатка после отмены/возврата FBS** — автоматический возврат (отмена покупателем до сборки, статусы «Новый»/«На сборке»); ручной возврат через приёмку, через задание «Возврат товара», или кнопку «Вернуть на остатки» в заказе (статусы «Возврат»/«Отменён»).
26. **Приоритет списания остатков** — настройка складов (приоритет 1, 2…); списание идёт со склада с высшим приоритетом, при нехватке — с других складов со связью к складу МП.

### Объединение и разделение
27. **Объединение остатков по SKU** (раздел «Склад → Остатки на складе → Объединение остатков») — товары получают одинаковый SKU → общий остаток, списание с любого → обновление на все маркетплейсы группы.
28. **Массовое объединение/разделение по SKU** через Excel (копирование существующих SKU; пустой SKU → возврат исходного).
29. **Объединение карточек с разных маркетплейсов** (раздел «Товары → Объединение») — по ШК/артикулу, с подтверждением; массовое объединение по ключу (поля маркетплейсов, порядок важен).
30. **Объединение карточек по цветам/моделям** — поле «Артикул для объединения в одну карточку», перенос цвета на другую модель; массово через Excel.
31. **Разделение неправильно объединённых товаров** — удалить привязки по маркетплейсам (ШК, ID, артикулы) или полное удаление товара.
32. **Дубликат/оригинал** — определение и смена оригинала через поле «ID оригинала» и кнопку «Сделать оригиналом».

### Инвентаризация
33. **Инвентаризация без адресного хранения** (раздел «Задания → Инвентаризация» или «Склад → Инвентаризации») — Excel-файл с текущими остатками, правка столбца «Остаток», загрузка обратно, закрытие; доп. столбцы (срок годности, дата производства, номер ГТД).
34. **Инвентаризация для адресного хранения** — через «Задания → Инвентаризация» (сканирование ШК ячейки → ШК товара → количество → «Товаров больше нет») или через «Склад → Инвентаризации» (Excel с разбивкой по ячейкам).
35. **Просмотр завершённых инвентаризаций** — переключатель «Показать завершённые инвентаризации».

### Адресное хранение
36. **Создание структуры склада** (Склад → Склады → Адресное хранение): проходы (буквы) → стеллажи → полки → ячейки (цифры); авто-нумерация, переименование, копирование прохода/стеллажа/полки.
37. **Динамическое адресное хранение** — в одной ячейке могут храниться разные товары, артикулы, штрихкоды (не обязательно «1 ячейка = 1 артикул»).
38. **Закрепление ячейки за товаром** — ячейка сохраняется за товаром даже при нулевом остатке (ручная смена).
39. **Ячейка по умолчанию** «А.1.1.1» (переименуемая, напр. «Приёмка») для вновь принятых товаров до раскладки; настраиваемая «ячейка для неразмещённых товаров».
40. **Две схемы хранения**: (а) с уникальным кодом товара на каждой единице (одежда, размерный ряд, маркировка, средние товары); (б) со штрихкодом товара без уникального стикера (большие партии одинаковых/мелких товаров).
41. **Задание «Ячейки хранения»** — сканирование ШК товара → мгновенный показ всех ячеек с остатками этого товара.
42. **Задание «Раскладка товара»** — перемещение товаров из ячейки неразмещённых на постоянные места (скан товара → скан ячейки → количество → «Переместить»).
43. **Задание «Ячейки хранения»/«Раскладка»/«Инвентаризация»/«Сборка»** — работа через ТСД.
44. **Маршрутизация склада и сортировка ячеек** — «Обновить сортировку ячеек»: заказы сортируются по приоритетной ячейке (для всех МП), товары внутри заказа — по ячейкам (особенно Ozon/Яндекс); порядок «проход → стеллаж → полка».
45. **Печать этикеток ячеек/стеллажей** — ШК места хранения, редактируемый шаблон (Настройки → Этикетки → Место хранения).
46. **Скрытие/удаление ячеек и стеллажей** — стеллажи скрываются (не удаляются), ячейки скрытых стеллажей нужно удалять вручную; удаление элемента с остатками запрещено.

### Приёмка и поставки
47. **Приёмка на склад / поступления** (Склад → Приёмки на склад): название, организация, поставщик, склад, способ ввода в оборот; добавление товаров (сканер, выбор +1, Excel); поля — закупочная цена, доп. расходы, ячейка, срок годности, дата производства, номер ГТД, маркировка; оприходование создаёт остаток.
48. **Накладные расходы** на приёмку — распределение по товарам, автоматический расчёт «в процентах от суммы в заказах».
49. **Оприходование/отмена оприходования** — повторное оприходование применяет дельту относительно последнего количества; «Удалить принятые остатки» — полное удаление.
50. **Связанные документы** — связь приёмки с закупкой поставщика, закрытие закупки из приёмки.
51. **Перенос остатков** — с маркетплейсов (WB, Ozon, МойСклад) кнопкой «Перенести остатки», файлом (Яндекс, МегаМаркет, 1С, Excel) через приёмку.
52. **Поставки** (Склад → Поставки) — группа заказов для отгрузки в 1 день; ШК коробов, ШК поставки, отметка отгруженной/закрытой; сверка с WB («Проблемные заказы»); массовое распределение заказов FBS по поставкам.

### История, отчёты, сверка
53. **История отправки остатков** (хранится 3 месяца) — что отправлено на маркетплейс, статус (успешно/ошибка), остаток передан/получен, склад списания, причина ошибки, дата; кнопка «Восстановить остатки».
54. **История операций с товаром (История остатка)** — все операции по ID остатка: изменение, резерв, «взял», «отмечен потерянным», «снят со стока», инвентаризация, «найден», «замена уникального», снятие резерва, списан/снят по статусу, отмена заказа, продажа (FBO); экспорт в Excel.
55. **Сверка остатков** FBS и FBO — сравнение SelSup с маркетплейсом/МойСкладом (только WB, Ozon, МойСклад — отдают остатки по API); фильтрация расхождений, «Изменить выбранные остатки в SelSup».
56. **Отчёт «Товарный остаток»** (Аналитика → Отчёты): Текущий остаток (FBS+FBO, прогноз дней до конца), Остаток по складам (FBO WB/Ozon в разрезе складов), Динамика остатков (до 12 периодов, FBS/FBO/сумма).
57. **Расчёт дней остатка комплектующей** — формула: (Общий остаток + Рассчитанный остаток) ÷ (Продажи ÷ дни периода), с учётом продаж комплектов.

### ТСД
58. **Работа с ТСД** (мобильное приложение SelSup, Android/Honeywell EDA50k) — сканирование в поле ввода, отключение виртуальной клавиатуры; сборка/инвентаризация/раскладка под логинами сотрудников (история операций); поддержка смартфона с камерой вместо ТСД.

## Ключевые сценарии (workflows)

### WF-1. Первоначальная настройка склада и перенос остатков (FBS)
1. Склад → Склады → «Добавить склад» (1 физический склад = 1 склад; фулфилмент — отдельно).
2. Настроить опции: «Склад для учёта остатков FBO» (+ выключить «Считать аналитику по последней себестоимости» для FIFO), «Не передавать остатки», «Не загружать заказы», «Использовать для заказов», «Приоритет списания остатков».
3. Установить связи со складами маркетплейсов (для Яндекс — ID склада из ЛК, МегаМаркет — числовой ID, AliExpress — любое значение, Webasyst — авто).
4. Объединить дубликаты товаров между маркетплейсами (и с 1С/МойСклад): в рамках одной организации — общая карточка; между организациями — объединение по остатку.
5. Импортировать все заказы и перевести их «На сборку»/«Собранные», чтобы они не резервировали остатки.
6. Перенести остатки: кнопкой «Перенести остатки» (WB/Ozon/МойСклад) или файлом через приёмку (Яндекс/МегаМаркет/Excel/1С). Проверить через «Сверку остатков».
7. Включить «Синхронизировать остатки» и «Автоматический импорт заказов» (Мои организации). Выключить «Обновлять только существующие остатки» (Настройки → Остатки).
8. Запустить «Импорт с обновлением остатков», проверить «Результаты импорта» и «Уведомления».

### WF-2. Изменение остатка вручную и отправка на маркетплейс
1. Склад → Остатки на складе → Остатки на моих складах.
2. Включить «Обновлять на маркетплейсе».
3. Найти товар, ввести остаток в поле «Остаток», нажать галочку.
4. Проверить статус отправки в «Истории отправки остатков» (значок часов) и ошибки в столбце «Ошибка»/«Уведомления».

### WF-3. Списание остатков
1. Склад → Списание остатков → «Создать списание».
2. Заполнить название, организацию, склад списания.
3. Добавить товары (сканер ШК / Excel / +1).
4. «Сохранить» → проверить → «Закрыть» (проведение).
5. (Опц.) Редактировать проведённое списание (выключить «Только актуальные списания»), можно только увеличить количество.

### WF-4. Перемещение между складами / ячейками
1. Склад → Перемещение → «Создать перемещение».
2. Название, организация, склад списания и склад принятия (для ячеек — один склад).
3. Добавить товары (+1), указать количество, «Взять с ячейки» / «Разместить в ячейке».
4. «Сохранить» → «Перенести остатки».
5. (Опц.) Скачать «Лист сборки» (шаблон в Настройки → PDF-документы).

### WF-5. Инвентаризация (без адресного хранения)
1. Задания → Инвентаризация или Склад → Инвентаризации → выбрать склад → «Начать инвентаризацию».
2. Включить доп. столбцы (срок годности, дата производства, ГТД).
3. «Скачать текущие остатки товаров» → править столбец «Остаток».
4. «Загрузить изменённые остатки товаров».
5. Закрыть инвентаризацию (синий крестик в «Закрыть»).

### WF-6. Инвентаризация для адресного хранения
- **Вариант А (Задания → Инвентаризация):** выбрать склад → начать → отсканировать ШК ячейки → ШК товара → количество → «Товаров больше нет» (повторить для всех ячеек). Только для первоначального размещения.
- **Вариант Б (Склад → Инвентаризации):** начать → включить «Скачивать файл с остатками с разбивкой по ячейкам» → скачать → править ячейки/остатки → загрузить → при включённой синхронизации остатки обновятся (или «Импорт с обновлением остатков»).

### WF-7. Обнуление остатков FBS (варианты)
- **A. Через интерфейс:** Склад → Остатки → Отключить остатки → тумблер по организации+МП → «Импорт с обновлением остатков».
- **B. Через карточку товара:** отметить логотип МП или тумблер «Убрать с остатков FBS» → сохранить → импорт.
- **C. Массово через Excel:** Товары → Экспорт → столбцы «Убрать с остатков FBS» / по МП → Импорт → импорт остатков.
- **D. Через связи со складами:** создать новый склад, связать с МП, на основном удалить связь → импорт.
- **E. Обнуление FBS при наличии FBO:** Экспорт с фильтром «Остаток FBS и FBO = Есть» → столбец «Убрать с остатков FBS» → Импорт → импорт остатков.
- Для **Яндекс/МегаМаркет** дополнительно: после обнуления разорвать связь со складом и вручную обнулить в ЛК товары, которых не было в SelSup.

### WF-8. Возврат остатка после отмены/возврата FBS
1. Проверить статус заказа (Заказы на отгрузку → Со своего склада).
2. Если покупатель отменил до сборки («Новый»/«На сборке») — возврат автоматический.
3. Иначе: через приёмку (Склад → Приёмки → «Создать поступление» → добавить → «Сохранить» → «Оприходовать»); или через Задания → Возврат товара; или кнопкой «Вернуть на остатки» в заказе в статусе «Возврат»/«Отменён».

### WF-9. Объединение остатков по SKU
1. Склад → Остатки на складе → Объединение остатков (или столбец «Объединить» в «Остатках на моих складах»).
2. Сначала нажать товар с нулевым остатком, затем — товар-донор.
3. Запустить «Импорт с обновлением остатков».
4. Разделение: «Показать дубликаты» → удалить в колонке «Дубликат» из карточки **оригинала**; массово — обнулить SKU в Excel и загрузить.

### WF-10. Приёмка на склад (поступление)
1. Склад → Приёмки на склад → «Создать поступление».
2. Заполнить название, организация, поставщик, склад, способ ввода в оборот.
3. Добавить товары (сканер ШК / +1 / Excel-шаблон).
4. Указать количество, ячейку, закупочную цену, доп. расходы, срок годности, дату производства, ГТД, маркировку.
5. «Сохранить» → «Оприходовать» (создаёт остаток, приёмка закрывается).

### WF-11. Адресное хранение: настройка структуры
1. Склад → Склады → склад → «Адресное хранение».
2. «Добавить проход» → переименовать → «Список стеллажей» → добавить стеллаж → «Список полок» → добавить полку → «Список ячеек» → добавить ячейки.
3. Скопировать проход/стеллаж/полку при необходимости.
4. Распечатать ШК ячеек (на проход/стеллаж/полку/ячейку).
5. Провести инвентаризацию для адресного хранения (привязка товаров к ячейкам).

### WF-12. Сверка остатков
1. Склад → Остатки на складе → Сверка остатков FBS/FBO (вкладка скрыта, если включена «Синхронизировать остатки»).
2. Выбрать организацию, маркетплейс/сервис → «Запустить сверку».
3. Отфильтровать расхождения → «Изменить выбранные остатки в SelSup».

## Сущности (entities)

### Склад (Warehouse)
- Название; тип (физический FBS / виртуальный FBO / фулфилмент); организация;
- Флаги: «Не передавать остатки», «Не загружать заказы», «Использовать для заказов»;
- Приоритет списания остатков (1, 2…);
- Связи со складами маркетплейсов (МП, склад МП, организация, ID склада);
- Ячейка для неразмещённых товаров;
- Структура адресного хранения (проходы/стеллажи/полки/ячейки).

### Остаток (Stock / Stock Item)
- ID остатка (партия, ключ партионного учёта);
- SKU (внутренний ID; общий для объединённых по остатку товаров);
- Товар (ссылка); склад; количество (текущее);
- Резерв (под заказ); отгружено;
- Закупочная цена; доп. расходы; номер ГТД/РНПТ;
- Срок годности; дата производства;
- Ячейка хранения (Место); маркировка; этикетка;
- Тип: FBS / FBO (API) / FBO (виртуальный);
- Статус товара (в наличии / отгружен / и т.д.).

### SKU (Stock Keeping Unit)
- Внутренний ID единицы хранения; может соответствовать нескольким карточкам на разных МП/организациях; одинаковое значение = общий остаток.

### Приёмка на склад (Income Order / Поступление)
- Название; организация; поставщик; склад; способ ввода в оборот;
- Товары (ШК, артикул, цена, доп. расходы, количество, ячейка, дата производства, срок годности, ГТД);
- Накладные расходы (распределение, % от суммы);
- Статус (черновик/оприходована/закрыта); связанные документы (закупка).

### Списание остатков (Write-off Order)
- Название; организация; склад списания; товары + количество; статус; история изменений; цены.

### Перемещение (Movement Order)
- Название; организация; склад списания; склад принятия; товары + количество; «Взять с ячейки» / «Разместить в ячейке»; статус; история; цены; лист сборки.

### Инвентаризация (Inventory)
- Склад; дата; файл остатков (с/без разбивки по ячейкам); доп. столбцы (срок годности, дата производства, ГТД); статус (открыта/закрыта).

### Структура адресного хранения
- Проход (буква) → Стеллаж (номер) → Полка (номер) → Ячейка (номер, ШК места хранения); видимость (скрыт/активен).

### Поставка (Supply)
- Группа заказов FBS на одну дату; ШК коробов; ШК поставки; статус (создана/отгружена/закрыта); заказы; «Проблемные заказы» (сверка с WB).

### Заказ FBS (в контексте остатков)
- Статус (Новый / На сборке / Собран / Отправлен / В пути / Возврат / Отменён / Выкуплен / Готов к выдаче); связь с резервом/списанием остатка; поставка.

### История операций (Item History)
- ID остатка; место; дата; заказ; пользователь; количество (дельта); общее количество; тип операции.

### История отправки остатков (Stocks History)
- Товар; SKU для объединения; остаток передан; остаток получен; склад списания; статус (успешно/ошибка); причина ошибки; дата. Хранится 3 месяца.

## Интеграции

- **Wildberries** — остатки FBS и FBO по API; сверка остатков; отчёты (Текущий/Остаток по складам/Динамика); связи со складами; поставки и сверка «Проблемные заказы»; данные «От клиента/К клиенту» в отчёте.
- **Ozon** — остатки FBS и FBO по API; сверка; отчёты; данные «Между складами» в отчёте; ограничения (КГТ-склад, неинтегрированные методы доставки, модерация, архив).
- **Яндекс Маркет** — остатки FBS по API; FBO **только файлом** (не отдаёт по API); ID склада из ЛК вручную; лимиты (ошибка 400 «Превышен лимит запросов»).
- **МегаМаркет** — остатки FBS по API (числовой ID склада из ЛК); обнуление требует разрыва связи + ручной правки в ЛК.
- **СберМегаМаркет** — поле «Артикул СберМегаМаркет» для привязки/разделения карточек.
- **AliExpress** — поле «SKU Aliexpress»; ID склада — любое значение.
- **Магнит Маркет** — ID склада из ЛК (Накладные → Остатки FBS → Настроить склады).
- **МойСклад** — двусторонний обмен остатками; сверка остатков FBS/FBO; опция «Снимать резервы в МС при отмене заказа до сборки».
- **1С** — обмен по CommerceML; перенос остатков файлом (формат 1С); ID 1С в карточке (участвует в конфликтах объединения).
- **Webasyst** — ID склада проставляется автоматически.
- **Дропшиппинг / прайс-листы / сторонние сервисы** — обновление остатков по API.
- **ТСД** — мобильное приложение SelSup (Android, RuStore); рекомендован Honeywell EDA50k; смартфон с камерой как замена ТСД.

## Бизнес-правила и ограничения

- **1 физический склад = 1 склад в SelSup**; фулфилмент — отдельный склад; ограничений по количеству связей склада со складами МП нет.
- **Партионный учёт**: каждая приёмка создаёт свой остаток с уникальным ID; история операций ведётся по ID остатка.
- **SKU**: одинаковый SKU у нескольких карточек = общий остаток; нельзя вставлять произвольные SKU (только копировать существующие); пустой SKU при загрузке → возврат исходного.
- **«Обновлять только существующие остатки» включено**: обновляются только заведённые товары; выключено — позиции без записи в SelSup обнуляются на МП.
- **История остатка обязательна для передачи 0**: если у товара нет истории движения, нулевой остаток не передаётся; нужно создать историю (приёмка/инвентаризация ≥1), затем обнулить.
- **Отрицательные остатки не используются** — при уменьшении ниже нуля ставится 0.
- **Защита от случайного обнуления**: «Синхронизировать остатки» включать только после корректного переноса остатков; склады МП без связи в SelSup получают 0 (защита селлера).
- **Сверка остатков доступна только для WB, Ozon, МойСклад** (отдают остатки по API); FBO по API — только WB и Ozon.
- **Яндекс Маркет** не отдаёт FBO по API — только файлом; МегаМаркет FBO — аналогично; для обнуления на Яндекс/МегаМаркет нужно разорвать связь со складом после отправки 0 и вручную править ЛК.
- **Автоматический возврат остатка** только при отмене покупателем до сборки («Новый»/«На сборке»); при отмене продавцом или возврате — вручную; со статуса «Собран» кнопка отмены продавцом недоступна.
- **Инвентаризация через «Задания»** — только для первоначального размещения; для пополнения существующих ячеек — через «Склад → Инвентаризации» (иначе обнулит отсутствующие в поставке товары).
- **Создавать инвентаризацию могут только роли «Администратор» и «Сотрудник склада»**.
- **Удаление элемента структуры адресного хранения с остатками запрещено** — сначала обнулить остатки; стеллажи скрываются, ячейки скрытых стеллажей нужно удалять вручную.
- **Объединение карточек не произойдёт при конфликте идентификаторов** (разный ID 1С; разные непустые идентификаторы одного МП).
- **Разделение неправильно объединённых**: обязательно из карточки **оригинала**; ШК дубликатов в рамках одной организации быть не может.
- **«Уменьшать остаток на»** не списывает товар и не меняет остаток в SelSup — влияет только на отправляемое на МП значение; при превышении фактического остатка передаётся 0.
- **Перенос остатков второй раз** нельзя запустить, пока на складе есть остатки — нужно сначала обнулить (через инвентаризацию).
- **Повторное оприходование приёмки** считает дельту относительно последнего оприходованного количества.
- **«Удалить принятые остатки»** удаляет остаток со всей информацией и резервом — необратимо; нельзя удалить, если остаток зарезервирован под заказ.
- **История отправки остатков хранится 3 месяца**.
- **Отчёты «Товарный остаток» (FBO/FBS в динамике)** — данные обновляются раз в сутки; динамика — не более 12 периодов; FBO/FBS в динамике только для WB и Ozon.
- **Сортировка ячеек** («Обновить сортировку ячеек»): порядок «проход → стеллаж → полка»; товары без ячейки в сортировке не учитываются.
- **Приоритет списания**: со склада приоритета 1 — в первую очередь; при нехватке ищется на других складах со связью к складу МП.

## Открытые вопросы / чего не хватает в доках

- **Точная периодичность «Онлайн остатков»** — статьи говорят о моментальной отправке при заказе/изменении и ночном импорте, но не указывают частоту фонового опроса маркетплейсов и задержки для каждого МП (кроме «Автоматического импорта заказов» — раз в минуту).
- **Разграничение «Онлайн остатки» vs «Синхронизировать остатки» vs «Автоматический импорт заказов»** — флаги пересекаются по описанию; чёткая таблица зависимостей и сценариев «что включать когда» отсутствует.
- **Обработка расхождений при сверке** — описан запуск и фильтрация, но не детализирован алгоритм разрешения (авто-применение, правила приоритета источника, отложенные операции).
- **FIFO-расчёт по виртуальным складам FBO** — упомянуто, что нужен для закупочных цен в аналитике, но формулы и связь с партионным учётом не раскрыты.
- **Разрешение конфликтов идентификаторов при массовом объединении** — описано, что объединение не произойдёт при конфликте, но не описан пользовательский сценарий разрешения (как выбрать, какой идентификатор оставить).
- **Поведение «Уменьшать остаток на» совместно с мин/макс остатком** — не указано, в каком порядке применяются трансформации отправляемого остатка (мин → макс → уменьшение → порог FBO).
- **Точные роли и права** — упомянуты только «Администратор» и «Сотрудник склада» для инвентаризации; полный матрица прав по операциям с остатками отсутствует.
- **Лимиты API по маркетплейсам** — только для Яндекс указана ошибка 400 «Превышен лимит запросов»; лимиты WB/Ozon/МегаМаркет не задокументированы.
- **Версионирование/откат операций** — «Отменить оприходование» и «Удалить принятые остатки» описаны, но нет отката инвентаризации/списания/перемещения после закрытия (только редактирование списания «в большую сторону»).
- **Массовые операции через API** — упомянут дропшиппинг/прайс-листы/сторонние сервисы, но публичное API для управления остатками не описано в этих статьях.
- **Хранение истории операций** — указан срок только для истории отправки (3 месяца); срок хранения истории операций с товаром не задан.
- **Поведение при одновременной работе нескольких складов с одним складом МП** — приоритет описан, но race conditions и блокировки не рассмотрены.
- **Импорт остатков с разными единицами измерения/комплектами** — рассчитанный остаток для комплектов описан, но правила пересчёта при приёмке/списании комплектующих не детализированы.
