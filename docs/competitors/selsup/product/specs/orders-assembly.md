# Заказы и сборка (FBS/FBO/DBS)

> Спецификация модуля SelSup для воссоздания функционала. Источник — 32 статьи базы знаний модуля «Заказы и сборка». Реквизиты/тарифы/точные URL интерфейсов — из оригинальных статей.

## Назначение

Модуль объединяет в едином окне весь цикл работы с заказами маркетплейсов и собственных продаж: импорт заказов, управление статусами, сборку/комплектацию/проверку заказов по схемам FBS и FBO (включая адресное хранение и маркированные товары), обработку DBS/realFBS (со сторонней доставкой), работу с оптовыми и розничными заказами, дропшиппингом и крупногабаритными товарами (КГТ). SelSup выступает единым центром управления заказами и отгрузками вместо личных кабинетов маркетплейсов: загружает заказы, формирует поставки, печатает этикетки, передаёт коды маркировки, ГТД и сроки годности, обновляет статусы и закрывает поставки.

Ключевая идея: разные схемы (FBS, FBO, Express, DBS/realFBS, гибридные DBS, DBW/DBM, заказы юрлиц) обрабатываются в одном интерфейсе с учётом логики каждого маркетплейса (Wildberries, Ozon, Яндекс Маркет, МегаМаркет, AliExpress).

## Возможности (capabilities)

1. **Импорт заказов с маркетплейсов (три режима)** — автоматический импорт (по событию API в момент поступления заказа), ручной «Импорт заказов» (без изменения остатков на МП), «Импорт заказов с обновлением остатков» (передаёт актуальные остатки из SelSup на МП). Первый импорт может тянуть заказы за 3 месяца; «Перезагрузить заказы за неделю» — для актуальных данных.
2. **Многотиповая обработка заказов** — в одном интерфейсе FBS, FBO, Express (EDBS/realFBS Express), DBS/realFBS, гибридные DBS (со сторонней доставкой), DBW/DBM (Delivery by Marketplace), заказы от юридических лиц (B2B), розничные и оптовые заказы.
3. **Лента заказов (отчёт)** — онлайн-отчёт по всем заказам (обновление по API каждые 30 минут) с фильтрами по типу/периоду/организации/статусу/маркетплейсу, финансовыми показателями (сумма, себестоимость, комиссия, логистика, валовая прибыль = Итого к оплате по API − Себестоимость − Самовыкуп), графиком заказов (в шт./руб., с группировкой по дням/неделям/месяцам/кварталам/годам), выгрузкой в Excel с настраиваемыми столбцами.
4. **Динамика заказов** — отчёт (модуль AI-Финдир) с группировкой по штрихкоду/цветомодели/артикулу/категории/бренду и по периодам; показывает остатки «доступные к продаже» и количество заказов в разбивке по дням.
5. **Массовое изменение статусов** — смена статуса выбранных заказов (галочками) или всех заказов списка (без выбора) через «Дополнительно → Массовое изменение статусов».
6. **Разделение FBS-заказов на несколько отправлений** — ручное (через вкладку «Разделение заказа» → «Добавить короб», перенос товаров между коробами) и автоматическое при импорте (для Ozon, Яндекс Маркета, МегаМаркета — отдельные тумблеры). Для Wildberries недоступно. Не применяется к маркируемым товарам. Заказы <2 шт. разделить нельзя.
7. **Массовое распределение заказов FBS по поставкам** — фильтр (склад/организация/маркетплейс), отбор заказов в статусе «Новый», создание новой поставки (название, дата доставки) или выбор существующей, привязка заказов.
8. **Получение этикеток заказов** — фильтр «Без этикетки» → «Загрузить этикетки у заказов, где их нет»; автоматически создаёт/дополняет поставку (для WB) и меняет статус заказа на МП на «Ожидает доставки» (Ozon/Яндекс/МегаМаркет/AliExpress).
9. **Лента заказов и Умная лента (документы)** — печать этикеток заказов, товарных этикеток, сборочных этикеток, информационной этикетки, этикетки видеофиксации, кодов маркировки; настройка обратного порядка печати, объединения по SKU, отключения дубликатов; экспорт в PDF (этикетки МП — PDF маркетплейса; товарные/сборочные — браузер; совмещённый PDF — через QZ Tray).
10. **Лист сборки** — PDF-документ с настраиваемыми колонками, порядком, фото, штрихкодом, высотой изображения; опции «Скрыть штрихкод», «Заменять комплекты на компоненты», «Сортировать по ячейке/дате»; три шаблона (FBS, FBO, перемещения).
11. **5 способов ручной сборки FBS** — (1) Лист сборки + Лента заказов; (2) Умная лента; (3) Умная лента + товарная этикетка; (4) Лента заказов + товарная этикетка (для WB); (5) Сборка по одному артикулу («Показать заказы этого же товара»).
12. **Сборка через задания (упрощённый интерфейс)** — «Комплектация заказов» (скан штрихкода товара → SelSup находит и резервирует заказ), «Сборка заказов» (скан QR/ШК заказа), «Проверка заказов» (контроль отгрузки, защита от дублей), «Сборка FBO», «Сборочное задание» (адресное хранение, до 10 заказов на задание).
13. **Сборка с адресным хранением** — маршрутизация по складу, отображение ячейки хранения и количества, интеллектуальное распределение по нескольким ячейкам, строгий контроль через ТСД/задание «Комплектация» (блок сканирования не из той ячейки), фильтр «Проходы», столбец «Ячейка хранения» в листе сборки.
14. **Сборка FBO** — задание для отгрузки на склад МП: отображение всех товаров заказа, резерв для сборки (предотвращает двойную сборку), кнопки «Собран»/«Нет остатка», обработка расхождений (меньше/больше с подтверждением).
15. **Сборка комплектов** — два режима замены: «Заменять комплекты на используемые компоненты» (только если в заказе остатки компонентов) и «Заменять все комплекты на компоненты»; автопечать этикетки комплекта после сборки всех комплектующих; фиксация времени начала сборки.
16. **Работа с маркированными товарами (Честный знак)** — настройка признака маркировки в категории + ТН ВЭД; сканирование штрихкода → КИЗ или сразу КИЗ (по GTIN); проверка GTIN по штрихкоду; привязка КИЗ к заказу; передача даты производства и срока годности (из КИЗ или вручную); печать дубликата кода маркировки; автоматический ввод/вывод из оборота; просмотр КИЗ в столбцах «Остатки»/«Маркировка»/«Коды маркировки»/раздел «Маркировка».
17. **Передача ДТ/ГТД** — номер декларации указывается в приёмке (способ «Импорт») на всю приёмку или по товарам; массовое заполнение через «Склад → Инвентаризация» (тумблер «Выводить номер ГТД»); автоматически передаётся в заказ Ozon/WB из зарезервированного остатка.
18. **Сборка для отгрузки WB в ПВЗ** — режим «Отгружаться на ПВЗ» в задании «Комплектация»: выбор поставки, создание короба (ШК начинается с WB-TRBX), скан заказов в короб, печать стикера короба.
19. **Закрытие поставок (индивидуальное и массовое)** — «Проверить и закрыть» с сверкой состава заказа SelSup↔МП (для WB; для Ozon/Яндекс/МегаМаркет — без проверки); генерация QR-кодов (WB), актов, способов доставки.
20. **Работа с заказами DBS/realFBS** — отдельные настройки и фильтры; автоматический импорт, печать стикеров, автоматическая передача статусов на МП; интеграция с ТК (СДЭК, Почта России, Деловые Линии, Яндекс Доставка) — создание заказа в ТК, трек-номер автопередаётся на Ozon; формирование накладных и стикеров ТК.
21. **Оптовые заказы** — отдельный раздел; грузополучатель — контрагент; автоматическое резервирование, списание при уходе из статусов «Новый»/«На сборке»; формирование счёта на оплату; создание заказа покупателя в МойСклад; аналитика на дашборде.
22. **Розничные заказы (офлайн/интернет-магазин)** — данные покупателя (ФИО, телефон, почта, адрес), склад списания, автоматический резерв; отправка заказа в СДЭК (тип «до двери»/«до ПВЗ», адрес/регион); статус меняется вручную.
23. **Дропшиппинг** — регулярный обмен с поставщиками (email, YML, Excel, JSON API/API Core, прямая интеграция Sima-Land, кастомный API); онлайн-обновление остатков и цен на МП; обнуление остатков при пропадании товара из прайса; создание заказа поставщику; закупки из заказов; создание карточек из YML.
24. **КГТ (крупногабаритные товары, Ozon)** — отдельный склад КГТ с остатками FBS; поле «Игнорировать склады FBS» и «Только склады FBS» в карточке/Excel для маршрутизации остатков на нужный склад.
25. **Заказы от юридических лиц (B2B)** — пометка значком портфеля в колонке «Бизнес»; для WB — раздельные поставки B2C/B2B; для Ozon — смешивание разрешено, но стикер доступен только после передачи маркировки.
26. **Синхронизация статусов с МП** — до отгрузки статусы в SelSup и МП разделены (внутренние статусы «Новый»/«На сборке»/«Собран»/«Отправлен» не передаются на МП); после отгрузки статусы синхронизируются (Отсортирован→В пути, Продано→Завершен, Отменён клиентом→Отменён, Выкуплен и т.д.).
27. **Камера телефона как сканер** — настройка «Использовать камеру для сканирования штрихкодов» для работы в заданиях без ТСД; мобильные приложения iOS/Android (RuStore).
28. **Работа через 1С** — модуль «Комплектация заказов» в 1С (эмуляция клавиатуры сканером); передача результата комплектации в SelSup; проверка GTIN; интеграция с МойСклад (автосоздание заказов/отгрузок, статус «Новый»).
29. **Выявление причин расхождений SelSup↔МП** — уведомления об ошибках импорта (нет карточки/несовпадение артикула символ в символ), перезагрузка за неделю, сверка по фильтрам (дата доставки, склад), анализ заказов на нулевой остаток (история остатка, заказов, обновления остатков FBS).

## Ключевые сценарии (workflows)

### WF-1. Полный цикл сборки FBS-заказа
1. Настроить склад SelSup, связь со складами МП, перенос остатков.
2. Включить автоматический импорт заказов (Настройки → Мои организации) или запустить «Импорт заказов» вручную.
3. Заказы появляются в «Заказы на отгрузку → Со своего склада (FBS)» в статусе **Новый**.
4. Отметить нужные заказы галочками → «На сборку» (без выбора — все с датой отгрузки «сегодня»/без даты). SelSup создаёт/дополняет поставку.
5. Включить фильтр «Без этикетки» → «Загрузить этикетки у заказов, где их нет» (для WB заказ привязывается к поставке; для остальных — статус МП → «Ожидает доставки»).
6. Выбрать способ сборки (Лист сборки + Лента / Умная лента / +товарная этикетка / по одному артикулу / через Задания).
7. Собрать товары, наклеить этикетки.
8. Отметить заказы собранными: галочками → «Отметить собранными все заказы» (или значок машинки в строке; или через задание — статус меняется автоматически после печати этикетки).
9. Закрыть поставку: «Проверить и закрыть» (сверка состава SelSup↔МП для WB). Заказы → статус **Отправлен**.
10. После приёмки на МП статус → **В пути**.

### WF-2. Сборка FBS с адресным хранением (через Сборочное задание на ТСД)
1. Настроить структуру склада адресного хранения, разместить остатки в ячейках; включить «Использовать задание для сборки заказов FBS» (Настройки → FBS).
2. Импортировать заказы; убедиться, что у всех позиций отображается место хранения (резерв должен быть создан; иначе — разместить остаток и переимпортировать).
3. Сформировать сборочное задание (кнопка простого формирования или «Распечатать задания» с лентой этикеток WB); на сегодня по умолчанию, есть кнопки «на завтра»/«распределить заказы старше одного дня».
4. На ТСД/телефоне: «Сборочное задание» → выбрать число заданий (≤10 заказов) и МП → «Взять заказы на сборку».
5. Система ведёт по ячейкам; отсканировать ШК/уникальный код товара; для WB — проверить стикер заказа; для маркируемого — отсканировать КИЗ.
6. Кнопки в задании: «Потерян» (подобрать другой остаток), «Пропустить» (переупаковка), «Отменить» (штраф за отмену возможен).
7. Перейти в задание «Комплектация заказов» для упаковки собранных товаров по заказам.

### WF-3. Сборка FBS с маркировкой Честного знака (WB/Ozon)
1. В категории товара включить «Товары категории маркируются», заполнить ТН ВЭД; в карточке товара указать GTIN.
2. В задании «Комплектация заказов» включить «Нужно проверять маркировку или срок годности» (отдельно от «Сборки заказов»); при необходимости — «Печатать дубликат кода маркировки».
3. Получить и зарезервировать КИЗ в «Заказы на отгрузку → Со своего склада (FBS)» (через «Коды маркировки»).
4. Скан ШК товара → КИЗ (или сразу КИЗ по GTIN); SelSup привязывает КИЗ к заказу.
5. Включить «Проверять GTIN по штрих-коду» (Настройки → Общие) для проверки совпадения GTIN маркировки и карточки.
6. При необходимости — указать дату производства/срок годности вручную или из КИЗ (для WB срок годности <30 дней — нельзя сохранить).
7. Передать маркировку на МП → загрузить этикетку.
8. После отгрузки — вывести КИЗ из оборота (Маркировка → Коды маркировки, `turnover=true`).

### WF-4. Сборка FBS с маркировкой для Яндекс Маркета
1. Собрать заказы по листу сборки.
2. В задании «Комплектация» просканировать ШК товара → КИЗ; SelSup отправляет маркировку на Яндекс Маркет.
3. После передачи КИЗ статус заказа меняется, этикетка становится доступна → загрузить и распечатать. (Нельзя загружать этикетку до передачи КИЗ.)

### WF-5. Разделение заказа FBS на отправления (Ozon/Яндекс/МегаМаркет)
1. Настроить «Разделить заказы при импорте» (Настройки → FBS) с тумблерами по МП. Для Ozon — включить «Ozon: не изменять статус заказа при отправке На сборку» (заказ должен быть «Ожидает сборки»).
2. Разделять ДО загрузки этикеток (после — нельзя).
3. На странице заказа → «Разделение заказа» → «Добавить короб» → перенести товары → «Сохранить» (габариты необязательны).
4. Результат: Ozon — несколько новых заказов; Яндекс/МегаМаркет — состав тот же, добавляются короба (Яндекс генерирует по 2 этикетки, требует скан 2 товаров).
5. Альтернатива: разделение через задание «Комплектация» после сборки.

### WF-6. Сборка и закрытие поставки FBS
1. Собрать все заказы поставки (статус Собран).
2. «Заказы на отгрузку → Поставки» → «Проверить и закрыть» (для WB — сверка состава и отсутствия несобранных; при расхождениях — предложение исправить).
3. Массовое закрытие: отметить поставки → «Проверить и закрыть».
4. После закрытия: заказы → Отправлен; WB — QR-код поставки; Ozon — способы доставки; Яндекс — акт; МегаМаркет — через API недоступно.

### WF-7. Сборка заказа DBS (realFBS) через СДЭК
1. Включить «Работать с заказами DBS» (шестерёнка на странице FBS).
2. Выбрать заказ СДЭК → «На сборку».
3. Запрос в СДЭК на накладную → получение стикера; заказ создаётся в ЛК СДЭК, в SelSup появляется трек-номер.
4. Распечатать стикер и накладную СДЭК; трек-номер автопередаётся на Ozon.
5. Для WB DBS — курьер указывает код покупателя в кабинете WB.

### WF-8. Оптовый/розничный заказ
1. Включить раздел («Настройки → Настройка меню» для опта; «Настройки → Заказы» — тумблеры «Работать с оптовыми/розничными заказами»).
2. Создать заказ: название, организация, грузополучатель/данные покупателя, склад списания, трек-номер (опт).
3. Добавить товары (скан ШК / «+1» / загрузка файла).
4. Сохранить → автоматический резерв.
5. Опт: сформировать счёт, создать заказ в МойСклад. Розница: отправить в СДЭК.
6. Списание остатков — при уходе из статусов «Новый»/«На сборке» (опт) или при финальном статусе (розница).

### WF-9. Контроль отгрузки (Проверка заказов)
1. «Задания → Проверка заказов».
2. Скан ШК с этикетки заказа → статус «Проверенный» с фиксацией даты/времени.
3. Повторный скан → предупреждение «уже проверен» (блокировка дублей).

## Сущности (entities)

- **Заказ FBS** — атрибуты: внешний номер (на МП), организация, маркетплейс, тип заказа, статус, дата заказа, дата покупки, дата отгрузки, дней в пути, склад, состав (товары/кол-во), сумма продажи, себестоимость, комиссия (руб./%), логистика, валовая прибыль, остаток (ссылка на зарезервированный остаток), этикетка, поставка, ошибка МП, кто собрал, дата начала сборки, маркировка (КИЗ), ДТ/ГТД, признак B2B (значок портфеля), ячейка хранения, проход.
- **Заказ FBO** — загружается по API как данные о продажах; атрибуты отчёта: маркетплейс, тип, статус, состав, даты, сумма, комиссия, логистика; не собирается как FBS; не уменьшает остатки так же, как FBS.
- **Заказ Express** — FBS со срочной доставкой; отдельный фильтр; настройка авто-приёма и перевода в доставку.
- **Заказ DBS/realFBS** — заказ на МП, доставка продавцом/ТК; атрибуты: служба доставки, трек-номер, стикер/накладная ТК.
- **Заказ гибридный DBS** — стикер МП + стикер службы доставки.
- **Заказ DBW/DBM** — товар на складе продавца, доставка МП; логика как FBS.
- **Оптовый заказ** — атрибуты: название отгрузки, организация, грузополучатель (контрагент), склад списания, трек-номер, товары/кол-во, оптовая цена, счёт.
- **Розничный заказ** — атрибуты: название, организация, ФИО/телефон/почта/адрес покупателя, склад списания, товары/кол-во, служба доставки, тип доставки (до двери/до ПВЗ), адрес/регион.
- **Поставка (FBS)** — атрибуты: название, дата доставки, маркетплейс, склад, организация, состав заказов, статус, QR-код (WB), признак B2B (портфель), короба.
- **FBO-поставка (отгрузка на склад МП)** — товары для передачи на склад МП, документы, коды маркировки.
- **Короб/отправление** — элемент разделения заказа; ШК (для WB ПВЗ начинается с WB-TRBX); габариты (необязательны при разделении).
- **Этикетка заказа** — формируется МП; доступна только в определённых статусах.
- **Товарная этикетка** — внутренняя (название, артикул, ШК, размер, бренд, модель, продавец, производитель, адрес производства); настраивается в «Настройки → Этикетки».
- **Сборочная этикетка** — товар для сборки, кол-во заказов с товаром, кол-во единиц, артикул WB.
- **Информационная этикетка** — кол-во заказов + кол-во сборочных этикеток (контроль полноты).
- **Код маркировки (КИЗ)** — привязан к заказу; статусы; дата производства/срок годности; GTIN; вывод из оборота.
- **ДТ/ГТД** — номер декларации, хранится в остатке приёмки.
- **Сборочное задание** — до 10 заказов; статус активности (зелёная иконка А); назначение на аккаунт.
- **Ячейка хранения / Проход** — элементы адресного хранения; ID остатка (партионный учёт).
- **Комплект** — товар из компонентов; режимы замены; этикетка комплекта.

## Интеграции

- **Маркетплейсы (Wildberries, Ozon, Яндекс Маркет, МегаМаркет, AliExpress)** — двусторонний обмен по API: импорт заказов (авто/ручной), обновление остатков, получение этикеток, передача статусов/маркировки/ГТД/сроков годности, закрытие поставок (для Ozon/Яндекс/МегаМаркет поставки не создаются через API — внутренние в SelSup).
- **Честный знак (Маркировка)** — получение/резервирование КИЗ, импорт даты производства/срока годности из КИЗ, ввод/вывод из оборота.
- **1С** — модуль «Комплектация заказов» (эмуляция клавиатуры, подсистема торгового оборудования); передача результатов в SelSup; проверка GTIN.
- **МойСклад** — автосоздание заказов/отгрузок при импорте, создание заказа покупателя (статус «Новый»), автосоздание контрагента; разделение заказа в SelSup до создания в МойСклад.
- **СДЭК** — создание заказа в ТК, получение накладной/стикера, трек-номер (автопередача на Ozon); для розничных/DBS-заказов.
- **Почта России, Деловые Линии, Яндекс Доставка** — интеграция с ТК (по запросу/настраиваемая).
- **Поставщики дропшиппинга** — email, YML, Excel по ссылке, JSON API (API Core), прямая интеграция Sima-Land, кастомный API; регулярный обмен остатками/ценами; создание заказа поставщику.
- **QZ Tray** — автоматическая печать этикеток/лент на принтер без диалогового окна; совмещённый PDF (товарная + этикетка заказа).
- **Сервисы учёта/аналитики** — выгрузки Excel (заказы FBS, отчёт по заказам, инвентаризация с ГТД).

## Бизнес-правила и ограничения

- **Статусная модель до отгрузки**: внутренние статусы SelSup («Новый»/«На сборке»/«Собран»/«Отправлен») не передаются на МП; после отгрузки статусы синхронизируются (Отсортирован→В пути, Продано→Завершен, Отменён→Отменён, Выкуплен, Возврат, Готов к выдаче и т.д.). Загрузка этикетки может перевести заказ МП в «Ожидает доставки» даже без сборки.
- **Сопоставление товара**: точное совпадение артикула продавца «символ в символ» (учёт регистра, пробелов); для WB — по штрихкоду, для Ozon — по артикулу. Несовпадение → заказ не импортируется.
- **Разделение заказов**: только Ozon/Яндекс/МегаМаркет; до загрузки этикеток; не для маркируемых товаров; заказ ≥2 шт. Для Ozon — заказ в статусе «Ожидает сборки». Для WB недоступно.
- **Маркировка**: этикетка заказа доступна только после передачи КИЗ; для Яндекс Маркета — строго сначала КИЗ, потом этикетка; передача КИЗ на разделённые заказы — только Ozon. Проверка GTIN: GTIN КИЗ должен совпадать с GTIN карточки.
- **Срок годности (WB)**: передаётся, если до окончания ≥30 дней.
- **Поставки**: закрывать только через SelSup (закрытие на МП → отображается незакрытым в SelSup). Для WB — обязательная сверка состава; QR-коды коробов не генерируются после закрытия поставки (только СЦ). Поставки Ozon/Яндекс/МегаМаркет — внутренние (через API не создаются).
- **B2B-заказы (WB)**: B2C и B2B — раздельные поставки; (Ozon — смешивание разрешено, но стикер после маркировки).
- **Резерв/списание**: в опте остатки списываются при выходе из «Новый»/«На сборке»; в рознице — при финальном статусе; нельзя удалять/восстанавливать отгруженный заказ (остатки не вернутся в резерв — создавать новый).
- **Адресное хранение**: ячейка отображается только при оприходовании через адресное хранение; заказ до приёмки → пересоздать; строгий отбор из указанных ячеек.
- **Сборка в ЛК МП**: требует ручного перевода в «Собран» в SelSup/1С (иначе зависший резерв); статусы не обновляются до «Передан в доставку».
- **КГТ (Ozon)**: отдельный склад; поле «Игнорировать/только склады FBS» во избежание ошибок при двух связях.
- **Первый импорт**: только «Импорт заказов» (без обновления остатков), чтобы не обнулить остатки МП; автоматический импорт/синхронизация — после ввода и проверки остатков в SelSup.
- **Этикетки/лента**: код маркировки в ленте — только после резервирования; не скачивается в PDF; привязанный через «Задания» код в ленту не попадает. Совмещённый PDF (товарная + этикетка) — только через QZ Tray.
- **Расхождения SelSup↔МП**: обновление раз в 15–30 минут; для устаревших ошибок — перезапуск импорта; кнопка «Обновить статусы и этикетки» — только для заказов текущей страницы.
- **МойСклад**: разделить заказ в SelSup ДО создания в МойСклад.
- **Ламода/прочие**: поддерживается расширенное соответствие статусов (Отправлен, В пути, Выкуплен, Отменён, Возврат и т.д.).
- **FBO**: поставки FBO не создаются через API МП (загрузка файлов вручную); SelSup не управляет остатками FBO, а транслирует от МП (обновление раз в день); при поставке остатки списываются только при включении «Списать остатки».

## Открытые вопросы / чего не хватает в доках

- **Срок годности**: «в SelSup пока нет возможности просмотреть указанный срок годности» (в разработке) — нет UI просмотра переданного срока.
- **Разделение маркированных заказов Ozon**: «работаем над решением» — нельзя разделить маркированный заказ на Ozon (статус меняется сразу).
- **МегаМаркет**: «работа с поставками и печать документов пока недоступны через API» — ожидается поддержка.
- **Поставки Ozon/Яндекс/МегаМаркет через API**: не создаются напрямую — только внутренние в SelSup; не описан механизм синхронизации статусов этих внутренних поставок с МП при расхождениях.
- **Точная частота обновления**: в разных статьях указано «раз в 15 минут» и «каждые полчаса» (30 минут) — противоречие в данных обновления по API.
- **Яндекс Маркет: «одна организация — один склад»** — описано как правило определения склада, но не описано, как обрабатывать несколько складов для одной организации или миграцию связей.
- **Лента заказов/совмещённый PDF**: ограничение «скачать такую ленту напрямую из SelSup нельзя» (товарная в браузере, этикетка МП в PDF) — нет встроенного решения, только QZ Tray; не описан fallback.
- **КГТ**: не описан полный цикл сборки/отгрузки КГТ-заказа, отличия от обычного FBS, ограничения по коробам/габаритам при отгрузке.
- **Гибридные DBS**: не детализирован сценарий формирования двух стикеров (МП + ТК) — только общее упоминание «используйте все стикеры».
- **Опт/розница — передача маркировки**: упоминается «как для заказов с маркетплейсов», но без пошагового процесса ввода/вывода из оборота и связи с B2B-документооборотом.
- **Дропшиппинг — заказ поставщику**: не описана автоматизация создания заказа поставщику из приходящего заказа покупателя (упомянута функция «Закупки из заказов», но без деталей интеграции статусов).
- **Штрафы/отмена**: при отмене позиции/заказа «в некоторых маркетплейсах вы получите штраф» — без перечня МП и условий.
- **1С**: настройка эмуляции/драйверов вынесена за рамки SelSup («настройку оборудования необходимо провести самостоятельно») — нет готового коннектора.
- **Камера телефона**: не описаны ограничения (качество скана, модели штрихкодов, производительность при больших партиях).
- **Видеофиксация**: настройка «Печатать этикетку о видеофиксации» описана, но интеграция с системами видеофиксации сборки не раскрыта.
- **Дата начала сборки**: фиксируется при сканировании комплекта — не описано, фиксируется ли для некомплектных заказов и как используется в KPI besides Excel-выгрузки.
