# Закупки, производство, комплекты и себестоимость

## Назначение

Модуль объединяет полный цикл управления товарными запасами селлера на маркетплейсах «до продажи»: планирование и оформление закупок у поставщиков, ведение базы поставщиков и взаиморасчётов с ними, учёт производственных операций (техпроцессы, техкарты, производственные заказы), работу с комплектами (создание, сборка, маркировка, автоматический расчёт остатков и себестоимости), три режима расчёта себестоимости (классический FIFO по партиям, упрощённый FIFO, последняя себестоимость), ввод и обновление закупочных цен, работу с товарами со сроком годности (FIFO-выдача, этикетки хранения), а также обработку возвратов и брака. Ключевое преимущество модуля — разделение конфиденциального процесса закупок (цены, поставщики) и процесса создания контента (карточки), а также максимально точный партийный учёт себестоимости, влияющий на корректность прибыли и unit-экономики.

## Возможности (capabilities)

1. **Создание заказа поставщику (закупки).** Формирование документа закупки с указанием названия, организации, валюты (для иностранных поставщиков), поставщика; добавление товаров с фото, количеством, закупочной ценой и стоимостью доставки на единицу; автоматический расчёт розничной цены по формуле `(Закупочная цена × Коэффициент) + доставка`; подсчёт общего количества и суммы закупки; автоприсвоение номера заказа.

2. **Автоматический расчёт розничной (закупочной→розничной) цены.** Расчёт по настраиваемому коэффициенту розничной цены в настройках закупок; возможность переопределения вручную для каждого товара.

3. **Приёмка товара из закупки.** Создание приёмки на склад напрямую из заказа поставщику; автоматическая двусторонняя связь закупки и приёмки через «Связанные документы»; перенос товаров из закупки в приёмку.

4. **Выявление расхождений при приёмке.** Сценарий «заказать всё → удалить → отсканировать фактический приход → сравнить»; вкладка «Расхождения» в заказе поставщику показывает недопоставку, излишки и иные расхождения между заказанным и принятым.

5. **Поля приёмки: «Есть?», «Брак», «Комментарий».** Отметка факта прихода товара, фиксация количества брака (подлежащего возврату поставщику) и комментариев — для контроля приёмки сотрудниками.

6. **Планирование закупок.** Анализ продаж/заказов за период, расчёт рекомендуемого количества к закупке для поддержания остатков N дней; параметры: маркетплейс, период анализа, «на сколько дней планировать остатки», «рекомендованное количество от», «пропускать дни без остатков», «делать расчёт по заказам» (с учётом возвратов/невыкупов) или по фактическим продажам; кнопка «Рассчитать» + добавление строк в заказ.

7. **Закупки из заказов (дропшиппинг).** Автоматическое формирование списка товаров из FBS-заказов со статусами «Новый»/«На сборке», не входящих в актуальную закупку; фильтрация по поставщику, привязанному к карточке; переход к созданию закупки у поставщика; независимость от остатков.

8. **Статус заказов «В закупке».** Внутренний статус FBS-заказа, проставляется автоматически при попадании заказа в закупку из раздела «Закупки из заказов»; не передаётся на маркетплейс; включается опцией в настройках.

9. **«Заменять комплекты на компоненты».** В выгрузках Excel по закупкам и FBS-заказам показывает составляющие вместо собранных комплектов — для точного планирования закупки компонентов; обратимо.

10. **База поставщиков.** Ведение справочника контрагентов: добавление поштучно (через карточку), импорт из Excel, добавление в момент закупки, экспорт базы в Excel; поля поставщика — название/ИНН, произвольное наименование, контактное лицо, email, телефон, ссылка.

11. **Привязка поставщика к товарам.** Массовая привязка через Excel (скачать файл с товарами → выбрать поставщика из списка → загрузить); массовое удаление привязки через столбец «Удалить = Да»; один товар может иметь нескольких поставщиков.

12. **Вкладка «Для закупки».** Рейтинг поставщиков по самому продаваемому товару — подсказка, у кого закупаться в первую очередь; переход к созданию заказа.

13. **Взаиморасчеты с поставщиками.** Две таблицы: обороты за период (сумма закупок и оплат без фильтра по поставщику, в виде таблицы/диаграммы) и детализация по поставщику (сумма закупки, оплаты, даты); ручное добавление платежей (контрагент, дата, сумма); редактирование/удаление платежей и связанных закупок; выгрузка в Excel.

14. **Отчёт «Продажи по поставщикам».** Продажи/возвраты в шт. и руб., выручка, остаток в шт. и закупочных ценах, проданный товар в закупочных ценах, средняя фактическая цена продажи `(продажи − возвраты, руб.) / (продажи − возвраты, шт.)`; фильтры по периоду и организации; выгрузка в Excel (две вкладки: по организациям и «без организаций»); попадают товары с продажами либо с остатком.

15. **Дропшиппинг-обмен с поставщиком.** Регулярный обмен прайс-листом поставщика; остатки поставщика автоматически транслируются на маркетплейсы через SelSup; уменьшение остатка у поставщика → уменьшение в SelSup и на маркетплейсах.

16. **Файлы заказа поставщику.** Скачивание заказа в Excel; отдельный «Шаблон для карго» (товары, возможный брак, цены, доп. расходы, ссылка на сайт поставщика; цены в валюте страны поставщика).

17. **Единицы измерения товаров.** Поля «Единица измерения» и «Количество в единицах измерения» (м, л, упаковка, пачка и т. п.); массовое заполнение через Excel; пересчёт аналитики (перезагрузка аналитики); отображение товарооборота в единицах измерения (настраиваемая опция) и в дашборде.

18. **Производство: процессы.** Создание производственных процессов и этапов (название, описание) с редактированием/удалением.

19. **Производство: технологические карты (техкарты).** Создание техкарт (название, описание, процесс); копирование техкарты с новым ID и переносом всех параметров; разделы «Материалы» (компоненты + количество), «Результат» (выпускаемая продукция), «Зарплата», «Документы»; поиск по названию/процессу.

20. **Производство: производственные заказы.** Создание заказа (название, даты начала/окончания, техкарта); вкладки «Детали/Материалы/Результат»; подтверждение заказа с выбором склада списания материалов и склада приёмки продукции; автоматическое резервирование материалов при подтверждении; статус «Заказ выполнен» → автоматическое списание материалов и оприходование результата; аналитика стоимости (материалы, доп. расходы, зарплата, общая стоимость).

21. **Производственные заказы из FBS-заказов.** Создание производственного заказа по товарам из FBS-заказов (при наличии техкарты с материалом, результатом, планом и ≥1 этапом); выбор складов списания/приёмки; объединение нескольких FBS-заказов на один товар в один производственный заказ; расчёт норматива (округление вверх); статус «Подтверждён» сразу; флаг «Есть производственный заказ?» в таблице FBS-заказов; список ошибок по неподходящим товарам.

22. **Расчёт норматива производства.** `Норматив = количество товара в FBS-заказах / количество результата за 1 норматив` с округлением вверх; оприходование избыточного количества готового товара на склад приёмки.

23. **Диаграмма Ганта для производства.** Визуализация производственных заказов по статусам (голубой — черновик, зелёный — подтверждённый, синий — выполненный); фильтр по периодам (четверть дня, полдня, день, неделя, месяц); детали заказа (дата начала, дедлайн, прогресс).

24. **Создание комплектов.** Тип товара «Комплект» в карточке (с возможностью указать тип для каждого размера); вкладка «Комплекты» — состав (один/несколько товаров) и количество каждой составной части; массовая загрузка через Excel (артикул/ШК комплекта, артикул/ШК составляющего, количество); проверка данных с отчётом об ошибках.

25. **Редактирование комплектов.** Одиночное редактирование состава в карточке (добавить/удалить крестиком, изменить количество); массовое редактирование через экспорт/импорт Excel.

26. **Создание комплектов из товаров разных организаций.** При импорте — флаг «Не учитывать организацию» (поиск комплектующих без привязки к организации); без флага — только комплектующие из той же организации.

27. **Изменение типа товара (Комплект ↔ Товар).** Массово через Excel (столбец «Вид товара»); при смене Комплект→Товар состав комплектующих не удаляется и восстанавливается при обратной смене.

28. **Автоматический расчёт остатков комплектов (Умный склад).** Колонка «Рассчитанные остатки» = максимальное количество комплектов, собираемое из остатков комплектующих (минимум по каждому компоненту); добавляется к ручному «Остатку»; пересчёт и трансляция на маркетплейс при заказе комплекта или любой комплектующей; связывание по остаткам — достаточно привязать только комплект.

29. **Автоматический учёт остатков комплектов на маркетплейсах.** Мгновенный пересчет всех связанных комплектов при заказе одного (каскадно — комплект из 7 частей, каждая в 500 комплектах → обновление 3500 комплектов).

30. **Гибкий расчёт себестоимости комплектов.** По умолчанию себестоимость комплекта задаётся отдельно; тумблеры «Пересчитывать закупочную цену комплектов» и «Пересчитывать доп. расходы комплектов» — автосумма себестоимостей компонентов при изменении цены любого компонента.

31. **Сборка заказов с комплектами.** Поддержка FBS/FBO/DBS; в заданиях на сборку отображается полный состав комплекта с фотографиями; подсказки по составу и замена комплектов на компоненты.

32. **Маркировка комплектов (Честный Знак).** Подготовка карточки комплекта в ЧЗ (GTIN, тип: Набор/Комплект/Групповая упаковка); получение кодов маркировки на комплект и комплектующие одной кнопкой; агрегация кодов (связывание кода комплекта с кодами комплектующих) с подписью и отправкой в ЧЗ; печать кодов, сгруппированных по комплектам; ввод в оборот только комплектующих (комплект вводится ЧЗ автоматически).

33. **3 режима расчёта себестоимости.** Классический FIFO (партийный, с приёмками), упрощённый FIFO (без склада — себестоимость из карточки на момент обработки аналитики), FIFO выключен (последняя себестоимость с пересчётом всей истории). Переключатель в настройках аналитики; FIFO включён по умолчанию.

34. **Ввод закупочных цен.** Через интерфейс раздела «Цены» или Excel; формула `Себестоимость = закупочная цена + доп. расходы`; доп. расходы — в рублях или в % от цены продажи (`Доп. расходы в руб. = Доп. расходы в % × цена «со скидкой текущая»`); кнопка «Обновить закупочные цены в аналитике».

35. **Обновление закупочных цен по режимам.** Классический FIFO — через новую приёмку (новую партию); упрощённый FIFO — в разделе «Цены» (применится при следующей загрузке аналитики); FIFO выключен — в «Ценах» с пересчётом всей истории.

36. **Формирование «Проданный товар в закупочных ценах».** Значение в отчёте юнит-экономики берётся из столбца «Закупочная цена на момент операции» отчёта по операциям с маркетплейса; корректировка цены возможна через экспорт/импорт этого отчёта.

37. **FIFO при работе со складом.** FBS — списание по FIFO (первыми уходят товары, принятые раньше); при адресном хранении в листе сборки указывается ячейка с самыми ранними остатками; даже возвращённые товары учитываются по дате первоначальной приёмки. FBO — FIFO для отгрузок; каждая продажа списывает товар с виртуального склада FBO; возврат идёт в остаток, и возвращённый старый остаток списывается в приоритете.

38. **Товары со сроком годности: ввод.** Указание срока годности в приёмке на склад (хранится и учитывается в остатках по партии); массовое заполнение протягиванием ячейки (как в Excel).

39. **Срок годности и маркировка (Честный Знак).** Сохранение срока годности в коде маркировки; автоподстановка срока годности в сборку FBS из КИЗа; получение даты производства и срока годности из ЧЗ (при сборке или вручную в разделе «Коды маркировки»).

40. **FIFO-выдача по сроку годности.** При сборке первыми выдаются товары с более ранним сроком (FEFO-логика поверх FIFO).

41. **Этикетка хранения.** Настраиваемый шаблон «Этикетка хранения товара»; печать из приёмки и из вкладки «Остатки»; данные — штрихкод хранения, номер модели, название, цвет, размер, срок годности, серийный номер партии; поддержка уникальных кодов партии.

42. **Обработка возвратов и брака.** Задание «Возврат товара»: сканирование штрихкода/QR заказа (WB, Ozon, Яндекс.Маркет, МегаМаркет) или штрихкода товара; автоматический возврат остатков с исходной закупочной ценой и местом хранения; частичный возврат (только отсканированные позиции); кнопка «Возврат получен» → статус «Возврат получен» и возврат в прежнюю ячейку; в аналитике возвраты и брак не учитываются.

43. **Интеграция с МойСклад.** Создание связанного документа заказа поставщику в МойСклад из закупки SelSup; импорт комплектов из МойСклад (тумблер в настройках импорта).

44. **Разделение прав (конфиденциальность).** Закупщики/владельцы видят закупочные цены и поставщиков; менеджеры/товароведы/фрилансеры работают с контентом без доступа к конфиденциальным данным.

## Ключевые сценарии (workflows)

### WF1. Создание закупки у поставщика
1. Раздел «Закупки» → «Создать».
2. Заполнить название заказа.
3. Выбрать организацию (фильтр).
4. Выбрать валюту (для иностранных поставщиков).
5. Выбрать/создать поставщика (кнопка «+», заполнить карточку: организация/ИНН, наименование, контакты).
6. «Добавить товар»: фото, название, количество, закупочная цена, стоимость доставки на единицу.
7. Розничная цена рассчитывается автоматически по коэффициенту (или вручную).
8. Сохранить → заказу присвоен номер.
9. (Опц.) Создать связанный документ в МойСклад кнопкой.
10. (Опц.) Скачать Excel / «Шаблон для карго».

### WF2. Приёмка и выявление расхождений с поставщиком
1. Открыть заказ поставщику → «Создать приёмку».
2. Указать название приёмки, склад, организацию, контрагента.
3. Выделить все автоматически перенесённые товары → «Удалить выбранные товары».
4. Отсканировать фактически полученные товары.
5. Сохранить приёмку.
6. Вернуться в заказ поставщику → вкладка «Расхождения»: посмотреть недопоставку/излишки.
7. Заполнить поля «Есть?», «Брак», «Комментарий» в таблице товаров заказа (при работе сотрудников).

### WF3. Планирование закупок
1. «Закупки» → «Создать» → указать название, поставщика, организацию.
2. Внизу → «Товары для покупки» → вкладка «Планирование закупок» (только если выключена опция «Закупки из заказов» в интеграциях).
3. Выбрать маркетплейс, период анализа.
4. Указать «На сколько дней планировать остатки».
5. Указать «Рекомендованное количество от» (минимум для рекомендации).
6. Настроить «Пропускать дни без остатков», «Делать расчёт по заказам».
7. «Рассчитать» → в таблице появятся рекомендованные товары и количества.
8. «Добавить» нужные строки → скорректировать количество в заказе → сохранить.

### WF4. Закупки из заказов (дропшиппинг)
1. Убедиться, что у карточек указан Поставщик (через интерфейс или импорт привязки).
2. Раздел «Закупки из заказов».
3. Просмотреть товары из FBS-заказов (статусы «Новый»/«На сборке», не в актуальной закупке).
4. (Опц.) Скачать Excel списка товаров.
5. Нажать поставщика в столбце «Название» → перейти к созданию закупки.
6. Добавить товары в закупку, сохранить.
7. Заказы получают внутренний статус «В закупке» (если опция включена).
8. Передать список поставщику, ожидать поступление.

### WF5. Работа с базой поставщиков
1. «Закупки → Поставщики → База поставщиков».
2. «Добавить поставщика» (или «Шаблон» → заполнить → «Импортировать», или добавить в момент закупки).
3. Привязка к товарам: вкладка «Привязка поставщика к товару (импорт)» → «Скачать файл с товарами» → выбрать поставщика → «Загрузить поставщиков товаров».
4. Массовое удаление привязки: столбец «Удалить = Да» → загрузить.
5. Редактировать/удалить поставщика через значки в «Базе поставщиков».

### WF6. Взаиморасчёты с поставщиками
1. «Закупки → Взаиморасчеты».
2. Просмотреть таблицу оборотов (таблица/диаграмма) и детализацию по поставщику.
3. «Добавить платеж» → выбрать контрагента (или «+» для нового), дату, сумму → «Сохранить».
4. Редактировать (карандаш) / удалить (крестик) платёж.
5. «Скачать Excel».

### WF7. Ввод и обновление закупочных цен
1. Определить режим учёта (Классический FIFO / Упрощённый FIFO / FIFO выключен) в «Настройки → Аналитика».
2. Ввести закупочную цену и доп. расходы (руб. или %) в разделе «Цены» (интерфейс или Excel).
3. Себестоимость рассчитается автоматически (`закупка + доп. расходы`).
4. «Обновить закупочные цены в аналитике».
5. Обновление цены:
   - Классический FIFO — через новую приёмку (новую партию).
   - Упрощённый FIFO — в «Ценах» (применится при следующей загрузке аналитики).
   - FIFO выключен — в «Ценах», система пересчитает всю историю.

### WF8. Создание и расчёт себестоимости комплекта
1. В карточке товара выбрать тип «Комплект» (для каждого размера отдельно, если нужно).
2. Вкладка «Комплекты» → добавить составные товары и количество → «Сохранить».
   - Альтернатива: «Товары → Импорт товаров → Комплекты файлом» (заполнить шаблон, загрузить, исправить ошибки по файлу ошибок).
3. Включить (опц.) «Пересчитывать закупочную цену комплектов» и «Пересчитывать доп. расходы комплектов» в «Настройки → Цены».
4. Остатки: «Склад → Остатки на складе» → колонка «Рассчитанные остатки» (минимум по компонентам) + колонка «Остаток» (ручной).
5. Проверить себестоимость: при FIFO — в приёмках комплектующих; при «Нет FIFO» — в карточке товара и отчёте по операциям.

### WF9. Производство: от техкарты до готовой продукции
1. «Производство → Процессы» → «Добавить процесс» → «Добавить этап процесса» (название, описание).
2. «Производство → Техкарты» → «Создать новую техкарту» (название, описание, процесс) → «Создать».
3. Заполнить разделы «Материалы», «Результат», (опц.) «Зарплата», «Документы». (Опц. «Копировать» для новой техкарты.)
4. «Производство → Производственные заказы» → указать название, даты, техкарту → «Создать заказ» → «Перейти к заказу».
5. Проверить вкладки «Детали/Материалы/Результат».
6. «Подтвердить заказ» → выбрать склад списания материалов и склад приёмки продукции → подтвердить (материалы резервируются).
7. По завершении — «Заказ выполнен» → материалы списаны, результат оприходован.
8. Просмотреть аналитику (стоимость материалов, доп. расходы, зарплата, общая стоимость).

### WF10. Производственный заказ из FBS-заказов
1. У товара должна быть настроена техкарта (материал, результат, план, ≥1 этап).
2. В FBS-заказах выбрать заказ(ы) → «Создать производственный заказ».
3. Выбрать склад списания материалов и склад приёмки продукции.
4. Подтвердить → заказ(ы) созданы в статусе «Подтверждён», материалы зарезервированы.
5. Норматив = (кол-во товара в FBS-заказах) / (результат за 1 норматив), округление вверх.
6. После завершения — материалы списаны, готовый товар на складе приёмки, статус «Выполнен». Флаг «Есть производственный заказ?» в FBS-таблице.

### WF11. Маркировка комплектов (Честный Знак)
1. Создать карточку комплекта в ЧЗ (GTIN, тип: Набор/Комплект/Групповая упаковка).
2. В SelSup проверить, что товар — «Комплект» с заполненным составом и GTIN у комплектующих.
3. Добавить комплект в заказ на отгрузку или приёмку.
4. На этапе получения маркировки — кнопка получения маркировки на комплектующие → получены коды комплекта и комплектующих.
5. Раздел «Агрегация» → «Агрегировать комплекты» → сформировать документ агрегации → подписать и отправить в ЧЗ.
6. Напечатать коды (сгруппированы: код комплекта + коды комплектующих).
7. Ввести в оборот комплектующие (комплект вводится автоматически).

### WF12. Работа с товарами со сроком годности
1. В приёмке указать срок годности (массово — протягиванием ячейки).
2. При приёмке с кодами маркировки — срок сохранится в коде; либо получить дату производства/срок из ЧЗ (при сборке или вручную в «Коды маркировки»).
3. При сборке FBS — автоподстановка срока годности из КИЗа; FIFO-выдача — первыми товары с ранним сроком.
4. Печать «Этикетки хранения» (из приёмки или «Остатков»); при использовании уникальных кодов партии — «Получить уникальные коды» перед оприходованием.

### WF13. Обработка возвратов и брака
1. «Задания → Возврат товара».
2. Выбрать организацию/склад/маркетплейс (необязательно, если сканируется штрихкод заказа).
3. Отсканировать штрихкод/QR заказа (WB, Ozon, Яндекс.Маркет, МегаМаркет) или штрихкод товара из заказа (статус «Возврат»/«Забрать возврат»/«Отменён покупателем»).
4. Отсканировать остальные товары заказа для возврата + печать этикеток.
5. (Опц.) «Возврат получен» без поштучного сканирования.
6. Заказ → статус «Возврат получен», остатки возвращены в прежнюю ячейку с исходной закупочной ценой. Частичный возврат — только отсканированные позиции. Возвраты и брак в аналитике не учитываются.

## Сущности (entities)

- **Заказ поставщику (закупка)**: ID/номер; название; организация; валюта; поставщик (ссылка); список позиций (товар, количество, закупочная цена, доставка на единицу, розничная цена); итоги (количество, сумма); статус; связь с приёмкой; поля позиции «Есть?», «Брак», «Комментарий»; вкладки «Заказ», «Цены», «Расхождения», «Товары для покупки» (с подпунктами «Планирование закупок»/дропшиппинг), «Связанные документы».
- **Поставщик (контрагент)**: ID; название/ИНН (организация); произвольное наименование; контактное лицо; email; телефон; ссылка; связи с товарами (один ко многим).
- **Привязка поставщика к товару**: товар → поставщик (с возможностью нескольких поставщиков); маркер удаления.
- **Приёмка на склад**: ID; название; склад; организация; контрагент; позиции (товар, количество, закупочная цена, срок годности, код маркировки/КИЗ); связь с заказом поставщику; вкладки «Расхождения», «Остатки».
- **Партия товара** (для FIFO): товар; количество; себестоимость; дата/время прихода; (для срока годности) срок годности, дата производства; источник — приёмка.
- **Платёж поставщику** (взаиморасчёты): контрагент; дата; сумма.
- **Взаиморасчёты (оборот)**: период; сумма закупок; сумма оплат (по поставщику / агрегированно).
- **Единица измерения товара**: единица измерения; количество в единицах измерения (на размер/цвет).
- **Производственный процесс**: ID; название; этапы (ID, название, описание).
- **Технологическая карта (техкарта)**: ID; название; описание; процесс; раздел «Материалы» (материал + количество); раздел «Результат» (выпускаемая продукция + количество за 1 норматив); раздел «Зарплата»; раздел «Документы».
- **Производственный заказ**: ID; название; дата начала; дата окончания; техкарта; норматив; склад списания материалов; склад приёмки результата; статус (черновик/подтверждён/выполнен); связь с FBS-заказами; вкладки «Детали/Материалы/Результат»; аналитика стоимости.
- **Комплект (тип товара)**: тип «Комплект»; состав (составной товар + количество); расчётная/ручная себестоимость; рассчитанный остаток; ручной остаток; GTIN; флаг «не учитывать организацию» при импорте.
- **Состав комплекта**: артикул/ШК комплекта; артикул/ШК составляющего; количество.
- **Закупочная цена / себестоимость товара**: закупочная цена; доп. расходы (руб. или % от цены продажи); себестоимость (`= закупка + доп. расходы`); «закупочная цена на момент операции» (историческая).
- **Код маркировки (КИЗ)**: код; срок годности; дата производства; GTIN; связи агрегации (комплект ↔ комплектующие); документ агрегации.
- **Возврат**: заказ; позиции; исходная закупочная цена; место хранения (ячейка); статус «Возврат получен».
- **Этикетка хранения**: шаблон; штрихкод хранения; номер модели; название; цвет; размер; срок годности; серийный номер партии.
- **Отчёт «Продажи по поставщикам»**: поставщик; продажи (шт./руб.); возвраты (шт./руб.); выручка; остаток (шт./закупочные цены); проданный товар в закупочных ценах; средняя фактическая цена продажи; разрезы — по организациям / «без организаций».

## Интеграции

- **Маркетплейсы (Wildberries, Ozon, Яндекс.Маркет, СберМегаМаркет и др.)**: приём FBS-заказов в закупки/производство; трансляция рассчитанных остатков комплектов; списание/возврат остатков; получение штрихкодов/QR заказов для возвратов; загрузка аналитики продаж (по WB — понедельно). FBO — работа через виртуальные склады FBO со списанием по FIFO.
- **Честный Знак (ЧЗ)**: получение кодов маркировки на комплекты и комплектующие; агрегация кодов с подписью и отправкой; получение даты производства и срока годности по КИЗу; авто-ввод комплекта в оборот при вводе комплектующих; ручное обновление кодов в разделе «Коды маркировки».
- **МойСклад**: создание связанного документа заказа поставщику из SelSup; импорт комплектов из МойСклад (тумблер в настройках импорта).
- **1С** (через общий механизм интеграций SelSup): учёт закупок и взаиморасчётов (упоминается в общем контексте SelSup, детально в данном модуле не раскрыт).
- **Поставщик (дропшиппинг)**: регулярный обмен прайс-листом; синхронизация остатков поставщика с маркетплейсами.
- **Регулярные обмены (автообмен)**: автоматическое обновление цен и остатков на маркетплейсах; использование при закупках из заказов.

  - «Коэффициент розничной цены» (формула `(закупка × K) + доставка`).
  - «Заменять комплекты на компоненты» (вкл/выкл).
- **Настройки → Заказы**:
  - опция «В закупке» (включение внутреннего статуса FBS-заказов).
- **Настройки → Аналитика**:
  - «Метод учета себестоимости (FIFO)» — ФИФО / Нет ФИФО (по умолчанию FIFO включён).
  - «Отображать товарооборот в единицах измерения товара» (вкл/выкл).
  - «Перезагрузить аналитику» (действие после изменения единиц измерения).
  - «Обновить закупочные цены в аналитике» (действие).
- **Настройки → Цены**:
  - «Пересчитывать закупочную цену комплектов» (вкл/выкл).
  - «Пересчитывать доп. расходы комплектов» (вкл/выкл).

- **Интеграции**: опция «Закупки из заказов» (вкл/выкл — взаимоисключает вкладку «Планирование закупок»); тумблер импорта комплектов из МойСклад; флаг «Не учитывать организацию» при импорте комплектов.

## Бизнес-правила и ограничения

- Раздел закупок и создания контента разделены: права доступа скрывают закупочные цены и поставщиков от контент-менеджеров/фрилансеров.
- Розничная цена по умолчанию рассчитывается автоматически: `(Закупочная цена × Коэффициент) + доставка`; может быть переопределена вручную.
- Себестоимость всегда = закупочная цена + дополнительные расходы; доп. расходы задаются в рублях или в % от цены продажи (`% × цена «со скидкой текущая»`).
- Вкладка «Планирование закупок» доступна только если выключена опция «Закупки из заказов» в интеграциях.
- Список «Закупки из заказов» показывает товары заказов в статусах «Новый»/«На сборке» и не входящие в актуальную закупку; закупки из заказов не связаны с остатками и не учитывают резерв.
- Статус «В закупке» внутренний, не передаётся на маркетплейс.
- Рассчитанный остаток комплекта = минимум по всем компонентам (кол-во компонента ÷ кол-во в комплекте); всегда добавляется к ручному остатку; для показа только расчётного — обнулить ручной.
- Достаточно связать по остаткам только сам комплект; комплектующие отдельно не связываются.
- Себестоимость комплекта по умолчанию задаётся отдельно; автосумма из компонентов — только при включённых тумблерах пересчёта.
- При FIFO себестоимость берётся из партий (приёмок); при FIFO + отсутствии остатка на момент продажи — из карточки; при «Нет FIFO» — всегда из карточки (последнее значение).
- При классическом FIFO менять цену просто в «Ценах» запрещено — только через новую приёмку (партию).
- При упрощённом FIFO аналитика считается по цене на момент её обработки (запаздывающая аналитика может посчитаться по новой цене).
- При выключенном FIFO изменение себестоимости пересчитывает всю историю задним числом.
- Аналитика по Wildberries импортируется только по неделям — на текущую дату данных может не быть.
- Производственный заказ требует техкарту с материалом, результатом, планом производства и ≥1 этапом; иначе товар не обрабатывается и выдаётся список ошибок.
- Норматив производства округляется вверх (`=` кол-во / результат за 1 норматив); излишек готовой продукции остаётся на складе приёмки.
- При создании производственного заказа из нескольких FBS-заказов на один товар создаётся один общий заказ; по уже созданному заказу повторное создание блокируется (ставится галочка).
- Карточка комплекта в SelSup не создаётся — сначала создаётся в Честном Знаке (GTIN, тип Набор/Комплект/Групповая упаковка); у комплектующих должны быть GTIN.
- В оборот вводятся только комплектующие; комплект вводится ЧЗ автоматически.
- Комплекты не создаются по артикулу Wildberries (только другие маркетплейсы / внешний артикул); у комплектующего должно быть заполнено хотя бы одно поле — ШК или артикул.
- При флаге «Не учитывать организацию» поиск комплектующих идёт без привязки к организации — нельзя использовать при одинаковых ШК в разных организациях.
- Смена типа Комплект→Товар не удаляет состав; обратная смена восстанавливает.
- FIFO/FEFO: первыми выдаются/списываются товары с более ранним сроком годности и более ранней приёмкой; при адресном хранении подсказывается ячейка с ранними остатками; возвращённые товары учитываются по дате первоначальной приёмки; при FBO возвращённый старый остаток списывается в приоритете.
- Возвраты и брак не учитываются в аналитике.
- «Проданный товар в закупочных ценах» формируется из «Закупочной цены на момент операции» отчёта по операциям с маркетплейса.
- Отчёт «Продажи по поставщикам» требует указания поставщика в карточке товара; при нескольких поставщиках у одной карточки аналитика отражается по всем.

## Открытые вопросы / чего не хватает в доках

- Детальная модель прав доступа: какие роли и какие именно поля/разделы скрываются (в доках описано только концептуально «закупки vs контент»).
- Механизм работы с браком как самостоятельной операцией: поле «Брак» фиксируется, но процесс возврата брака поставщику (документы, взаиморасчёты, списание) отдельно не описан.
- Алгоритм расчёта «проданных товаров» и резервирования при планировании закупок (формула рекомендованного количества за исключением общих параметров не раскрыта).
- Поведение модуля при частичных оплатах и зачётах авансов во взаиморасчётах (только фиксация платежей).
- Интеграция с 1С на уровне закупок/себестоимости не детализирована в статьях модуля.
- Сроки и триггеры автообновления остатков комплектов на маркетплейсах (частота, лимиты каскадного пересчёта).
