# Аналитика и финансы

> Спецификация модуля для воссоздания функционала. Источник: 27 статей базы знаний SelSup (раздел «Аналитика и финансы»).

## Назначение

Модуль «Аналитика и финансы» — это ядро управленческого и финансового учёта SelSup. Он автоматически собирает по API сырые операции с маркетплейсов (Wildberries, Ozon, Яндекс Маркет, МегаМаркет), сводит их в единую систему показателей и рассчитывает сквозную финансовую картину: выручку, себестоимость, валовую и чистую прибыль, маржинальность, налоги (УСН / ОСНО) и НДС. Цель модуля — дать селлеру прозрачную, проверяемую (с публичными формулами) аналитику по всем маркетплейсам и организациям в одном месте, без ручного сведения десятков отчётов, а также инструменты для сверки данных с ЛК маркетплейсов.

Ключевой принцип — **прозрачность формул**: каждое значение можно посмотреть во всплывающей подсказке и проверить в Excel-выгрузке (формулы сохраняются). Большинство данных тянется по API; ручная загрузка отчётов — резервный механизм на случай сбоев API.

## Возможности (capabilities)

### А. Сбор и хранение данных
1. **Автоматическая загрузка операций по API** из маркетплейсов (продажи, возвраты, комиссии, логистика, штрафы, реклама, хранение, удержания, услуги, прочие начисления). Глубина по API — последние 3 месяца (бесплатный тариф); «Джем» для WB даёт всю историю; Ozon Премиум — 6 месяцев, Премиум Плюс — вся история.
2. **Ручной импорт финансовых отчётов** из ЛК маркетплейсов (Excel/zip) — резерв при сбоях API или для данных старше 3 месяцев. Поддерживаются WB, Ozon, Яндекс Маркет, МегаМаркет.
3. **История загрузки отчётов** — журнал ранее загруженных вручную файлов с фильтрами (организация, маркетплейс, дата) и удалением ошибочно загруженных.
4. **Перезагрузка (пересчёт) аналитики** вручную за выбранный период/организацию/маркетплейс после изменения настроек или данных.
5. **Обновление данных**: заказы/продажи — каждые 30 минут; финансовые показатели — после обработки маркетплейсом (WB раз в неделю/день, Ozon раз в месяц, Яндекс Маркет раз в неделю).
6. **Аналитика в разных валютах** — пересчёт всей финансовой аналитики и отчётов в выбранную валюту (для управленческого учёта не в рублях), курс на дату операции, источник курса — ЦБ РФ или Ozon. Не влияет на цены в карточках товаров и отправку цен на МП.

### Б. Финансовые отчёты
7. **Отчёт о прибылях и убытках (P&L)** — главный отчёт: доходы, расходы, валовая/маржинальная/чистая прибыль, маржинальность, рентабельность, ДРР, доли логистики/комиссии/рекламы в выручке, налоги. Детализация по дням/неделям/месяцам/годам. Сводный отчёт по нескольким организациям. Детализация налога (УСН/НДС, ОСНО: налог на прибыль + НДС). Детализация расходов на МП по статьям.
8. **Товарная аналитика (юнит-экономика)** — прибыль по каждому артикулу/категории/бренду/цветомодели/штрихкоду. Параметры: продажи/возвраты (шт., руб.), логистика, комиссия, штрафы, доплаты, услуги, СПП, себестоимость, ROI, маржинальность, эффективности по выручке/прибыли, ДРР. Группировки, «среднее за 1 единицу», настраиваемые столбцы Excel.
9. **Отчёт по операциям с маркетплейса (Profit Report)** — сырые данные по всем операциям со всех площадок в одной таблице. Фильтр по типу операции, переключатель «Без карточки». Возможность через Excel-импорт разметить «Самовыкуп», править закупочную цену и прочие расходы на момент операции.
10. **Отчёт о движении денежных средств (ДДС)** — доходы/расходы, не связанные напрямую с МП (зарплата, аренда, закупки), влияющие на чистую прибыль как «Прочие расходы». Загрузка банковской выписки 1С, ручной ввод, массовый импорт Excel, регулярные платежи. Распределение расходов между организациями/МП пропорционально выручке (или по организации записи при включённом переключателе).

### В. Аналитические отчёты
11. **Дашборд (Рабочий стол)** — верхняя панель ключевых показателей (выручка общая/чистая, валовая/чистая прибыль, маржинальность, заказы, средний чек, реклама, возвраты), графики заказов по типам (FBS/FBO/розница/опт/все), динамика выручки-прибыли-маржинальности, структура прибыли и расходов, повторные продажи Ozon, топ/антитоп товаров по валовой прибыли, разбивка по организациям, статистика по сотрудникам (сборка, поставки, задания).
12. **ABC-анализ** — разбиение ассортимента на группы A (80% выручки), B (15%), C (5%) по выручке или валовой прибыли. Режим «Выделить основные товары». Связка со стратегией ценообразования.
13. **План/факт продаж** — планирование продаж (шт./руб. по неделям/месяцам) через Excel-импорт плана и сопоставление с фактом из товарной аналитики + динамика остатков.
14. **Динамика продаж** — продажи (за вычетом возвратов) по каждому товару во времени (день/неделя/месяц/квартал/год), шт./руб., с возможностью «схлопнуть дубли» карточек.
15. **Процент выкупа** — показатель с разными формулами по маркетплейсам (WB, Ozon, остальные); доступен в «Ценах» (за всё время/год) и «Товарной аналитике» (за период).
16. **Повторные продажи Ozon** — уникальные/новые/повторные покупатели, распределение по числу покупок (отчёта нет в самом Ozon).
17. **Аналитика по гипотезам** — тестирование методов увеличения продаж на конкретном товаре (период, МП, сравнение прибыли с предыдущим периодом; по умолчанию с предыдущей неделей).
18. **Аналитика по складам** — суммарные остатки, количество позиций, остаток в закупочных ценах, сумма дополнительных расходов по каждому складу с остатками.
19. **Прочие связанные отчёты**: планирование поставок, проблемные товары, товарный остаток, продажи по поставщикам (корректно работают по данным профит-репорта).

### Г. Расчётные движки
20. **Расчёт налогов** — УСН «Доходы», УСН «Доходы минус расходы», ОСНО, с/без НДС. Автоматический выбор большего из основного и минимального (1%) налога для УСН Д-Р. НДС исходящий/входящий, налог на прибыль для ОСНО.
21. **Расчёт НДС** и формирование **УПД нового формата** с НДС (особенно для УСН и WB).
22. **Учёт себестоимости по FIFO** — first in, first out по партиям; хранение закупочной цены в рублях и валюте для каждой партии; опция расчёта по последней себестоимости при выключенном FIFO.
23. **Расчёт логистики в юнит-экономике** — по тарифу организации и габаритам товара, с формулами для Ozon (FBO/FBS, прямая/обратная, наценка за нелокальную продажу, объём из габаритов) и Wildberries (литраж, коэффициент склада, индекс локализации, индекс распределения продаж, прямая/обратная/СГТ, «логистика итого» с долей выкупа).

### Д. Сверка
24. **Сверка отчётов с маркетплейсами** — пошаговые маппинги показателей SelSup ↔ отчёты ЛК для WB, Ozon, Яндекс Маркета, МегаМаркета (с учётом особенностей API vs интерфейса, расхождений по датам списания, СПП, рекламы, удержаний).

## Ключевые сценарии (workflows)

### Сценарий 1. Автоматический сбор аналитики и просмотр P&L
1. Подключить интеграцию с маркетплейсом (API-ключ).
2. SelSup загружает операции за последние 3 месяца по API; продажи/заказы — каждые 30 минут.
3. Открыть «Аналитика и финансы → P&L», выбрать период, организацию (одну или несколько), маркетплейс, период детализации (день/неделя/месяц/год).
4. Нажать «Применить фильтры». Изучить основные показатели, детализацию налога, детализацию расходов на МП.
5. При необходимости нажать «Дополнительно → Перезагрузить аналитику» (только для одной организации) для пересчёта.

### Сценарий 2. Ручная загрузка финансового отчёта (резерв при сбое API)
1. Скачать нужный отчёт из ЛК маркетплейса:
   - **WB**: Финансовые отчёты → Еженедельные/Ежедневные/Архивные → 3 точки → Детализация → Скачать Excel; разархивировать.
   - **Ozon**: Позаказный отчёт о реализации; Отчёт о перевыставлении услуг; Отчёт о компенсациях (3 файла).
   - **Яндекс Маркет**: Финансы → Финансовые отчёты → По заказам.
   - **МегаМаркет**: файл «заказы-…-все.xlsx» (FBS → Все заказы) + файлы комиссий «Отчёт №МПБЛ-…» (Отчётность → Финансовые отчёты), строго последовательно.
2. В SelSup: «Аналитика и финансы → Импорт» (или «История загрузки отчётов → Импорт»), выбрать маркетплейс, загрузить файл(ы).
3. Для WB выбрать период вручную; для Ozon/Яндекса период определяется по шапке файла; для МегаМаркета — сначала заказы, затем комиссии.
4. Сервис пересчитает аналитику по загруженному отчёту.

### Сценарий 3. Анализ юнит-экономики (Товарная аналитика)
1. Заполнить закупочные цены в разделе «Цены» (обязательно для корректной себестоимости/прибыли).
2. Открыть «Аналитика и финансы → Товарная аналитика», выбрать период, организацию, маркетплейс.
3. Выбрать группировку (по штрихкоду/цветомодели/артикулу/категории/бренду).
4. Анализировать прибыль, маржинальность, ДРР, эффективности; включить «Среднее за 1 единицу» при необходимости.
5. Скачать в Excel (с настраиваемыми столбцами через кнопку-шестерёнку).

### Сценарий 4. ABC-анализ ассортимента
1. Открыть «Аналитика и финансы → Отчёты → ABC-анализ».
2. Выбрать период (для сезонных товаров — сезон; для неоднородных — полгода/год), организацию, МП, категорию/бренд, параметр анализа (выручка или валовая прибыль).
3. Оценить разбивку A/B/C; при необходимости включить «Выделить основные товары».
4. Выгрузить Excel; применить стратегии ценообразования по группам.

### Сценарий 5. Планирование продаж (План/факт)
1. Открыть «Аналитика и финансы → План/факт продаж», вкладка «План продаж», выставить фильтры.
2. Скачать шаблон Excel, заполнить план (шт./руб., по неделям/месяцам; без данных за год).
3. Загрузить файл обратно (кнопка «Импорт»); сформируется «Факт продаж».
4. Во вкладке «Факт продаж» скачать Excel — сопоставление плана с фактом + динамика остатков.

### Сценарий 6. Учёт прочих расходов (ДДС) для чистой прибыли
1. Открыть «Аналитика и финансы → ДДС» (или «Отчёты → Движение денежных средств»).
2. Добавить платёж одним из способов: загрузка выписки 1С (Импорт из банка), кнопка «Добавить платёж», массово через Excel («Скачать ДДС» → заполнить зелёные столбцы → «Импорт»), регулярный платёж.
3. Указать тип (доход/расход), организацию, сумму, дату, статью, контрагента.
4. Расходы попадают в P&L как «Прочие расходы» и уменьшают чистую прибыль (маржинальная прибыль их не учитывает).

### Сценарий 7. Настройка и расчёт налогов / НДС
1. В «Настройки → Мои организации» выбрать организацию, указать систему налогообложения, ставку УСН (по умолчанию 6%), ставку НДС (исходящий/входящий для ОСНО), тумблеры «Списывать себестоимость в расход», «Учитывать входящий НДС в себестоимости».
2. Для ОСНО ставка НДС берётся из карточки товара.
3. Налог отображается в P&L (с детализацией) и в Товарной аналитике (столбцы «Налог УСН», «Налог НДС»).
4. При ненулевом НДС SelSup формирует УПД нового формата; для WB — через создание заказа на отгрузку FBO с загрузкой файла штрихкодов из детализации WB.

### Сценарий 8. Сверка с маркетплейсом
1. В P&L выставить период/организацию/маркетплейс, нажать «Применить фильтры», скачать «Скачать финансовый отчёт» (Excel).
2. В ЛК маркетплейса открыть соответствующий отчёт (WB — Отчёты реализации; Ozon — Финансы → Баланс → Доходы и расходы или Аналитические отчёты; Яндекс — Отчёт по платежам; МегаМаркет — Закрывающие документы, Приложения 1/4а/4б).
3. Сопоставить показатели по маппинг-таблице; учитывать особенности (СПП, реклама из WB Продвижение, расхождения по датам списания, разные статьи API vs интерфейса, тип детализации WB по дням/неделям).
4. При расхождениях проверить период, выбранную организацию/МП, актуальность API, прочие доходы/расходы, заполненную себестоимость.

### Сценарий 9. Тестирование гипотез
1. Открыть «Аналитика и финансы → Отчёты → Аналитика по гипотезам» (или из карточки товара → вкладка «Гипотезы»).
2. Нажать «Добавить гипотезу», выбрать товар, заполнить: название, маркетплейс, дата начала/окончания, сохранить.
3. Внести тестируемое изменение (например, SEO-описание через вкладку «Ключевые слова»).
4. В отчёте «Аналитика по гипотезам» сравнить прибыльность за период гипотезы с предыдущим периодом (по умолчанию — с предыдущей неделей); принять решение о масштабировании.

## Сущности (entities)

- **Организация** — юрлицо/ИП. Атрибуты: система налогообложения (УСН Доходы / УСН Доходы-Расходы / ОСНО), ставка УСН (по умолч. 6%), ставка НДС исходящего/входящего, тумблер «Списывать себестоимость в расход», тумблер «Учитывать входящий НДС в себестоимости», связи карточек. Для нескольких организаций — сводный P&L и таблица разбивки по организациям.
- **Маркетплейс** — Wildberries, Ozon, Яндекс Маркет, МегаМаркет (и др.). Источник операций по API; определяет структуру расходов, формулу процента выкупа, состав логистики.
- **Операция маркетплейса** — сырая запись (продажа/возврат/логистика/комиссия/СПП/штраф/доплата/услуга/прочее начисление/хранение/реклама/платная приёмка/удержание/авансовая оплата). Атрибуты: дата, тип операции, сумма (руб. и валюта), привязка к товару (при наличии связи карточки), закупочная цена на момент операции, доп. расходы, признак «Самовыкуп».
- **Товар / Карточка товара** — артикул, штрихкод, цветомодель, категория, бренд, фото, габариты (длина/ширина/высота для расчёта объёма логистики), закупочная цена (по партиям, руб. + валюта), доп. расходы на товар, себестоимость, стратегия ценообразования, привязка менеджера, НДС (для WB/ОСНО).
- **Партия товара** — единица учёта FIFO: закупочная цена, дата, количество.
- **Платёж ДДС** — тип (доход/расход), организация, сумма, дата, статья доходов/расходов, контрагент (МП или иной), регулярность.
- **Регулярный платёж** — рекуррентный платёж ДДС: регулярность, организация, сумма, статья, контрагент, дата.
- **Гипотеза** — название, товар, маркетплейс, дата начала, дата окончания.
- **План продаж** — план по товару в шт./руб. с разбивкой по неделям/месяцам.
- **Загруженный отчёт** — запись в истории загрузок: маркетплейс, организация, период, дата загрузки, файл.
- **Показатели (расчётные метрики):** Выручка (руб./шт.), Продажи (руб./шт.), Возвраты (руб./шт.), Отмены (шт.), Логистика, Платная приёмка, Комиссия (с эквайрингом), СПП на WB, Штрафы, Доплаты, Услуги, Прочие начисления, Платное хранение, Реклама, Сумма расходов на МП, Итого к оплате, Себестоимость (единицы/проданного), Закупочная цена проданного, Доп. расходы на проданный, Товарный остаток (FBS/FBO/общий, шт./в зак. ценах), Процент выкупа, Валовая прибыль, Маржинальная прибыль, Чистая прибыль, Маржинальность, Валовая маржинальность, Рентабельность, ROI, ДРР, Доля логистики/комиссии/рекламы, Средний чек, Эффективность по выручке/валовой прибыли, Доли в выручке/прибыли/остатке, Самовыкупы.

## Интеграции — с какими внешними системами и что делает

- **Wildberries (API)** — продажи/заказы онлайн (раз в 30 мин), еженедельные/ежедневные финансовые отчёты (по неделям — пн/вт за прошлую неделю; по дням — ежедневно). Реклама — напрямую из API «Продвижения» (с детализацией по SKU + ДРР), включая ВБ Медиа. Воронка продаж (выкупы/отмены) для процента выкупа за год. Тариф/Джем — доступ ко всей истории. Автокорректировка при получении финальных отчётов.
- **Ozon (API)** — заказы/выручка онлайн каждый день; финальные финансовые отчёты раз в месяц с автокорректировкой. Баллы Ozon (1 балл = 1 рубль) — по умолчанию не отдельной статьёй, можно загрузить дополнительно. API Ozon Performance — для рекламных расходов в товарной аналитике (ДРР). Источник курса валют — Ozon (опционально). Глубина по тарифу: 3 мес / Премиум 6 мес / Премиум Плюс вся история.
- **Яндекс Маркет (API)** — продажи/возвраты/расходы записываются в 2 строки (логистика + услуги); комиссия — в услуги; реклама пока в общих услугах (в планах выделить); хранение пока не учитывается (в планах); СПП не выделяется. Метод `getOrdersStats`. Заказы FBO — отдельная задача «Импорт заказов FBO». Аналитика обновляется каждые 30 мин (задержка до 4 часов). Глубина — 3 месяца. Сопоставление ID магазина ↔ организации.
- **МегаМаркет** — API аналитики отсутствует; только ручная загрузка файлов заказов и комиссий. Продажи — по статусу «Доставлен покупателю», возвраты — «Отменен покупателем» с начисленной комиссией.
- **1С (банка)** — загрузка банковской выписки в формате 1С в ДДС (зарплата, аренда, закупки) для учёта прочих расходов и чистой прибыли.
- **ЦБ РФ** — источник курса валют для пересчёта аналитики в иностранную валюту.
- **Честный Знак / ЭДО (косвенно)** — формирование УПД нового формата с НДС (для ОСНО/УСН), скачивание из интерфейса отгрузки.
- **Транспортные компании (СДЭК, Почта России и др.)** — расходы на доставку для FBS/опта/розницы подтягиваются автоматически на основе данных ТК в Profit Report (не в себестоимость).

## Настройки (settings)

- **Настройки → Цены и акции → «Расчёт юнит-экономики»**: валюта аналитики; источник курса (ЦБ РФ / Ozon); тариф организации и габариты товара для расчёта логистики.
- **Настройки → Аналитика** (`/settings/analytics`):
  - «Группировать аналитику по дублям» — объединение товаров, связанных по остаткам.
  - «Данные аналитики конфиденциальны» — скрытие данных от техподдержки.
  - «Не учитывать кредит в прочих удержаниях» — исключение кредитов МП из P&L.
  - «Период детализации отчётов Wildberries» — по дням или по неделям (после смены — перезагрузить аналитику WB).
  - «Обновление данных Ozon» — блок загрузки баллов Ozon.
  - «Выгружать прочие расходы по всему клиенту» (в P&L) — распределение прочих расходов по организации записи, а не пропорционально продажам.
- **Настройки → Мои организации**: система налогообложения, ставка УСН, ставки НДС (исходящий/входящий), тумблеры «Списывать себестоимость в расход» (УСН Д-Р, ОСНО), «Учитывать входящий НДС в себестоимости» (ОСНО); связи карточек.
- **Карточка товара**: НДС (для WB и для ОСНО), габариты, закупочная цена, доп. расходы.
- **Настройки → Интеграции → Яндекс.Маркет**: сопоставление ID магазина ↔ организация.
- **P&L (переключатели)**: «До СПП» / «После СПП» (только отображение WB; прибыль/налог неизменны, налог всегда от «После СПП»); «Выручка с/без баллов Ozon» для расчёта налоговой базы.
- **Товарная аналитика**: настройка состава/порядка столбцов Excel (кнопка-шестерёнка); переключатель «Среднее за 1 единицу».
- **Дашборд**: фильтры периода (Сегодня/Вчера/Неделя/Месяц/произвольный), организаций, маркетплейсов; «Остатки как при адресном хранении» (Настройки → Остатки) для графика сборки/раскладки.

## Бизнес-правила и ограничения

- **Глубина данных по API — 3 месяца** (бесплатный тариф). Для большей глубины: подписка (Джем WB — вся история; Ozon Премиум — 6 мес, Премиум Плюс — вся история) или ручная загрузка отчётов.
- **Период детализации**: WB — еженедельные отчёты приходят в пн/вт за прошлую неделю (по неделям) либо ежедневно (по дням); Ozon финальные финансы — раз в месяц; Яндекс Маркет — раз в неделю; SelSup автоматически корректирует данные при получении финальных отчётов. Данные за один период сходятся при любом режиме детализации.
- **Сводный P&L по нескольким организациям** — только для анализа; перезагрузка аналитики и ручной импорт требуют выбора одной организации.
- **Налог считается от «Выручки после СПП»**. Для УСН Д-Р берётся большее из основного налога и минимального (1% от выручки). Для ОСНО ставка НДС берётся из карточки товара, а не из «Мои организации».
- **Валовая прибыль** = Итого к оплате − Себестоимость − Самовыкупы; не учитывает прочие доходы/расходы и налоги. **Чистая прибыль** = Валовая − (Налог + НДС) − Прочие расходы; при прочих доходах может превышать валовую или быть положительной при отрицательной валовой.
- **Маржинальная прибыль** = чистая без учёта OPEX и доп. доходов из ДДС; вычитаются только переменные расходы (себестоимость, накладные, налог).
- **ДРР** рассчитывается только при Выручка > 0. **Маржинальность** в Excel = 0 при валовой прибыли или выручке ≤ 0.
- **Комиссия в Товарной аналитике** учитывает эквайринг; на WB может быть отрицательной при возмещении СПП.
- **Логистика** состав различается по МП: WB — логистика по РФ, международная, услуги Поверенного (выдача/возврат на ПВЗ), НДС; Ozon — обработка/доставка (FBO без размещения, FBS, последняя миля, НДС) + возвраты/отмены (обработка возвратов, частичного невыкупа, отменённых/невостребованных, обратная логистика).
- **WB: записи с «Номер документа = 0» не обрабатываются** до замены на реальный номер (обычно несколько дней).
- **Себестоимость**: при включённом FIFO — по схеме «первый пришёл — первый ушёл» на момент продажи; при выключенном — по последней себестоимости. Без заполненной закупочной цены прибыль считается некорректно.
- **Процент выкупа** — разные формулы: WB = Выкупы/(Выкупы+Отмены); Ozon = Невозвращённые заказы/Все заказы (по отправлениям, каждый отправление имеет единственный итоговый статус); остальные = Завершённые/(Завершённые+Возвраты+Отмены).
- **Аналитика в белорусских рублях**: данные отображаются в BYN, но расчёты юнит-экономики всегда в RUB; для BYN нужен экспорт цен в Excel и ручной пересчёт; при обратном импорте нельзя записывать закупочные цены в RUB (автоконвертация).
- **Сверка**: период SelSup должен точно совпадать с периодом отчёта МП; прочие удержания WB напрямую не сравниваются (API vs интерфейс дают разные статьи); рекламные расходы сверяются через WB Продвижение → Финансы (фильтр «Источник списания = Баланс»), включая ВБ Медиа.
- **Расходы на доставку** (FBS/опт/розница) — автоматически из ТК, не в себестоимость, в Profit Report; ручное изменение суммы доставки не влияет на Profit Report. **Накладные расходы** (упаковка, страховка) — вручную при приёмке, включаются в себестоимость, уменьшают валовую прибыль.
- **Прочие расходы ДДС** распределяются между организациями/МП пропорционально выручке (или по организации записи при включённом переключателе).
- **SelSup не заменяет бухгалтера**: расчёты налогов носят информационный характер.

## Открытые вопросы / чего не хватает в доках

- **Точная бизнес-логика «выделения основных товаров»** в ABC-анализе описана качественно («каждый процент участия приносит ~15%/5%/1%»), но математический критерий отнесения к группам A/B/C в режиме «Выделить основные товары» формально не задан.
- **Формулы ряда показателей** в «Терминах и формулах» помечены как «Требует уточнения» (Самовыкупы руб., Средняя фактическая цена продажи, Фактическая наценка %) — они скрыты (`display:none`), но технически присутствуют; точные формулы не раскрыты.
- **Точный алгоритм распределения прочих расходов ДДС пропорционально выручке** (по каким продажам, за какой период, как округляется) описан поверхностно.
- **Логика авто-конвертации закупочных цен** при импорте Excel (особенно для белорусского рубля) описана как предупреждение, но правила конвертации не формализованы.
- **МегаМаркет**: API отсутствует полностью; точные правила маппинга «вознаграждения оператора ПЛ» и «комиссии за транзакции» (1 руб./заказ и 2%/1,8%/1,5%) в статью «Комиссия», а приложений 4а/4б в «Логистику» описаны, но не автоматизированы — ручной расчёт.
- **AliExpress** упомянут в формуле процента выкупа («остальные маркетплейсы»), но отдельной статьи по интеграции/аналитике AliExpress в корпусе нет — неясна степень поддержки.
- **Яндекс Маркет**: хранение и выделение рекламы отдельной статьёй заявлены «в планах» — текущая реализация не полная; не указаны сроки. Планирование поставок и товарный остаток для Яндекса недоступны (остатки не передаются по API).
- **Сверка «Итого к оплате»** явно помечена как «нельзя сравнивать» с метрикой ЛК WB — но альтернативный источник для сверки итога не указан.
- **Логика автокорректировки данных** при получении финальных финансовых отчётов МП (что именно пересчитывается и как разрешаются конфликты с уже загруженными операциями) не описана детально.
- **Сроки пересчёта аналитики** при смене валюты указаны как «некоторое время» без конкретных SLA; аналогично — время перезагрузки аналитики за длинный период.
- **Границы округлений**: допускается разница в несколько рублей между общей суммой и суммой по организациям из-за округления, но допустимый порог не нормирован.
- **«Рука на пульсе»** и **«Рука на пульсе по-товарно»** упоминаются (включая использование данных План/факт), но в бета-версии — полная спецификация в статьях модуля отсутствует.
- **Внутренняя аналитика по сотрудникам** (задания, сборка, раскладка) требует заполнения роли/склада/организации в карточке сотрудника и настройки «Остатки как при адресном хранении» — но детальная модель учёта KPI сотрудников не раскрыта.
