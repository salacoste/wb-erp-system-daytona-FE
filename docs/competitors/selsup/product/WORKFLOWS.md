# Ключевые воркфлоу SelSup

> Каталог end-to-end сценариев пользователя для воссоздания функционала SelSup в другом сервисе. Для каждого сценария указаны модуль, триггер, пошаговая таблица «действие пользователя → реакция системы», участвующие сущности и интеграции. Источник — спецификации из `product/specs/`.

**Принятые сокращения:** МП — маркетплейс, ЧЗ — Честный Знак, ШК — штрих-код, КИЗ — код идентификации маркировки, ТСД — терминал сбора данных, FBS/FBO — схемы работы, СУЗ — Станция управления заказами ЧЗ, УПД — универсальный передаточный документ, ЭДО — электронный документооборот, SKU — единица учёта остатков, GTIN — глобальный код товара, ВПР — вертикальный поиск Excel.

---

## WF-01. Онбординг: регистрация, быстрый старт и первый импорт

- **Модуль:** Онбординг, аккаунт, тарифы и организации
- **Триггер:** Новый пользователь открывает страницу регистрации SelSup.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | Открывает `/signup`, вводит номер телефона и email, ставит галочку согласия с Политикой обработки персональных данных и Договором-офертой, нажимает «Зарегистрироваться» | Создаётся учётная запись; открывается мастер быстрого старта |
| 2 | В мастере выбирает маркетплейс (WB/Ozon) → «Сохранить» | Открывается раздел «Интеграции» с инструкцией по подключению ЛК маркетплейса |
| 3 | Настраивает подключение по инструкции (вставляет API-токен; для WB — токен без «Только чтение», для Ozon — Client ID + ключ типа «Admin»), настраивает тумблеры → «Сохранить» | Статус интеграции меняется на «Уже настроено»; ключ шифруется AES-256 |
| 4 | Нажимает «Импортировать товары» → подтверждает настройки → «Сохранить» → снова «Импортировать товары» | Запускается фоновый импорт карточек; одновременно стартует автоматическая загрузка аналитики за последние 2 недели |
| 5 | Дожидается завершения | Карточки появляются в разделе «Товары»; в «Уведомлениях» — результаты импорта и ошибки в таблице «Ошибки импорта» |
| 6 | При необходимости добавляет организацию (ИНН → автозаполнение полей, налоговый режим, юр. адрес, банковские реквизиты, печать/подпись) | Организация создаётся; становится доступной привязка ключей API |

- **Сущности:** Account, Tariff, Organization, Store, API-ключ.
- **Интеграции:** Маркетплейсы (API), AES-256 шифрование ключей.
- **Бизнес-правила:** Нет пробного периода; 1 организация = 1 ключ API МП; правила тарификации SKU (1 товар на 5 МП = 1 SKU); лимит 2 устройства на аккаунт.

## WF-02. Создание карточки товара и публикация на маркетплейсах

- **Модуль:** Карточки товаров и каталог (PIM)
- **Триггер:** Селлер заводит новый товар для продажи на нескольких МП.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | «Товары → Создать товар» → вариант «Один товар или несколько модификаций» | Открывается форма создания с шагами |
| 2 | Шаг 1. Выбирает/создаёт категорию SelSup; настраивает связь с категорией WB/Ozon, ТН ВЭД, габариты | Категория фиксируется; доступны параметры МП |
| 3 | Шаг 2. Заполняет служебные параметры: артикул объединения, название, бренд (обязательно), тип товара, организация, производитель + страна производства, цены со/без скидки (обязательно), закупочная, габариты/вес (обязательно) | Себестоимость считается как `закупочная + доп. расходы`; для одежды добавляется таблица цветов и размеров; ШК генерируется автоматически |
| 4 | Для одежды добавляет цвета (артикул цвета + цвет из справочника) и размеры (Размер, Российский размер WB, Размер производителя) | Штрихкод на каждый размер генерируется автоматически |
| 5 | (Опц.) Вставляет текст описания → нажимает «Сгенерировать текст» (SEO) или «AI-создание» (Формализатор) | AI заполняет параметры МП (выделены оранжевым), не перезаписывая уже заполненные; SEO-описание до ~2000 знаков с учётом ключевых слов |
| 6 | Шаг 3. Загружает фото drag&drop; управляет «значками» МП на фото, выбирает главное | Фото привязываются к цветам; автодобавление белого фона под требования МП |
| 7 | Включает тумблер нужного маркетплейса → «Сохранить» | SelSup транслирует карточку в формат МП и отправляет по API; при успехе — «Карточка отправлена на маркетплейс», при ошибке — детальное сообщение |
| 8 | Для публикации на других МП — включает их тумблеры и дозаполняет параметры площадки | Карточка публикуется на дополнительных МП |

- **Сущности:** Карточка товара (модель), Цвет, Размер, Категория, Бренд, Производитель, Параметр, Фото/Видео, SKU, Штрихкод.
- **Интеграции:** WB, Ozon, Яндекс Маркет, AliExpress, МегаМаркет, Честный Знак; браузерное расширение (копирование конкурента); внешние хранилища (Яндекс.Диск, Google Диск).
- **Бизнес-правила:** Бренд, страна производства, цены, габариты — обязательны; WB лимит 1000 новых карточек/сутки; бренд Ozon привязывается по числовому ID (не создаётся по API); категория фиксируется при первом создании.

## WF-03. Настройка склада FBS и первичный перенос остатков

- **Модуль:** Остатки, склад и адресное хранение
- **Триггер:** Селлер начинает вести товарный учёт в SelSup (переход с ЛК МП).

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | «Склад → Склады → Добавить склад» (1 физический склад = 1 склад в SelSup; фулфилмент — отдельно) | Создаётся склад |
| 2 | Настраивает опции: «Склад для учёта остатков FBO» (выключает «Считать аналитику по последней себестоимости» для FIFO), «Использовать для заказов», «Приоритет списания остатков» | Настройки сохраняются; для FBO создаётся виртуальный склад |
| 3 | Устанавливает связи со складами МП (для Яндекс — ID склада из ЛК, МегаМаркет — числовой ID, AliExpress — любое значение, Webasyst — авто) | Связи привязывают склад SelSup к складам МП для передачи остатков/заказов |
| 4 | Объединяет дубликаты товаров между МП (и с 1С/МойСклад): в одной организации — общая карточка; между организациями — по остатку | Дубли получают общий SKU и общий остаток |
| 5 | Импортирует все заказы и переводит «На сборку»/«Собранные», чтобы они не резервировали остатки | Заказы выходят из статуса «Новый» |
| 6 | Нажимает «Перенести остатки» (WB/Ozon/МойСклад) или загружает файлом через приёмку (Яндекс/МегаМаркет/Excel/1С) | Остатки переносятся; проверяются через «Сверку остатков» |
| 7 | Включает «Синхронизировать остатки» и «Автоматический импорт заказов» в «Мои организации»; выключает «Обновлять только существующие остатки» | При заказе/изменении остаток мгновенно обновляется на всех МП; раз в минуту проверяются новые FBS-заказы |
| 8 | Запускает «Импорт с обновлением остатков» | Остатки отправляются на МП; проверяет «Результаты импорта» и «Уведомления» |

- **Сущности:** Склад, Остаток (партия), SKU, Связь складов МП, Заказ FBS, Виртуальный склад FBO.
- **Интеграции:** WB, Ozon, Яндекс Маркет, МегаМаркет, AliExpress, МойСклад, 1С; ТСД.
- **Бизнес-правила:** Защита от случайного обнуления — включать синхронизацию только после корректного переноса; склады МП без связи в SelSup получают 0; FBO по API — только WB и Ozon; FBO Яндекс/МегаМаркет — только файлом.

## WF-04. Сборка FBS-заказа (полный цикл)

- **Модуль:** Заказы и сборка
- **Триггер:** Поступил новый FBS-заказ с МП (автоимпорт).

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | Система автоматически импортирует заказ (по событию API; раз в минуту проверяются новые FBS-заказы) | Заказ появляется в «Заказы на отгрузку → Со своего склада (FBS)» в статусе **Новый**; товар резервируется |
| 2 | Отмечает нужные заказы галочками → «На сборку» (без выбора — все с датой отгрузки «сегодня») | SelSup создаёт/дополняет поставку FBS |
| 3 | Включает фильтр «Без этикетки» → «Загрузить этикетки у заказов, где их нет» | Для WB заказ привязывается к поставке; для Ozon/Яндекс/МегаМаркет/AliExpress статус МП → «Ожидает доставки» |
| 4 | Выбирает способ сборки (Лист сборки + Лента / Умная лента / +товарная этикетка / по одному артикулу / через Задания) | Формируется Лист сборки FBS (PDF) с настраиваемыми колонками, фото, ШК, ячейкой хранения |
| 5 | Собирает товары, наклеивает этикетки (товарную и этикетку заказа; при адресном хранении — по маршруту ячеек) | При сборке через ТСД/задание «Комплектация» — скан ШК товара резервирует заказ |
| 6 | Отмечает заказы собранными: галочками → «Отметить собранными» или значком машинки в строке | Статус SelSup → **Собран** (на МП до отгрузки не передаётся) |
| 7 | Закрывает поставку: «Проверить и закрыть» | Для WB — сверка состава SelSup↔МП и отсутствие несобранных; при расхождениях — предложение исправить |
| 8 | После приёмки на МП | Заказы → статус **Отправлен** → **В пути** (синхронизация статусов с МП после отгрузки) |

- **Сущности:** Заказ FBS, Поставка, Остаток (резерв), Этикетка заказа, Товарная этикетка, Лист сборки, Сборочное задание, Ячейка хранения.
- **Интеграции:** МП (двусторонний обмен: импорт заказов, обновление остатков, этикетки, статусы); МойСклад (автосоздание заказов/отгрузок); 1С (модуль комплектации); QZ Tray (печать); Честный Знак.
- **Бизнес-правила:** До отгрузки внутренние статусы SelSup не передаются на МП; сопоставление товара «символ в символ»; первый импорт — только «Импорт заказов» (без обновления остатков), чтобы не обнулить остатки МП; закрывать поставки только через SelSup.

## WF-05. Сборка FBS с адресным хранением и маркировкой Честного Знака

- **Модуль:** Заказы и сборка + Маркировка, Честный Знак
- **Триггер:** Маркируемый товар (одежда/обувь и др.), адресное хранение, поступил FBS-заказ.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | В категории товара включает «Товары категории маркируются», заполняет ТН ВЭД; в карточке указывает GTIN; настраивает структуру адресного хранения | Появляются параметры ЧЗ; формируется структура (проход → стеллаж → полка → ячейка) |
| 2 | Включает «Использовать задание для сборки заказов FBS» (Настройки → FBS) | Активируется адресная сборка через ТСД |
| 3 | Импортирует заказы; убеждается, что у всех позиций отображается ячейка хранения | Резерв создаётся; отображается «Место» |
| 4 | Формирует Сборочное задание (на сегодня/завтра/старше одного дня; до 10 заказов на задание) | На ТСД/телефоне — «Сборочное задание» → выбрать число заданий и МП → «Взять заказы на сборку» |
| 5 | На ТСД: система ведёт по ячейкам; отсканировать ШК/уникальный код товара; для маркируемого — получить и отсканировать КИЗ | КИЗ привязывается к заказу; включена проверка GTIN по ШК |
| 6 | Передаёт маркировку на МП (автоматически при сканировании) | В столбце «Остатки» — жёлтая галочка (принят) или серая (ошибка → повторить сканирование) |
| 7 | Загружает этикетку заказа (доступна только после передачи КИЗ) | Этикетка МП становится доступна; для Яндекс Маркета — строго сначала КИЗ, потом этикетка |
| 8 | После отгрузки | КИЗ выводится из оборота (Маркировка → Коды маркировки, `turnover=true`) |

- **Сущности:** Код маркировки (КИЗ), GTIN, Сборочное задание, Ячейка хранения, Заказ FBS.
- **Интеграции:** Честный Знак (СУЗ), МП (передача КИЗ), ТСД/смартфон, ЭДО (УПД ДОП).
- **Бизнес-правила:** Этикетка доступна только после передачи КИЗ; GTIN КИЗ должен совпадать с GTIN карточки; срок годности WB передаётся при ≥30 дней до окончания; строгий отбор из указанных ячеек.

## WF-06. Создание и отгрузка поставки FBO (на склад маркетплейса)

- **Модуль:** Отгрузки, упаковка и поставки на склады МП
- **Триггер:** Селлер пополняет остатки на складе FBO маркетплейса.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | «Заказы на отгрузку — На склад маркетплейса» → «Создать заказ» | Открывается форма заказа на отгрузку FBO |
| 2 | Заполняет: Название, Организация, Маркетплейс, Склад МП, Склад списания остатков; для WB — Тип поставки (микс/моно/моно-паллет/суперсейф); включает «Списать остатки» | При сохранении остатки резервируются |
| 3 | Добавляет товары (планирование / ШК / +1 / файл); указывает количество | Позиции попадают в заказ |
| 4 | (Планирование) Раскрывает «Планирование поставок»: период анализа, «на сколько дней планировать», склады → «Рассчитать» | Формируется список рекомендованных товаров с количеством; «Добавить все товары в заказ» |
| 5 | «Сохранить» → переводит в статус **Собран** → **Упакован** | Резерв списывается; доступно задание «Упаковка FBO» |
| 6 | «Задания → Упаковка FBO» → отсканировать ШК короба (по префиксу), затем товары (с автопечатью этикеток) | Контроль вложения; автогенерация файла ШК коробов; видны только заказы в статусе «Новый» |
| 7 | Скачивает файл заказа и файл ШК коробов; в ЛК WB создаёт поставку, загружает файл; копирует номер поставки WB в поле «Внешний номер» | Присваивается внутренний номер поставки SelSup |
| 8 | Заполняет пропуск (короба, водитель, авто, тип упаковки), печатает ШК поставки | Дожидается статуса «Приемка разрешена» (~20–30 мин) |
| 9 | Меняет статусы SelSup вручную: **Готов к поставке → Отгружен → Закрыт** | Заказ закрывается (МП не передаёт статусы FBO по API, кроме Ozon до таймслота) |
| 10 | Для WB — импортирует Акт приёмки (zip) в заказ → вкладка «Расхождения при приемке WB» | Сверка упаковано/принято; при расхождении — «Исправить заказ» |

- **Сущности:** Заказ на отгрузку FBO, Поставка, Короб (ШК), Тип поставки WB, Акт приёмки WB, Резерв/Списание.
- **Интеграции:** WB (ЛК + частично API остатков FBO), Ozon (API создания отгрузки до таймслота), Яндекс Маркет (ЛК), Честный Знак, ТСД/сканер.
- **Бизнес-правила:** Запрещено объединять товары разного типа поставки в одном коробе; вес микс-короба ≤ 25 кг; одно событие — один уникальный ШК короба; статусы SelSup меняются вручную; для Ozon заказ создаётся один раз после упаковки.

## WF-07. Маркировка и Честный Знак: получение кодов, ввод/вывод из оборота

- **Модуль:** Маркировка, Честный Знак, этикетки и печать
- **Триггер:** Производство/импорт маркируемого товара, необходимость получить коды маркировки.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | Получает УКЭП, устанавливает КриптоПро CSP + браузер-плагин; регистрируется в ЧЗ; вступает в ГС1 РУС (GTIN на «46…») | Предусловия выполнены |
| 2 | В SelSup: «Интеграции → Честный знак → Работать с Честный знак» → вводит OMS Id → «Получить идентификатор соединения» (ЭЦП) → «Получить Токен» (действует 10 ч) → «Проверить СУЗ» | Интеграция настроена |
| 3 | Добавляет производителей с корректным ИНН (как в ЭЦП/ЧЗ); настраивает категории (ТНВЭД, тип категории ЧЗ, тумблер «маркируются»); добавляет сертификаты качества | Категории готовы к маркировке |
| 4 | Создаёт заказ FBO или приёмку; в заказе появляется окно этапов получения кодов; нажимает «Получить маркировку» | Создаётся заказ СУЗ (≤10 позиций, отдельный на каждый тип товара); ждёт статуса «Обработан»; выдаётся ровно по количеству товаров |
| 5 | Нажимает «Подписать карточки» (можно до или после маркировки) | Карточки ЧЗ подписаны ЭЦП |
| 6 | Нажимает «Ввести в оборот маркировку» | Создаётся документ «Ввод в оборот»; подтверждает удаление криптохвоста |
| 7 | Вкладка «Документы» → «Обновить статус кодов маркировки» | Коды получают статус «Введён в оборот» |
| 8 | Распечатывает коды маркировки (до ввода — с криптохвостом) из заказа или «Коды маркировки» | Этикетки КИЗ (58×40/58×80) печатаются через QZ Tray без диалогового окна |

## WF-11. Возврат товара и обработка брака

- **Модуль:** Заказы и сборка + Закупки, производство
- **Триггер:** Покупатель вернул товар или выявлен брак.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | «Задания → Возврат товара» | Открывается задание приёмки возвратов |
| 2 | Находит заказ одним из способов: (1) сканирование стикера заказа (QR/ШК) — рекомендуется; (2) сканирование ШК товара → выбор заказа из списка; (3) сканирование КИЗ/DataMatrix | Заказ идентифицирован |
| 3 | Отсканировать остальные товары заказа для возврата + печать этикеток | Товары отмечены к возврату |
| 4 | Нажимает «Возврат получен» | Автовозврат остатков на склад с исходной закупочной ценой и прежней ячейкой; заказ → статус «Возврат получен» |
| 5 | (Частичный возврат) Возвращает только отсканированные позиции | Только они возвращаются на остаток |

| 8 | При необходимости — вводит КИЗ в оборот обратно (Маркировка → Коды маркировки → «Возврат в оборот») | Статус кода → «Введён в оборот» |

- **Интеграции:** МП (стикеры заказов), Честный Знак (возврат в оборот), ТСД/сканер.
- **Бизнес-правила:** Автовозврат остатка только при отмене до сборки («Новый»/«На сборке»); при отмене продавцом или возврате — вручную; возвращённые товары учитываются по дате первоначальной приёмки (FIFO/FEFO); возвраты и брак не учитываются в аналитике; для МойСклад — только через возвратный документ.

## WF-12. AI-стратегии и «Рука на пульсе по-товарно» (управленческие решения)

|---|---|---|

| 9 | Фиксирует действия в «Комментарии» и «Стратегии» | Ежедневная планёрка: только красные стрелки → тултип → решение → комментарий → проверка динамики на следующий день |

## WF-17. Аналитика и финансы: P&L, юнит-экономика, налоги

- **Модуль:** Аналитика и финансы
- **Триггер:** Селлер оценивает прибыльность по всем МП и организациям.

| № | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | Подключает интеграцию с МП (API-ключ) | SelSup загружает операции за последние 3 месяца (продажи/заказы — каждые 30 минут) |
| 2 | Заполняет закупочные цены в «Ценах» (обязательно для себестоимости/прибыли) | Себестоимость = `закупочная + доп. расходы`; при FIFO — по партиям |

| 4 | Изучает детализацию налога и расходов на МП; при необходимости «Дополнительно → Перезагрузить аналитику» (только для одной организации) | Пересчёт аналитики |

| 6 | (Налоги) «Настройки → Мои организации» → система налогообложения (УСН Доходы/Д-Р, ОСНО), ставка УСН, ставки НДС (исходящий/входящий), тумблеры «Списывать себестоимость в расход», «Учитывать входящий НДС в себестоимости» | Налог отображается в P&L (с детализацией) и Товарной аналитике; для ОСНО ставка НДС — из карточки товара; при ненулевом НДС формируется УПД нового формата |

| 8 | (Сверка) Скачивает «Скачать финансовый отчёт» (Excel); в ЛК МП открывает соответствующий отчёт → сопоставляет по маппинг-таблице | Учитывает особенности (СПП, реклама WB Продвижение, расхождения дат списания, разные статьи API vs интерфейса) |

- **Интеграции:** WB (еженедельно/ежедневно, реклама из API «Продвижения», «Джем» для всей истории), Ozon (раз в месяц + Ozon Performance), Яндекс Маркет (раз в неделю), МегаМаркет (только ручная загрузка), 1С (выписка банка), ЦБ РФ (курс валют).

## Сквозные сущности и интеграции (общие для большинства воркфлоу)

**Сквозные сущности:**
- **Организация** (ИНН, налогообложение, тип тарифа FBO/FBS/DBS, ID в ЭДО) — контейнер товаров и ключей API.
- **Карточка товара (модель → цвет → размер)** — единый внутренний справочник PIM с тумблерами публикации на МП.
- **SKU** — внутренний ID учёта остатков; одинаковый у объединённых по остатку карточек.
- **Остаток (партия)** — партионный учёт с закупочной ценой, GTIN, сроком годности, ячейкой; FIFO/FEFO.
- **Заказ (FBS/FBO/DBS/опт/розница)** — с внутренними статусами SelSup и синхронизацией с МП после отгрузки.

## Кросс-воркфлоу бизнес-правила (ключевые ограничения)

1. **SelSup — единый центр управления;** модуль 1С работает через API SelSup, не с МП напрямую.
2. **Статусная модель заказов:** до отгрузки внутренние статусы SelSup не передаются на МП; после — синхронизируются.
3. **Матчинг товаров:** приоритет по ШК, затем по артикулу МП; комбинация «Артикул+Цвет+Размер» уникальна.
4. **Партионный учёт FIFO:** каждая приёмка создаёт остаток с уникальным ID; себестоимость по FIFO (3 режима).
5. **Защита от обнуления:** «Синхронизировать остатки» включать после корректного переноса; защита 50% при дропшиппинге.
6. **Маркировка:** для операций нужны ТНВЭД + тип категории ЧЗ + GTIN; ИНН производителя обязателен; коды выдаются ровно по количеству; криптохвост удаляется после ввода.
7. **Цены:** не меняются автоматически без действия пользователя (кроме репрайсера и защиты от автоакций Ozon); мин. цена только снижается.
8. **FBO:** статусы/материалы отгрузок FBO не передаются МП по API (кроме Ozon до таймслота) — меняются вручную; остатки FBO по API — только WB/Ozon.
9. **Тарификация SKU:** 1 товар на 5 МП = 1 SKU; разные размеры/цвета = разные SKU; 1 организация = 1 ключ API МП.
10. **Аналитика:** глубина по API — 3 месяца (больше — по подписке/ручной загрузке); налог от «Выручки после СПП»; SelSup не заменяет бухгалтера.
