# Интеграции SelSup

> Матрица интеграция SelSup для воссоздания функционала продакт-менеджером.
> Источники: спецификации `product/specs/integrations-marketplaces.md`, `integration-1s-moysklad.md`, `marking-labels.md`, `ai-modules.md`, `prices-strategies.md`, `stocks-inventory.md`, `orders-assembly.md`, `fbo-deliveries.md`, `crm-customers.md`, `analytics-finance.md`, `automation-tasks.md`, `purchasing-production.md`, `support-misc.md`, `onboarding-account.md`, `product-cards.md`, `import-export.md` (сводка по 419 статьям базы знаний корпуса `product/corpus/`).

SelSup — единый центр управления продажами на маркетплейсах. Все внешние системы подключаются в разделе **Настройки → Интеграции**. Глубина интеграции определяется API самого сервиса: где API не даёт функцию — SelSup её не предоставляет. Объём операций (карточки / цены / остатки / заказы / маркировка / документооборот) указан по каждой площадке.

**Принципы работы интеграций (общие):**
- **Многокомпанийность:** ключ/токен привязывается к конкретной организации; интеграция настраивается поочерёдно для каждой.
- **Статусы настройки:** «Настроить» / «Уже настроено» / «Частично настроено» (по организациям).
- **Уведомления о невалидных токенах:** для каждого просроченного/отозванного ключа — отдельное уведомление с кнопкой «Перейти к настройкам».
- **Ключи копировать только кнопкой копирования** (не выделением); выбирать правильный тип токена (WB — все типы; Ozon — «Admin»; Яндекс — «Полное управление», аккаунт «Владелец»).
- **Привязка ключа к аккаунту:** один магазин — один аккаунт; подключение того же магазина на другом аккаунте блокируется; удаление ключа из кабинета не освобождает его для других аккаунтов.
- **Обновление данных:** заказы/продажи — каждые 30 минут (автоимпорт FBS-заказов — фоном ~раз в 2 минуты); цены/остатки — ежеминутно (и после ручных изменений); обращений CRM — каждые 10 минут; финансы — по расписанию маркетплейса (WB раз в неделю/день, Ozon раз в месяц, Яндекс раз в неделю).
- **Тарификация:** часть интеграций — в базовом наборе бесплатно, часть — за помесячную плату (7 дней пробного периода), часть — индивидуальная разработка.

## 1С

SelSup — единый центр управления продажами; модуль 1С работает через API SelSup, а не напрямую с маркетплейсами.

**Два способа обмена 1С ↔ SelSup:**

1. **Расширение конфигурации (модуль SelSup для 1С)** — основной рекомендуемый способ. Реализует API SelSup, проверен на безопасность, опубликован на GitHub (`https://github.com/SelSup/1C`). Файлы расширения: `ИнтеграцияСSelSup.cfe` (УТ/КА/ERP), `ИнтеграцияСSelSupУНФ.cfe` (УНФ), `ИнтеграцияСSelSup_БП.cfe` (БП); файлы обработок автообмена: `ОбменSelSup_УТ.epf`, `ОбменSelSup_УНФ.epf`, `ОбменSelSup_БП.epf`.
   - **Поддерживаемые конфигурации:** 1С:УНФ 3.0+, 1С:КА 2.5+, 1С:УТ 11.4+, 1С:БП 3.0+, 1С:ERP, 1С:Розница, 1С:Ювелирное дело; для Узбекистана — отдельный модуль на базе УНФ; для 1С:Fresh — через аудит.
   - **Требования:** платформа ≥ 8.3.22; клиент-серверная база (не файловая, не демо — нет авторегламентного обмена).
   - **Что делает (направление данных, двустороннее):**
     - **1С → SelSup:** товары/карточки (создание/редактирование, фото, атрибуты, категории, бренды), цены, остатки (приоритет списания из SelSup), маркировки, статусы заказов, отчёты комиссионера.
     - **SelSup → 1С:** заказы FBS (автосоздание документов), реализации/расходные накладные, передачи на комиссию (для Яндекса — «Реализация товаров»), счёт-фактуры, возвраты («Возврат товаров от покупателя»), поступления (опция «Создать приобретение к заказам»), полный пакет документов для собственного производства.
     - **Сборка заказов FBS прямо в интерфейсе 1С** (рабочее место сборщика, эмуляция клавиатуры сканером) — скорость сборки +80%; печать этикеток из 1С; лист сборки.
   - **Сопоставление товаров:** одна схема (не комбинируется): `Код_Артикул1C`, `Артикул_Артикул1C`, `Код_АртикулOZON`, `Артикул_АртикулOZON` и аналоги для WB/Яндекса/МегаМаркета. Результат — заполненный «Идентификатор 1С» в карточке SelSup.
   - **Связи справочников:** организации SelSup ↔ 1С; склады SelSup ↔ 1С (приоритет списания); категории; бренды.

2. **Обмен по CommerceML 1/2** — устаревший/резервный способ (SelSup подключается к 1С как интернет-сайт). Файлы `import.xml` (каталог/карточки) и `offers.xml` (остатки и цены), опционально `prices`/`rests`.
   - Направление: 1С забирает из SelSup только заказы; товары и остатки из SelSup в 1С автоматически не уходят (нужна отдельная доработка).
   - Ограничения: проблемы с резервированием остатков, нет авто-создания реализаций, нет авто-отмены заказов; CommerceML не поддерживает «Файлы/Картинки». Подходит для устаревших/кастомных конфигураций без модуля.

**Бизнес-правила:** модуль не ставится на демо/файловые базы; обмен остатками должен передавать только изменения (полную выгрузку — раз в день, товары — не чаще раза в час/день); для создания нового товара из 1С нужны обе выгрузки (`import.xml` затем `offers.xml`); при сильных доработках базы — аудит.

## Честный Знак (маркировка)

Полный цикл обязательной маркировки товаров через ГИС МТ / СУЗ / Национальный каталог.

**Что делает (двусторонний обмен):**
- Создание и подписание карточек в Национальном каталоге (отправка в архив вместо удаления); модерация и публикация.
- Заказ кодов маркировки (КИЗ) через СУЗ (заказ ≤ 10 позиций, отдельный заказ на каждый тип — единица/комплект/набор/групповая упаковка); выдача ровно по количеству товаров.
- Ввод кодов в оборот (способы: Производство, Импорт, Маркировка остатков, Перемаркировка, Комиссия от ФЛ); вывод из оборота (по FBS — выкупленные заказы; по FBO — импорт 10-го отчёта WB «Отчёт по товарам с обязательной маркировкой» по API/Excel); возврат в оборот.
- Отчёт о нанесении маркировки (для категорий, кроме одежда/обувь/парфюмерия/шины/электроника).
- Резервирование свободных кодов; передача кодов между своими организациями (УПД, обе организации в «Мои организации», владелец по ИНН).
- Агрегация кодов (наборы/комплекты, агрегация комплекта в заказе, задание «Агрегация» — ≥ 2 кода, GLN = первые 7 цифр).
- Автоотслеживание смены организации кода; импорт карточек и кодов из ЧЗ; обновление статусов.

**Направление данных (двусторонний):**
- **ЧЗ → SelSup:** коды маркировки, статусы кодов, дата производства/срок годности, карточки нац. каталога, товарные группы.
- **SelSup → ЧЗ:** карточки (подписание ЭЦП), заказы СУЗ, документы ввода/вывода/возврата, отчёт о нанесении, агрегация, УПД.

**Связанные интеграции (маркировка):**
- **ЭЦП / КриптоПро CSP + КриптоПро ЭЦП браузер-плагин** — УКЭП (усиленная квалифицированная, обычная не подойдёт); подписание карточек, документов, получение токена ЧЗ (действует 10 часов) и идентификатора соединения.
- **GS1 RUS** — получение GTIN (коды на «46…»), GLN организации (для агрегации); бесплатно до 100 карточек, далее 3000 ₽/год через Национальный каталог (24000 ₽ напрямую).
- **Меркурий** — ручной ввод номера ВСД для ветеринарных товаров (автоподтягивания нет).
- **Маркетплейсы** — авто-передача кодов на WB, Ozon, Яндекс.Маркет, МегаМаркет при сканировании в заданиях «Комплектация/Сборка заказов»; импорт маркировки из Ozon; настройки форматов этикеток (58×40 / 58×80; WB по умолчанию, Ozon — в ЛК, Яндекс — в SelSup).
- **ЭДО** — формирование и отправка УПД / УПД ДОП (с маркировкой / полный) через ЭДО-операторов (Контур.Диадок — только ручная загрузка файла, отправка из SelSup недоступна; ЭДО Лайт — ID абонента в «Мои организации», нельзя менять имя файла; СБИС).

**Настройки SelSup:** тумблер «Работать с Честный знак», OMS Id, «Получить идентификатор соединения», «Получить Токен», «Проверить СУЗ». Стоимость кода — 60 коп. с НДС. Срок вывода из оборота: 3 рабочих дня (продажа конечному потребителю FBS) или 30 календарных дней (порча/утрата/возврат/инвентаризация).

## Открытые вопросы / чего не хватает в доках

1. **Точные форматы API и контракты** — в статьях описаны поля учётных данных и шаги настройки, но нет схем API-запросов SelSup, эндпоинтов, форматов YML, Excel-файлов массового редактирования, акта приёмки WB, УПД ДОП (.xml), JSON-конфигурации API Core, XML СБИС. Требуется реверс-инжиниринг или доступ к реальным файлам.
2. **Детальный mapping статусов заказов** — упоминается для Lamoda/WooCommerce/МегаМаркета, но полная таблица соответствия статусов каждой площадки статусам SelSup не приведена.
3. **Расписание и гарантии синхронизации** — разные статьи указывают «раз в 2 минуты», «каждые 30 минут», «каждые 15–30 минут»; полное расписание фоновых задач по всем площадкам не приведено.
4. **Идемпотентность и retry-политики** — не описаны поведение при частичных сбоях, разрешение конфликтов при одновременном изменении остатков, очереди.
5. **Лимиты и тарифы** — упомянуты точечно (Почта России 1500 ₽/мес, Avito доп. оплата, фулфилмент от тарифа «Бизнес», индивидуальная разработка, лимиты организаций), но полная сетка тарифов/лимитов не приведена.
6. **Безопасность токенов и аудит** — не описано хранение токенов, ротация, журналирование действий по интеграциям, RBAC на уровне интеграций.
7. **Версионирование API маркетплейсов** — для AliExpress прямо сказано, что разработка не поддерживается; для остальных нет политики поддержки версий и миграции.
8. **Глубина PIM-связок и правил параметров** — упомянуты «правила заполнения параметра в зависимости от другого» (WB→Avito цвет), но конструктора правил в корпусе нет.
9. **Покрытие AI** — AI-Стратегии только для WB; расчёт поставок только WB/Ozon; сроки расширения на другие МП не указаны. Параметры AI-моделей (лимиты промтов, разрешения/форматы фото/видео, длительность видео) не раскрыты.
10. **Amazon / М.Видео / Uzum / Детский мир** — подключаются через поддержку; нет публичной документации по их API и ограничениям.
11. **Интеграция с 1С в части маркировки и закупок/себестоимости** — в статьях модулей не раскрыта детально.
12. **СБИС / МойСклад / СБИС XML** — не описаны конкретные вызовы API МойСклад и полная структура XML СБИС.
