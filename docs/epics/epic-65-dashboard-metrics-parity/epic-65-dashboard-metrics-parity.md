### Раздел 1: ПРИБЫЛЬ (розовый фон — ухудшение)

| #   | Метрика                             | Формат значения | Формат сравнения | Пример                                  |

| 1   | **Чистая прибыль / Маржинальность** | `₽ / %`         | `±₽ (±%)` ↗↘     | 40 794 ₽ / 24,21% · -27 516 (-40,28%) ↘ |
| 2   | **Прибыль / Марж. без опер. расх.** | `₽ / %`         | `±₽ (±%)` ↗↘     | 40 794 ₽ / 24,21% · -27 516 (-40,28%) ↘ |

**Формулы**:

- Чистая прибыль = Продажи − Все расходы − Себестоимость − Опер. расходы − Налоги
- Маржинальность = Чистая прибыль / Реализация × 100
- Прибыль без опер. расх. = Чистая прибыль + Операционные расходы

## UX-паттерны конкурента

### 1. Цветовая кодировка фона карточек

- **Розовый/красный** — метрика ухудшилась (расход вырос или доход упал)
- **Зелёный** — метрика улучшилась (расход снизился или доход вырос)
- **Серый/нейтральный** — нет данных или нет изменений

### 2. Формат двойного значения

Почти каждая карточка показывает **два значения через `/`**:

- `₽ / %` — абсолютное значение + процент от выручки (или маржинальность)
- `₽ / шт` — сумма + количество
- Пример: `23 748 ₽ / 14,09 %`

### 3. Формат сравнения с прошлым периодом

- Абсолютная разница: `±число`
- Процентная разница: `(±%)`
- Стрелка направления: `↗` (рост) или `↘` (падение)
- Цвет: красный (ухудшение) / зелёный (улучшение)
- Пример: `-1 907 (-7,43%) ↘`

### 4. Тултипы-разбивки

Некоторые виджеты имеют иконку `[📋 N]` — при клике показывают подкатегории:

- **Логистика: 4** — разбивка по типу перемещения
- **Комиссия: 3** — скидка МП / номинальная / эквайринг
- **Остатки: 3** — на складах / в пути к / в пути от
- **Налоги: 1** — (не раскрыто на скриншотах)

### 5. Кнопка "Импорт"

На карточке "Хранение" есть кнопка "↑ Импорт" — возможность загрузить данные по хранению вручную.

### 6. Настройка виджетов

Сверху справа кнопка "⚙ Настройка виджетов" — пользователь может выбрать, какие карточки показывать.

### 7. Layout

- Сетка 3 колонки на десктопе
- Каждый ряд — логическая группа метрик
- Порядок: от P&L верхнего уровня → к деталям и средним

## Предварительная приоритизация (Stories)

### Wave 1: Расчётные метрики (только фронтенд)

Не требуют нового бэкенда, считаются из имеющихся данных:

- 65.1: Процент выкупа
- 65.2: Средние показатели (цена продажи, логистика/шт, прибыль/шт)
- 65.3: ROI
- 65.4: ДРРз (реклама от заказов)
- 65.5: Возвраты (₽/шт) — данные уже в fulfillment

### Wave 2: Подкатегории с тултипами

- 65.6: Логистика — разбивка по 4 типам (нужен бэкенд)
- 65.7: Комиссия — разбивка: скидка МП / номинальная / эквайринг
- 65.8: Настройка виджетов (пользователь выбирает, что показывать)

### Wave 3: Новые данные (бэкенд + WB API)

- 65.9: Остатки + капитализация (WB Stocks API)
- 65.10: Оборачиваемость (зависит от остатков)
- 65.11: Налоги и налоговая база
- 65.12: Штрафы и компенсации (отдельно от комиссий)
- 65.13: Реализация (отдельная метрика)
- 65.14: Операционные расходы (пользовательский ввод)

### Wave 4: UX-улучшения

- 65.15: Цветовая кодировка фона карточек (красный/зелёный)

## Заметки

1. **Отличие "Реализация" от "Продажи"**: В WB "Реализация" = полный отчёт по реализации (включает возвраты, сторно). "Продажи" = только выкупы. Наш `sale_gross` ближе к "Продажи".

2. **Скидка МП** — это возврат продавцу части скидки, которую WB берёт на себя. Может быть отрицательной в итоге комиссии (как в примере: -8 872 ₽). Наше поле `wb_commission_adj` вероятно содержит это значение.

3. **Налоги** — конкурент рассчитывает налоги автоматически на основе налоговой базы и выбранной системы налогообложения (УСН 6%, 15%, ОСН). Для нас это новая функциональность.

4. **Операционные расходы** — вводятся пользователем вручную (аренда, зарплата, и т.д.). Конкурент позволяет их учитывать в P&L.

5. **Оборачиваемость** — ключевая метрика для управления запасами. Требует данных об остатках из WB Stocks API.
