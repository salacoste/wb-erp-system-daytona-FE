## 🚀 Запуск проекта в PM2

### Предварительные требования

1. **Node.js 20.x или выше** установлен
2. **PM2** установлен глобально:
   ```bash
   npm install -g pm2
   ```
3. **Backend API** должен быть запущен и доступен

### Шаг 1: Подготовка окружения

```bash
# Перейти в директорию проекта
cd /Users/r2d2/Documents/Code_Projects/wb-repricer-system-new/frontend

# Установить зависимости (если еще не установлены)
npm install

# Создать .env.local файл (если еще не создан)
cp .env.example .env.local

# Отредактировать .env.local с вашими настройками:
# NEXT_PUBLIC_API_URL=http://localhost:3000
# Примечание: URL без /api - endpoints начинаются с /v1/
# NEXT_PUBLIC_APP_NAME=WB Repricer System
# NEXT_PUBLIC_APP_VERSION=1.0.0
```

### Шаг 2: Сборка production версии

```bash
# Собрать production build
npm run build

# Проверить что сборка успешна
# Должно быть: "✓ Compiled successfully"
```

### Шаг 3: Создание PM2 ecosystem файла

Создайте файл `ecosystem.config.js` в корне проекта:

```javascript
module.exports = {
  apps: [
    {
      name: 'wb-repricer-frontend',
      script: 'node_modules/.bin/next',
      args: 'start',
      cwd: process.cwd(),
      instances: 1,
      exec_mode: 'fork',
      env: {
        NODE_ENV: 'production',
        PORT: 3100,
      },
      error_file: './logs/pm2-error.log',
      out_file: './logs/pm2-out.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss Z',
      merge_logs: true,
      autorestart: true,
      max_restarts: 10,
      min_uptime: '10s',
      watch: false,
    },
  ],
};
```

**Примечание:** Файл `ecosystem.config.js` уже создан в корне проекта с правильной конфигурацией для порта 3100.

### Шаг 4: Запуск через PM2

```bash
# Запустить приложение
pm2 start ecosystem.config.js

# Или запустить напрямую:
pm2 start npm --name "wb-repricer-frontend" -- start

# Проверить статус
pm2 status

# Посмотреть логи
pm2 logs wb-repricer-frontend

# Посмотреть логи в реальном времени
pm2 logs wb-repricer-frontend --lines 50
```

### Шаг 5: Настройка автозапуска (опционально)

```bash
# Сохранить текущую конфигурацию PM2
pm2 save

# Настроить автозапуск при перезагрузке системы
pm2 startup
# Выполните команду, которую PM2 покажет
```

### Полезные PM2 команды

```bash

pm2 stop wb-repricer-frontend

# Перезапустить приложение
pm2 restart wb-repricer-frontend

pm2 monit
```

## 🆘 Troubleshooting

### Проблема: Приложение не запускается в PM2

**Решение:**
```bash
# Проверить логи
pm2 logs wb-repricer-frontend --lines 100

# Проверить что порт не занят
lsof -i :3100

# Пересобрать проект
npm run build
pm2 restart wb-repricer-frontend
```

### Проблема: CORS ошибка - "Access-Control-Allow-Origin"

**Симптомы:**
- В консоли браузера ошибка: `has been blocked by CORS policy`
- `Access-Control-Allow-Origin` header имеет значение `http://localhost:5173`, но frontend на `http://localhost:3100`

**Решение:**
1. **КРИТИЧНО:** Backend должен разрешить запросы с `http://localhost:3100`
2. См. детальные инструкции: `docs/request-backend/03-fix-cors-for-frontend-port-3100.md`
3. После исправления на backend перезапустить: `pm2 restart wb-repricer-api`
4. Очистить кеш браузера (Ctrl+Shift+R)

**Быстрая проверка:**
- Открыть Network tab в DevTools
- Найти OPTIONS или POST запрос к `/v1/auth/login`
- Проверить Response Headers: должно быть `Access-Control-Allow-Origin: http://localhost:3100`

### Проблема: API запросы не работают

**Решение:**
1. Проверить `NEXT_PUBLIC_API_URL` в `.env.local` (должно быть `http://localhost:3000` без `/api`)
2. Проверить что backend запущен и доступен: `pm2 status`
3. Проверить CORS настройки на backend (см. выше)
4. Проверить Network tab в DevTools для деталей ошибок
5. Проверить что backend отвечает: `curl http://localhost:3000/v1/health`

### Проблема: Токен не сохраняется

**Решение:**
1. Проверить что localStorage доступен (не в приватном режиме)
2. Проверить DevTools → Application → Local Storage → `auth-storage`
3. Проверить что Zustand persist middleware работает
